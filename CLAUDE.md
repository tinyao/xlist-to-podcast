# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pip install -r requirements.txt           # install deps
python -m generate                         # run pipeline (respects publish_hour)
python -m generate --force                 # ignore publish_hour, force generate
python -m generate --podcast <ID>          # only process one podcast
python -m generate --force --podcast <ID>  # combine flags
```

## Architecture

### Overview
Serverless pipeline that turns an X (Twitter) List into a daily podcast. Podcasts are defined in `podcasts.yaml`, generated by GitHub Actions (or locally), and stored on Alibaba Cloud OSS.

```
podcasts.yaml → generate.py (GitHub Actions) → OSS/CDN → feed.xml → Podcast clients
```

### Project structure
```
├── generate.py          # CLI entry point (GitHub Actions runs this)
├── podcasts.yaml        # Podcast definitions
├── app/
│   ├── config.py        # Pydantic BaseSettings, reads .env
│   ├── storage.py       # JSON file-based storage (Podcast/Episode models)
│   ├── pipeline.py      # Core logic: fetch tweets → LLM → TTS → feed
│   ├── main.py          # Minimal FastAPI for local static file serving
│   └── services/
│       ├── twitter.py   # X API v2 client
│       ├── llm.py       # LLM content generation
│       ├── tts.py       # OpenAI TTS
│       ├── feed.py      # RSS feed generation
│       └── oss.py       # Alibaba Cloud OSS upload/download
├── requirements.txt
├── .github/workflows/generate.yml  # Hourly cron + manual dispatch
└── .env.example
```

### generate.py flow
1. Load podcast configs from `podcasts.yaml`
2. Bootstrap each podcast: write local `podcast.json`, restore episode index from OSS
3. Check Asia/Shanghai current hour vs `publish_hour` (skip with `--force`)
4. Call `generate_episode()` from `pipeline.py`
5. Upload episode index: `{id}/episodes/index.json`

### OSS file layout
```
{podcast_id}/
  feed.xml                                 # RSS feed
  episodes/
    index.json                             # episode list index (no script field)
    {YYYY-MM-DD}/
      episode.json  posts.md  script.md  audio.mp3  shownotes.md
```

### Key design decisions
- **No frontend / no server** — RSS feed is the product. GitHub Actions cron replaces APScheduler. OSS replaces local file serving.
- **Config as code** — `podcasts.yaml` in repo, not UI-created.
- **Blocking calls** in the pipeline use `asyncio.to_thread()`.
- **Episode index** (`episodes/index.json`) contains pre-computed URLs since Pydantic `@property` fields don't serialize.
