# AI Builders Daily 节目文稿分析与 Prompt 改进建议

> 基于 2026-03-04 至 2026-03-16 共 12 期节目文稿的系统性分析

---

## 一、整体质量评价

文稿整体质量很高：信息密度好，策展人视角鲜明，口语化表达自然，选题判断力强。以下分析聚焦于"听 12 期之后能感知到的模式化问题"，这些问题单期听不明显，连续听就会产生疲劳。

---

## 二、核心问题分析

### 1. 结构高度模板化，听感可预测

每期严格遵循同一骨架，连续收听后节奏感完全可预期：

| 环节 | 固定模式 |
|------|---------|
| 开场 | "今天是X月X日，欢迎收听 AI Builders Daily。今天我们要聊三件事：A、B、C。" |
| 主体 | 恰好 3 个重点 segment，每个 2-4 分钟 |
| 过渡 | "好，我们来聊/看第二个话题" |
| 快讯 | "好，我们进入今天的快讯环节" |
| 收尾 | "如果今天只带走一个 takeaway…" + "记得订阅，明天见" |

**问题**：像在听同一集的变体，而不是每天都有新鲜感的节目。真人播客主播会自然地变化节目节奏——有时候某天只有一个大事件值得深聊 8 分钟，有时候全是快讯没有深度话题，但当前 prompt 强制了固定结构。

### 2. 过渡词和连接句重复率极高

以下短语在 12 期中反复出现，部分每期出现 2-3 次：

- "好，我们来聊/来看/来说…" — 几乎每个 segment 切换都用
- "我觉得…" — 12 期中出现超过 40 次
- "值得注意的是…" / "值得单独拎出来说" — 高频
- "这是一个信号" / "这个信号…" — 12 期中出现约 20 次
- "这不是一个遥远的趋势" / "这不是科幻" — 多次
- "说到这里/说到这个…" — 过渡万能句
- "这条推文的收藏量超过 X" — 几乎每个 segment 都引用互动数据

### 3. 互动数据引用过于频繁，变成了"填充物"

几乎每个话题都会引用推文的点赞数、收藏数、书签数。例如：

> "这条推文拿到了超过3600个赞，2000多个书签"
> "两千三百零一个点赞，三百八十六个收藏"
> "接近六千个点赞，四百多次转发，五千八百个书签"

偶尔引用数据来说明关注度是合理的，但当每个话题都这样做，它就变成了噪音。听众会疲于这些数字，而且点赞数的绝对值对听众来说缺乏参考系。

### 4. 人物介绍的不一致

频繁出现的人物（Peter Steinberger、Aaron Levie、swyx、Thariq、郭宇）的介绍方式不稳定：
- 有时每次都完整介绍："Vercel 的 CEO Guillermo Rauch"
- 有时假设听众已知："swyx 在推特上说"
- 对于连续几天都出现的人物，没有建立"老朋友"的熟悉感

### 5. 话题连续性处理仍有改进空间

尽管 prompt 已有"话题连续性"部分，且回顾机制有效，但实际效果仍不够理想：
- Karpathy 的 autoresearch 从 3/7 到 3/11 连续 5 期都是重点 segment，虽然每天有新进展，但听感上仍然像"Karpathy 专题周"
- 某些跨天的话题，衔接语不够自然："我们昨天聊过…" 出现时有时无

### 6. 收尾 takeaway 经常是对正文的重复总结

收尾的 "takeaway" 在很多期只是将某个 segment 的结论换个说法再讲一遍，缺乏升华或新视角。比较好的例子是 3/9 期（引用了 Karpathy 的原话作为 takeaway），较差的是直接总结"今天最大的感受是：工具层正在发生重构"——这在正文里已经说过了。

### 7. 快讯板块长度不稳定

prompt 要求快讯每条 20-40 秒，但实际产出中部分快讯超过了 100 字，接近一个迷你 segment。特别是 3/6、3/9、3/11 期的快讯板块，多条超长。

### 8. 缺乏听感变化的"呼吸感"

- 没有幽默/轻松的小段（偶尔提到但很少）
- 没有"今天例外地只聊一件事"的变化
- 每期都试图覆盖尽可能多的内容，导致信息密度持续偏高，听众容易疲劳

## 三、Prompt 改进建议

### 改进 1：放松结构约束，允许灵活变化

**现有 prompt：**
> 重点 Segment（每个 2-4 分钟，总共约 8-10 分钟）

**建议改为：**
```
重点 Segment（总共约 8-10 分钟）：
- 通常 3-5 个话题，但不必每期固定数量
- 如果当天有一件特别重大的事，可以只用 1-2 个主题深入展开
- 如果当天没有特别突出的大事，可以用更多中等篇幅的话题组合
- 话题之间的篇幅要有张弛，不要每个都 3 分钟
```

### 改进 2：增加"变化词库"约束，减少口头禅

**建议在"风格要求"中增加：**
```
- 避免在同一期中重复使用相同的过渡句。以下常见表达每期最多使用一次：
  - "我觉得"（改用"在我看来"、"我的观察是"、"坦白说"、直接陈述不加前缀等）
  - "好，我们来聊/看/说"（改用"接下来"、"说完这个"、"换个方向"、不加过渡直接进入等）
  - "值得注意的是"（改用"有意思的是"、"容易被忽略的是"、直接陈述等）
  - "这是一个信号"（改用具体描述影响，而非用"信号"这个抽象词）
- 段落与段落之间不必每次都有显式的过渡句，直接切入下一个话题有时更有节奏感
```

### 改进 3：控制互动数据引用频率

**建议在"内容策展原则"中增加：**
```
- 推文的互动数据（点赞、收藏、转发）不是必须提及的信息。只在以下情况引用：
  - 互动量本身就是新闻的一部分（如某条推文引发了远超平常的讨论）
  - 需要佐证"这件事受到了广泛关注"这个判断
  - 每期最多引用 2-3 次互动数据，不要每个话题都引用
```

### 改进 4：建立"常驻人物"机制

**建议在"风格要求"中增加：**
```
- 对于在近期节目中多次出现的人物，不需要每次都介绍身份。可以用更自然的方式：
  - 首次出现：完整介绍（"Vercel 的 CEO Guillermo Rauch"）
  - 再次出现：简短提及（"Guillermo 又发了一条"、"老朋友 swyx 说"）
  - 如果某人连续多天都有重要内容，可以用"这两天频繁出镜的 XX"来建立连续感
```

### 改进 5：强化话题连续性的"自控"机制

**建议修改"话题连续性"部分，增加：**
```
- 如果同一个人物或项目连续 3 天以上成为重点 segment，第 4 天开始除非有重大突破，否则降为快讯处理
- 对于持续数天的话题，优先使用"进展更新"的形式，一两句话衔接背景后直接讲增量，而不是作为独立的新 segment 重新展开
```

### 改进 6：提升收尾 takeaway 的质量

**建议修改"收尾"部分：**
```
收尾（约 15-30 秒）：
- 不要简单重复正文中某个 segment 的结论
- 好的 takeaway 应该是：跨主题的洞察、一个引人思考的问题、一句值得记住的引用、或者对听众的具体行动建议
- 可以偶尔不做 takeaway，改为提一个开放性问题留给听众思考
- 引导订阅的方式也要有变化，不要每次都是"记得订阅，明天见"
```

### 改进 7：增加"呼吸感"的引导

**建议在"播客结构"中增加：**
```
- 允许偶尔插入一个轻松的"花絮"或有趣的小观察，调节节奏
- 如果某个话题有幽默或反差的角度，不要回避，大方地笑一下或者调侃一句
- 整期的信息密度不必均匀分布——开头可以密一些抓住注意力，中段可以稍微松一些，快讯板块再拉上来
```

### 改进 8：严格控制快讯长度

**建议修改"快讯板块"部分：**
```
快讯板块（每条严格控制在 1-2 句话，30 秒以内）：
- 只说"发生了什么 + 一句话为什么值得知道"
- 如果发现某条快讯需要超过 2 句话才能说清，要么提升为重点 segment，要么砍掉多余的分析
- 快讯总数控制在 3-6 条，宁少毋多
```

## 四、开场白的变化方案

当前每期都是"今天是X月X日，欢迎收听 AI Builders Daily。今天我们要聊三件事：A、B、C。"

建议在 prompt 中提供几种开场模式，让 LLM 轮换使用：

```
开场白（约 15-20 秒）可以采用以下任一方式，不要连续两期用同一种：
1. 关键词预告型："今天几个关键词：X、Y、Z。" 然后直接进入
2. 悬念引入型：从今天最有意思的一个细节切入，制造悬念，再说"这就是今天的节目"
3. 回顾衔接型："昨天我们聊了X，今天这件事有了新进展，而且……"
4. 直入主题型：跳过预告，直接开始讲第一个话题，快速建立兴趣
```

---

## 五、总结

当前 prompt 的核心优势是：选题判断标准清晰、话题连续性有回顾机制、输出格式规范。主要改进方向集中在三个字：**反模板化**——给 LLM 更多灵活度去调节节奏、变化表达、控制信息密度，让每期节目听起来是"同一个策展人在自然地聊天"，而不是"同一个模板填入了不同的内容"。
