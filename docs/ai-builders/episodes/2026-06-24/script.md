大语言模型开始以团队成员的身份，直接进驻 Slack 了。Claude Tag 昨天正式发布。这不再是那种你喊一声就回一句的聊天机器人，而是一个有自己身份、有记忆、会主动干活的异步实体。

Anthropic 负责该项目的 Boris Cherny 详细解释了它的工作方式：你在频道里 @Claude，它会立刻拉起一个独立的沙箱环境。它可以自己克隆代码仓库、写代码、跑测试、编译，任务完成之后直接把沙箱销毁，不留痕迹。每个频道里的 Claude 拥有独立的记忆和权限，这意味着你可以让不同频道的 Claude 扮演不同角色。

Karpathy 对这个产品给了非常明确的定义。他认为这是大语言模型人机交互的第三次重大设计变革。第一代是你自己打开网站去找模型，网站是目的地。第二代是把模型下载成本地应用。而第三代，模型变成了一个自包含的、持续在线的、异步的实体。它拿着全公司的工具和上下文，和真人团队一起工作。Karpathy 的原话说，这真的是要花点时间才能转过来弯，但它一旦跑通，极其强大。

还有个数字值得一说。Anthropic 内部已经大规模使用 Claude Tag 的早期版本。Boris 透露，他们产品团队的新代码里，有 65% 是由内部版 Claude Tag 产出的。另外，Claude Tag 的安全架构做了四层防护，涵盖模型训练阶段、顶部分类器、工具访问权限以及频道和 workspace 的边界隔离。如果你是 Claude 的 Enterprise 或 Team 用户，今天起可以在 Slack 里直接试用，更多平台随后跟上。

说到 Claude，它的设计工具和 Vercel 的整合也值得看一眼。Guillermo Rauch 昨晚转发了一条演示，现在你可以在 Claude Design 里一键把界面部署到 Vercel，从设计到上线，链路进一步压缩。这对那些依赖 AI 做前端原型的团队来说，是个挺直接的效率提升。

另一边，老朋友 swyx 昨晚对 SpaceX 的算力布局做了个数学拆解。起因是 CNBC 爆出 SpaceX 和 Reflection 签了一笔 63 亿美元的大单，Reflection 将获得 GB300 芯片用来训练开源模型。

swyx 指出，SpaceX 已经不仅仅是在造火箭了，它同时扮演着顶级模型实验室和新一代云服务商的角色。它投资 Cursor 的钱，已经有将近一半通过算力租用合同收了回来，如果 Composer 3 跑得好，剩下的一半也能覆盖掉。swyx 认为，业界目前没有第二家公司能同时吃下模型训练和云端算力这两块。这个组合极其有效，前提是你得提前规划好 GPU 的供应链——无论自家内部训练是疯长还是一般。

另一件值得说的事。Cursor 的设计师 Ryo Lu 昨天放出了他在 Cursor Compile 大会上的完整演讲视频。Ryo 在推特上写了一句很耐人寻味的话：“这是我在 Compile 上的演讲，关于我们在 AI 时代如何构建软件，以及什么不会改变。”

在演讲里，他问了一个问题。工具链正在一日千里地加速“制造软件”这件事，但“理解我们到底在帮谁解决什么问题”并没有变快。他认为，AI 让从想法到原型的路径缩短了几个数量级，这反而让那些愿意花时间去泡在用户真实使用场景里的人，获得了比以前大得多的时间窗口优势。

Ryo 不认为约束会消失。他说，代码的复杂性、用户的不可预测性、系统的脆弱性，这些限制永远都在。技术能抹平的是实现的门槛，但抹不平判断力。你得知道，什么值得做，什么不应该做。这对工程师出身的听众来说，可能不是一句新话，但在 AI 每天都能帮你多写几千行代码的今天，这个提醒显得有点扎耳。

Ryo 的整个演讲时长二十多分钟，已经上传到 YouTube。建议你如果今天有通勤之外的时间，可以拉出来看看。

接下来这段我们多说几句。
今天在 AI 圈里，有一条几乎被 Claude Tag 淹掉但是非常值得展开的推文，来自 Box 的 CEO Aaron Levie。他写了一句话，在圈子里传了一夜。他说：“几乎所有的 AI 模型和 agent 进步，都来自下游的评估。开放权重的后训练，agent 的改进，企业级的 agent 部署，最后拼的，全是评估。这将是未来每一家企业必须拥有的核心能力。”

说实话，这句话初听像是常识。你不出测评，怎么知道模型好不好。但他把话说得绝对到这个程度，还是在 agent 正在往企业生产环境里猛冲的节骨眼上，值得停下来想一下。

我们先说现场发生了什么。Aaron Levie 是在回复另一位创业者关于 agent 部署的讨论时写下这段话的。他的逻辑可以拆成三层。第一，开放权重的定向训练，最后能不能跑在你自己的数据上，完全取决于你有没有一套能和你的业务对齐的、可重复的评测。第二，agent 能力的每一次实质提升，不是来自更花哨的框架，而是因为你找到了一种新的办法去测它、去逼它犯错。第三，任何一家想把 agent 真正塞进自己业务流程的公司，最终会卡在同一个点上：你不够了解你自己的业务流长什么样，你就不可能设计出对路的评测，没有评测，agent 就永远是一个漂在生产环境外面的演示盒子。

Anthropic 负责 Claude Code 和 Cowork 的 Fiona Fung，她在 Lenny 的播客里也触及了同一类问题。她提到，最近她看到很多工程师开始陷入一种迷茫。工具链太快了，自动生成的代码量暴增，但大家反而不知道该怎么规划自己的职业能力了。Fiona 的建议是，当所有可以量化的输出都被 AI 加速，剩下的就是你对“这件事值不值得做”的判断力。而判断力，是没法靠刷榜练出来的。

我的观察是，Aaron 和 Fiona 两个人在完全不同的语境下，撞到了同一个结论。agent 的下一步不是更滑顺的多步规划，也不是更快的代码生成，而是你能不能在心里有一张清晰的地图，画出你的用户到底在经历什么，哪一步机器可以帮上忙，哪一步必须由你来喊停。这张地图，某种意义上就是 Aaron 所说的评估系统。

如果你今天在带团队，这不一定意味着马上把所有人都转成测评工程师。但你要开始留意一件事：那些能在 AI 不断改写的节奏里，依然能清晰复盘一次失败、准确指出 agent 在哪一步做错了决定的人，会比只搬运最新 prompt 技巧的人要走得远。

再说几条快讯。Google AI Studio 的产品负责人 Logan Kilpatrick 给了一个挺猛的数据：过去一个月里，人们直接在 Google AI Studio 上生成了超过一百万款原生安卓应用。一边是 Google 在推低门槛应用生成，另一边是 Replit 也在强化 vibe coding 路径。让普通人做出可运行软件的门槛，正在以月为单位往下掉。

Lenny 昨天推荐的客座文章来自 Joe Hudson，他同时给 Sam Altman 以及苹果、谷歌的高层做教练。Joe 的观点是，在这场变革里，知识越多和越努力反而不是最稀缺的筹码，因为这两样都是 AI 最擅长的事。真正拉开差距的能力是“情绪清晰度”：咬住艰难对话的能力，失败之后不自毁也不迁怒别人的能力。这篇文章放在 Lenny 的 newsletter 里，属于那种不聊技术但比技术更决定你能走多远的内容，值得一读。

最后说一个被裁之后反而拿到大量社区支持的案例。一位前谷歌工程师 Justin，因为开发了一个非官方的 Workspace CLI 工具被谷歌解雇。但这个工具在 GitHub 上拿下了数千颗星，在内部大量真实用户里传开。他从被要求和法务谈话，到眼睁睁看着谷歌在 Cloud Next 大会上宣布官方 CLI 即将到来，整个时间线只隔了两天。Peter Yang 转发了他的长文，说这个工具有用，早该被鼓掌。

这件事本身没有太多技术分析要做，但它像个微缩的切片，让我们看到 agents 进入成熟组织时必然要撞上的那堵墙——工具越有用，组织越觉得失控。你觉得呢？你所在的公司，是那种会拥抱一个野生内部工具的，还是会第一时间走合规流程的？
