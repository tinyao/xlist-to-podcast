Cognition 完成了超过 10 亿美元的新一轮融资，估值达到 260 亿美元。
领投方是 Lux Capital、General Catalyst 和 8VC。
swyx 随后发了一条很长的分析，说 Cognition 现在已经是全球最大的独立 agent 实验室。

有几个数字值得注意。Cognition 的企业客户使用量从今年年初到现在增长了超过 10 倍。
年化收入达到了 4.92 亿美元。
swyx 还提到一个他称之为"200% 利用率"的图表，说如果你对投资有兴趣，应该拿这个销售增长速度自己跑一遍模型。

不过 swyx 的重点不在这些数字本身。
他想说的是，Cognition 的壁垒不是单一模型或产品，而是一个 agent 实验室的完整体系。
这个体系里有长期的模型多样性、长期在推理和工具调用上的积累、自研的评测框架、特定领域的强化学习微调，还有完整的 agent 软件开发生命周期。
他甚至提了一句，Cognition 的首席 partner 角色，是在帮 CIO 对抗来自人和 agent 的"token 浪费"。

另一件值得说的事。OpenAI 基金会宣布了一笔 2.5 亿美元的初始承诺，专门用于 AI 经济影响的研究。
Sam Altman 亲自发布了这个消息，他说 AI 应该大幅提升全球人民的生活质量和个体自由。
这笔钱会投向三个方向：衡量、转型支持，以及探索新的共享繁荣路径。

Sam 还转发了一条 Hermeus 的超音速飞机新闻，顺便就引来了一个经典吐槽。
Factory AI 的 CEO Matan Grinberg 发推讽刺说，AI 公司的剧本已经固定了——先跟投资人说"所有工作都会被我们的模型取代，人类都是麻烦"，几周后再跟公众说"我们这家热爱人类的公司相信人类不可替代"。
Aaron Levie 倒是认真地回应了"AI 会不会导致就业末日"这个问题。

他说，硅谷之外，他接触的很多企业一边在部署 agent，一边还在招人。
企业内部需要大量的技术和工程人才来构建软件，或者充当 agent 的前向部署工程师。
Aaron 的核心论点是，agent 自动化的是任务，不是整个工作。
被自动化的任务需要有人来引导、审核、整合输出。
而在那些自动化潜力较低的领域，公司会把效率提升省下来的钱，重新投到客户销售和成功团队里。
他的结论很直白：公司不会静止不动。它们自动化能自动化的任务，然后把释放出来的资金投向下一个产生差异化的事。

Justine Moore 昨天发了一段视频，展示了一个新的视频 agent。
她只做了一件事——给 agent 发了一条 Zillow 房源链接。
agent 自己从链接里提取了图片，做了动画，配了乐，生成了一段完整的房产宣传片。
Justine 说她完全没有提供任何额外输入。
她的判断是，这种技术会彻底改变物理空间的广告方式——住宅、办公室、餐厅、酒店都算在内。

这个 demo 让人想起我们前天聊的 Runway MCP 发布。
当时 Amjad 说可以在 Replit 里直接用 Runway 生成视频。
今天再看 Justine 这个例子，你会发现视频生成正在从"需要专业 prompt 工程"变成"给一条链接就行"。
门槛降低的速度，比大多数人预想的要快。

Guillermo Rauch 昨天发了一条在圈子里传了一夜的推文。
起因是 GitHub 出了故障。Vercel 的异常检测系统在 GitHub 官方状态页更新前 16 分钟，就自动发现了部署量的骤降和激增。
Guillermo 说，尽管所有人都在谈论编程 AGI，软件基础设施仍然是一个极其困难的问题。

他接着抛出了一个很尖锐的观察。
GitHub 的团队肯定是一流的，他们也不缺模型和 agent。
别忘了，正是这家公司做出了 Copilot，AI 编程的第一个重大突破产品。
但即便如此，一句"让 GitHub 扩展，让一切都极快，别犯错"的提示词，根本不够用。

Guillermo 还调侃了一下 Codex 的 /goal 指南。
他说那份指南里真的写了一个类似的 prompt，他欣赏这种野心，也真心认为 agent 能找到一些低垂的果实——比如并发控制不足、缺数据库索引这类问题。
但对于中等复杂度的生产系统，这种 prompt 已经接近 AI 的幻觉了。
他开玩笑说，为什么不干脆让 p99.9 延迟降到 10 毫秒呢？

这条推文之所以引发共鸣，是因为它戳中了一个真实的断层。
一边是 agent 能力的快速提升，让大家觉得"让 AI 管基础设施"已经近在眼前。
另一边是任何一个真正跑过生产系统的人都知道，基础设施的复杂性不是靠更聪明的 prompt 能解决的。

Riley Brown 昨天发了一条高度相关的更新。
他说 Codex 最近的更新里，浏览器里的应用能保持登录状态了。
如果你看过 Lenny 和 Dan Shipper 那期播客，就知道这件事有多重要。
Riley 的预测是，Codex 很快会支持每个 session 里开多个浏览器标签，并且学习你为不同任务打开哪些标签。
他说这可能会完全取代他现在的浏览器使用方式。

把 Guillermo 和 Riley 的观察放在一起看，你会发现一条很有意思的线索。
agent 正在从"帮你写代码"进化到"帮你操作整个工作环境"。
但当你把 agent 放进浏览器、放进服务器、放进生产环境的时候，你面对的不再是代码对不对的问题，而是整个系统的可靠性、可观测性和故障恢复能力。
这些恰好是 Guillermo 说的"仍然极其困难"的部分。

对听众来说，这里有一个很实际的启发。
如果你正在把 agent 集成到自己的工作流里，现在就可以问自己一个问题：当 agent 搞砸了，我的回滚路径是什么？
如果答案是"我不知道"或者"手动修"，那你的 agent 集成还缺了一整层工程化的思考。
Guillermo 的话翻译过来就是：agent 能帮你做很多事，但别指望它能替你理解你的系统。
