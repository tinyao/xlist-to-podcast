AI 写的代码越多，人的手艺感消失得越快吗？一个大模型让 Vercel 的 CEO 说“改变局面”，它到底改变了什么？当我们讨论 agent 循环时，我们在害怕什么？先从最让工程师睡不着的那件事开始。

GLM-5.2 的代码能力在圈子里传了一夜。昨天 Vercel 的 CEO Guillermo 在 X 上说，他对这个由 zai_org 推出的新模型“几乎感到震惊”，认为它“改变局面”。

这不是一条普通的客套话。Guillermo 专门点出了模型在编程任务上的表现，措辞很重。目前没有公开的跑分数据，但从他的一贯发言风格看，能让他在公开渠道单独拎出来夸的模型并不多。另一边的信号也很有意思，就在同一天，Replit 的 CEO Amjad 用一条极具诗意的推文纪念了二十年的网络演变，他说“我们发了二十年帖，以为是在彼此对话。然后 Transformer 上线了，网络读完了我们写的一切，从而成了它自己。”

结合这两个消息，竞争正在从单纯的模型能力，转向模型如何与开发者已有的工作流咬合。GLM-5.2 如果真在代码这个窄域上追上了第一梯队，接下来工程团队要回答的问题就很具体了。你的发布流水线里，有没有准备好接纳第三个模型做候选？如果你现在依赖单一模型做代码生成，今天就可以拿一个典型任务跑一下 GLM-5.2，看看结果差距。

Vercel 的首页被团队彻底“烹”了一遍。Guillermo 昨天还发了一段 24 秒的视频，详细展示了他们如何优化 vercel.com 的渲染性能。他说团队用“Everything the light touches”的力度，把绘制、布局、WebGPU shader 和阻塞脚本全压了一遍，一帧一帧地审。更关键的是，他承诺接下来会把经验教训更新到 skills.sh 这个 Agent Skills Directory 上。这意味着你我可以直接让 agent 去读那些优化技巧，复用到自己的项目里。

说到 agent，HyperFrames 今天正式开源了制作发布视频的完整教程。Peter Yang 放出了对 Heygen 团队的专访和配套代码仓库。核心思路很有意思，他们没有试图训练一个“视频 agent”去理解画面构图，而是把视频制作回归到 HTML、CSS 和 JavaScript。Heygen 的 Bin Liu 解释说，agent 没有视觉智能，强行让它做视觉判断会非常痛苦。HTML 反而是 LLM 的母语，它能在代码里同时表达信息和美学。你现在只要在 Claude Code 或 Codex 里指向这个 repo，就能用一个 URL 直接生成产品发布视频。过去花三万美金的事，现在免费。

另一件值得说的事是 Peter Yang 昨天发起的一个讨论，关于 agent 循环的信任问题。他说自己对无监督的构建循环“非常怀疑”，怕 agent 趁人不注意生成一堆“slop”。他问圈子里，有没有哪些值得一试的循环用法？

这个问题很诚实。Peter 自己还贴了一个玩笑式的 agent 指令：循环执行、直到赚到 100 万美元、前提是不准卖毒品。底下有一条回复也很有意思，他说：“我是不是该让这个跑着，然后出门过父亲节？”这种看似戏谑的对话，精准地戳中了一个真实的决策困境——你敢不敢把长期任务交给一个没有你那种“害怕搞砸”的本能的系统上运行？

紧接着还有个很巧的工具思路。构建者 Zara Zhang 说自己收藏了一大堆 X 书签但从来不看。于是她做了一个浏览器扩展，每次打开 X 的时候，像广告一样往时间线里注入一条她收藏过的帖子。她说秘诀在于“劫持”了一个你每天会看 50 次的界面位置。如果你也有书签坟场的问题，这是个低成本的解法。

接下来这段我们多说几句。

今天 X 上最值得展开的话题，其实是围绕着代码质量和 AI 加速形成的一股张力。引起这次讨论的是 OpenCode 的作者 Dax Raad。

他在 Pragmatic Engineer 的采访里说了一句话，直接被 Linear 产品负责人 Nan Yu 转发引用：“质量是非理性的。” Dax 的观点很锋利，他认为现在靠 agent 工作流，产品腐烂的速度前所未有地快。一个产品上线一年，可能就已经开始变渣了。他把这归因于 agent 带来的快速产出，开发团队在享受超高吞吐量时，不自觉地把“长期整洁度”这项非理性投入给压缩了。

Dax 讲了自己团队一个反直觉的决定: 他们当时刚发布 OpenCode，要和 Claude Code 竞争，一个关键差异点就是终端体验。他们为此自己手写了整套终端框架。所有人都说不要自己写框架，这是最不理性的选择。但他们还是做了，因为不这样做，就达不到想要的那种爽感。

这个“非理性坚持”的调子一出来，Vercel 的 Guillermo 紧接着发了一条。他说代码 agent 会把你身上的“宜家效应”一点不剩地挤出来，如果你由着它来的话。所谓宜家效应，就是人对自己亲手组装的东西会赋予更高的价值判断，会本能地更用心、更在乎。Guillermo 的潜台词很明白，如果你把实现完全交给 agent，你会失去那种亲手制作的拥有感和责任感。

而设计师 jenny wen 的抱怨则从用户侧回响了这个问题。她说自己现在用一些人做的软件会火大，因为她明明知道 AI 能做得更好。这句话里隐含的期待变化值得琢磨，用户对软件质量的评判基线正在抬高，不是因为人变挑剔了，而是因为 AI 能力的上限在眼前摆着，再容忍低质量显得不合理。

这三组声音合在一起，指向一个很具体的张力：AI 让产出更快了，但“在乎”这种情绪并不会跟着变快。Dax 讲的是团队要有决心为质量做非理性投入，Guillermo 提醒的是个体如果失去组装过程就会失去在乎，jenny 则在表达受不了敷衍。

说到这，有意思的地方在于，Anthropic 的 Claude Code 团队负责人 Fiona Fung 昨天在 Lenny 的播客里也间接回应了这个问题。她透露团队现在正在招两类人：一类是有产品感的创造性 builder，另一类是深层系统专家。你仔细品，这两类人的共同点是都能做出判断。前者判断什么是好产品，后者判断系统怎么构建。他们都无法被一个只会写代码的 agent 替代。

对听众来说，与其把这个问题理解成“要不要限制 agent 用得太猛”，不如换个实用角度。你可以试着给团队的 code agent 加一条永不自动合并的规则。从代码生成到合入主线，中间必须有一道至少是人肉扫一眼的门槛。这不是不信任 agent，而是把“人在乎”这个环节，变成流水线上的一个不可跳过的硬节点。你会怎么设定你们团队的这道门槛？

再说几条快讯。

Claude 的 PM Robert Bye 展示了一个实战案例，用 Claude 结合 Autodesk Fusion 的 MCP 服务，再从 Bambu Lab 3D 打印机直接出实体。一次提示词，几小时内，一个茶包收纳盒就从想法变成了实物。这个链路的意义在于，它打通了“AI 设计 — 模型处理 — 物理制造”这三个曾需不同专业角色协作的环节。

Replit 正式招人了，方向是日本团队。Amjad 亲自转发确认。如果你或你周围的人对在日本做开发者工具有兴趣，可以留意这次机会。

Zara Zhang 还抛出一个问题：加入大公司是不是比加入初创公司风险更大？她的判断是，现在看来，大公司的稳定性叙事可能正在失效。这跟今天讨论的那种“非理性投入才能做出好产品”的声音，某种程度上是一条回路。

如果你对 agent 安全和自主循环的信任边界还有疑虑，去看看 Peter Yang 昨天那条讨论 thread 的回复区。里面有很多工程师贡献了他们在用和不用的循环类型，很实用。如果你在用 X 书签但从不回看，Zara 那个扩展思路值得动手装一下。
