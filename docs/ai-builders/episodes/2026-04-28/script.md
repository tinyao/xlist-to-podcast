OpenAI 和微软的独家云合作关系，昨天深夜被重新定义了。这意味着什么？Browser Use 反过来做了一个沙盒，agent 的基础设施层是不是在重新洗牌？Aaron Levie 提出了一个盖尔曼失忆症的 AI 版本，为什么这可能是今天关于 AI 和就业最冷静的一篇分析？先从最重磅的那条消息说起。

OpenAI 和微软的排他性云合作协议，昨天被正式松绑了。
Sam Altman 亲自发的公告。原话是，微软依然是 OpenAI 的主要云合作伙伴，但 OpenAI 现在可以把产品和服务部署到所有云上了。协议里的两条时间线很具体：OpenAI 会继续向微软提供模型和产品直到 2032 年，收入分成则持续到 2030 年。
这件事的直接影响是，OpenAI 的 API 和模型未来可以跑在 Google Cloud 或者 AWS 上。对于已经在某个云上深度绑定、但因为合规或数据驻留要求没法迁到 Azure 的团队来说，这是一个等了很久的变化。你不需要为了用最新模型而改整个基础设施的底子。
而另一层含义更微妙。Sam Altman 选择在这个时间点宣布，恰好卡在 GPT 5.5 刚发布、Codex 四百万月活、并且本周可能还有新东西要出的节奏里。当 OpenAI 从模型层向应用层越走越深，它需要摆脱基础设施层面的单一依赖。这不只是一份合同更新，是 OpenAI 作为一家公司，在给自己接下来几年的扩张铺路。

另一件值得说的事。Agent 的基础设施层，昨天出现了一个很有意思的反向操作。
郭宇半夜提了一个观察。他说，通常的逻辑是 agent 平台先做沙盒环境，再接入浏览器操控工具。但 Browser Use 昨天发布了一个叫 Browser Use Box 的新产品，缩写 bux，直接反过来——从浏览器操控出发，做了一个 24 小时不间断运行的沙盒。
这个产品的逻辑很直接。创始人 Larsen Cundric 说，他们受够了合上笔记本 agent 就消失这件事。所以把 agent 放到了服务器上。真正的 Chrome 浏览器、持久登录态、内嵌 Telegram 支持。你睡觉的时候它在跑。他举了自己的例子：订机票、回 LinkedIn 消息、处理待办清单，醒来之前全搞定了。
郭宇的评论是，他很好奇最后市面上胜出的沙盒产品会是哪个。这个问题问到了点子上。因为 agent 的基础设施层现在有两条完全相反的路径。一条是 sandbox 先行，比如 Blacksmith 或者 E2B，先提供一个安全隔离的运行环境，再往上接各种工具。另一条是应用先行，像 Browser Use 这样，从具体的浏览器操控场景切入，然后发现自己需要一个持久化的运行环境，于是反过来做了一个沙盒。两条路径最后会不会收敛到同一个产品形态？还是说，agent 的 infra 层本身就会分化成两种不同的架构？如果你在搭 agent 管线，这个选择会直接影响你选哪家的底层。

换个方向。Peter Steinberger 昨天发了一条让很多工程师感同身受的帖子。
他说最近在 OpenClaw 的开发上一直被 CPU 资源卡着。然后他试着把本地测试切到了 Blacksmith 的 Testbox 上，原话是 IT IS SO GOOD。Codex 可以直接拉起 32 核虚拟机的实例，把他的测试套件跑穿。他放了一个链接，是 Blacksmith 的 Testbox 产品页面，目前还在 Beta 阶段。
顺带说一句，Peter 的 birdclaw 也在圈子里传了一夜。这是一个把 X 推文做真正本地化存储的工具。导入你的推文存档、备份到 GitHub、还能每天自动抓取你的 X 书签——因为书签数据在 API 里拿不全。他自己说，就是想要一个真正属于本地的推文存储。如果你也在担心自己的社交数据锁在平台里出不来，birdclaw 这个工具值得看一眼。

说到郭宇，他昨天 quote 了一条很酷的实践。
有人用 Google 地图的街景和 3D 视图，结合 OpenAI 提取关键地点，再套上设计好的角色卡，调用 Seedance 的 API，自动生成了一段从起点到终点的导览视频。角色会融入沿途的标志性地点进行引导。郭宇的评论是，实话说他也没想到 AI 还能用来做这个。
这件事有意思的地方不在于技术有多深。而在于它把地图数据、视觉生成、角色扮演这三样东西串成了一条完整的管线。做出来的东西不是 demo，是直接可用的内容。如果你在做文旅、地产或者教育类的产品，这条实践路径值得仔细拆一下。

接下来这段我们多说几句。

Aaron Levie 昨天写了一篇被大量收藏的分析。他提出了一个概念，叫盖尔曼失忆症的 AI 版本。
盖尔曼失忆症原本是 Michael Crichton 提的一个说法。你翻开报纸，读到一篇你懂行的文章，发现里面错误百出。然后你翻到下一篇，讲的是你不懂的领域，你却全盘接受了。
Levie 说，AI 时代正在出现一个变体。你用自己的 AI 工具干本行，发现各种最后一公里的问题。数据拿不到、上下文不够、输出得反复审、审完还得嵌进业务流程。你对这些坑一清二楚。然后你转头看别人的工作，觉得 AI 分分钟就能替代掉。他原话是：我们倾向于严重低估让 AI 在别人的工作里同样有效所需要付出的努力。
这个观察很锋利。因为它解释了一个很奇怪的现象。为什么硅谷在说 agent 替代一切，而全球两千强的高管在说两年前花了大钱买 AI 聊天，生产力是零。
Matt Turck 昨天也发了一条呼应这个判断的推文。他说他从来没见过硅谷和传统大公司之间的认知鸿沟有这么巨大。硅谷这边：AI 在自我加速、agent 在跑一切、老年人不懂。大公司那边：工程师喜欢那个写代码的 AI 工具、其他人不关心、agent 很吓人。
Levie 的结论是，这恰恰是对很多 AI 替代就业理论保持怀疑的理由。这些理论来自于从单个任务能被 AI 做的视角出发，而不是从完整理解一份工作到底包含什么出发。Karri Saarinen 也提供了一个佐证。他说 AI 最让人惊艳的时刻，往往是你对那个领域一窍不通的时候。一旦你知道一个东西应该长什么样、应该有什么感觉，让 AI 达到那个标准就变得几乎不可能。绝对没法一次到位。
这三条放在一起，给听众的对照是很具体的。你对自己工作的复杂程度，是不是比对外部世界的判断要清晰得多？如果是的话，那别人看你的工作，是不是也在犯同样的低估？Levie 没有说 AI 不会改变就业。他说的是，改变的速度和方式，可能比那些画曲线的预测要慢、要乱、要更依赖具体行业里那个最后一公里的人。

再说几条快讯。

Lenny 昨天分享了他和 Snap CEO Evan Spiegel 对谈的十大要点。里面有两条很反直觉。第一条，Snapchat 早期增长靠的是聚焦密友，而不是最多好友。连接一个人和他最好的朋友，比把他和所有认识的人连起来更有价值。第二条，Evan 预测 AI 会遭遇显著的社会抵触。技术行业严重低估了人类对新工具的抗拒。他说，造出强大的 AI 是必要但不充分的——赢得人类信任才是更难的题。Lenny 的播客链接在 shownotes 里。

Logan Kilpatrick 昨天连发两条，强调同一件事。每一家基于 AI 做产品的公司，都应该自建 benchmark。他说 Zapier 和 Sierra 已经在做了。原话是，这里有巨大的 alpha。如果你是创始人或者业务负责人，你的团队明天就应该开始。对听众来说，这句话的背面是，如果你还在靠通用榜单选模型，对手可能已经在用自己业务数据跑出来的评估体系做决策了。

Peter Yang 周末给自己的健身 App 搭了一个 MCP Server。现在他可以在 Claude 或者 Codex 里直接拉取最新的锻炼数据、更新训练计划。他说这件事太好玩了。一个产品经理，用周末时间给自己做了一个 App Store 里找不到的私人工具。这就是 Levie 说的那种，在自己领域里把最后一公里跑通的人。

你最近在用 agent 跑自己工作流的时候，有没有碰到过一个坑，让你觉得“外面的人肯定不知道这个有多难搞”？
