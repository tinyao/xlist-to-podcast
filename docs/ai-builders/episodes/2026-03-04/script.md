今天是2026年3月4日，欢迎收听 AI Builders Daily。今天我们要聊三件事：Claude 流量爆炸式增长背后的稳定性危机、AI Agent 在生产环境里搞出的真实幺蛾子，还有正在悄悄改变软件开发流程的一个终极问题——代码审查，还有存在的必要吗？

我们先从最热闹的那条线索说起。

过去这一周，Claude 和 Claude Code 经历了一次用户们感受非常直接的事件：服务不稳定，时不时掉线。Anthropic 的 Claude Code 工程师 Thariq 在推特上正面承认了这件事，原话是"我们这周看到了前所未有的流量增长，确实难以预测"，并且说团队在"不眠不休地扩容"。

这条推文本身的数据很有意思：四千多个点赞，两百多条回复。对于一条服务公告来说，这个热度说明用户情绪是真实的。很多人已经把 Claude 当成工作流里不可或缺的一部分了。

这里有一个有趣的反差。产品经理 Peter Yang 说了一句话，我觉得说得很准："Claude 宕机可能会让整个白领阶层的生产力下降 20%。"这话听起来夸张，但你细想——有多少工程师、产品经理、内容创作者现在每天都在用 Claude Code 或者 Claude API 干活？稳定性已经不再是加分项，而是基础设施级别的要求了。

不过 Hamel Husain 也提供了一个反方视角，他说：在你批评 AI 编程工具之前，先想想 GitHub 当年宕机有多频繁。这倒也是实话。任何基础设施在快速扩张期都会有阵痛，关键是你怎么应对。

说到 Claude Code，还有一个数字值得单独拿出来说一说。Lenny Rachitsky 在推特上分享了一张截图，全球已经有超过 80 个 OpenClaw 线下 Meetup 在日历上排好了，而且还在持续增加。Lenny 的评价是："这个产品才出来几个月，我从来没见过这种情况。有什么特别的事情正在发生。"

OpenClaw 是基于 Claude Code 的开源 CLI 工具，由 Peter Steinberger 主导维护。一个命令行工具，能在全球范围内自发形成这么密集的线下社区，这在开发者工具的历史上确实罕见。这不只是产品的成功，更像是一种文化现象——开发者们在重新定义"什么叫做编程"。

好，我们来说第二个话题，这个故事非常具体，而且有点让人后背发凉。

Vercel 的 CEO Guillermo Rauch 分享了一个真实的生产事故。一个用户在使用 OpenClaw 加上 Claude Opus 4.6 做自动化部署的时候，发现自己的 Vercel 账号下突然出现了一个完全陌生的 GitHub 仓库被部署了进来。

听起来像是安全漏洞对吧？Vercel 工程团队立刻启动了安全调查。结果发现不是黑客，是 Agent 自己干的。

具体来说：Agent 在调用 Vercel API 的时候需要填一个 GitHub 仓库的 ID，这个 ID 本来应该通过 GitHub API 查询获得。但 Opus 4.6 没有去查，直接"脑补"了一个看起来合理的数字——913939401——然后填进去了。恰好这个数字对应了一个真实存在的公共仓库，于是就真的部署了。

Rauch 的总结很到位。他说，人类会犯很多错误，但人类不会随机编造一个仓库 ID。这种失败模式是 AI 特有的，和我们熟悉的 bug 完全不同。

这个案例的影响不仅仅是"模型会幻觉"这个老生常谈的问题。更深层的信号是：当 Agent 被赋予调用强大 API 的权限时，幻觉的代价会从"输出了错误文本"变成"在生产环境执行了错误操作"。这是一个量级的跃升。

Rauch 也给出了一个实践建议：在这种场景下，让 Agent 走 CLI 或者 MCP 而不是直接调用 API，可能会更安全，因为链路更透明，更容易被拦截和审查。

这件事让我想到一个更大的问题：我们现在给 Agent 的权限，到底有多少是经过认真设计的？还是说，大家都在"先跑起来再说"？

这自然引出了今天的第三个话题，也是最具前瞻性的一个讨论。

swyx，也就是 Latent Space 播客的主理人，分享了一篇文章，标题叫做"如何干掉代码审查"。他的原话是："这是 Agentic Engineering 的最终 Boss。"

逻辑是这样的：现在 AI 生成代码的速度和体量都在爆炸式增长。Pull Request 的数量和大小都在飙升。人工 Code Review 已经成为整个软件开发流水线里最大的瓶颈。那么，下一步自然就是：能不能让 AI 来做 Code Review？

文章里提出了一个五层的框架，来描述如何逐步把人从代码审查这个环节里移出去。swyx 说他自己"还没到那一步"，但他估计自己通常比这些先行者落后三到六个月。

这个讨论的背景是，Mitchell Hashimoto，HashiCorp 的联合创始人，前几天发了一条很犀利的推文："AI 公司正在以比 GitHub 变成 AI 公司更快的速度，变成 GitHub。"swyx 转发并加了一句："Holy shit，OpenAI 做到了。"

这里暗指的是 OpenAI 在代码托管和协作工具方向上的动作，虽然细节我们还不完全清楚，但这个方向的竞争已经非常明显了。

Code Review 这件事，表面上是工程流程问题，但背后是一个更根本的问题：在一个 Agent 可以自主写代码、自主测试、自主部署的世界里，人类工程师的角色是什么？是 Reviewer？是 Architect？还是 Prompter？

这个问题现在还没有标准答案，但它正在被真实地讨论和实验，不是在学术论文里，而是在一线工程团队的日常工作里。
