Vercel 的 AI Gateway 每个月能自动恢复超过一万亿个 token，它是怎么做到的？一位前 Meta L8 工程师用 agent 每天提交 40 个 PR，他公开了哪些工具？当 AI 让开发成本趋近于零，Box 的 CEO 和 iPod 之父为什么同时指向了同一个答案？先从最让工程师睡不着的那件事开始。

Vercel AI Gateway 月均恢复的 token 数超过了一万亿。
这个数字是 Guillermo 昨天亲自公布的。他说这很像 Stripe 用智能重试帮商户找回失败的付款，只不过 Vercel 找回的是被浪费的推理 token。而且他们是在零加价的基础上做到的，同时提供冗余、零数据留存、可观测性和用量 API。
对开发者来说，这意味着什么？你不需要改任何一行推理代码。只要把请求走 AI Gateway，它会在模型返回超时、格式错误或者拒绝回答时，自动换一个模型重试。一个月下来，能白捡回海量被丢弃的计算结果。
如果你已经在用 Vercel 部署 AI 应用，去后台看一眼 Gateway 的恢复面板。那个数字可能会让你吓一跳。

另一件值得说的事，是 Peter Steinberger 的月度提醒。
他昨天发了一条推文，说你不应该再给编码 agent 写提示了。你应该设计循环，让循环去提示你的 agent。
这话听起来有点绕，但逻辑很直接。过去我们像教官一样，给 agent 下达精确指令。现在他的建议是，你只需要定义目标、约束和验收标准。然后写一个外层循环，让它自己去拆解任务、生成提示、执行、检查、修正。人退到循环外面，只在关键决策点介入。
这个思路和今天另一条热门内容完全吻合。Roblox 的产品经理 Peter Yang 采访了前 Meta L8 工程师 Kun Chen。Kun 现在每天能提交超过 40 个 PR，靠的就是一套自建的 agent 工程系统。

这套系统里最核心的有三个开源工具。
第一个叫 Lavish，能把 AI 生成的计划直接渲染成可视化的 HTML 页面，方便快速审阅。第二个叫 gnhf，全称是 good night, have fun。你睡觉前告诉它目标，它会调度多个 agent 通宵工作。第三个叫 No Mistakes，是一个 AI 代码验证流水线，在合并前自动抓错。
Kun 在采访里说了一句很实在的话：如果我还在一行行审查代码，我就是瓶颈。要真正规模化地利用 agent，我们必须把自己移出循环。
如果你还在手动 review 每一行 AI 写的代码，今天这两条消息值得你停下来想一想。你现在的流程里，哪个环节是你在充当人肉胶水？那个环节，可能就是下一个该被自动化掉的地方。

换个方向。Justine Moore 昨天展示了一段视频编辑效果，挺让人意外的。
她上传了一段青蛙的视频，然后告诉 Omni 把青蛙换成一只小猫。结果除了青蛙真的变成了猫，视频里其他所有元素完全没变。光线、背景、镜头运动，一模一样。
这种精准的局部编辑能力，以前需要专业软件加大量手动遮罩。现在一句话就完成了。Justine 自己评价说，这对专业工作流会非常有用。你怎么看？你最近有没有试过用 AI 直接改视频里的某一个物体？

先把节奏放慢一点，说一下今天最值得想清楚的一件事。
起因是昨天 Box 的 CEO Aaron Levie 转发了一条推文。那条推文说，AI 让开发应用变得极其容易，但这也把准入门槛降到了零。因为谁都能做，所以代码本身不再是护城河。未来唯一的优势只剩销售和营销。
Aaron Levie 同意一半。他说，市场对 AI 吃掉企业软件这件事有误解。过去开发好软件确实很难，AI 让它变容易了一些。但要做出有品味、有差异化、高质量、安全的产品，依然很难。而更关键的是，这仅仅是构建平台的一个环节。大多数企业软件公司，大部分成本其实花在市场推广上。因为企业级软件很难靠 PLG 自己长出来，它需要大量的顾问式销售、实施和集成支持。AI 没有减少这部分需求。当开发变便宜、变丰富，发现和差异化就成了最难的事。

巧的是，Lenny 昨天也发布了一期重磅播客，嘉宾是 iPod 和 iPhone 的联合创造者 Tony Fadell。
Tony Fadell 在采访里抛出了几乎一样的观点。他说，品味是 AI 时代最大的护城河。营销和产品本身一样重要。做第一版产品时，基于观点的决策是必须的，因为数据还没出现。
他把这种危险叫做对 AI 的认知投降。意思是，如果你把所有思考和决策都外包给 AI，你就失去了建立独特品味的能力。而品味，恰恰是当所有人用同样的模型、同样的工具时，唯一分高下的地方。
前 Google 产品主管 Madhu Guru 昨天也从另一个角度补充了这个话题。他说，很多人误以为训练数据是低技能的苦力活。但真正推动模型前沿的数据，是高价值经济任务里的领域知识。这些知识没有文档，藏在老旧的、彼此不对话的工具里。这也是为什么我们有软件工程 agent，却还没有知识工作 agent。创造这种训练数据的公司，在做的事被严重低估了。

这三条线串在一起，指向同一个现实。工具和模型在快速平价化。开发一个能跑的东西，会越来越不是壁垒。但知道要做什么、怎么做才有用、怎么让需要它的人真的用上，这些事情的难度一点没降。
对听众来说，这可能是今天最值得对照检查的一点。你正在做的产品里，有多大比例是在拼开发速度，有多大比例是在拼你对问题的理解深度和你对体验的偏执？如果是前者，你的护城河可能正在被填平。

郭宇昨天在 X 上说，他接入的 DeepSeek V4 Pro 模型坚称自己是 Claude。他调侃说已经几乎不用 Claude Code 了，所以把剩余额度接进了自己做的 VAS 系统里，跑完算数。

Zara Zhang 的前端幻灯片工具在 Claude Code 社区活动上又火了一次。有人做完分享后，被一堆人追着问幻灯片怎么做的。Zara 的观察是，用 HTML 做幻灯片的人，会被下意识地认为更 AI-native。她的开源仓库叫 frontend-slides，如果你下次做技术分享，可以试试。

郭宇的 wanman.ai 正在灰度上线新版本。他这几天在给 wanman 和 mails 做授权打通，让 agent 能直接操作企业邮箱收发件。他的设计思路很有意思：不把所有功能塞进聊天界面，而是允许 agent 在必要时打开传统网页 UI，让人能更快扫到关键信息。如果你也在纠结 agent 产品到底该用纯 chat 还是混合界面，他的这个实践值得关注。

说到产品设计，今天 Aaron Levie 和 Tony Fadell 都指向了品味这件事。如果品味真的成了最后的护城河，你最近做的产品里，哪一处设计是你坚持就该这样、哪怕别人说没必要？我们明天一早再见。拜拜。
