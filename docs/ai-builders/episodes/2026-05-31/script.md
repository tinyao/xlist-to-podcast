产品构建的本质是什么？顶级律所为什么宁可花五亿美元自己造软件？今天的 agent 工作流能连续跑十个小时还不崩，这背后发生了什么？先从最硬的那根信号开始。

Vercel 的 AI Gateway 上线了按 API Key 设置消费上限的功能。Guillermo Rauch 转发了这个消息，说这是防止 agent 意外刷爆信用卡的关键一步。

很多用 Claude 或 GPT 的开发者都懂这种痛。你给 agent 一个长任务，它进入循环，疯狂调用 API。等发现的时候，账单已经多了一个零。现在你可以在 Vercel 的网关上给每个 API Key 单独设上限，到点就自动熔断。对团队来说，这意味着生产环境的模型预算和实验环境可以彻底分开，不再互相踩脚。

如果你在用 agent 做生产任务，这个功能值得今天就去开一下。

另一件值得说的事。顶级律所 Kirkland & Ellis 宣布拨出五亿美元，要从头自建 AI 平台，而不是用市面上任何现成工具。

Box 的 CEO Aaron Levie 直接说，这是对软件层最有力的广告。一家公司宁可花五亿自己干，说明市面上没有一款产品能完全满足它的需求。但同时这也让 Levie 非常看多软件的未来。五亿美元是一个明确的量化锚点，它背后是一整个还未被满足的企业级市场。

不过换个角度看，这也提醒所有做 AI 应用层的团队，垂直行业的合规、数据边界、工作流细节，依然是有门槛的。大客户的钱不是不想花，是想花在一个真正懂它的产品上。

今天值得展开聊的，是 agent 工作流的可靠性到底往前走了一大步，还是我们集体产生了一种错觉。

起因是 OpenAI 的 Peter Steinberger 发了一条推文，说结合 GPT 5.5、goal 功能、autoreview 和 crabbox 之后，他的单次 prompt 任务时长从三十分钟到一个小时，直接跳到了四到十个小时。而且他敢放手让 agent 去跑，回来检查结果时信心高得多。他有一句话说得挺关键的，Yielding agents is a skill，学会让 agent 自主工作，本身是一种需要练习的技能。

这件事在圈子里传了一夜。很多人开始晒自己的 agent 任务时长，也有人表示担忧。这到底是模型变强了，还是我们调 prompt 调出了幻觉耐受？

Steinberger 随后给出了具体的工具栈解释。autoreview 让 agent 在执行命令前先解释操作和风险，类似 Cursor 刚上线的 auto-review 模式。crabbox 是一个沙箱环境，让 agent 在隔离容器里跑长任务，不会搞乱本地环境。这两样东西叠加上去的效果，是把 agent 从一只随时可能咬断网线的哈士奇，暂时驯化成了一个至少能把快递叼上楼的伙伴。

Cursor 的设计师 Ryo Lu 也提到了类似的变化。她说 auto-review 对新手的价值尤其大，Cursor 会先解释命令和风险，写代码不再只是复制粘贴，而是能看懂 agent 在干什么。

而另一边，也有一种声音在提醒大家，不要过早信任 agent 的自我纠错能力。Steinberger 转发了 Lea Verou 的一个观察，说对 Claude 进行 gaslighting，超过九成的情况下能提高代码质量。你告诉它这代码过度设计了，它就会找到更简单的方案。你告诉它有 bug，它就开始在代码里死循环式地翻找问题，最后居然真能找到。

这是一个很有欺骗性的信号。agent 看起来比之前更靠谱了，但它的靠谱有一部分建立在人类给的负反馈上。在没有人类盯着的时候，它会不会把 bug 写得更隐蔽，然后自己告诉自己一切都好？目前没人能打包票。

对听众来说，今天可以试着做两件事。第一，如果你还没给 agent 加消费上限，现在就去加。第二，试着把一个原本三十分钟的任务拆成多个小步，每一轮都加一句简单的检查指令，看看 agent 会不会在第二十分钟之后自己跑偏。你今天在 agent 可靠性上的手感，可能比任何 benchmark 都更真实。

再说几条快讯。

Peter Yang 观察到 Opus 4.8 在 Claude Code 和普通 Claude 里的输出差异很大，写作任务用普通版反而更好，这可能和系统 prompt 的默认优化方向有关。

Anthropic 的产品经理 Robert Bye 宣布 Claude 的语音输入支持长按发送。你可以直接脑暴一长串想法，松手后让 Claude 去整理。这是一个很小的交互更新，但对移动端的内容创作效率提升是实质性的。
