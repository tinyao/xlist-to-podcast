Claude Fable 5 在短暂下线后重新上线了，但订阅用户只能用到 7 月 7 号。
Anthropic 的 Claude Code 团队成员 Thariq 昨天在 X 上确认了这件事。
原话是，Fable 会在 7 号之后从订阅套餐里撤出，等算力宽裕了再争取恢复成标配。
这直接关联到上周 Fable 突然被移除时引发的那场混乱。
很多重度用户的生产力瞬间掉了一截，Riley Brown 的感受是“我的天，我太想念用 Fable 的感觉了”。
现在模型回来了，但倒计时只有 4 天，气氛有点像技术预览版加了个截止日期。

Guillermo 从这件事出发，点出了一个更隐蔽的风险。
模型被突然退役这件事，在生产环境里一直是个大坑。
他的数据团队发现，很多用户的正经工作负载还跑在一些被官方视为过时的旧模型版本上。
而 GPU 算力本来就抢手，模型退场远比人们想象得频繁。他打了个比方，把 Vercel 的 AI Gateway 叫做“Token Delivery Network”，像 CDN 一样动态路由 AI 请求。
为了应对 Fable 这次事件，他们昨天直接上线了新功能：AI Gateway Rules。
你现在可以一条 CLI 指令重写模型路由，把请求透明地切到替代模型，不用改一行代码。
指令很简单，把源模型设为 Fable 5，目标指向 Opus 5。
如果你在生产环境强依赖某个单一模型，这条规则值得现在就配上。
你怎么处理模型突然变动的？是改代码还是走网关？

另一件值得说的事，是 OpenAI Codex 桌面应用的负责人 Andrew Ambrosino 和 Lenny 做了一场深度对谈。
Andrew 抛出了一个在圈子里传得很快的观点：很多公司正在砍掉产品经理这个角色，让所有人直接动手构建。
他原话是“这是个可怕的想法”。
在他看来，产品管理这个学科积累了多年的最佳实践和踩过的坑，不能因为“人人都会写几行代码”就被抛弃。
这和昨天很多人在讨论的“品味”刚好接上了。
Felix Lee 也发了一条数据密集的推文，说现在最火的岗位不是工程师，而是产品设计师。
Instagram、Sesame 这些公司给普通产品设计师开到接近 30 万美元年薪，远超 12 万的全美平均水平。
他的结论是，AI 让写代码的门槛降到几乎为零之后，瓶颈不再是工程实现，而是知道该做什么、以及做出“人味儿”的鉴赏力。
Lenny 的访谈里 Andrew 还分析了另一个维度：为什么 AI 目前做设计还很糟。
一方面是优先级问题，实验室先攻克了编程以加速自身研究，而好设计很难像好代码那样自动打分。
结构上更麻烦的是，真正好的设计需要新意和对当下文化的理解。
目前的模型非常善于输出已知模式，比如生成一个 Linear 风格网站信手拈来，但要创造一个从没见过的东西，还很难。
“新奇”和“文化敏感度”这两个坑，短期内不太容易填上。

说到 Vercel，他们昨天还悄悄做了一件事，让服务之间可以直接通过内部 URL 通信。
Guillermo 介绍了 Service Bindings，本质上就是微服务之间的私有网络连接，配置只需要一行代码。
对一个日益依赖多个微服务和 API 的 agent 架构来说，这种内网连接能省掉很多安全上的麻烦。

今天值得展开聊的，是 Elena Verna 发表的一篇文章，题目很直接：《请停止 AI 信心剧场》。
Lenny 转发了它，并标注为重要文章。

Elena 的背景是，她是一位长期研究增长和产品策略的资深分析师，在圈子里以数据思维和冷静判断出名。
这篇文章的核心矛盾在于，越来越多的公司高管要求团队全面拥抱 AI，但团队为了满足这种“必须用 AI”的期待，开始在汇报和内部演示里表演一种过度自信的 AI 能力展示。
她用了一个很形象的词：Confidence Theater，信心剧场。
意思是，人们不是在实质性推进 AI 应用，而是在用华丽的演示和夸张的言辞来表演“我们已经 AI 就绪了”。
这导致资源被错配到表面光鲜但实际无效的项目上，而真正需要耐心、脏活累活的数据整理和工作流重构反而没人碰。

针对这个现象，圈子里其实有多条线索在相互印证。
Hamel Husain 昨天冷不丁说了一句：“一个人写博客大谈品味，但博客本身是 AI 生成的垃圾，这本身就说明了一切。”
这话看似尖刻，但接在 Elena 的文章之后读，讽刺点其实一样：我们在用 AI 表演某种形象，而不是创造真实的价值。
甚至 Zara Zhang 也分享了一个令人反思的观察：有刚毕业的大学生告诉她，他们上学时把课件扔给 AI，让 AI 代替教授来授课，因为他们常常觉得 AI 教得更好。
这件事本身挺酷的，但它也暗示了一套潜在的表演逻辑正在渗透教育：学生用 AI 完成的不仅是作业，甚至连“教授”这个角色本身也在被 AI 静悄悄地替换，而整个系统假装一切如常。

回到你自己的工作和团队里，这件事的启发其实很具体。
检查一下你们最近的 AI 项目评审会。
演示稿里“用了多智能体协作”、“基于大模型进行深度推理”这些词出现的频率，是不是远远高于“这个功能上线后用户留存提升了多少”、“数据清洗掉了多少脏数据”这一类实在的指标。
如果是，那你很可能也身处一场信心剧场之中。
Elena 的建议是，与其追逐 AI 变革的名头，不如回归到用 AI 去放大那些已经被验证过的产品和商业价值。
比如说，与其用 AI 生成一堆没人看的周报，不如让它去自动分析流失用户的最后一屏行为数据。

先把节奏放慢一点，说一下今天最值得想清楚的一件事。

Peter Yang 昨天发了一篇文章，提出了一个观察：只靠前沿模型的生态正在碎裂。
他有几个非常具体的论据。

第一，Uber 在 2026 年前四个月就把全年的 AI 预算烧光了，微软已经把部分工程师从 Claude Code 上撤下来，原因很简单，就是太贵。
第二，Coinbase 把一部分人工智能开销砍了近半，方法是用中国的开源模型比如 GLM 和 Kimi 替换掉了一些 API 调用。
Airbnb 和 Pinterest 也做了类似的事，开始用阿里的 Qwen 系列。
他的判断是，公司未来会走多模型组合路线，高精尖任务用 Fable、Opus 这种前沿模型，日常任务用更便宜的开源模型顶上去。

Box 的 CEO Aaron Levie 在同一天给出了另一个维度的佐证。
他在点评 Devin 新发布的 Security Swarm 功能时，提出了“Agentic MapReduce”这个概念。
意思是未来会有成群的 agent 并行扫描海量代码和文档，做类似安全审计这类人类以前根本做不完的工作。
Levie 的推论和 Peter Yang 直接相通：要跑得动这种体量的 agent 集群，你绝对不可能只押注最贵的模型。
他说，部署混合模型的能力——前沿模型负责核心推理，便宜模型处理外围任务——就是应用层人工智能的下一个核心价值主张。

这条逻辑线其实和第一段要闻里的 Fable 离线事件连在一起看，压力就扑面而来。
一方面，每个人都知道 Fable 厉害，用它写出过惊人作品的开发者根本不想放手。
另一方面，公司的财务主管看到的是无法预测的计费账单和随时可能被下线的供应风险。
Matan Grinberg 的评论更加直白：“依赖任何单一模型提供商的公司在战略上是不独立的。它的路线图、成本、能力天花板甚至产品哲学，都会变成另一个公司的下游输出。”
他的公司 FactoryAI 的主打概念就是模型无关，用最好的智能无论它来自哪里，并且在成本和质量的变动中随时切换。

对听这期节目的你来说，接下来有一件具体的事情可以做。
在选下一个 AI 功能的技术栈时，尝试在非核心路径上切一刀。
把某个不太关键的模块——比如内部工具的数据摘要、用户反馈的分类器——换成开源的轻量模型。
做一周对比，看成本和延迟的真实差距，以及维护两套模型调用的工程负担到底有多大。
如果这条路走通了，你就有了一个战略上的安全垫。
下次 Fable、Opus 或者其他任何前沿模型突然下线或者大幅涨价，或者再来一个只在订阅上晃 4 天的窗口，你的业务能稳定得多。

再说几条快讯。
NVIDIA 的副总裁 Bryan Catanzaro 昨天接受了 Matt Turck 的长篇访谈，详细解释了 NVIDIA 为什么要把几百个研究员的人力投入到大模型研发然后免费开放。
核心逻辑很直接：模型越普及，对 GPU 的需求越大，而 NVIDIA 是卖芯片的。

Justine Moore 测试了 Seedance 2.0 的 4K 画质，直说效果惊人，但成本也惊人，一段 15 秒的片段花了 47 美元。
她用一个大语言模型根据原始提示词改编了一个美国高中场景的版本，画面近乎完美重现了早期 2000 年代的手持摄像机质感。
这背后透露出一个趋势——生成式视频的“导演”技能正在和提示工程解耦，未来的创作者可能更接近一个提供灵感和核心约束的编剧。

Peter Steinberger 昨天发了一条挺真诚的动态，说他开始理解 Steve Yegge 当年的远见了。
Yegge 很多年前就在讲软件工程会变成流水线工厂，Steinberger 说当时大家觉得他太超前，而现在所有人都在忙着建这种工厂。
如果你手头的工作流还在靠人和 Git 分支做主要调度，是时候去研究一下你们的 cloud agent hub 长什么样了。

Anthropic 刚刚宣布 Claude Tag 的推广计划，企业内部版已经让 Anthropic 自己 65% 的产品 PR 由 Tag 直接完成。
现在他们拿出了两万五千美元的额度补贴企业试用，直到 9 月 1 号。
如果你在负责公司内部工程效率，这个数字值得拿去找你的老板聊一聊。

Zapier 的 CEO Wade Foster 干了一件更彻底的事：他直接公开了高管团队在 Slack 里发私密消息的比例。
他的逻辑是，每一条私密消息都是对 AI 和团队共享大脑的一次断流。
把讨论放在公开频道里，决策和理由就能被所有 agent 索引到，而不是在 DM 里蒸发掉。
你的团队也可以试试这个思维实验：如果现在停掉所有 DM，哪个项目会立刻因为信息不足而出问题？

今天聊的都是硬核的工程和战略取舍，最后问一句：你的团队现在有没有在做一个看起来很 AI、但实际上只是在扮演“我们接入了 AI”的剧场项目？如果发现了，你敢第一个提出来喊停吗？
