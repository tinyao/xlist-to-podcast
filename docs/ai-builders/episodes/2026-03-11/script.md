今天是2026年3月11日，欢迎收听 AI Builders Daily。今天我们要聊的关键词是：Claude Code 的新玩法、AI 自动调参的未来已来，还有一个关于"什么才是好产品"的反思。我们开始吧。

先从今天最热的一条说起。

Claude Code 这两天动作挺多。Anthropic 的工程师 Thariq 发了一个功能，叫做 /btw，用视频演示了一下，结果在推特上炸了——五千多个点赞，一千两百多个收藏，三百多条回复。这个数字对于一个技术功能更新来说，真的不低。

那 /btw 是干什么的？简单说，就是当 Claude Code 正在帮你干活的时候，你可以用这个命令插一句话，问一个"顺带一提"的问题，Claude 会回答你，但不会打断手头的工作。

听起来很简单对吧？但你想想实际使用场景——你让 Claude 在后台跑一个比较长的任务，突然想到一个问题，以前你要么等它跑完，要么新开一个窗口。郭宇就说"我平常都是新开一个窗口"，相信很多人都有这个体验。现在 /btw 一下，问完继续，工作流不断。

从技术角度来说，Thariq 补充了一些细节：这个 side chain 不能调用工具，是单轮输出，但它有完整的对话上下文。也就是说它是"只看不动手"的模式，用来做快速咨询非常合适。这个功能是团队成员 Erik Schluntz 作为 side project 做出来的。

同一天，Claude 移动端也推了一批更新，包括语音模式改进、LaTeX 渲染、MCP 连接、大型 prompt 的性能优化等等。Anthropic 的 Mobile PM Robert Bye 在推特上列了一串清单。

还有一篇 Anthropic 工程博客，专门讲 agentic coding 评测的噪声问题。结论有点反直觉：基础设施配置的差异，可以让评测结果偏移好几个百分点，有时候甚至超过了排行榜上顶级模型之间的差距。换句话说，你以为在比模型，其实可能在比服务器配置。Thariq 也转发了这篇，说这解释了为什么 agentic coding 的评测结果这么不稳定。这对于所有在做 AI 编程工具评测的团队来说，是一个很重要的提醒。

说完 Claude Code，我们来聊一个更宏观的话题，关于 AI 自动做科研这件事。

Andrej Karpathy 发了一条很长的推文，Kevin Weil 转发并评论说"这就是未来，或者说现在"。Karpathy 在讲什么？他让一个 AI agent 在他的 nanochat 项目上跑了两天自动调参，agent 一共测试了大约七百个改动，找到了二十个有效的优化，最终把训练效率提升了大约 11%。

更关键的是，这些优化都是真实有效的，不是随机乱改，而且在更大的模型上也能迁移。Karpathy 说，他做神经网络训练优化二十年了，这种"让 agent 全程自主完成实验、分析结果、规划下一步"的工作流，对他来说是第一次。

他举了几个例子：agent 发现他的 QK normalization 没有 scaler，导致 attention 太分散；发现 Value Embedding 没有做正则化；发现 AdamW 的 beta 参数设置有问题。这些都是很具体的、有价值的发现，不是玄学。

Karpathy 最后说，所有前沿 AI 实验室迟早都会做这件事，这是"最终 boss 战"。你只需要一个可以高效评估的指标，就可以用 agent swarm 来自动搜索优化方向。

这件事的意义在哪里？我觉得有两层。第一层是工程层面的：AI 辅助科研不再是"帮你写代码"，而是真的在做实验、做分析、做决策。第二层是更深的：如果连模型训练本身都可以被 agent 优化，那这个正反馈循环会走向哪里？Karpathy 说他正在研究多个 agent 如何协作来解锁并行化，这个方向值得持续关注。

顺带提一条相关的消息。Kevin Weil 还转发了另一条推文，说有团队用 GPT-5.4 Pro 解决了 Epoch AI 的 Frontier Math 开放数学难题之一，一个关于超图的 Ramsey 型问题，并且用 Lean 做了形式化验证。如果这是真的，这将是 Frontier Math 系列题目里第一道被 AI 解决的开放问题。Kevin Weil 说"if true"，所以还需要社区验证，但这个方向的信号已经很强了。

好，下面我想聊一个稍微不一样的话题，关于"如何对抗 vibe coding 带来的 slop"。

这两天 swyx 转发了一条推文，来自 OpenCode 项目的 dax，内容是他们团队内部的一些原则。swyx 总结了三条：不要因为能做就去做；让代码比你接手时更好；修复功能和流程比新功能更重要。这条推文有将近五百个点赞，两百五十多个收藏，说明很多人都有共鸣。

这个背景很有意思。现在 vibe coding 的风潮下，大家都在快速用 AI 生成代码、快速上线，但随之而来的问题是：代码质量越来越难保证，技术债越积越多，功能越堆越多但体验越来越差。dax 说的是，真正的好产品需要延迟满足感，能忍住"我可以做这个"的冲动，专注把已有的东西做好。

这让我想到郭宇也在推特上聊了一个很有意思的问题：我们用人类工作者的视角去设计 agent 的工作流，这到底是真正有用的设计，还是只是看起来合理？他的观点是，组织的目标可能是一致的，但实现路径不是固定的，agent 需要的是探索空间，而不是被强行塞进一个流水线。

这两个观点其实是同一枚硬币的两面。一个是说，别因为 AI 能做就什么都做；另一个是说，别把 AI 强行塞进人类的工作模式里。本质上都是在问：我们到底想用 AI 解决什么问题？

这个问题没有标准答案，但值得每一个在用 AI 构建产品的人认真想一想。

接下来快速过几条值得知道的消息。

另外，Vercel CEO Guillermo Rauch 宣布，他们的 AI SDK 周下载量突破了一千万次。npm install ai，一个包，支持所有主流模型。这个数字说明 AI SDK 已经成为前端开发者接入 AI 能力的事实标准之一，增长速度相当惊人。

顺带一提，Nous Research 发布了一个叫 Hermes Agent 的开源 agent，主打多级记忆系统和持久化机器访问，会随着使用越来越聪明。Greg Isenberg 问"这是新的 OpenClaw 吗"，引发了不少讨论。开源 agent 这个赛道最近真的越来越热，值得持续关注。

快速说一条，Google 发布了多模态向量化模型，支持用文字搜图片、用图片搜视频。郭宇转发说"agent 可以用文字搜图片、用图片搜视频了"，这对于构建多模态 RAG 系统的开发者来说是个好消息。

另外，Meta 收购了 Moltbook，这个消息在中文推特圈引发了一些讨论。郭宇说"太抽象了"，还调侃扎克伯格有没有自己 vibe 过。这个收购背后的逻辑还不太清晰，但 Meta 在 AI 工具层面的布局越来越积极是肯定的。

还有一个有意思的小故事。OpenCode 的 iOS 开发者 Thomas Ricouard，他之前做了一个叫 Codex Monitor 的开源应用，专门用来监控 OpenAI Codex，结果直接被 OpenAI 看上，邀请他加入团队。swyx 评论说"这是很好的 proof of work"。这个案例印证了一个观点：在 AI 工程领域，能跑起来的开源项目比简历更有说服力。

另外，a16z 的 Justine Moore 分享了一个挺有趣的应用场景：Redfin 在房源页面加了一个"重新设计"按钮，可以用 AI 图像编辑帮你重新装修任意一个房间。这个功能对于那些需要翻新或者没有布置好的房源来说很实用，也是 AI 图像编辑走进普通消费场景的一个典型例子。

最后说一条，NYT 做了一个盲测，让读者判断人类写作还是 AI 写作，结果八万六千人参与，54% 的人更偏好 AI 写的内容。Linear 的 head of product Nan Yu 看完只说了三个字："I am cooked"，意思是我完蛋了。Justine Moore 的反应更辛辣，她说那也应该立法要求标注"蠢人写的文字"，不想花时间分辨人类废话。这个数据当然有很多可以质疑的地方，比如样本偏差、题目设计等等，但它确实说明 AI 生成内容的质量已经在某些场景下超过了普通人类写作的平均水平。这对内容创作者来说是一个需要认真面对的信号。

好，今天就到这里。

今天最大的 takeaway 是什么？我觉得是这句话：工具越来越强，但"做什么"比"怎么做"更重要。不管是 Claude Code 的 /btw，还是 Karpathy 的 autoresearch，还是 OpenCode 的反 slop 原则，背后都是同一个问题——你真正想解决的问题是什么？
