第一个话题，Claude Code 新功能：/btw。

这个功能昨晚上线，截止我们录制的时候，已经拿到了超过 5000 个赞、1200 多个书签。在 Claude Code 的更新里，这个互动量算是相当高的。

功能本身很好理解。你在用 Claude Code 跑一个任务，agent 正在工作，这时候你突然想问一个问题——但你不想打断它，不想开新窗口，也不想等它跑完。现在你可以直接输入 /btw，然后问你想问的事情。Claude 会在不中断当前任务的情况下，给你一个单次回答。

发布这个功能的是 Anthropic 的工程师 Thariq，他补充了一个技术细节：/btw 不能做工具调用，是单轮输出，但它拥有你整个对话的完整上下文。这个设计很克制——它不是给你开了一个新的 agent，而是让你在 agent 工作的间隙，能和它说一句话。

这个功能是 Anthropic 工程师 Erik Schluntz 作为 side project 做出来的。

我想在这里多说两句，因为我觉得这个功能的意义不只是"方便"。它揭示了一个更深的用户体验问题：当 AI 开始跑长任务，人和 AI 的交互节奏就变了。你不再是一问一答，而是你在等待，它在工作，偶尔你有个念头，但你不确定该不该打断它。/btw 是 Anthropic 对这个问题的第一个明确回答：你可以问，但我不会停下来。

这让我想到一个更大的问题：随着 agent 任务越来越长，"人机交互"这件事的设计语言会完全变掉。以前的 UX 是围绕"即时响应"设计的，但现在你需要设计的是"异步协作"——人和 agent 各自在做事，偶尔同步一下。这个方向，我觉得整个行业都还在摸索。

另外，Claude 移动端也在同一天推送了更新，包括语音模式、LaTeX 渲染、大 prompt 性能优化、MCP 连接等等。这些更新没有单独的大功能，但说明 Anthropic 在同时推进好几条线。


好，第二个话题，我们来聊一个开源 agent 的新信号。

Greg Isenberg 昨天转发了一个项目，Nous Research 发布的 Hermes Agent。他的问题很直接："这是下一个 OpenClaw 吗？"这条推文拿到了 471 个赞、529 个书签，评论区也很热闹。

Hermes Agent 的核心卖点是两个：多层记忆系统，和持久化的专属机器访问权限。换句话说，它不是一个用完就忘的 agent，而是一个会记住你、会随着时间变得更懂你的 agent。Nous Research 的定位是"grows with you"，这个措辞很有意思——它在暗示一种长期关系，而不是一次性工具。

把这个和 OpenClaw 放在一起看，我觉得有一个有意思的对比正在形成。OpenClaw 是闭源的、有品牌的、开了实体展厅的；Hermes Agent 是开源的、学术背景的、强调记忆和成长性的。这两条路代表了 AI agent 工具化的两种方向：一个在做品牌和体验，一个在做能力和开放性。

说到 OpenClaw，Peter Steinberger 这两天有一个很好笑的互动。有人发现华尔街铜牛旁边出现了一个大龙虾雕塑，问说"这是什么情况"——Peter 直接回复"new claw dropped"，拿到了 1300 多个赞。另外有人开玩笑说，OpenClaw 这个名字是因为要被 OpenAI 收购，Moltbook 是因为要被 Meta 收购，Peter 的回应是"没成功，clawbot 没 work"。这个玩笑背后是一个真实的市场信号：现在 AI 工具层的收购预期，已经高到连命名都被脑补成暗示了。

顺带一提，Codex Monitor 的作者 Thomas Ricouard 宣布月底加入 OpenAI，负责 Codex 的 iOS 和 macOS 开发者体验。Peter Steinberger 转发时配了一个法棍面包的 emoji——因为 Thomas 是法国人。这种细节很硅谷，也很真实。Codex Monitor 本身就是用 Codex 给 Codex 做的工具，这个项目帮他拿到了 OpenAI 的 offer。swyx 评论说，这就是最好的 proof of work。


第三个话题，我觉得是今天信息密度最高的一条：GPT-5.4 可能刚刚解决了 AI 数学界最难的一道开放题。

Kevin Weil，OpenAI 的 VP of Science，昨天转发了一条推文，加了一句话："如果属实，这将是 Epoch AI 的 FrontierMath 开放难题中，第一道被 AI 解决的题目。"

背景先说一下。FrontierMath 是 Epoch AI 维护的一个数学题库，专门用来测试 AI 的数学推理上限。这些题目不是竞赛题，而是真正的研究级数学问题，设计的初衷就是"人类专家可能也需要几小时甚至几天才能解决"。之前顶级模型在这个 benchmark 上的通过率一直很低，所以它被认为是一个相对可信的能力上限测试。

这次被解决的是一道 Ramsey 型超图问题。发推的用户说，他们用 GPT-5.4 Pro 跑了一次，得到了解答，然后用 GPT-5.4 XHigh 跑了几个小时，把结果精化成了 Lean 语言的形式化证明。

Kevin Weil 用了"如果属实"这个措辞，说明这个结果还没有经过官方验证。但他作为 OpenAI VP 选择公开转发，本身就是一个信号——他认为这件事值得关注。

我想说的是：这件事的重要性在于它的象征意义，而不只是这道题本身。FrontierMath 被设计出来，就是为了让 AI 在很长时间内都无法通过。如果 AI 真的开始突破这个 benchmark，我们对"AI 能做什么数学"的认知需要更新。而且这个解题过程——单次 Pro 运行得到解答，再用 XHigh 做形式化验证——本身就是一个有趣的工作流：用强力模型生成思路，用形式化工具验证正确性。这个组合，和 Karpathy 说的 agent 做科研，方向是一致的。

不过我也想提醒一点：这个结果还没有经过数学社区的独立验证，Lean 证明是否真的正确，还需要专家来审查。这个消息值得关注，但不要过度解读。


第四个话题，我们来聊一个关于产品和分发的信号，有点分散，但我觉得放在一起看很有意思。

Vercel 的 CEO Guillermo Rauch 发布了一个数据：Vercel 的 AI SDK，也就是那个 npm 包 ai，现在每周下载量达到了 1000 万次。他的描述是"npm i ai 就够了，一个包，任何模型"。这个数字说明在 AI 应用开发层，Vercel 已经成了一个相当重要的基础设施节点。

但同一天，Peter Yang，Roblox 的产品负责人，提出了一个我觉得很有价值的问题：如果未来你的产品主要是被 agent 而不是人类使用，你怎么衡量用户留存？怎么建立客户忠诚度？是看每周调用你 API 或者 MCP 的 agent 数量？你怎么让 agent 发现你的产品，是让 LLM 在训练数据里更容易找到你？

这些问题目前没有标准答案，但它们是真实的产品问题。现在大家还在用人类用户的逻辑来做产品，但如果 agent 成为主要的"用户"，整个产品设计、增长策略、分发逻辑都需要重写。

Lenny Rachitsky 今天也发了一篇关于产品定位的深度文章，作者是定位领域的专家 April Dunford。核心观点是：当"怎么建"变得越来越容易，"建什么"和"怎么让人知道你建了什么"就成了真正的竞争门槛。这篇文章有 190 个书签，在 Lenny 的文章里算是高互动的，感兴趣的可以去读原文。

把这几条放在一起，我觉得有一个贯穿的主题：AI 工具层的基础设施正在成熟，但上面的产品逻辑还没有被重新定义。Vercel 的 SDK 在解决"怎么建"，但"建出来给谁用、怎么让人发现、怎么衡量成功"，这些问题还处于开放状态。


第五个话题，稍微聊一个有深度但容易被忽略的技术信号：Anthropic 工程博客发了一篇关于 agentic coding eval 的文章。

Claude Code 的工程师 Thariq 转发并推荐了这篇文章。核心观点是：基础设施配置的差异，可以让 agentic coding benchmark 的结果在不同跑次之间相差好几个百分点，有时候这个差距比排行榜上两个顶级模型之间的差距还要大。

这个发现很重要，但也很容易被忽视，因为它不是一个"某个模型更强了"的好消息，而是一个"我们对评测结果的信任度需要打折扣"的坏消息。

换句话说，当你看到某个模型在 coding benchmark 上比另一个高了 3 个百分点，你现在有理由怀疑：这个差距是真实的能力差异，还是测试环境配置不同导致的噪声？

这对整个行业有实际影响。如果 eval 结果不可靠，那么依赖 eval 来做模型选型的团队，可能在做错误的决策。Anthropic 选择公开这个问题，我觉得是一个负责任的做法，但这也意味着整个 agentic eval 领域还有很多工程工作要做。


好，快讯时间，我们快速过几条。

第一条，郭宇发布了 sandbank v0.3.2，这是他维护的一个让 AI agent 在沙箱里真正跑起来的工具。这个版本解决了几个实际问题：Claude Code 的 OAuth 登录自动化、agent 工具调用的可观测性、非 root 用户权限配置，以及对最新 BoxLite SDK 的适配。如果你在搭 agent 沙箱环境，这个更新值得看。

另外，Google AI Studio 发布了一个多模态向量化模型。郭宇的描述很直白：agent 现在可以用文字搜图片、用图片搜视频了。这是 embedding 层的一个重要进展，对 RAG 系统和多模态搜索应用有直接影响。

顺带一提，Redfin 上线了一个 AI 重装修功能，叫"redesign"按钮。你在看任何一个房源的时候，可以点一下，让 AI 帮你重新装修这个房间，换风格、换家具。a16z 的 Justine Moore 分享了这个功能，说对于需要翻新或者没有布置的房源很有用。这个用例很具体，也很实用——不是在演示 AI 能做什么，而是真的解决了看房时"脑补装修效果"的问题。

再说一条，Zara Zhang 分享了一个有机增长的小故事：她做的 Frontend Slides 工具，最近连续遇到三个人主动拿出用这个工具做的 slides 给她看，都是自然用户，没有推广。她说这是她第一次看到这个工具的真实有机传播。这个细节很小，但对于独立工具开发者来说，这种时刻是很有意义的。

还有一条，OpenCode 这个项目分享了他们内部的反 slop 原则，被 swyx 转发。三条规则：不要因为能做就去做某个功能；让代码比你找到它时更好；修 bug 和优化流程比加新功能更重要。这三条原则听起来老生常谈，但在 vibe coding 盛行的现在，能把它写成团队规则并且执行，我觉得是一件很难得的事。

最后一条，NYT 做了一个盲测，让读者判断哪篇文章是人写的、哪篇是 AI 写的。8.6 万人参与，54% 的人更喜欢 AI 写的版本。Linear 的产品负责人 Nan Yu 看到这个结果，发了一条"I am cooked"。我不确定这个结果说明 AI 写得更好，还是说明 NYT 的人类写作已经达到了某种平均水平，但这个数据点本身值得记一下。


好，今天就到这里。

如果今天只带走一件事，我会选 /btw 背后的那个问题：当 agent 开始跑越来越长的任务，人和 AI 的交互节奏会根本性地改变。我们现在的所有产品设计、所有工作流，都还是围绕"即时响应"建立的。但"异步协作"这个模式，才是 agent 时代的真正交互范式。这个范式还没有被定义清楚，而第一批想清楚这件事的人，会有很大的先发优势。
