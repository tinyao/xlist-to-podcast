Kimi K3 在代码能力评测上登顶了，但市场反应有点微妙。模型厂商的军备竞赛，会不会反而让芯片股承压？Vercel 把 React 和 GraphQL 的创始人都招了进来，他们想做什么？先从模型圈最戏剧化的一幕说起。

Kimi K3 在 Frontend Code Arena 的前端代码评测中拿下了第一名。

一天之内，Kimi 的排名从第十八位直接跳到了榜首，分数是 1679 分。这个排名来自 Arena.ai 的评测，在七个细分领域里，Kimi 拿下了六个第一。唯一个没拿第一的，是游戏开发，输给了 Claude 的 Fable 模型。

但最有意思的不是排名本身，而是围绕它的争论。Replit 的 CEO Amjad Masad 发了一条推文，说那个蒸馏出来的小模型，居然超过了老师模型。他说的老师，很可能就是 GPT-5.6。Sam Altman 倒是转发了 Kimi 的欢迎页面，只说了一句“这个挺酷”。

不过，市场对这件事的反应完全是另一回事。Amjad 还补了一句，按常理，这种开源模型冲击的消息应该利好英伟达，因为更多公司会需要买卡来跑自己的模型。但事实上，英伟达的股价昨天是跌的。

Box 的 CEO Aaron Levie 和投资人 Gavin Baker 都加入了分析。他们的核心观点是，Kimi 这类开源模型的崛起，对 OpenAI 和 Anthropic 是潜在威胁，但对整个生态里的其他公司，包括芯片、云和软件层，都是好事。因为模型层的利润率会被压低，钱会流向基础设施。

但这里有个关键细节，Kimi K3 的推理成本其实并不低。Gavin 指出，Kimi K3 在执行同样任务时，消耗的 token 数更多，算下来比 GPT-5.6 还贵。如果你在工作流里用它，得算总账，不能只看单价。

另一个值得说的事。OpenClaw 的老哥 Peter Steinberger，也就是经常被大家叫做龙虾哥的那位，分享了一个很反直觉的模型使用体验。

他把自己用来做 GitHub 代码审查的机器人，从 GPT-5.6 Sol 换成了 Terra high。结果发现，Terra high 整体速度提升了大约 40%，质量几乎没有下降，而且成本大幅降低。他特别强调，在他自己的代码审查场景里，Terra high 的表现远远好过 Sol low。

这种对比挺有意思的。Sol 是 GPT-5.6 里参数最大的模型，按理说应该最强。但在具体的、重复性的工程任务上，更快更便宜的 Terra 反而更实用。龙虾哥的原话是，别信那些通用基准测试。

他把这个发现叫做“IFKYK”，也就是“如果你懂，你自然懂”。这大概也是为什么，很多工程师现在都在重新评估自己的模型选择策略。不是所有任务都需要最重型的武器。

换个方向。Vercel 的 CEO Guillermo Rauch 昨天宣布了两起重磅人事任命。

他把 React 的早期核心成员 Pete Hunt，和 GraphQL 的联合发明人 Nick Schrock 都招进了 Vercel。Pete 将负责领导 Next.js 框架团队，Nick 则会负责一个叫“Agentic Developer Experience”的新方向，目标是让下一个十亿个智能体也能顺畅地做开发。

swyx 看到这个消息后，用了一个很夸张的词，说这是 React 复仇者联盟集结了。Guillermo 自己也说，这是他创业以来梦寐以求的时刻。

对听众来说，这信号很明确。Vercel 正在把前端框架的未来，和 AI 开发者的体验牢牢绑在一起。他们不只是想做人类开发者的工具，更想定义 AI 智能体怎么写代码、怎么和开发环境交互。

接下来这段我们多说几句。

昨天 Claude Code 团队的 Boris Cherny 发了一篇长文，在圈子里传了一夜。他提出了一个 AI 在工程团队里的四阶段采用模型。

起因是 Boris 每天和不同公司的工程师聊天。他发现，几乎每个团队里，都会有一两个人已经用 Claude 把效率翻了十倍，但整个组织完全跟不上。他把这个现象总结成了四个步骤。

第一步，叫个人英雄主义。少数工程师私下用 AI 写代码，但团队没有共享的工作流。

第二步，团队开始建立信任。给 AI 设置自动验证机制，让它能自己检查自己的工作。同时开启自动模式，让 AI 可以自动执行一些需要权限的操作。

第三步，是规模化。团队开始用上了批量处理、动态工作流、子任务隔离这些高级功能。AI 不再是一个助手，而是能独立完成一整类工作。

第四步，他称之为“超越”。当修复和维护在后台自动运行，团队里的人可以专注做那些以前根本不敢想的事。

Boris 说，Anthropic 自己目前正在第三步向第四步冲刺。他个人的体验是，已经达到了第四步。

另一条线，Meta 的 AI 高级总监 Madhu Guru 也聊到了企业落地 AI 的困境。他观察到，大多数企业还困在第一步，连一套像样的评估体系和模型调度系统都搭不起来。他说，这背后最稀缺的，不是模型，也不是算力，而是能把这一切搭起来的人才。

这两个观点放在一起看，就很有意思了。Boris 在讲一个理想路径，从个人到团队，再到全自动。而 Madhu 在讲现实，大部分人连入场券都还没拿到，因为缺人。

对你的启发是什么？如果你现在在团队里，就是那个“十倍的个体贡献者”，你可以把 Boris 的四个步骤当成一张路线图。先别急着推全公司转型，而是先建一套可共享的验证和信任机制。比如，让 AI 生成的代码必须经过自动化审查，或者搭建一个共享的提示词库。这件事不需要管理层批准，你就能做。
