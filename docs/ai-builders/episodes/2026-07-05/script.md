AI 写的代码你还敢不看就直接合并吗？给 agent 一台自己的电脑会发生什么？为什么用户越来越不愿意为单纯的工具付钱？先从昨天那条让工程师集体反思的提问说起。

Claude Fable 5 展现出了更强的分析判断力，这是 Anthropic 工程师 cat 昨天在 X 上分享的一手体验。她在做用户留存分析时，Fable 5 没等指令就自动用上了倾向性得分匹配，把活动相近的用户分组比对，确保结论不是被行为偏差带歪的。cat 说这不是一次偶发亮点，Fable 5 在写邮件、写文档、调试复杂错误的任务里，判断质量都在整体提升。另一个细节是，它的 CoT 里时常会冒出“如果……那会不会是……”这类自我反问，跟人在推敲数据时差不多。
如果你最近也在用 Fable 5，有没有类似的感觉？它的推理明显变得更像你期待的那个 senior 同事，还是偶尔仍会掉回实习生模式？

另一件值得说的事。Peter Steinberger 昨天给 agent 配了一台单独的电脑，专门跑端到端测试。不是模拟，是真实桌面环境。他在 X 上晒了这张图，一台 Mac mini 屏幕亮着，正被 agent 远程操控。

最让人印象深刻的是他补的那句：agent 会帮你把 macOS 那些烦人的权限弹窗和系统通知全部点掉，不需要你隔着屏幕干着急。这让 end-to-end 测试从“帮我生成一段脚本”往前迈进了一大步——现在 agent 能真的在生产环境里点点按按，碰到弹窗自己处理，跑完再汇报结果。Peter Steinberger 是 OpenClaw 和 OpenAI 两头跑的角色，他这条推送显然不是纸上谈兵，而是自己工程流里已经跑起来的东西。如果你也在搭那种需要跨工具、跨桌面操作的 agent 流程，给 agent 一台自己的电脑，这个想法挺值得试一下。

换个方向，昨天 Zara Zhang 发了一条被很多人引用的观察：现在人们越来越不愿意为工具付钱，因为用 coding agent 自己就能搭出来，但他们愿意为“雇佣某种自己不具备的专业知识”的体验买单。她打了个比方，用户不再买一把梯子，他们买的是“爬上屋顶并且不出事”的保证。这个转向对 AI 工具开发者的影响很大：如果你的产品还只是一个功能清单，别人用 Codex 或者 Claude Code 一个下午就能重建一个，但如果你把领域经验、默认最佳实践和决策判断一起打包成一个“专家服务”的触感，用户就会停下来付费。Zara Zhang 自己就是一个动手能力极强的 builder，她的这条感受来自一线，不是隔岸观火。
你怎么看？你最近付费的产品，是为了那个工具本身，还是为了用完之后那种“有人替我把关”的踏实感？

先把节奏放慢一点，说一下今天最值得想清楚的一件事。

起因是前天，Theo 在 X 上抛出一个问题：模型要好到什么程度，你才会停止阅读它写的代码？这个提问没有预设立场，但它像一颗石子，砸出了很多不同的回响。

Justine Moore 转发了这条推文，并在自己的时间线上放出一个投票截图，选项分别是“永远不会完全信任”“当模型写代码比我强”“等 AGI 出现我再说”。投票没有公开最终分布，但引发的讨论量说明，这在开发者圈里是一个尚未达成共识的紧张区域。

Linear 的产品负责人 Nan Yu 也加入了讨论。他没有直接回答信任尺度，而是跟着问了一句：如果你把生产库所有表都删了，是模型被开除，还是你被开除？这瞬间把信任问题从“我该不该看代码”拽进了“出事了谁负责”的现实里。Nan Yu 随后还写了一段很长的内容，直指一个容易被忽略的事实：过去很多人根本没认真做过代码审查。他说，真正合格的代码审查应该是在 dev 环境跑一遍，确认它达成了目标，然后逐行读过并同意“换我写也差不多会这么写”。但现实里，大部分团队根本做不到这一点。

紧接着他又解释了审查的另一个重点：找 bug 其实不是读代码的主要目的，大部分 bug 要靠实际使用才能揪出来。审查代码主要是为了控制架构和技术债的增长，确保新代码没有在系统里埋下长期的坑。

这三层声音放在一起，讨论的框架就清晰了很多。Theo 问的是“模型够不够好”，Justine 的投票把问题引向“开发者愿意让渡多少信任”，而 Nan Yu 把问题拉回到一个更根本的工程真相：无论代码是谁写的，人和流程的责任边界从来就没有被认真定义过。AI 只是把这张旧账本重新翻开了。

对听众而言，这件事其实有一个非常具体的落点。你可以今天就去翻一下团队最近三个 pull request 的审查记录，看看大家留下的评论是集中在“这行逻辑会不会死循环”这类 bug 猜测上，还是集中在“这个抽象层选得对不对、会不会让未来三个月不敢改”这类架构判断上。如果前者的比例远高于后者，AI 的出现其实是在提醒你：你的 code review 流程，一直缺了一根承重梁。
