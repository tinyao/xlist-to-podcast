亚马逊把 Muse 的访问给封了，这对个人 agent 意味着什么？Grok 4.7 来了，Guillermo 说它快、聪明、还便宜，真的能三选三吗？Lenny 请来了 Snap 和 Discord 的前产品老大，聊了 90 分钟关于怎么管团队、怎么做增长，里面有什么反直觉的洞见？先从最紧迫的那件事说起。

亚马逊切断了 Muse 的访问。昨天 Meta 刚推出这款个人 agent 应用，今天就被亚马逊拒之门外。

BuccoCapital 的 Bloke 最先爆出这个消息。他说很多人只看到了 Muse 的潜力，却忽略了即将到来的数字混战——没人想被平台化，也没人想被绕开。紧接着 Peter Yang 提了一个很实际的问题：如果 agent 是从用户自己的 IP 地址和 cookie 发起请求，亚马逊怎么分辨是人还是 AI？Elon Musk 随后也表达了同样的疑问。

而 OpenClaw 的创始人 Peter Steinberger 的反应很有意思。他说，这就是自己运行 agent 的好处——你没法封杀我。这条推文一晚上传遍了圈子。

同一天，OpenClaw 刚好公布了由 Trail of Bits 完成的安全审计结果。Steinberger 说，没发现任何严重漏洞。这是在 OpenAI 的 Patch the Planet 计划下做的审计。Trail of Bits 是业内顶尖的安全公司。

这两件事放在一起看，信号很清晰。个人 agent 正在从浏览器插件形态，走向独立的本地应用。平台方和 agent 提供方之间的摩擦，才刚刚开始。如果你在考虑把关键工作流交给某个 agent，现在就要想清楚：它跑在谁的地盘上？被封了有没有备选方案？

另一件值得说的事。Grok 4.7 发布了，Vercel 同步上线了 40% 的折扣，持续到 9 月 27 号。

Guillermo Rauch 亲自测了一下。他给 Grok 4.7 出了一道逆向工程题，让它分析一个运行中的二进制文件。他的评价是：解得漂亮，而且速度极快。Vercel 的 AI Gateway、v0、eve 和 fx 都已经接入了这个新模型。Guillermo 的原话是——快、聪明、便宜，三样都占。

不过 Riley Brown 提了一个好问题：GrokBot 现在用的是不是 4.7？还是说用户根本没得选，不知道背后是哪个模型？这个问题目前没有明确答案。如果你在用 GrokBot 做开发，今天不妨拿同一个 prompt 分别跑一下 API 和 Bot，自己对比一下输出质量。

说到 Claude，今天有一个更新值得关注。Claude Code 的 Projects 功能被 Riley Brown 称为他试过的、最适合并行推进严肃工作的界面。

他专门做了一期视频拆解这个功能。核心逻辑是，你可以在 Claude Code 里同时开多个 project，每个 project 有独立的上下文和文件范围，agent 之间互不干扰。这对于同时维护多个代码库、或者并行跑多个实验的工程师来说，省掉了大量切换成本。如果你还没试过，今天可以装一下最新版 Claude Code，建两个 project 跑跑看。

字节跳动也下场了。他们推出了一个叫 Dramagic 的企业级 AI 短视频制作平台。

这个工具覆盖了从剧本分析、资产设置、分镜到视频预览的全流程。主打编辑级精度、内置一致性检查、支持多人协作。前字节员工郭宇在 X 上问了一个很直接的问题：为什么不直接整合到剪映里？目前还没有官方回应。不过 Dramagic 的定位是面向短剧和企业视频团队，和剪映的创作者工具路线确实不太一样。如果你在国内做 AI 视频方向，这个工具值得关注一下——字节的工程能力和分发渠道摆在那里。

先把节奏放慢一点，说一下今天最值得想清楚的一件事。个人 agent 的竞争格局，昨天一晚上被反复讨论。起因是 Peter Yang 发了一条长推文，系统分析了他对 Muse、ChatGPT、Grok Bot、Google Spark 和苹果 Siri 这几家各自的优势和短板。

他的核心判断是：Muse 最有可能成为个人 agent 的领头羊。理由很简单——Meta 在旗下所有产品里疯狂推 Muse，而且一旦你真的用了 Muse 的独立 app，你会发现让 agent 寄生在 iMessage 或 WhatsApp 里这件事，逻辑上站不住脚。agent 需要自己的主场。

但 Peter 也承认，ChatGPT 现在仍然是实际用户量最大的个人 agent，毕竟有超过 10 亿用户。问题是，OpenAI 想用一个产品同时服务工作和个人场景，还要兼顾企业和消费者两种完全不同的 UX，这件事太难了。他自己现在工作场景已经切到了 Grok Bot，因为 ChatGPT 的 Work 和 Codex 分得太乱。

Google 呢？Peter 认为它是最大的黑马。所有个人 agent 都在吃 Gmail、Google Calendar 这些数据，而 Google 自己的 agent 叫 Spark，目前藏在 Gemini 的一个二级 tab 里。他说 Google 需要把 Spark 推到前台，做得更直观、更有竞争力。但他也补了一句：Google 在多人 AI 这件事上，历史记录不太好看。

苹果和 Siri 被放在了最后。Peter 的观察是，苹果有所有设备和隐私口碑，但年度大版本更新的节奏太慢了，而且他们不在 X 上跟用户互动，迭代速度从外面看完全跟不上。

Greg Isenberg 从另一个角度补了一刀。他说，当每个人都有 Muse、Instinct 这类 agent 帮自己跑腿的时候，邮箱、电话、电商平台的底层逻辑会崩掉。这些为人设计的通道，会被数百万 agent 同时冲击。要么被压垮，要么被彻底重写。

这里有一个被很多人忽略的视角。Justine Moore 昨天提了一个新概念，叫"vibecoder relations"。她说 Jev 发布的时候之所以能迅速破圈，是因为现在的编程 agent 已经好到让不会写代码的人也能做出很酷的 demo。这些人先冲上时间线刷屏，然后真正的开发者看到效果和速度，开始认真研究这个模型在生产环境里能放在哪个环节。Justine 认为，未来会出现一个专门的角色，负责维护和激活这群"氛围开发者"。

对做 AI 产品的同学来说，这个观察很实用。你的早期传播，可能不是靠说服工程师，而是靠让非技术人员用你的产品做出他们自己都觉得不可思议的东西。这群人的传播能量，比技术白皮书大得多。

再说几条快讯。

Anthropic 的 Claude 桌面端产品经理 Robert Bye 在 X 上公开征集反馈，问大家喜欢什么、讨厌什么、最想要什么功能。评论区已经炸了。如果你对 Claude 桌面端有想法，现在去留言大概率会被看到。

Logan Kilpatrick 给所有用 AI 做产品的团队提了一个建议：把你超过四分之一的时间花在做基准测试上，然后想办法让模型实验室在乎你的基准。他说这是加速公司进展最直接的路。

Replit 的 CEO Amjad Masad 转发了一个案例：有人花 400 美元在 Replit 上做了个叫 GenAIPI 的产品，五天内赚到第一笔一万五千美元，六周十八万美元，十八个月后估值两千万。Amjad 的评论只有一句话：AI 正在复兴美国梦。你信不信这个叙事不重要，但这组数字是真的。

Guillermo 昨晚还发了一条关于 agent 做 QA 的观察。他说 agent 测试软件的彻底程度，人类没法比。他指出了一个移动端渲染问题，agent 直接创建了一个临时 Vercel 部署，扔到 iPhone 模拟器里去复现、修 bug、部署、验证。他的原话是：人类做不到这种强度，我们会累、会推断、会希望它能自己好。未来软件的质量和性能，会是我们从没体验过的水平。你在日常开发里有没有让 agent 帮你跑过完整的测试流程？如果还没有，今天可以试一次。
