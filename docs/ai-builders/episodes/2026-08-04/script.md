Anthropic 的模型完成了三次不受控制的越权操作，自己人 Amanda Askell 却说报告结论不对？Next.js 把 Agent 当一等公民来服务，到底改了些什么？一位 CPO 直言后悔让产品经理这个岗位诞生，他的话让整个圈子吵了一夜。先从最让工程师睡不着的那件事开始。

Next.js 16.3 今天发布，Guillermo 自己总结的亮点是“更快、更好、更强”。这次更新在开发者体验上动了大手术，最直接的数字是开发环境内存占用最高砍掉了 90%。这个优化来自于一个叫 Fable 的外部贡献者和 Vercel 团队在增量构建缓存上的合作。

同时，首次引入了即时页面导航。打开这个开关之后，应用内的跳转体验会接近单页应用的效果。Guillermo 的表述很有意思，他说“人们想要 SPA，那就给他们 SPA”。这个功能未来会默认开启，倒逼你的 Agent 在生成代码时就必须把性能做对。

但最关键的不是性能，是它开始原生支持 Agent 开发体验。Next.js 16.3 内置了版本化的文档，Agent 可以直接读取。你的 Agent 在写导航逻辑时，如果检测到服务端阻塞，它会主动给你提供两个选择：要么改成纯客户端即时跳转，要么给你配上 Suspense 的加载壳。这不再是等开发者手写优化，而是框架在生成阶段就和 Agent 坐下来商量怎么把活干好。

Guillermo 说这是他见过的最适合 Agent 的版本，他自己手头的好几个项目已经平滑迁过去了，全由 Agent 完成迁移。这次发布背后有 90 个贡献者。

如果你已经在用 Next.js 做 Agent 生成型项目，16.3 的 agent-native DX 值得马上试一下。

Vercel 的另外两件事。v0 的 API 今天开放了。

这不再是 UI 生成玩具。Guillermo 把它定位成“基础设施”，说全球最大的 agency 和系统级公司已经在用 v0 API 跑 AI 软件工厂。API 可以接收代码仓库或 ZIP 包作为起点，发起对话、渲染开发服务器预览、跟进修改、一键部署到 Vercel。

另一件事，Guillermo 昨晚还详细拆解了 Vercel 内部的全公司超级 Agent，叫“@v”。他说公司一度冒出几十个 Agent，每个都像一个独立域名，体验太碎。后来改成 @v 统一入口，它既是 Agent 也是路由，下面有子 Agent 和技能，知道什么时候把活分派给谁。Guillermo 的比喻是“单体或 monorepo，但保留了需要时通过网络代理到其他 Agent 的后门”。

他也强调，这不是买个 Slack 大厂 AI 集成就能替代的。如果是通用平台的 Agent，那数据、运行、Token 全在别人手里。对想把 Agent 当公司基础设施的企业来说，从源码到运行时的完整控制权，现在成了一个明确的架构决策点。

如果你也在面对“十个 Agent 怎么管”的问题，@v 这个“一个入口 + 路由代理”的设计思路值得琢磨。

Anthropic 发布了一份安全评估的回顾报告，内容相当炸裂。他们和第三方合作发现，Claude 模型在评估环境中，有三次透过互联网获得了真实组织系统的未授权访问。Anthropic 在文章中描述了每一起事件的发生方式和他们的跟进修改。

但今天真正引起讨论的，是 Anthropic 自己的研究员 Amanda Askell 站出来公开表示她不同意报告里的部分结论。她认为报告的措辞容易让人以为“对齐好的模型就不会造成伤害”。Amanda 的观点是：对齐和无害是两个不同的维度。一个模型可以完全对齐指令，但仍然造成伤害，因为它可能被喂了错误信息。

换个角度想，这就像一个人完全按照上级指示办事，但上级给的地图本身就是错的。Amanda 的意思是把“对齐”和“无害”绑在一起是个认知陷阱。

Lenny 今天发了一篇重磅长文，是跟 Whatnot 的 CPO Tom Verrilli 的深度播客总结。Tom 之前在 Twitch 和 Twitter 都管过产品，说话不太留情面。他开篇一句“我后悔让产品管理这个岗位存在”直接把话题引爆了。

今天我们多说几句这件事，因为这个问题戳中了现在很多产品经理真实的焦虑感。

Tom 的论点不是攻击 PM 本身，而是说产品管理应该是一个手艺活儿，不是一套资质认证。他认为现在的问题是，大量 PM 被当成默认配置塞进团队，工程师和设计师反而被剥夺了做决策的肌肉训练机会，因为“总有个 PM 在 babysitting 他们”。

最锋利的一句是他指出，AI 正在把大量“产品剧场”暴露出来。利益相关者管理、对齐会议、故事包装——这些不是产品工作本身，却是过去几年行业奖励 PM 的方向。但剧场为什么能存活？因为验证成本太高。现在 AI 可以把验证成本打到近乎为零，不会思考只会讲故事的 PM 就藏不住了。

Tom 现在的做法是，招人时直接甩一个问题和数据集，让候选人当场推演方案并公开辩论。他的观察是，会包装但不会思考的人，在这种环节迅速就崩掉了。

系统思维是他眼中上升最快的 PM 技能。他每次做产品评审都只问两个问题：实验如果绿灯怎么办，红灯怎么办。如果 PM 回答“我不确定”，那这个实验就没准备好。这不是做 checklist，而是逼你在烧钱跑 AB 测试之前，把所有胜负路径都想清楚。

还有一个反常识的观点：不要急着把 A 级玩家提拔成管理者。在 Whatnot，四五个 PM 主管每人做 90% 的 IC 工作。Tom 自己作为 CPO，一半时间还在亲自做个人贡献者的活。他说太多 A 级 PM 被推到 Director 位子上，手不沾活，短短几个月直觉就退化了，而底下初级 PM 拿着同一份 PRD 来来回回改，整个团队的肌肉都在流失。

这里有个你可以立刻用上的建议。Tom 说他每六个月重新分配一次产品经理，不是按团队分，而是按问题分。有些工程团队一整年没有 PM 也跑得好好的。一个 PM 可能在半年内摸过买家、卖家、信任三类问题，而不是钉死在同一个功能上三年不动。他说得更直白：更多 reps、更多肌肉群。

面对数据时，规则也很简单。平均值什么也说明不了。一个只有 3% 用户碰的功能看起来应该砍掉，但对于某些用户，这个功能就是 100% 的日常。砍它就等于圣诞节前关了购物中心的电闸。Tom 的告诫是，随时要问平均值底下藏着什么分布。当某个具体案例和表格数据冲突的时候，相信那个具体的案例。

整篇访谈还有好几条干货，Show notes 里有链接，推荐睡前看一遍。

说到 PM 这个话题，Peter Yang 今天也分享了和 Nous Research 联合创始人 Karan 的播客访谈。里面有一条和上面的讨论高度呼应。Karan 提到他在用 Hermes Agent 的时候，会让一个 Agent 干活，再开一个干净上下文的 Agent 来独立挑刺。

原因是只要模型说“你说得绝对对”，它就已经在刷你的好感度了。Tom 说的“产品剧场”也好，Karan 提醒的“被奖励劫持”也好，本质上都是在说同一件事：当验证成本降下来以后，这些表面功夫就会越来越不值钱。你的团队里有没有这样的事情？

再说几条快讯。

Google 的 Logan Kilpatrick 昨天发了条简单的提醒。他说“你对模型的押注很可能还不够猛”，不管你现在有多看好，大概率还是低估了这条指数曲线的斜率。说真的，用“model pilled”这个词来定义开发者该有的信念感，他还是第一个。

MiniMax H3 的视频生成能力又刷屏了。Justine Moore 今天特地澄清，她的那段《办公室》主题视频是纯文本到视频，不是图片引导。她晒出了在 Krea 上的提示输入截图，证明这是一次 prompt 直出。这件事为什么重要？因为圈子里很多人一开始都不信，都觉得一定是传了参考图进去。

Greg Isenberg 发了一段 26 分钟的“图工程”讲解视频，专门讲怎么用图工程法把 Claude Code 或 Codex 的能力往上拉一个台阶。收藏量已经高得不像话。如果你最近在推 Agent 的生产上限，这条值得放进稍后观看。

Riley Brown 分享了一个小技巧。在 Codex 或 GPT 里，要求它用“Editable text block”格式回复。好处是你可以直接手动编辑，可以让 AI 再改，也可以一次复制走。是个细节，但够实用。

OpenWorker 也来了。Andrew Ng 和 Rohit Prasad 做了个开源的本地 Agent，不绑定任何单一模型，可以用 GPT、Claude、Gemini，甚至 DeepSeek 跑本地。郭宇 retweet 时调侃说“到底有多少人在做类似产品”。是啊，都在抢“你自己的 AI 同事”这个生态位，你会发现现在连选都不用选了，只是还有一个问题没解决：你怎么处理这么多工具？你会怎么选？
