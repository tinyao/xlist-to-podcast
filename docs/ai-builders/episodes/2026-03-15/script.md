昨天下午，Boris Cherny 和 Thariq 连发了一批公告。第一条是"春假大礼包"：接下来两周，Claude 在非高峰时段——也就是工作日太平洋时间早上五点到十一点之外，以及所有周末——会把使用额度直接翻倍。Thariq 在公告里说，Claude 最近增长太快，扩容过程中遇到了一些稳定性问题，翻倍额度是对用户耐心陪伴的一种感谢。Boris 也补了一句话："非常感谢每一位一直在用 Claude Code 的人，无论是最早那批还是今年才加入的。正是你们的反馈让我们能每天把产品做得稍微好一点。"这条推文三千多个点赞，互动量对技术公告来说不低。

但这只是热身。真正让我觉得有意思的，是 Thariq 同一时间发出的"end of week ships"里的一个新功能。

`/effort max`。你现在可以用这个命令让 Claude 进入更深度的推理模式——它会花更长时间思考，用尽能用的所有 token。代价是会更快消耗你的使用额度，所以需要每个 session 单独开启，不是全局生效的。这条推文接近三千个点赞，一千两百六十五个收藏，是今天互动量最高的 Claude Code 更新。

这个功能意味着什么？以前你想让 Claude 在一个问题上多花时间，只能靠 prompt 技巧。现在有了一个明确的模式切换：普通模式和 max 模式，一个命令，按需开关。对于真正需要深度推理的复杂任务，这是一个实用的控制旋钮，而不是玄学。

同一批更新里还有几条：`claude --name` 可以在启动 session 时直接命名；`/color` 可以改变 prompt 输入框的颜色；进入 plan mode 之后 session 会自动命名；另外加了一个 `postcompact` hook，在 context 被压缩之后触发；Claude Code 的 Web 版和桌面版现在都支持设置 setup script，你可以在启动前自动跑一段初始化脚本。

把这些放在一起：翻倍额度、`/effort max`、session 命名、颜色定制、setup script、postcompact hook。没有一个是颠覆性的大功能，但每一个都在解决真实的工作流摩擦。Anthropic 的迭代节奏越来越密，而且每次都踩在工程师的真实痛点上。

好，我们说说郭宇。

今天他发了一份新的 wanman AI 实验报告，跟昨天那个 Qwen 游戏公司实验完全不同——目标换成了在东京创办一家装置艺术公司。同样用纯 Qwen 3.5，六个 AI agent：CEO、Dev、Marketing、Finance、Feedback、DevOps。

agent 自主给公司取了名字：KOUROKU，写作"光録"，定位是数字装置艺术加 WebGL 沉浸式体验，客群面向东京画廊、商业空间和品牌旗舰店。

这次实验跑了一千零三十六轮、六点六小时，最后因为 BoxLite sandbox 的 bridge 请求超时三百秒而强制终止。最遗憾的地方是：交付物没能从 sandbox 里提取出来保存。

但在终止之前，agent 已经做了八十二个文件。Dev agent 开发了 Three.js 加 Vite 的官网，含 WebGL 粒子系统演示，还有一个 React 组件库，里面有五个装置模板——LightFlow、ParticleSystem、ProjectionMapping、VirtualGallery、InteractiveFeedback；Marketing 出了十七份文档，包括品牌视觉识别指南、完整商业计划书、定价标准、首展策划案；Finance 做了财务预算，启动资金五百三十万日元；DevOps 出了五部分部署文档，覆盖 Vite 构建到生产运维。

从改进对比来看，上次实验 CEO agent 越权操作发生了两三次，这次只有一次。大文件拆分和 DevOps 按需启动也都有效。但 `task.done` 命令 workers 还是没有采用——这个问题没解决。

郭宇的判断很直接：sandbox 稳定性是当前最大瓶颈，六点六小时的产出全部丢失，在工程上是完全可以规避的，需要加心跳检测和中间保存机制。

他同一天还在单向街做了公开分享，来的人远超预期，说了几小时话喉咙哑了。他提到用 bun 把 wanman AI 打包成了二进制文件，在活动现场直接演示。"打包成二进制现场展示"这个细节说明 wanman 在逐渐走向可分发的工具，不再只是他一个人在自己机器上跑的实验。

说到这个，我想聊一聊今天 Aaron Levie 发的两条推文。

第一条讲流程再设计。他说，把 AI agent 叠加到现有流程上，和从零开始为 AI agent 重新设计一个流程，是两件完全不同的事。他给了一个具体的思维框架：如果你有无限多个能写代码、能调 API 的工程师，你会怎么设计这个流程？在营销、财务、运营里，有大量重复性任务，只要用这个视角重新设计，就能获得量级的提升。能做到这一步的团队，会和只是"在现有流程上叠 AI"的团队拉开巨大差距。

第二条更有意思，讲的是 agent 和软件采购。他的核心判断是：在未来，AI agent 会逐渐代替你和你的公司做大量的软件选型决策。对已有技术标准的地方，agent 会遵守；但对所有新工作流，agent 是主要的决策者。而且 agent 会非常功利——根据哪个工具最容易被调用、效果最好、价格最低来选，没有人类的品牌偏好和惰性。他的结论是：如果你的平台没有可以被 agent 轻松调用的 API，你对 agent 来说基本上是不存在的。

这两条加在一起，画了一张挺清晰的图。内部流程要为 agent 重新设计，不只是修补；外部软件市场，选择权正在从人类转移到 agent。对于在做 B2B SaaS 的人来说，这两个判断，现在就需要认真对待。

Meta 宣布将裁员超过百分之二十的员工，来源是路透社。Peter Yang 的评论一句话："FAANG 的工作已经没有安全感可言了。"这条推文两千四百多个点赞，说明不少人感同身受。

另外，agent-browser 这个工具发布了一个新版本，把底层完全用 Rust 重写，冷启动快了一点六倍，内存减少了十八倍，安装包缩小了九十九倍。Vercel CEO Guillermo 转发评论说，AI 会帮我们把大量基础设施用 Rust 重写，然后我们会活在安全性、速度和内存效率的美好里。这个判断我觉得越来越像一个预言而不是期望。

swyx 今天分享了一条观点：agentic AI 从根本上是后端工程，而不是 AI。事件驱动系统、数据管道、分布式系统、API 设计、可观测性——这些才是真正的 agent 工程核心，不懂这些的人正在把 agent 工程想得太简单。swyx 补充说他已经说这话说了三年了。
