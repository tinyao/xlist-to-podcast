Instinct 这个 AI 助手被发现在未经用户许可的情况下索引和保留邮件。而且用户无法从记录中删除这些数据。

AI 教程作者 Peter Yang 昨天在 X 上发出警告。他是在另一位用户 Claire Vo 的提醒下发现的。Peter 直接对 Instinct 喊话，说这不行。他明确表示，在问题解决之前不会向任何人推荐这个工具。不过，他也承认 Instinct 的入门体验做得非常流畅。连接 iMessages、Google Workspace 和 MCP 服务器的过程很顺滑。但隐私底线被触碰，再好的体验也没用。AI 助手在追求主动性的同时，数据处理的透明度是个绕不开的坎。

如果你正在试用 Instinct，现在就去检查它连接了哪些数据源。确认是否有敏感信息被索引。

Guillermo Rauch 昨天在 X 上分享了内部测试的过程。这个工具基于 Ora 的研究，能运行超过 100 项检查。它还能可视化 agent 如何浏览你的网站，并一键生成修复提示。最有意思的是，Vercel 团队把这个工具用在自己网站上，反复跑测试直到拿到满分 100 分。Guillermo 说，这个过程让他们补上了不少缺口。虽然满分听起来像噱头，但背后的逻辑是认真的。未来 agent 会越来越多地访问你的网站。如果你的内容对 agent 不友好，就等于在 AI 世界里隐形。

如果你在维护任何面向开发者的网站或文档，现在就可以用 is-agentic.com 跑一次审计。看看 agent 能不能读懂你的内容。

说到 agent，今天还有一件事。Anthropic 的 Claude Code 团队公开了一个内部高频使用的技能：ELI5。就是“像对完全不懂的人解释”。

Claude Code 团队成员 Thariq 昨天分享了用法。这个功能用 /eli5 命令触发，会生成一个带有大图和少量文字的 HTML artifact。它能把复杂问题讲得极其通俗。Thariq 举了几个典型场景：解释某个模块怎么工作、为什么做了某个技术权衡、某次事故的原因。他说团队内部在考虑是否把它做成官方插件。但目前已经可以通过社区插件市场安装。

如果你日常需要向非技术同事解释技术决策，这个插件能省下大量画图时间。安装命令已经在社区仓库里了。

今天值得展开聊的，是这件事。

创业者、Startup Ideas 播客主理人 Greg Isenberg 昨天发了一条长推文。他详细拆解了他的朋友 Billy 如何用 Grok Bot 的 AI agent 团队运营整个 newsletter 生意。Greg 认为，Grok Bot 可能是第一个让非技术人员用 AI agent 团队跑通整个业务的工具。他预测我们即将看到超过 10 万个类似的小生意冒出来。

Greg 总结了七条实践，核心思想是把 agent 当员工管，而不是当工具用。第一条，一个 agent 只负责一个使命。避免上下文膨胀烧 token。第二条，先设一个 Chief of Staff agent。让它审计你的现有文档，然后告诉你最该先建哪三个 agent 来驱动收入。第三条，先让人验证任务流程，再让 agent 自动化。你得先自己跑通一遍，再让机器人接手。第四条，限制本身就是特性。Grok Bot 只给你有限数量的 agent 和单线程对话。这反而逼你保持聚焦，不会为每个随机想法都开一个 bot。第五条，人做决策，agent 执行。Billy 的团队曾花了三周纠结内容该放哪里。最后是他拍板就用 Notion，不再折腾。第六条，第一周不加新 agent，先学会驾驶现有团队。到第三周再根据真实缺口扩展。第七条，设置夜间自动例程，让生意在你睡觉时自己跑。

这套方法论听起来像管理课，但它背后的逻辑很实在。agent 的瓶颈不是模型能力，而是人的注意力。如果你正在尝试用 agent 自动化工作流，不妨从这三步开始。先列出现在最消耗你时间的三个重复任务。然后挑一个最标准化的，手把手跑通一遍。最后再让 agent 接手。别一上来就建五个 bot。那样只会让你同时管理五个实习生，累的是你自己。
