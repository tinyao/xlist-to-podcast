最前沿的 AI 模型在软件工程基准测试上只拿了 13.8% 的分数，这意味着什么？
创始人 Tony Fadell 说，AI 时代最大的护城河不是数据，而是品味。他做对了什么？
而 OpenAI 罕见地发布了他们关于公司未来的最新计划。
先从最硬的那道基准测试题说起。

Cognition 发布了一套全新的编码基准测试，叫做 FrontierCode。
结果很惊人：在当前最难的钻石级任务里，Opus 4.8 的得分只有 13.8%。

这个基准是 swyx 昨天亲自发布的。
他和 Cognition 团队请了一批顶尖的开源项目维护者，花了超过一千个小时来构建这些编程任务。

这套题和我们以前熟悉的那些测试不一样。
以前的 SWEBench 或者 HumanEval，基本是在看模型生成的代码能不能跑通测试。
而 FrontierCode 盯着的是一道更难的题：你写的代码，维护者到底愿不愿意合并进主仓库？

swyx 引用了 METR 的一项发现：在 SWEBench 上跑通的代码，有一半以上其实是没法合并的烂代码。
FrontierCode 直接针对这个痛点，做了三千多条评分细则。
它不光看你结果对不对，还要看代码质量，还要防作弊——以前那些靠碰运气刷榜的“奖励攻击”手段，在这里基本不管用了。

这事里有一个细节，值得你琢磨一下。
swyx 特别要求团队对历史上的老模型也跑了一遍回溯测试。
他们发现，FrontierCode 里最简单的那三分之一任务，在 2025 年底被模型突然集体攻克了。
Opus 的通过率在四个月里从 41% 跳到了 74%。

这正好和去年底圈子里那股 “WTF happened” 的氛围对上了。
Karpathy 和 DHH 当时都提到过这种体感突变。
背后的原因，可能就是模型从需要重试六次才能成功，变成了重试两次就能成功。
这让 agent 在循环工作的时候终于不用提心吊胆，担心跑到一半彻底翻车了。

如果你也在重度使用 AI 编程，我的建议是：抽空去看看 FrontierCode 的题目风格。
这其实是在告诉你，未来自动代码审查工具的第一性原理会落在哪里——不再是能不能跑，而是能不能维护。

换个方向。
Sam Altman 昨天发了一篇长文，标题是“为普惠全民而建：我们的计划”。

文章的具体内容，说实话，仍然是 OpenAI 一贯的风格，比较宏观。
核心信息是围绕如何平衡公司盈利与社会责任，以及未来技术治理的方向。
但一个有意思的信号是，Sam Altman 本人亲自发这篇文章的时机。

OpenAI 最近在商业化上的步伐明显加快，而社区里关于“模型到底应该怎么变现”的讨论也越来越多。
Box 的 CEO Aaron Levie 昨天就提出了一个很具体的分层观点。

Levie 认为，未来一到两年，AI 的用例必然会按模型能力进行分层。
20% 的高端任务，比如科学突破、高层级 agent 编排，会继续跑在最前沿、最昂贵的模型上。
而剩下 80% 的高频工作负载，会被逐步剥离出去，交给便宜 99% 的模型来处理。

Levie 还特别提到，在这个趋势下，最有价值的东西会变成那个能“智能路由”的中间层。
也就是 agent 编排系统自己来决定：这个提示词到底该发给便宜的模型还是贵的模型。
这不再是简单的成本优化，而变成了 agent 时代一个全新的技术难题。

你觉得呢？你团队里现在的 token 用量，是还在硬扛着用最贵的模型跑一切，还是已经开始做分层路由了？

今天值得展开聊的，是这件事。
Lenny 昨天发布了他和 Tony Fadell 的深度对谈。
信息量巨大，我快速帮你把最硬的干货筛出来。

起因是 Lenny 请来这位横跨 iPod、iPhone 和 Nest 的传奇硬件人，聊聊他在 AI 时代对产品构建的看法。
Tony 这两年说话一直很冲，但每次都能打中一些我们选择性忽略的盲区。

他第一个核心观点就很反直觉。
他说，在做 v1 产品的时候，你的决策必须基于观点，而不是数据。
当你试图创造一个世上从未见过的东西时，根本没有靠谱的数据可以参照。
如果硬要一切都用数据驱动，做出来的只可能是同质化的平庸产品。
你需要找一两个有品味的掌舵人，让他们在广泛吸收信息后，用自己的直觉来拍板。

听起来有点像个人英雄主义，对吧？但他给了个硬核案例。
当初 iPhone 键盘的争论，是团队历史上最长、最激烈的辩论。
他和团队花了几个月做测试，对比实体键盘和虚拟键盘的打字速度和错误率。
最后数据摆出来，结论根本不明确，支持哪一方的都有。
这时候 Steve Jobs 直接拍板：要全尺寸虚拟键盘。
那些无法接受这个决定的成员，被要求离开团队。

Tony 还抛出了一个很重的词：认知投降。
就是他所谓的 “cognitive surrender”。
他看到现在很多 AI 产品经理和工程师，正在把架构决策、品味判断和伦理边界，全都交给 AI 去做。
在他看来，这是最大的风险。
AI 可以帮你做原型、执行子任务。但在确定产品灵魂、判断“什么是更好”的那一刻，人类的判断力绝对不能缺席。

Tony 还预测，下一个颠覆性的消费设备将是“语音优先，屏幕最后”的。
我们现在是人机交互先点屏幕、再用键盘，最后才是语音。
将来这个顺序会完全倒过来。
而这里头有一个坑，大多数做语音 agent 的人都踩过。
他说，做产品必须要思考“完整的客户旅程”。
你做的不只是一个语音助手，而是一个系统。
就像当年 Nest 温控器，它不光改变了产品功能，还改变了用户怎么买到它、怎么安装它、它怎么学习的整个链条。

说回咱们自己。
你有没有想过，你现在做的产品决策里，有多少是数据告诉你的，又有多少是你自己真正坚持的品味？
Tony 给的操作建议很具体：想要做好 v1，先去找那些被用户习惯性忽略的真实痛点，再问自己一句——“为什么现在能解决了？”

再说几条快讯。
Google 的 NotebookLM 昨天迎来了一次大版本更新。
Google Labs 的 VP Josh Woodward 说，它现在能突破你自己的源文件，去更广泛的范围里做搜索了。
同时还能生成 PDF、PPT、Excel 图表这些新格式的输出。
目前只推给 Google AI Ultra 订阅用户。

前 Meta L8 工程师 Kun Chen 介绍了他那个相当硬核的 agent 工程系统。
Peter Yang 昨天做了总结。
核心是他的“无悔”代码验证流水线，能在 267 次 agent 变更里自动抓出并修复 68% 的错误。
Kun 现在基本不手动审 AI 写的代码了，而是让另一个 agent 来审。
他的整套工具，包括可视化计划工具 Lavish 和并行 agent 管理器 Treehouse，都已经在 GitHub 上开源了。
如果你觉得手动 review 代码已经在拖慢你的速度，这些工具值得装一下。

独立开发者郭宇昨天发了一条很有触动的观察。
他说，许多独立开发者最终会陷入一种平衡姿势：在某个小众领域精心打磨自己喜欢的产品，维系一小批忠实用户。
他管这叫“守墓人陷阱”，并且直说自己非常警惕这种状态。
真正的韧性，不是在舒适区里反复打磨细节，而是持续地在看似相反的道路之间做选择——既要独特，又要不怕无人理解。
对今天全凭一个人扛着产品的 builders 来说，这条很值得想一想。

还有一条，MagicPath 发布了一个新计划叫 Builder。
月费十美元，可以无限调用外部 agent，还带一个支持 Figma 导出的多人协作画布。
瞄准的直接就是 Codex、Cursor、Claude Code 这些已有工具的工作流。

今天这么多信号，其实都指向同一种张力：模型的能力还在陡峭爬坡，但真正决定产品能否突破的，早就不只是那百分之几的 benchmark 分数了。
你会用什么来校准自己下一个产品的方向？
