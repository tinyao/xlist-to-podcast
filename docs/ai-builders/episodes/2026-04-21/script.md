Cloudflare Workers AI 悄悄上线了一大批新模型，这意味着什么？Atlassian 更新了隐私政策，你的 Jira 数据会被拿去训练 AI 吗？Sam Altman 说 Codex 的新功能内部代号叫“心灵感应”，它到底能做什么？先从昨晚最让人睡不着的那件事说起。

Atlassian 更新了隐私政策。从今年 8 月 17 号开始，你在 Jira 和 Confluence 里的数据，会被默认拿去训练 AI。

这件事是 Obsidian 的创始人 kepano 昨晚在 X 上爆出来的。他直接贴了 Atlassian 官方公告的截图，文字里压着一股火。公告写得很清楚：除非你手动退出，否则数据就会被用于改进 Atlassian 的 AI 体验。

更让人不舒服的是退出机制。如果你的组织用的是 Enterprise 版，你可以选择不共享。但如果你用的是 Free、Standard 或者 Premium 版，你的数据贡献是强制开启的，没法关。Atlassian 的说法是，这些数据会做去标识化和聚合处理，名字和邮箱会被移除。

kepano 的评论很尖锐。他说，只要你的数据存在一个公司能随意读取的数据库里，而不是端到端加密的，这家公司迟早会更新服务条款，把你的数据拿去训练 AI。诱惑太大了，谁都扛不住。

如果你团队在用 Jira 或者 Confluence，今天就去后台看一眼那个数据共享开关。尤其是存了内部架构讨论、客户信息或者未公开产品路线图的那些空间，确认一下你的计划到底有没有退出选项。

另一件值得说的事。Cloudflare Workers AI 昨天深夜上新了一大波模型。

郭宇是最早发现的那批人之一。他半夜发帖说，Nano Banana 2、Opus 4.7 这些流行的模型全都有了，而且他感觉自己以后不用再去调 Open Router 了。他紧接着晒了账单，上个月所有产品的流量是六百万次请求，用了将近两百 G 带宽，独立访问量一百二十四万，Cloudflare 扣了他七美元。

这是个什么概念？一个百万级访问量的产品，基础设施成本七美元。郭宇自己的说法是，这个数字低到让他有点恍惚。

但这件事的意义不只是便宜。郭宇之前在折腾音乐可视化产品的时候，踩过一次坑。他发现用 Codex 可以一次生成质量很高的内容，但换成 API 调用模型，就很难复现同样的效果。原因在于，API 层面缺少 agentic loop，单次调用的错误率很高。他当时的结论是，不应该让模型在沙箱里执行命令行，而应该让模型写代码交给沙箱跑。

现在 Cloudflare 把 Opus 4.7 这种级别的模型直接嵌进了 Workers 的边缘网络，等于把推理能力和边缘计算放在了同一个 runtime 里。对于在搭 agent 工具链的人来说，这意味着你可以省掉一层网络跳转，在离用户最近的节点上同时完成推理和执行。

如果你现在在用 Vercel Edge Functions 或者 Lambda 跑 agent，郭宇这条实践路径值得关注一下。不是因为七美元便宜，而是因为推理节点和执行节点合并之后，延迟和故障点都会少很多。

换个方向。OpenAI 给 Codex 推了一个实验性功能，叫 Chronicle。

这个功能的核心是，Codex 会自动读取你最近在电脑屏幕上看到的内容，然后形成记忆。你不需要再重复解释上下文，它就知道你刚才在干嘛。Sam Altman 转发了开发团队的公告，补了一句：这个功能的内部代号叫 telepathy，心灵感应，而且他说用起来就是这种感觉。

swyx 对这个功能的评价很高。他说，Codex 收购 Sky 可能是 OpenAI 在过去一年里最划算的一笔交易。他从 2024 年那场 AI Engineer World's Fair 上 Romain Huet 用 ChatGPT 桌面端演示 4o Vision 的时候，就在等真正的电脑操控能力。他说直到现在，这个东西才真正以可用的形态推出来。

不过，另一边有一个不太乐观的信号。Roblox 的产品 Peter Yang 昨天花了一个多小时，试图让 OpenClaw 用 GPT 模型跑一个简单的任务。就是每周发一封统计汇总邮件。他说 Opus 跑这个任务毫无问题，但 GPT 完全不行。他贴了一段对话记录，里面他反复在说“你搞砸了”、“算了你打开模板我自己改”。最后他的结论是，这个模型目前就是没办法稳定地执行 agentic 任务。

这两条放在一起看，挺有意思的。Codex 的记忆功能在往前跑，但底层模型的 agentic 稳定性，至少在非 Opus 模型上，还是拉胯的。如果你的 agent 工作流最近也在频繁翻车，Peter 这条帖子下面七十多条回复里，有不少人在分享自己的模型组合方案，值得翻一翻。

说到 Vercel 的安全事件，今天有重要的后续。

Guillermo Rauch 昨晚又发了一条澄清。他说很多人把“删除”和“轮换”搞混了。你如果只是在 Vercel 面板里把环境变量删掉，密钥本身在第三方服务那里还是活的，攻击者照样能用。正确的做法是去那个密钥的签发方，把它作废，然后生成一个新的。

Vercel 的安全公告也在持续更新。Guillermo 说他们已经联系了所有确认受影响的客户，并且正在和 Google Mandiant 团队合作做取证。他还特别感谢了 Mandiant 的快速响应。

如果你前两天已经轮换了密钥，今天可以再核对一件事：你轮换的范围是不是覆盖了所有关联的第三方服务，而不仅仅是 Vercel 上能看到的那些。

今天值得展开聊的，是 Aaron Levie 和 Lenny 在指向同一件事，但得出了完全相反的结论。

起因是两条线。一条是 Aaron Levie 转发了 a16z 合伙人 Andrew Chen 的一条推文，然后写了一篇长分析。Andrew 的原话是，AI 时代最受益的人，是那些本来就很擅长自己工作的人。AI 是一个放大器，不是一个均衡器。

Levie 接过去展开了一层。他说，很多人觉得 AI 会让工作变简单，然后岗位就消失了。这是一个巨大的误解。真实的情况是，当所有人都有了同样强大的工具，大家会集体把工作标准往上抬。以前一个律师助理的核心能力是审合同，以后审合同这件事被 AI 做了，但律师助理的工作不会消失，它会变成在 AI 审完之后，处理那些更复杂的例外情况。工作不是变简单了，是变难了。

他举了几个具体的例子。一个工程师用 AI，比一个不会写代码的人用 AI 去搭同一个软件，产出要高得多。搭一个轻量级 app 不再是软件开发的及格线。剪辑一段视频不再是视频编辑的定义。提供基础金融研究不再是金融分析师的活儿。Levie 的判断是，AI 会让大多数岗位的复杂度上升，而不是下降。

另一条线来自 Lenny 和 Nikhyl 的播客。这期我们昨天聊过，但今天 Lenny 又发了一条长总结，里面有几个数字非常具体。Nikhyl 预测，大公司会在未来一年到两年内裁掉三万人，然后重新招八千人。这八千个人，全部都是 AI 原生的建设者。被裁掉的三万个岗位，一部分是产出不够的人，一部分是工作本身可以被自动化掉的人。

两边的逻辑放在一起，张力就出来了。Levie 说岗位不会消失，会升级。Nikhyl 说一半的 PM 熬不过这次转型。这两件事其实不矛盾，但节奏完全不一样。

Levie 说的是长期均衡。他的逻辑链条是，工具强了，标准高了，人的能力跟着水涨船高，最终留下的还是那些对行业有深度理解的人。这个逻辑在历史上成立。电子表格没让会计消失，反而让财务分析变成了更高级的工作。

但 Nikhyl 说的是短期阵痛。他的视角不是“岗位会不会消失”，而是“你这个人能不能熬到升级完成的那一天”。他说那些在旧游戏里玩得最好的人，反而是这次最难转身的。因为你需要扔掉的东西太多了。而且这个过程不是你自己说了算，是公司的裁员节奏说了算。公司会先把不产生足够价值的人清掉，然后再用更少的人、更高的标准重新招。

Levie 自己也承认了这一点，只是他没把话说得那么直白。他说，如果你能做得更多，你就会去挑战更大更难的问题。这句话的背面是，如果你做不到更多，你连原来的问题都没资格碰了。

这对听众来说，有一个很实际的对照。你在现在的岗位上，是在用 AI 做原来工作量的十倍，还是在用 AI 把原来的工作量省掉一半之后，多出来的时间去刷手机？前者是 Levie 说的升级路径。后者是 Nikhyl 说的危险区。

郭宇昨天在折腾 wanman 的时候，说了一句话挺应景。他说 deadline 真的是第一生产力，为了给大爷大妈演示，他疯狂熬夜修 bug。他是在做一件具体的事，而且这件事逼着他把工具用到了极限。Lenny 那篇总结里也有一句类似的话：找到那个让你快乐的小项目，然后一切都会跟着来。

再说几条快讯。

Google AI Studio 现在支持用 Google AI 的订阅账号直接登录了。VP Logan Kilpatrick 说 Pro 和 Ultra 用户都能用，速率上限更高。不过他也补了一句，配额 bug 还在修，部分功能暂时还需要 API key。

郭宇试了一个叫 wanman 的 agent 产品，评价很高。他说这是他用过最丝滑的 harness 产品，完全不需要动脑子。跟 OpenClaw 和 Hermes Agent 不同，这个产品是真正面向普通人的。

说到 Hermes Agent，Greg Isenberg 昨天拉着创始人 Imran 录了一期播客，手把手教怎么安装。他列了三个 OpenClaw 的痛点：没有记忆、网关一直重启、看不到 token 花费。Hermes 的方案是内置记忆、四十多种工具开箱即用，而且 token 成本能降到 OpenClaw 的十分之一。

腾讯团队基于 OpenClaw 做了一个叫 QClaw 的产品，可以通过 WhatsApp 或者 Telegram 发指令，不需要打开终端。Peter Steinberger 说腾讯团队还帮忙做了性能评估，部分改进会回馈到开源仓库。

Peter Steinberger 还发了一个很有意思的观察。他说现在很多 AI 订阅是高度补贴的，目标就是拿你的代码去训练模型。如果你用 AI 做的是非编码类的事情，你对这些公司来说就没有价值。他链接了一个 Reddit 帖子，里面说某家 AI 平台开始限制非编程用户的额度。
