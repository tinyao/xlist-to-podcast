Fable 5 回来了，但这次带回了一套新的限制规则，这对工程师意味着什么？Vercel 连续推了好几个 agent 相关的能力，Guillermo 还说了句很有意思的话，说 skills.sh 是新的 npm 和 GitHub。另外，Greg Isenberg 和 Sarah Tavel 几乎同时谈到了同一个趋势：不是卖软件，是卖"工作本身"。先从最让代码推不动的那个消息开始。

Claude Fable 5 在消失十八天之后，今天正式回归。Anthropic 昨天发公告确认，美国商务部已经解除了对 Fable 5 和 Mythos 5 的出口管制，模型重新上线。

但回来的不是原版。Anthropic 在公告里说得很清楚：他们和美国政府进行了一系列沟通之后，给 Fable 5 加了一套新的分类器，目标是拦截更多的网络安全类任务。

这意味着什么？在 Anthropic 负责 Claude Code 的 Thariq 随后补充了细节。他说和之前的分类器一样，日常编码和调试任务中有"一小部分"会被标记，然后降级到 Opus 4.8。

Thariq 还特别说明他们在继续优化这些防护，目标是把真正的滥用和合法请求分开，降低误报。但现阶段，如果你用 Fable 写代码，随时可能被切到 Opus，而且你不会提前知道哪条指令会触发。

Box 的 CEO Aaron Levie 昨天发了一段分析，把这个事件放进了一个更大的框架里。他的判断是：Fable 5 的回归过程，以及之后很可能要经历的 GPT-5.6，正在给前沿模型发布建立一个先例。核心问题是——以后的模型如果具备足够强的编码和网络能力，发布之前可能都要走类似的政府审查流程。

Levie 还提到了一个关键风险：这个流程的主观性很强。不同风险的"可被利用程度"在实践中差异很大，而现在的框架依赖的是实验室和政府之间的反复判断。他的担忧写在最后一句：如果每次达到这个能力阈值的版本发布都要走同样的审查，我们可能不会再看到之前那种突破速度。

这个判断挺冷的，它不是在聊一个模型，而是在聊一个刚刚露出轮廓的发布机制。

对于今天就要上手 Fable 的人来说，还有一个让人头疼的细节。Peter Yang 发了一张截图，显示 Fable 5 有一个"每周用量上限"，超过 50%之后模型就不再可用。Yang 说他完全不清楚这个限制的具体规则是什么。这个体验设计相当模糊。

接下来这段我们多说几句。

昨天 Greg Isenberg 在播客里讲了一个完整的创业方法论，标题直接就是"如果我今天开一家新公司，我会做 agent 生意。"他的核心观点很简单：SaaS 是一个几千亿美元的市场，而 agent 可以触达的是一个几万亿美元的市场，因为 agent 卖的不是软件，卖的是"已经完成的工作"。

他把路径拆得很细：找到利基市场、找到有预算的工作流、影子跟踪真人操作、写 agent 规格、手动跑通一遍、先做出最小可用版，然后像卖人力一样把 pilot 卖出去，最后把重复的部分产品化。整段话的逻辑非常清晰，而且每一步都有可操作性。

同一个时间，a16z 的 Justine Moore 转发了 Sarah Tavel 的一段话。Tavel 的表述更精炼：过去二十五年，应用软件创业只有一个目标，提高生产力。AI 带来的变化是——与其卖软件让用户提效 15%，不如卖"工作本身"，直接提效 95%。

Tavel 还说了一句很直接的话：老牌公司不仅在卖软件这件事上有优势，他们也被困在那条赛道里。你不需要按他们的规则玩。

Zara Zhang 看到这段话之后，评论了四个字："怎么会有人想到这么早。"这句话本身挺说明问题的——这个商业逻辑不是刚刚被推理出来的，它在圈内已经被思考了很久。

那落到我们自己身上，这个视角到底怎么用？Greg Isenberg 的那八步路径，本质上就是把"人力外包"的销售逻辑移植到 agent 上。如果你现在手里有一个客户，你不需要说服他买一个工具，你只需要问他：你现在是不是每个月花两万块请人做这件事？我收你八千，结果更快。这套话术不需要教育市场，因为买家已经习惯了为结果付费。

而 Tavel 说的那句"老牌公司被困住了"，其实是一句很具体的竞争策略建议——不要在产品层面跟大公司打，你直接跳到"卖结果"这个维度，他们的现有客户结构和收入模型反而变成包袱。

同一时间，Guillermo 昨天发的一条推文也很有意思。他说 skills.sh 是新的 npm，也是新的 GitHub。你的项目里不再需要那么多模板和大堆代码，他说他已经很久没 clone 过仓库了。你真正需要的是指令和最佳实践，告诉你怎么把最好的东西做出来。

这句话和 Zara Zhang 昨天讲的方法论可以叠在一起看。Zara 的核心观点是：你不应该从 skill 开始，skill 是你工作流程的最后一步。你先手动把一个任务跑通、优化、理解它的每一个决策点，然后才把它固化成 skill。

Guillermo 在另一条推文里也呼应了这个逻辑。他推荐用 eve 和 Sanity 搭建内容 agent，说这类 agent 可以自动处理文档反馈、写修复草稿、提交给人审核。他的建议是：把你可以在聊天里 @ 的那个 agent 做出来，让它修文档、改文案、写发布说明。

Vercel 昨天还推了一个 agent 专用的部署功能，vc deploy --dry。Guillermo 说 agent 在推代码之前总想先检查一遍——你会看到你的 agent 会话里不断跑 node --check、tsc --noEmit、next build，现在 Vercel 把这个预检步骤做进了部署流程，降低了 agentic 部署的成本和风险。

这个功能不大，但它说明一件事：Agent 已经不再是用人类工具凑合着干活了，工具链开始围绕 agent 的使用习惯重新设计。

另外一件事值得说一下。Peter Steinberger 昨天用 Codex 给自己的 OpenClaw iOS app 做了一次改进 pass。他只用了两次 prompt，Codex 不仅改了代码，还用 computer use 能力自动截了修改前后的对比图贴到 PR 里——因为 GitHub API 并没有直接提供这个功能。

Steinberger 的结论是：虽然结果还不够好，但只用了两次 prompt，不算差。他还特别提到了一个细节：Codex 可以切到 GLM 模型。Zara Zhang 也转发了同样的信息，说你可以把 Codex 的底层模型换掉。

另一边，GLM 在 Next.js 上的表现获得了 Guillermo 的直接认可。他引用了 Next.js 的 evals 结果，也引用了 Chamath Palihapitiya 在 8090 平台上的测试数据——用 GLM 5.2 替代 Opus 4.8 之后，成本降了 16.4 倍，虽然速度慢了三倍。

Steinberger 昨天还转发了一条关于 Claude Code 隐写标记的推文。有人发现 Claude Code 会在请求里藏一些隐写信息，他评论了四个字：偷偷的，但也挺聪明。这类基础设施层面的小细节，往往是安全团队接下来要重点扫的地方。

再说几条快讯。

Vercel 昨天和 Resend 达成了深度集成。现在你可以从 Vercel 的 Dashboard、CLI 和 v0 里直接创建和管理你的 Resend 账号，账户配置、结算、DNS 全部打通。Replit 和电商平台 Whop 也达成了合作，在 Replit 上做的应用现在可以直接在 Whop 上卖。Amjad Masad 说得很直接：既然建应用已经变得容易了，接下来的重点是帮开发者触达第一个客户、赚到第一块钱。

Notion 昨天推了一个很有意思的新 block 类型：HTML。你现在可以直接在 Notion 页面上嵌入交互式 HTML，让 AI 把内容转成可交互的原型或图表。Claude Code 的 Thariq 转发了这条消息，配文就一个词："HTML mentioned."这句话的梗在圈内很出名。

Justine Moore 昨天还分享了两个观察。一个是 Instagram 上的 AI 生发产品广告视频正在批量收割男性用户，这些视频动辄几千万播放，评论区全是问链接的。另一个是越来越多人用 LLM 发现了自己的慢性健康问题，很多是医生不会注意到的那种——比如你用的枕头和桌子高度是不是真的适合你。

这些事情都在说同一件事：AI 正在进入一些意想不到的接触面。

如果你今天只做一件事，把 Fable 5 开出来跑一个你最在意的项目，感受一下那个 50% 上限到底在哪、被切到 Opus 的时候体感差多少。另外，如果你有一个重复性的、目前靠人在盯的流程，今天可以花半小时把它拆成 Greg Isenberg 那八步的前三步。不用做到最后，只要找到那个"有预算的痛点"就行。
