今天我们要聊三件事：Claude Code 发布了一个让人眼前一亮的新功能 /loop；Karpathy 开源了一个"让 AI 自己做 AI 研究"的项目；还有一个越来越清晰的趋势信号——Codex 不只是写代码的工具。好，我们开始。


第一个话题，Claude Code 的 /loop 功能。

昨天，Anthropic 的 Claude Code 团队发布了一个新命令，叫做 /loop。这条推文来自 Claude Code 的工程师 Boris Cherny，发出去之后迅速成为昨天互动量最高的内容之一，超过一万个点赞，将近七千个书签。

/loop 是什么？简单说，它让你可以给 Claude Code 安排定期执行的任务，时间跨度最长可以到三天。

举两个官方给的例子：你可以说，"/loop 帮我盯着所有 PR，如果 build 出问题了就自动修，如果有人留了 comment 就用 worktree agent 去处理"。或者，"/loop 每天早上用 Slack MCP 给我总结一下昨天有哪些重要帖子 at 了我"。

这听起来像是什么？像是给 AI 设了一个值班表。

我觉得这个功能的意义不只是"方便"。它背后有一个更深的逻辑转变——以前我们用 AI 是"我有需求，我去问 AI"，是 pull 模式。/loop 把这个翻转了，变成了 push 模式：AI 在后台持续运行，主动帮你完成任务，不需要你每次手动触发。

这和另一条推文形成了有趣的呼应。swyx 在推特上说，他录了一期可能是 Latent Space Podcast 历史上最重要的对话，聊的是 OpenAI 内部的 Frontier 工程、Symphony 和 Harness Engineering，他认为这是"AI Native 组织的未来"。同一时间，OpenAI 官方也分享了一个案例：一个小团队用 Codex 开了 1500 个 PR，交付了一个有数百名内部用户的产品，全程零手动写代码。

把这几件事放在一起看，你会发现一个方向越来越明确：AI agent 正在从"工具"变成"同事"，从单次调用变成持续运行的协作者。/loop 这个功能，是这个方向上一个很具体的落地。

顺带说一句，Claude Code 团队里还有另一位工程师 Thariq，他昨天发了一张截图，配文是"machines of loving grace"，那是一首诗的名字，也是很多 AI 从业者对 AI 未来的一种浪漫化想象。在 /loop 发布的同一天发这张图，不知道是不是有意为之，但时机挺妙的。


好，我们来看第二个话题，Karpathy 的 autoresearch 项目。

Andrej Karpathy 昨天开源了一个叫 autoresearch 的项目，这条推文拿到了将近五千个点赞，将近五千个书签，是昨天技术圈转发量最高的内容之一。

项目本身不复杂，但想法很有意思。它的核心是这样的：你有一个 LLM 训练的基础代码库，大概六百三十行，单 GPU 可以跑。然后，人类负责迭代 prompt，AI agent 负责迭代训练代码本身。每次训练跑五分钟，agent 在一个 git 分支上自主循环，不断提交更好的设置——更低的 validation loss，更好的架构参数，更优的 optimizer 配置。

Karpathy 自己说，"目标是让 agent 在没有你参与的情况下，无限期地做出最快的研究进展"。他还补了一句，"part code, part sci-fi, and a pinch of psychosis"，一部分是代码，一部分是科幻，还有一点点精神失常。

我喜欢这个描述。

他还提到，他有一个更大的版本在生产环境跑着，八张 H100，更大的模型，他说"我就让它一直跑着"。

这个项目让我想到一个问题：如果 AI 可以自己做 AI 研究，那研究的瓶颈在哪里？Karpathy 的回答其实藏在项目设计里——瓶颈在人类怎么写 prompt，也就是怎么定义研究方向。agent 负责执行和迭代，人负责提问题。这个分工，和我们之前讨论的 /loop 有异曲同工之处。

值得注意的是，autoresearch 现在还是一个周末玩具级别的项目，Karpathy 自己也说是"让大家周末玩一玩"。但它代表的方向——用 agent 加速科研循环——是很多顶级实验室都在认真探索的事情。这个项目的价值更多是概念上的示范，而不是生产可用的工具。但有时候，一个好的示范，比一个复杂的产品更能推动行业认知。


第三个话题，我想聊一个正在形成的新共识，关于 Codex 和 AI 工具的边界。

OpenClaw 的联合创始人 Peter Steinberger 昨天发了一条推，互动量非常高，将近六百五十个点赞，两百多个书签。他说的是一件很简单的事：大家还在把 Codex 当成一个写代码的工具，但其实你可以用它做各种数据分析工作。

他自己的例子是，他用 Codex 分析了 Discord 的用户数据——他之前开源了一个叫 discrawl 的命令行工具，可以把 Discord 的消息爬下来存到 SQLite 数据库里，他的数据库有四个 GB，六十六万条消息。然后他用 Codex 在这堆数据里找用户痛点，决定接下来开发什么功能。

这件事本身不复杂，但他说出来之后引发了很多共鸣，因为它打破了一个默认的心理模型——很多人在用 AI coding 工具的时候，脑子里想的还是"我要写一个函数"、"我要 debug 这段代码"。但其实这些工具的能力边界早就超出了"写代码"这件事。

同一天，他还分享了一个叫 PinchBench 的基准测试网站，专门测各个模型在 OpenClaw 这类任务上的成功率。他说这是他们内部用来判断"哪个模型最适合我们产品"的参考。这种"为具体任务定制 benchmark"的做法，我觉得是一个很务实的信号——通用 benchmark 的参考价值在下降，针对具体使用场景的评测越来越重要。

另外，他还提到了一件有点让人哭笑不得的事：他们的开源项目现在收到的安全漏洞报告里，有一条说"详细测试了 GOT-4o"——这个模型根本不存在。AI 生成的 slop 报告已经开始污染开源社区的维护工作了。这是一个小细节，但值得记一下。


好，接下来是快讯板块，我们快速过几条。

另外，GPT 5.4 这两天收到了不少正面评价。a16z 的投资人 Justine Moore 说，这个模型"感觉像在和一个聪明的朋友聊天"，她觉得它在人格塑造上做得特别好，不只是在写代码这件事上，在解释概念、讨论问题上也是。OpenAI 的 Kevin Weil 也转发了一篇关于 GPT 5.4 推理能力的分析文章，说"值得你的团队读一读"——虽然他发推的时候手滑写成了 GPT-4，后来自己更正了。

顺带一提，Kling 发布了新的 Motion Control 功能，支持换脸。Justine Moore 测试了一下，她用的是大家都认识的真实面孔，算是困难模式，结果她说"不完美，但处理多角度镜头的效果出乎意料地好"。视频生成工具的能力边界又往前推了一步。

快速说一条，Anthropic 的哲学家兼伦理研究员 Amanda Askell 昨天做了一件很有意思的事：她让 Claude 帮她写了一份"Amanda 的 constitution"，也就是她个人的价值观宪法。她说 Claude 写的版本让她很感动。这条推文拿到了两千多个点赞，三百多条回复。有趣的地方在于，Askell 本人就是 Claude 性格和价值观设计的核心参与者之一，她让 Claude 来反过来定义"她的价值观"——这个循环本身就很耐人寻味。

还有一条，Replit CEO Amjad Masad 在 a16z 的采访里提出了一个新职位概念，叫"Generalist Automator"，中文可以理解为"通用自动化工程师"。他的逻辑是，以前最有想法的员工被工程资源卡住了，现在他们可以自己用 AI 工具把想法落地，创造直接的商业价值。他说 Replit 正在组建一支"vibe coders"团队，专门在公司内部找低效环节然后用 AI 解决掉。这个概念和 Aaron Levie 在 Box 说的逻辑是一致的——AI 降低了软件开发成本，所以软件的使用场景会爆炸式增长，对工程能力的需求反而会上升，而不是下降。

最后一条，有人在推上分享说，有几个朋友为了能 24 小时监督自己的 coding agent，开始练习多相睡眠法，也就是把睡眠拆成多个短时间段。Linear 产品负责人 Nan Yu 转发了这条，评论说"我不知道新生儿也会写代码"。这个玩笑背后是一个真实的焦虑：agent 在跑，但你不放心让它完全自主，又不想一直盯着。这个人机协作的信任边界问题，接下来会越来越普遍。


好，今天就到这里。

如果让我说今天最大的一个 takeaway，我觉得是这个：AI 工具的能力边界，一直在被我们自己的心理模型低估。/loop 让 Claude Code 变成了一个持续运行的协作者，autoresearch 让 AI 开始自己做研究，Codex 被用来分析 Discord 数据——这些都不是工具本身的突破，而是使用方式的突破。

下次你打开一个 AI 工具，不妨多问一句：除了我现在想到的用法，它还能做什么？
