今天是 2026 年 3 月 21 日，欢迎收听 AI Builders Daily。cat 是 Anthropic 负责 Claude Code 产品的人，昨天她在推特发了一个帖子谈 PM 在 AI 时代该怎么工作，拿到了今天最高的收藏数，快接近一千了。让我们从这里开始。

---

cat 的全名是 @_catwu，bio 写的是"claude code + cowork @anthropicai"，以前在 Dagster 和 Scale AI。

她这个帖子配合了 claude.com/blog 上的一篇文章，标题是"product management on the AI exponential"，采访了 Decagon 和 Datadog 的 PM，加上 Anthropic 内部的经验整合。

核心前提只有一句话：传统 PM 的工作假设，是底层技术相对稳定。这个假设，现在不成立了。

她拆了四条新的工作方式。

第一条：短周期迭代，而且是真正的短周期。说的不是方法论层面的"敏捷"，而是"长期路线图竞争不过高频小实验"。举的例子很具体：Claude Code 现在的好几个功能——桌面端集成、AskUserQuestion 工具、todo list——都不是从 roadmap 里出来的，是有人在团队里提了一个想法，做了原型，内部用了觉得不错，然后发布了。不是规划出来的，是跑出来的。

第二条：用原型说话，不用文档说话。Claude Code 加 Opus 4.6，现在做一个能展示概念的可运行原型，成本已经低到和写文档差不多了——但带来的反馈质量是不同量级的。一个能点的东西，和三页 PRD，你拿去让内部用户看，两者的对话完全不是一回事。她说的逻辑是：快速把原型推到真实用户面前，让现实来校准你，比提前在文档里规划要高效得多。

第三条：每次模型更新，翻出那个"放弃功能的清单"重新测一遍。很多功能是因为上一个模型做不好才搁置的，不是因为需求不存在。新模型出来，值得重新验证。另外，之前为了让旧模型能工作而搭的那些脚手架，如果新模型不需要了，清掉——不要让旧架构拖着新能力往前走。

第四条：找最简单的那个解。这条有一个 agent 特有的理由：在 agentic 系统里，失败会随着复杂度叠加。越复杂的架构，失败的路径越多，调试也越难。所以她说的不是"能做更复杂就做更复杂"，而是"找到能解决问题的最简单方案，先跑起来"。

Decagon 的产品总监 Bihan Jiang 和 Datadog 的高级 PM Kai Xin Tai 在文章里补充的经验是：现在把原型推到真实用户面前的速度，已经快到他们之前想象不到的程度。一个以前要花两周做评审才能测试的想法，现在可能一天之内就有了用户反馈。

这四条合起来，底层逻辑是同一件事：在高度不确定的环境里，减少信息代差的最快方式，是快速接触现实，让现实来告诉你下一步该走哪里，而不是提前规划太多。

坦白说，这份 playbook 不只是 PM 的事。对任何在 AI 加速期做产品决策的人，这个逻辑都适用。

说完这个，说 Karpathy 的新播客。

他昨天上了 Sarah Guo 的 No Priors，接近一小时十分钟，话题很散但密度很高。我挑几个点说。

"AI psychosis"——他提出了这个词，指的是当你把越来越多的判断和决策外包给 AI 之后，你自己的认知结构会发生什么变化。不是在讨论"AI 会对用户做什么坏事"，而是在问：持续重度使用 AI 的人，思维习惯、判断力、对自己能力的感知——这些东西会怎么演变？他没有给答案，只是提出了问题。但他在认真问。

关于 coding agent 的掌握程度，他说了一句很干脆的话：真正会用 coding agent，核心是知道什么时候让它自己跑、什么时候要盯着、什么时候要接手。这不是技术层面的问题，是判断力的问题，是元认知的问题。工具已经在那了，但怎么跟它协作、怎么保留你自己的判断主导权——这是一个需要主动去培养的能力。

他也谈到了 AutoResearch 方向，用 agent 来做科学研究的自动化。他认为这是接下来几年最值得关注的方向之一，他自己正在投入时间。他说这里有一个类似 SETI@Home 的机会——让大量分散的计算能力协同起来做同一件科学工作。

关于就业市场，他们看了数据，软件工程的就业目前没有出现预期中的大幅下滑。他的解读是时间差，不是"替代没发生"——影响还没有完全传导进来，但这只是窗口期，不是结论。

还有一个"模型物种分化（model speciation）"的框架，他认为开源和闭源不是走向同一个终点的两种路径，而是会在不同生态位上各自进化出不同形态。没有唯一赢家，而是不同的物种适应不同的环境。

这期访谈很难得，是那种一个真正在做事的人说真实想法的对话，不是讲给外行听的科普，也不是融资路演。Zara Zhang 用 AnyGen 工具把里面最有意思的 insights 做成了一个可交互网页，每条可以直接跳到视频对应时间戳，链接在 shownotes。

接下来说一件比较具体的产品更新，但背后有一个值得停一下的模式。

Guillermo 昨天说了一句话：Next.js 16.2 is an agent-native framework.

具体来说发生了什么。

首先，AGENTS.md 现在是 create-next-app 的默认模板文件——你新建一个 Next.js 项目，这个文件就在里面了。它的作用是让 agent 知道这个项目在用的是哪个版本的 Next.js、该怎么处理这个框架的特有逻辑和约定。Guillermo 说的目标是：让你的 agent 成为你用的这个具体版本的专家，而不是用一个泛化的通用认知来处理你的代码。

其次是 @vercel/next-browser，一个专门为 agent 设计的浏览器调试工具，浏览器里的错误直接转发到 terminal，agent 能看到并处理，不需要人来中间传话。

他说了一件很具体的事：在 Vercel 内部，这套工具帮助 agent 做到了一些连专业前端工程师都没有做到或者觉得太难的前端优化。理由不是 agent 更聪明，而是 agent 有耐心把每一个细节都系统性地试一遍，不会因为优先级判断或者工作疲劳而跳过什么。

这里有一个模式需要停一下。三月十九号我们聊过 Google Stitch 引入了 DESIGN.md，一个携带品牌设计规范的可移植文件。CLAUDE.md 是项目里 agent 的行为规范。现在 Vercel 在框架层面加入了 AGENTS.md。

这三个文件，做的是同一件事：在你的项目里放一个 markdown，告诉 agent 这个项目的特定上下文、这里的规则是什么、哪些事要怎么处理。这个模式，正在从 Claude Code 的特有惯例，演变成整个 agentic 工具链的通用约定。Google 在设计工具里用了，Vercel 把它做进了框架的默认模板。

当一个模式同时被多家公司独立采纳，这通常不是巧合，而是说明这个模式解决了一个真实的问题，而且解法足够通用。

最后一个重点话题，是 Jensen Huang 的一句话。

我们在三月二十号聊过企业里 token 预算的问题，今天有一个更锋利的版本。

Jensen 说：如果一个年薪五十万美元的工程师，消耗的 token 成本不到二十五万，我会非常警觉——这就跟一个芯片设计师说"我觉得纸笔就够了，不需要 CAD 工具"一样。

Aaron Levie 在这个基础上做了展开。他说这不只是工程师的事，律师可以同时审更多合同草稿，营销可以同时测更多创意方案，销售可以接触更多客户——这些工作量本质上都是 token 密度的问题。他的判断是，这笔钱最终不会放在 IT 预算里，会进入业务部门直接管理，可能 CFO 会成为实际上的 AI 负责人。

以前的问题是"AI 有没有价值"，现在已经移动到了"花多少才是合理的"。问题重心的移动，往往比答案本身更能说明事情进展到了什么阶段。

几条快讯。

Claude Code 现在支持在云端沙箱里跑定时任务了——你设好 repo、执行时间和 prompt，Claude 按时在云端自动跑，不需要你的电脑保持开着。这是把 coding agent 从"需要你在场"往"可以后台独立运行"推进了一步。

Amjad Masad 出来回应了 Apple App Store 那件事，我们前天说过苹果要求 Replit 和 Vibecode 做修改。Amjad 说 Replit 在 App Store 上架四年，核心功能从来没变过——你输入或生成代码，服务器编译，打开 webview。苹果最终也承认他们没有违规。事情本身还在进行中，但创始人的立场是清楚的。

Granola 是一个基于会议记录的工具，现在接入了 Replit 的 MCP。Amjad 描述的场景是：你刚开完一个产品需求会，Replit 通过 Granola MCP 已经在帮你搭 MVP 了。会议记录直接变成需求上下文，直接驱动 coding agent 开始工作。还在早期，但这个方向很清晰。

claude.ai 的桌面端和网页端变快了，不是大公告，是一条工程更新：通过把架构从服务端渲染改成 Vite 加 TanStack 的边缘静态部署，首字节响应时间在 p75 降了 65%，prompt 的出现速度快了 50%。Boris 转了这条工程更新并说"我们在意这件事，会继续做"。这种让产品每天好一点点的节奏，值得记录一下。

郭宇的 mails.dev 昨晚连发几个版本，从 v1.3 到 v1.5.1。新增了邮件附件的完整收发支持、云端邮件本地同步命令、更智能的搜索排序，还修了一个 SQLite 通配符安全漏洞——之前搜"100%"会匹配到所有邮件，现在不会了。测试从 146 个扩展到 225 个，三语文档同步更新。他昨天还把 vibelab 跑了一轮大规模重构，把 Codex 的周额度也用完了。如果你在给 agent 配通信基础设施，这个项目在快速变好。

今天这几件事，说的其实是同一件事。

cat 说 PM 的工作方式要变，因为底层技术不再稳定；Karpathy 说真正会用 agent 是一种新的判断力；Vercel 把 AGENTS.md 做进了框架的默认模板；Jensen 说用 AI 的量已经是衡量工程师的指标之一了。

这些不是在谈工具，是在谈"做得好"这件事本身的定义正在被重写。在每一层——产品方法论、工程框架、团队预算管理——这个重写都在同时进行。

没有统一的新答案。但问题的形状，在变清晰。
