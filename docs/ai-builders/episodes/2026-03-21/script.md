Jensen Huang 最近在一个活动上说了这么一句话：

"如果你们公司一个年薪五十万美元的工程师，没有消耗至少二十五万美元的 token，我会感到非常警觉。这和一个芯片工程师说'我就用纸和铅笔，不打算用任何 EDA 工具'，没什么两样。"

Aaron Levie 昨天转发了这句话，然后展开说：这个逻辑不会只停在工程师这里。律师可以同时处理十份合同草稿，营销可以同时跑多套方案，销售可以同时推进更多线索。每增加一个 agent，就多一份算力消耗。个人的产出上限，开始和 token 预算直接挂钩。他顺便说，这笔预算最终不会是 IT 部门在管，而是 CFO 的事——"没准 CFO 就是下一任 AI 负责人。"

Aaron 前两天在节目里聊过企业 AI 趋势，提到 token 预算应该进运营成本。今天这句 Jensen 的话把同一件事说得更锋利，也更具体：不是企业整体怎么算账，而是单个工人——你用多少算力，决定你能做多少事。不消耗，就是浪费。

今天第一件想认真讲的事，来自 Anthropic 内部。

Claude Code 团队的产品负责人 cat——之前在 Dagster 和 Scale AI，现在做 Claude Code 的产品——昨天在 claude.com 博客发了一篇文章，标题是《AI 指数级时代的产品管理》。

这类"内部实践公开化"的文章，干货密度通常很高。写的是真正在用的东西，不是为了营销写的。

她整理了四条原则。

第一，短 sprint，放弃长 roadmap。长期路线图没办法和高密度的小实验竞争。她举的例子很直接：Claude Code 里的 AskUserQuestion 工具、todo list 功能，都是团队有了一个想法，直接做原型，内部喜欢，然后上线。没有提前规划进路线图，没有等待排期。

第二，demo 和 eval 优先于写文档。做一个真实可点的原型，现在门槛低到了几小时以内。和写一份需求文档相比，原型的反馈速度更快，也更准确——用户看到真实的东西，才知道自己想不想要。Decagon 和 Datadog 的产品负责人在文章里也提到，他们现在把原型拿去找用户的速度，比以前快了一个数量级。

第三，每次模型更新，翻一遍之前"做不到"的功能列表。这是一个很实际的建议：之前模型能力不够，某个功能做了体验很差，就搁在那里；新模型出来了，同样的功能可能现在就能做好。同时，把以前为了绕过模型限制加的脚手架代码清掉——那些 workaround 可能已经不需要了，留着反而是负担。

第四，做最简单的那个选项。在 agentic 系统里，失败会随复杂度叠加。系统越复杂，出错越难排查。能简单就简单，先让它工作起来，再考虑优化。

四条原则背后有一个共同的假设：你脚下的技术地基在快速移动。长 roadmap、厚文档、一次性做对——这些方法论，是在技术栈大致稳定的前提下有效的。那个前提现在已经失效了，工作方式也要跟着变。

坦白说，有意思的地方在于：cat 管的产品，正是它自己在加速底层技术的进化速度。她在用 Claude Code 做 Claude Code。这是一个有点奇怪的递归。

最近 OpenClaw 的生态密集运动，值得单独讲一下。

Greg Isenberg 昨天发布了一期一小时的 OpenClaw 免费公开课。书签数：3333。这比大多数产品发布公告都高。

书签和点赞是两种行为。点赞是"不错"，书签更接近"我之后要用"或者"我要发给某人"。三千多个人存下这个链接，很大概率是想自己反复看，或者发给身边那些"装了 OpenClaw 但没用起来"的人。

课里讲的东西很落地。MEMORY.md，是让 agent 随着使用积累经验的机制——你把重要的偏好和规律提炼进去，它下次就记得，越用越准。identity.md，是告诉 agent 你是谁、你怎么工作；这个文件写得不好，所有输出都会感觉和你无关，像是给陌生人写的。Cron，是让 agent 在你不在的时候自动跑任务——每日报告、定期内容工作流，设置好让它自己跑。

Greg 说的核心是：大多数人只差一步就能让 OpenClaw 真正工作起来。那一步，就是这些配置没做好。

同一时间，OpenClaw 的核心开发者 Peter Steinberger 发了一篇技术文章：ClawHub 怎么扩展到了百万周活用户。ClawHub 是建在 OpenClaw 上的社区工具，背后用 Convex 做基础设施，现在撑住了这个量级的流量。

Lenny Rachitsky 在评论里说了一句话：每个 AI 公司都在做自己版本的 OpenClaw，但没有一家做出那种用户粘性和热情。有什么东西很难复制。

他说的"很难复制的东西"是什么？我的观察是：不只是功能，而是围绕这个工具形成的用户飞轮。有人在写教程，有人在做周边工具，有人在分享配置文件——这种生态一旦运转，靠发布一个功能更多的竞品，很难直接替代它。

前天聊过 Apple 暂停 Replit 和 Vibecode 更新的事，今天有了新进展。

Replit 的 CEO Amjad Masad 正面回应了。他说：Replit 在 App Store 上已经四年，核心功能始终如一——用户输入或生成代码，在服务器上编译，用 webview 打开结果。从来没有违反过任何条款，Apple 最终也承认了这一点。

他在反驳的是"Replit 用了 AI 生成做了什么新花样所以被卡"的叙事。实际情况是，Replit 的做法从来没变过。变的是规则，不是 Replit。

另一边，Vibecode 被要求完全移除生成 Apple 设备应用的功能之后，选择了一个非常直接的方向：既然 iOS 不让做，就做 Android。昨天，Vibecode 的 Android app 正式上架 Google Play，用户现在可以直接在手机上生成 Android 应用，计划很快支持提交到 Play Store 发布。

Vibecode 的联合创始人 Riley Brown 顺手转发了 Epic Games CEO Tim Sweeney 的推文——Sweeney 说 Apple 这是在对抗开发者，也是在对抗那些想学编程的孩子，最终是在打击自己平台的未来。Riley 的评论只有四个字：I like this guy。

苹果那边关了一扇门，他们找了另一个方向走。不是抵制，是非常务实的产品决策。
