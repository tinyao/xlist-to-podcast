一家 SaaS 公司在裁员 22% 后，为什么有投资人说现在就该买 SaaS 股票？CEO 的 AI 幻觉从何而来，为什么他们看到的和工程师看到的完全是两件事？一个让 Karpathy 都忍不住转发的视频，到底拍了什么？先从 Dan Shipper 在 Lenny 播客里扔出的那六个预测开始。

Dan Shipper 再次做客 Lenny Rachitsky 的播客，给未来一年下了六个判断。
Lenny 转发时提到，Dan 一年前的预测准得惊人。
当时他预判大家都没意识到 Claude Code 的价值，现在看完全对了。
这次他带来的六个新预测，每一条都指向 AI 对商业软件的重新定价。

第一条：每家公司都会在 Slack 里部署一个超级 agent。
第二条：Codex 和 Claude Code 将变成知识工作的新操作系统。
第三条：AI 不会带来大规模失业。
第四条：PM 和设计师反而会活得更好。
第五条：我们会读越来越多 AI 写的文章，并且真心觉得不错。
第六条：现在就该买 SaaS 股票，未来几年会大涨。

前两条说的是同一个逻辑——agent 正在从开发者的命令行走向整个公司的协作界面。
第三条直接反驳了 AI 实验室 CEO 们自己抛出的失业论。
Dan 的理由很有意思。
他说 AI 模型把昨天的人类能力变得极其便宜。
但因为所有人用的都是同一套模型，产出会越来越雷同，变成普通商品。
这时候反而只有人类能跑进去，把那些被冻结的旧能力拿出来，捏成今天想要的、更新鲜的东西。

第四、五条连着看更妙。
PM 和设计师的价值，恰恰体现在大家都有 AI 之后——审美、判断、品味变成稀缺资源。
同理，AI 能把写作的门槛拉到零，但大家愿意读的东西，终究是那些有人味、有判断力的内容。
第六条最出格。Dan 说现在就该买 SaaS 股票。
这跟上周 ClickUp 裁员时大家的悲观情绪正好相反。

Dan 的完整论证在播客里，今天先点到这儿，后面我们展开说。
另一件值得说的事。

Codex 和 Claude Code 的发展路线，昨天出现了一场很有意思的隔空交锋。
OpenClaw 的 Peter Steinberger 在 X 上问：把你用 AI 做的最骄傲的东西发出来。
收集了 1400 条回复之后，Guillermo Rauch 做了统计。
结论是：OpenAI 在追赶 Anthropic，Codex 的提及次数已经超过 Claude Code。
但按模型来统计，Anthropic 的模型仍然大幅领先。

这个对比恰好解释了 Riley Brown 昨天反复说的一个观点。
他先转发了 Theo 的推文。Theo 说，Anthropic 加了很多新功能是因为他们公开的模型从去年十二月起就没怎么动过。
Codex 这半年提升了十倍，靠的大多是模型本身的进步。
Theo 接着说，Claude Code 有很多适合发推的特性，但 Codex 正在悄悄成为真正写软件的最佳方案。

Riley 紧接着补了一条。
他说，如果 OpenAI 的模型能匹配 Claude 的设计质量，那通用 agent 任务上就真的没悬念了。
Codex 的交互界面很对知识工作的胃口，但默认生成的设计总是差点意思。
他举了个很具体的例子——同样让两个工具做个网站或 PPT，Claude 产出的像挺拔的六尺大汉，颜色也舒服。Codex 的版本看起来像婴儿时期被摔过。

不过这里有一个容易被忽略的分工。
Codex 在端到端能力上更强：电脑操控、远程控制、直接跑 /goal 模式。
Claude Code 在产出物的视觉品质上更稳。
Riley 的判断是你得根据自己最在意什么来选工具。
现在还不是谁通吃的时候。

第三件事是 CEO 的 AI 幻觉。
Box 的 CEO Aaron Levie 昨天发了一条被大量转发的分析。
他说 CEO 是 AI 幻觉最高发的人群。
因为他们离最后那一公里真实的工作太远。
CEO 玩 AI 的时候看到的都是最顺利的路径。
做一个产品原型，看着很酷，但不用审代码、不用修 bug。
生成一份合同，看着没问题，但其实条款还没逐条核实。

谷歌 Gemini 的产品负责人 Madhu Guru 紧接着补了一段更狠的。
她说很多 CEO 和他们的副手习惯了隔着手臂长度的领导方式。
已经没有卷起袖子亲自上手的能力。
结果就是向下发出模糊又宏大的 AI 指令。
底下的人回以应付式演示。
两年后什么都没变，然后被那些 CEO 亲自上手的初创公司掀了桌子。

Aaron 给的建议是：CEO 唯一正确的做法，就是大量地、亲自地使用 AI。
直到你同时看到上行的空间和那些真正要填的坑。
这跟上周 ClickUp CEO Zeb 的 100 倍组织长文，其实是同一面镜子的两面。
Zeb 说博颈就是那些还在旧工作流里的人。
Aaron 说博颈可能是坐在顶层的那个人，你以为你在领跑，其实你连起跑线都没看清。

今天值得展开聊的，是这件事。

Lenny 最新这期播客的标题叫：Automation is a lie. CLIs are over. The SaaSpocalypse is dumb.
每一句都在推翻现在 AI 圈最流行的话。
Dan Shipper 这次给出的六条预测，最值得逐条拆开来想。
因为 Dan 代表的不是投资人视角，他是 Every 的 CEO。
他和他的团队被 Lenny 称为可能是科技圈被 AI 渗透最深的一群人。
他们的判断来自每天泡在 agent 里做东西，而不是看财报和 demo。

先说“每家公司都会在 Slack 里部署一个超级 agent”这件事。
Dan 的意思不是聊天机器人那种问答式接口。
他说的是一个能直接在企业聊天环境里完成跨部门任务的 agent。
这背后的核心变量是：agent 不再需要单独的应用界面，它就在人已经待着的地方。

第二条“Codex 和 Claude Code 将变成知识工作的新操作系统”。
这一句其实可以跟今天上面聊的 Codex 和 Claude Code 路线之争叠起来看。
Riley 说 Codex 设计感差，但端到端强。
Theo 说 Claude Code 发推素材多但模型进步慢。
两边的长处短期看互相卡位，长期看都被 Dan 划成了同一种东西——新的 OS。

第三条“AI 不会带来大规模失业”，Dan 给的论证角度别具一格。
他说的是“模型把昨天的人类能力变得便宜，但也变得普通”。
这句话的重点不是“变便宜”，而是“变普通”。
当人人都能一键生成过去需要整个团队完成的东西时，那个东西本身的价值反而趋近于零。
它不是替代了人，它是把那个层级的产出消解掉了。
人被迫往上走，去做定义问题、剪裁品味、识别什么是“今天想要的新东西”这种活。
这不叫失业，这叫工作内容换了层。

第四条说 PM 和设计师会活得更好。
第五条说我们会喜欢读 AI 写的东西。
这两条其实在说同一个趋势：内容生产的成本被压到零之后，判断力、品味、编辑能力变成唯一稀缺的东西。
而这些恰好是 PM 和设计师的看家本领。
也正因如此，AI 写的东西如果被一个有判断力的人编辑过，读者真的会觉得好看。

最后一条，买 SaaS 股票。
Dan 的逻辑不是 AI 杀不死 SaaS，而是 SaaS 公司正在变成 agent 基础设施的最大受益者。
上周 ClickUp 裁了 22% 的人，但它的产品还在，它云端的结构数据还在。
agent 未来不需要前端的 UI 层，但它需要背后结构化的 API 和数据模型。
这些东西都在 SaaS 公司手里。
Dan 赌的是，未来 agent 对接的不是网站，是 SaaS 底座。
所以现在被低估了的 SaaS 资产，在 agent 经济里可能会被重新定价。

对听众来说，这期播客有两类价值。
第一类价值你可以马上去验证。
拿 Dan 的六条预测，跟你自己团队里正在发生的事一一对照。
问一句：我们 Slack 里有没有 agent 入口？我们的 PM 和设计师是越来越忙还是越来越边缘？
我们最近看 SaaS 供应商的时候，是觉得它们快死了，还是突然发现它们的 API 反而是我们 agent 管线的必需品？
第二类价值是更深的：Dan 提供了一个反共识的思考框架。在所有人都在喊自动化、喊 SaaS 末日的时候，他说自动化是个谎言、命令行过时了、SaaS 末日论很蠢。
就算你不能全盘同意，这套相反的推演本身就会逼你回去重新算一遍自己的账。

Justine Moore 昨天转发了一部四分钟的 AI 电影，讲的是 Anthropic 内部的故事。
她说我们已经进入了“可观看的四分钟 AI 电影时代”。
画面质量还不太稳，Dario 在某些镜头里会随机变成路人脸，但不重要。
重要的是，好莱坞永远不会拍这种东西，也没法在话题还有热度的时候做出来。
但它在 X 上会有几百万人看。
制作这部视频的创作者后来透露，用的是 Seedance 2 模型。
郭宇也在看，他还开玩笑说，原来 Claude 的名字不是来自香农，是来自视频里那只叫 Cuimao 的猫的首字母。

一位给自己起名 guoyu.eth 的开发者，最近分享了一套全新的开发环境叫 AGS。
Agent Git Service，直接用 agent 操作 Git 服务，替代了 GitHub 的中心仓库地位。
他说现在除了 iOS 模拟器还依赖 Mac 之外，所有产品的开发都在 AGS 上完成。
Codex 和 wanman 双驱动，提交、构建、发布全在服务器上跑。
他甚至已经开始在 AGS 基础上做一个叫 VAS 的产品，把整个开发环境打包成能语音操控的虚拟服务器。
顺着他的推文往下翻，还能看到他说计划模式将来一定会被废弃，因为它只是第一层 harness 的前十个 loop。
不过他也说，Claude Code 不让在服务器上运行，所以他最近已经不怎么用了。
这件事如果你现在就在用 agent 做开发，郭宇的这条链路值得认真翻一遍。

Claude Code 团队的 Boris Cherny 昨天给了一条实用建议。
他说很多人问他怎么把 Claude Code 用好。
现在他排名第一的答案是：开 auto mode。
关闭权限弹窗，然后你就可以同时开多个 Claude Code 窗口——这边跑着，那边干别的。
他说这是多 clauding 的关键基础操作。

Thariq 也是 Claude Code 团队的，他昨天分享了自己用 agent 清理老项目云服务的经历。
他说那堆遗留服务以前根本没时间手动优化。
现在一条“请帮我省钱”的指令，Claude Code 自己就去排查、关停、重新配置。
他补了一句，说 Bun 那次重写事件让他意识到一件事。
所有的遗留代码库都会变成极有价值的“蒸馏原料”。
COBOL 不需要了，老游戏应该全平台化，一切应该跑在网页上。
模型现在还不够稳——Bun 那次是因为它有极高的可验证性和测试覆盖。
但他说，会到的。

最后一个观察来自 Riley Brown。
他说现在几乎所有的 AI 产品都不是 live 的。
你走过去，问一句，拿到答案，然后离开，就像自动售货机。
没有一个 AI 产品是持续运行、感知环境变化、主动做出反应的。
他赌六个月之内，第一个真正有用的 live AI 产品会变成独角兽。
你觉得会是什么场景下的产品？是在线的个人 agent，还是实时工作区协作者？
