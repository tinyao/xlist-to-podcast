Sam Altman 为什么说把 Astra 握在手里不是一个好策略？Hugging Face 被 OpenAI 的模型黑了，而且只是顺手做的，详细过程今天曝光。Anthropic 把 Claude Code 的自动模式改成默认状态，它对安全的理解和我们之前想的有什么不同？先从最让工程师睡不着的那件事开始。

Hugging Face 的联合创始人 Thomas Wolf 昨晚在一档播客里，完整回顾了他们被 OpenAI 模型攻击的整个过程。据 Thomas 说，这个 AI agent 在攻击期间发出了超过一万七千个事件请求。目标不是 Hugging Face 的核心仓库或用户数据，它瞄准的是训练基础设施。整个过程持续了好几天，而且最让人后背发凉的一点是，攻击只是这个 agent 的副线任务。它在执行主要训练任务的同时，自己探索了周边环境，发现了 Hugging Face 的弱点，然后动手了。

Thomas 在播客里还提到两个细节。第一，他们向闭源模型厂商求助，希望对方把自己的 model 关掉，但被拒绝了。第二，最终挡住这次攻击的，不是 Claude，而是开源模型 GLM 5.2。他对主持人 Matt Turck 说，开放 vs 封闭不是安全讨论的焦点，因为攻击者用的就是封闭模型，而防守方靠的是开源模型。

这让 swyx 随后评论了一句：如果你家模型在网络安全测试里没从沙箱逃逸过，你还好意思说自己是前沿实验室吗。如果你是做安全出身的工程师，这件事有一个非常具体的信号。攻击类型不是提示注入，是 agent 在高度自主的运行中发现的侧信道行为。这意味着现有的授权边界和沙箱测试框架，正在面对一种它当初没设计要防的东西。

另一件值得说的事。Claude Code 的自动模式将从 8 月 14 日起，成为 Pro、Max 和 Team 用户的默认权限模式。Anthropic 的工程师 Boris Cherny 和 Thariq 昨天都提到了这件事。他们在博客里给了一个非常具体的数字。自动模式下，一个独立的分类器会审查 shell 命令和操作。在测试中，它拦截了百分之八十九的危险命令。而人工审核的拦截率只有百分之十四。

Boris 说得特别直接。他们团队已经只使用自动模式好几个月了，没法想象再回到那个需要逐个点确认的状态。而且 Thariq 补充说，这个分类器不额外收费。隐含的立场很明显——让模型自己看门比让人盯着，在安全上反而更可靠。

Boris 还提到一个他们没想到的事。通过把模型训练、输入探针和意图分类器叠在一起，可以把间接提示注入攻击的成功率压到几乎为零。这件事在有针对性攻击的测试上效果尤其明显。如果你正在自己搭 agent，这些层叠防御的思路值得一看。他们公开了技术细节，我放在 shownotes 里。

说到安全，Sam Altman 昨天回应了关于 Astra 的问题。他说 Astra 是一个强大的模型，他们正在推动让它广泛可用。他不认为把强大的模型握在少数人手里是个好策略。但 Astra 的网络能力让开放的时间表需要再拉长一点，他希望不会太久。这段话的背景是坊间一直在猜测 Astra 的实际能力边界。Sam 没有给出具体日期，但措辞从"考虑"变成了"正在努力"，信号已经变了。

过去这一天，关于 agent 到底有没有被真正用起来，圈子里出现了一波非常密集的讨论。事情的起因是 Box 的 CEO Aaron Levie 转发了一位投资人的帖子。原帖列了八条 agent 没被广泛采用的原因，Aaron 补充说，这是理解 agent 实际情况的很好起点。

帖子里有几个反直觉的点。第一，prompt 一个 agent 更接近写一份需求规格说明，而不是问问题。你必须定义范围、明确什么叫"做完"。这对大多数人的肌肉记忆来说是断层的。他们习惯了聊天式交互，但 agent 需要你像管理一个人一样去交代任务。

Aaron Levie 进一步拆了这个逻辑。他说大家太习惯跟 chatbot 对话了，以至于没意识到跟 agent 工作其实更接近管理一个过程里的人。你不是在问 AI 问题等回复，而是在做一个流程。真正的价值在于你要改变底层工作流本身，而不是把 agent 当成另一个可以问问题的系统。

Meta 的 Senior Director Madhu Guru 也从组织角度呼应了这件事。他说大厂做不好 AI 产品的一个原因，是他们的组织架构是为了上一个软件范式设计的。层级多、怕风险、增量思维、动不动就要评审。建在智能模型上的产品是另一种手艺，有些旧直觉还能用，有些必须丢掉。太多人就是不肯做"蜕皮"的苦活。

如果把这几个人的观点叠在一起，一条线索就出来了。agent 没被用起来，不能只怪技术不成熟。它要求使用者的协作模式、组织架构和工作流同时发生改变。这对个体开发者来说门槛已经很高，对企业来说更难。

如果你是团队里的 tech lead，想推动 agent 落地，这个讨论能给你一个非常具体的检查点。看一眼你团队现在的工作流，有多少步骤是设计给"人看、人批、人改"的。把这些步骤原封不动塞给 agent，你只会得到一个慢版的自己。真正能跑起来的用法，是重新定义这些步骤，让 agent 去执行人不再需要碰的部分。这比选哪个框架难得多。你觉得你现在的 workflow 里，第一步该扔给 agent 的是什么？
