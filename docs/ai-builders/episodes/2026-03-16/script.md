今天是2026年3月16日，欢迎收听 AI Builders Daily。今天要聊的有三件事：OpenClaw 的周末更新来得很猛，三条高互动公告连发；Obsidian 的创始人 kepano 发了今天点赞和收藏双料第一的推文，说了一句几乎每个人都在转发的话；还有郭宇上线了他的第十一个 vibe 产品，专门给 vibe coder 做的直播平台。我们开始。

先说 OpenClaw。Peter Steinberger 这个周末连续三条高互动推文，每一条说的都是不同的事。

第一条，也是今天我觉得最值得单独拎出来聊的一个案例：他做了一个 OpenClaw 推特提及屏蔽的 cron job，每五分钟跑一次，自动识别并屏蔽他 Twitter 提及里的垃圾评论、刷屏 reply guy、还有各种营销推广内容。Peter 说效果"好得不合理"，现在他的提及里终于能看到真正有用的回复了，"Twitter 又变得令人愉快了"。接近一千九百个点赞，三百三十五个收藏。

为什么要在节目里专门说这件事？不只是因为互动量高，而是因为这是一个非常典型的 agent 落地方式。没有精心设计的 demo，没有复杂的架构图，就是"我有一个真实的烦恼，我写了一个 agent 每五分钟跑一次，问题解决了"。这个思路，对日常工作里任何重复性的烦人问题，都是值得直接复制的模板。

第二条：/btw 功能即将进入 OpenClaw。Peter 说在"下一个 claw release，大约周日"发布，一千八百五十个点赞，四百一十八个收藏。

/btw 是什么？简单说，就是在 agent 正在跑任务的时候，你可以随时插话。这个功能在 Claude Code 里已经有了，现在 OpenClaw 也要集成进来。根据 Peter 的描述，当 agent 正忙的时候，你可以旁注一个问题或者补充一个指令，agent 会在合适的时候回答你，同时继续原来的任务，两件事不互相打断。

对于跑长任务的工作流来说，这个功能解决了一个真实的焦虑：任务跑到一半，我突然想确认一件事，以前的选择是中断任务或者忍住等，现在可以直接插话，等答案，继续。这个改变看起来小，但对于真正在用 agent 干活的人来说，体感差异很明显。

第三条：OpenClaw 正在做 Claude Code 和 Codex 的 plugin bundle 支持。Peter 说这个功能已经在一个未提交的分支里了，还加了 MCP 支持，需要更多测试。两百二十八个点赞。意味着以后可以直接把 Claude Code 或 Codex 的 skill 打包成 OpenClaw 的 bundle，在 OpenClaw 里直接调用，不需要在不同工具间来回切换。

把这三条放在一起看：一个屏蔽垃圾提及的自动化案例，/btw 插话通道，还有即将打通的 Claude Code 生态。OpenClaw 从"Claude Code 开源替代品"这个标签，正在逐渐变成一个有自己生态语言的平台。这个转变在加速。

好，我们来说 kepano。

kepano 是 Obsidian 的创始人，今天他发了今天全榜互动量最高的一条推文。两千三百零一个点赞，三百八十六个收藏，就一句话：

"your edge is whatever you know that the models don't know"

你的护城河，是所有你知道但模型不知道的东西。

他在后续的评论里补了几句话："把你的秘密全部教给模型，然后创造新的秘密。""真正的问题是：你愿意放弃什么秘密，以及你会创造什么新的知识？"

为什么这句话让这么多人转发？我觉得是因为在 AI 把大量通用知识的门槛拉平之后，很多人的焦虑不是"我不会用 AI"，而是"我会用 AI，但感觉和所有人都差不多了，我的差异化在哪"。kepano 这句话给了一个清晰的方向：不是你用了什么工具，而是你在模型之外积累了什么——你的第一手经验、你独特的行业判断、你踩过的那些具体的坑、你和用户之间真实建立的信任和洞察。这些是模型暂时还不知道的，也是别人无法直接复制的。

kepano 今天还发了第二条，也值得单独说一下。四百四十七个点赞，一百四十九个收藏，讲的是 MCP 的隐私风险：

"如果你在用第三方 MCP 访问你的数据，你实际上是在把你数据的明文访问权限，完整地交给那个第三方。如果你在乎隐私，第三方 MCP 根本就不是一个选项。端对端加密会让 MCP 基本上失效。"

这话说得很直，也很重要。大家在讨论 MCP 的时候，通常聊协议设计、工具能力、生态兼容性，数据安全这层讨论相对少。kepano 说的这个问题不是技术缺陷，而是架构级的信任问题：你接入一个第三方 MCP 服务，你就在做一个信任决定，相当于给一个外部服务商开了你数据的完整读权限，和给第三方 SaaS 开 API token 没有本质区别。

对个人用户来说这可能无所谓，但对于任何处理敏感数据的公司来说——客户数据、财务数据、内部代码——这个提醒值得认真对待。在 MCP 生态快速扩张的现在，把这条边界提前想清楚，比出了事再说要好。

说到这个，我们来说说郭宇。

今天他有两个实质性的新进展，都是产品层面的，和前几天的 AI 公司模拟实验性质不太一样。

第一个：他上线了 vibelab，是他的第十一个 vibe 产品。三百二十个点赞，一百九十二个收藏，五十一条回复——这个互动密度，对技术产品来说不低。

vibelab 是什么？它的定位是专门给 vibe coder 用的直播平台。传统直播的做法是主播在本地开发，用采集工具把屏幕推出去，观众只能旁观；vibelab 的做法是把整个开发环境放在云端沙箱里，主播可以直接把这个沙箱共享给观众，还可以邀请伙伴进来协同编程，大家共享同一个终端和浏览器窗口。

底层用的是郭宇自己开源的 Sandbank Cloud，开箱支持 Claude Code、Codex 等 coding agent，支持快照保存登录状态和临时文件，还可以接 GitHub，在沙箱里做的工作不会丢失。

我觉得 vibelab 有意思的地方在于，它把"写代码这件事"做成了一个可以共享、可以参与的协作体验。你现在做 vibe coding，整个过程是私密的，别人看不到；vibelab 说，这个过程本身就可以是内容，而且可以是双向的。有点像 Twitch 对游戏直播做的事，只不过对象变成了 vibe coding。这个方向值不值得，目前不好判断，但思路是清晰的。

第二个：Sandbank Cloud 浏览器自动化服务正式上线，九十一个点赞，一百零一个收藏。所有在 Sandbank 上创建的沙箱，现在都可以通过内置的 browser CLI 和 skill，操作网站、跑 e2e 测试、模拟用户登录，还可以用 snapshot 功能把凭证和用户状态持久化保存。我们在三月十四日的节目里提过郭宇在这个方向上的进展，今天是正式上线版本。对于在用 Sandbank 做 AI agent 开发的人来说，这意味着 agent 在沙箱里可以完整跑浏览器工作流，而且状态是持久化的，不需要每次重新登录。

另外他还分享了一个有意思的小发现：Ghostty 终端可以直接粘贴剪贴板截图，不需要先把图片保存成临时文件。这对做端到端 debug agent 的人来说是个好消息——browser use agent 截到的截图，可以直接粘进去和 coding agent 通信，少了一个摩擦环节。

有意思的是，vibelab 上线之后，郭宇立刻就用它做了直播，顺带给 Sandbank Cloud 做了一次压力测试，"收获了很多宝贵的沙箱崩溃日志"。上线即测试，产品和工具一起磨——这个做法倒是挺实际的。

好，快讯时间，我们快速过几条。

Vercel CEO Guillermo Rauch 今天发布了一段一小时的 TravisCore 建设过程视频，两千九百七十六个点赞，两千四百三十二个收藏，是今天所有推文收藏量第一，而且领先幅度相当大。TravisCore 是一种把 AI 辅助建设过程完整录下来的内容格式，Guillermo 在一小时内构建并部署了某个实际的东西。这个"边做边记录"的形式，和郭宇在 vibelab 上直播 vibe coding 其实是同一个方向——亲历式的、过程可见的 AI 建设记录，正在成为一种有吸引力的内容形态。

Ramp 的 CPO Geoff Charles 和 Peter Yang 的完整访谈今天正式上线，七百九十三个收藏。昨天节目里我们提到过这个访谈的内容梗概，今天完整版出来了。节目里最值得记下来的一句新话是："管理可能已经死了。你现在应该优化的，不是成为一个管理者，而是成为世界上最好的 builder。"他还分享了 L0 到 L3 的框架，帮助公司里每一个人都能写出生产代码。链接放在 shownotes 里。

swyx 发了一个关于 CPU 短缺的预警，九百零一个点赞，五百一十八个收藏。他的判断是：从 2025 年 12 月开始，整个云计算基础设施的需求曲线出现了一个明显拐点，所有云服务商的有效服务创建数量都在垂直起飞。他说，下一波短缺不是 GPU，不是内存，是 CPU。随着大量 agent 同时跑起来，每一个都在消耗真实的计算资源，端侧设备会成为重要的算力补充。Replit CEO Eric Simons 的判断和他一致，认为"on-device compute"会在今年明显走向前台。

Zara Zhang 观察到一个趋势：越来越多用户不再为各种模型封装产品付订阅费，而是直接拥有模型 API 订阅，然后用 agent skill 搭出个性化版本。她称之为"Bring your own API key"时代。一百九十一个点赞，五十五个收藏。这是一个平台竞争格局的变化信号，如果越来越多用户选择直连模型 API，中间层封装产品的价值就会受到压力。

Replit CEO Amjad Masad 转发了一个用户用 Replit Agent 4 在两小时内搭出完整诊所业务系统的案例——官网、预约平台、iOS App、宣传视频、客户提案，全套。他给这个时代的转变起了一个名字："从 prompt to app，进化到 prompt to business stack。"两百六十四个点赞，一百五十九个收藏。

Linear 产品负责人 Nan Yu，在一条关于"coding agent 的瓶颈是测试和代码质量"的讨论里，回了一句两百二十五个点赞的话：瓶颈从来都是、也永远都是——先做出人们真正想要的东西。这句话放在现在特别对味，因为大量关于 coding agent 能力上限的讨论，其实都是在一个更前面的问题还没解决的时候就开始的。

最后一条，Matt Turck 发了个产品路线图时间跨度的段子：2022 年路线图做一年，2024 年做六个月，2026 年做一周。他的回复是："2028 年：不知道，让我问问 agent 它一直在构建什么。"一百一十八个点赞。这个笑话背后，是很多产品团队真实经历着的困境——迭代节奏太快，传统的路线图规划逻辑已经跟不上了。
