昨晚十点多，一条没有任何铺垫的推文在英文科技圈传开。就这一句话："Your edge is whatever you know that the models don't know。" Obsidian 作者 kepano 发的，两千三百多个点赞，将近四百个收藏。

这句话为什么打到那么多人？等会儿我们展开说。

今天是 2026 年 3 月 16 日，欢迎收听 AI Builders Daily。今天还有：郭宇上线了他的第十一个 vibe 产品，这次性质和之前的实验完全不同；swyx 在反复说一件事，力度越来越强；以及 Ramp 的 CPO 访谈全集今天上线，里面有几句话比昨天快报里提到的更值得展开。我们开始。

先说 kepano 的那句话。

过去两年，关于"人和 AI 的关系"的讨论，大多数停留在技能层面：AI 会不会写代码，会不会做分析，会不会替代这个职位那个职位。这是防御性的焦虑，本质上是在追问"我的技能还有没有用"。

kepano 换了一个维度。他说的是知识，不是技能。模型有训练数据截止日，它不知道你今天在客户那边听到的真实反馈，不知道你的行业里那些没有写在任何公开文档里的潜规则，不知道你踩过的坑和爬出来之后形成的判断。这些，才是真正的 edge，而且是你在日常工作中持续积累、模型暂时复制不了的东西。

这个逻辑有一个很实际的操作意义。你可以问自己：我知道什么是 Claude、GPT-4、Gemini 都没有见过的？是你公司内部的用户数据？是你跟某类客户打了几年交道之后积累的直觉？还是你在某个细分市场做过的五次失败实验？这些，才是你应该带进 AI 工具链里去放大的东西，也是你真正的杠杆点。

他随后补了一句："give away all your secrets and create new ones"。把你已经有的知识分享出去、用 AI 加速执行，然后把省出来的时间用来积累新的、还没进过任何模型训练集的东西。这是一个进攻性的框架，不是防守。对于很多感觉焦虑的人来说，这两句话加在一起，有一种实质性的解压效果。

但 kepano 同一天还发了另一条，话锋就严肃得多了。

他说：如果你在用第三方 MCP 访问你的数据，你就是在把未加密的数据访问权限交给一个外部服务。如果你在意隐私，第三方 MCP 不是一个选项。他甚至说，端对端加密从技术上会让 MCP 失去意义——MCP 的核心功能就是让 AI 读取和处理你的数据，加密了就读不到了。这是一个基础设施层面的结构性矛盾，不是某家服务商做好做坏的问题。

这条推文将近一百五十个收藏，比点赞量高出很多。收藏高于点赞的推文，通常是在提醒人们去做某件具体的事——不只是表示赞同。

两条加在一起，kepano 说的其实是同一件事：知道你拥有什么知识，知道谁在访问这些知识，然后持续生产新的知识。这三点，才构成完整的护城河。

接下来说郭宇。

他这周出镜率很高，AI 公司实验、装置艺术公司实验、单向街活动——我们跟了好几天了。今天的新东西，性质和之前的实验不太一样。

第十一个 vibe 产品：vibelab。一个给 vibe coder 专属的直播平台。

普通的 coding 直播是这样的：主播在本地电脑开发，观众隔着屏幕看。vibelab 把开发环境整个搬到了云端沙箱，主播和观众共享终端和网页，还可以邀请人进来，大家在同一个环境里一起编程、一起看 agent 跑任务。

底层跑的是他之前开源的 Sandbank Cloud，内置支持 Claude Code 和 Codex，有 snapshot 功能保存登录状态——开直播不需要每次重新给 coding agent 配环境走一遍登录流程。他今天实际播了一整天，顺手给 Sandbank 做了一次压力测试，说拿到了不少沙箱崩溃日志。听起来是在认真迭代，不是单纯的发布宣传。

同天他也宣布 Sandbank Cloud 正式上线了浏览器自动化服务：所有沙箱内置 browser CLI 和操作技能，可以自动化操作网站、跑端对端测试、模拟用户登录，凭证和用户状态打成快照备份。

这两件事合在一起，我注意到郭宇的轨迹有一个变化。之前他做的是实验——方法论验证，"AI agent 能不能跑出一个公司"。今天的 vibelab 是真实产品，面向真实用户，而且用的是他自己在实验中研发出来的基础设施。从"跑实验"到"造工具再造产品"，这个转变，在今天才真正完整。

vibelab 的形态本身也踩在一个合适的时机点上。Coding 直播一直有社区需求，但传统直播方式和 AI coding agent 的工作方式是错配的——agent 在云端跑任务，主播在本地开发没有意义。把开发环境整体搬到云端共享沙箱，"看直播"变成"一起参与"，这个形态改变，需要 AI coding 生态先成熟到一定程度才有人会来。现在，大概就是那个时机点。

说完这个，往更大的视角走一步。

swyx 这两天在反复说一件事，力度越来越强：CPU 短缺要来了。

他的原话是"something broke in Dec 2025 and everything is becoming computer"。他观察到，从去年十二月开始，所有云服务商——不只是 Render，包括各家竞争对手——创建的付费服务数量都出现了陡峭的增长曲线。忘了 GPU 短缺，忘了内存短缺，他说 CPU 才是下一个真正的瓶颈。

这背后有一个结构性的逻辑。AI agent 系统的架构，需要的不只是推理能力，还需要大量并发执行环境——沙箱、容器、parallel agent 在各自隔离的计算单元上同时跑。这类任务消耗的主要是 CPU，不是 GPU。随着 coding agent 跑的任务越来越长、越来越多、越来越复杂，并发需求在持续爆炸，CPU 成了实际的资源约束。

Replit CEO Amjad 也在说类似的事：每个用户桌上都有一台强力电脑闲着，为什么要去租云上的计算机？Bolt CEO Eric Simons 在讨论 on-device compute 的机会，说随着云资源趋于饱和，agent 公司会越来越多地把任务推到本地算力。

这几个判断放在一起，说的是同一件事：当 agent 变成基础设施，算力需求的形状会根本性地变化。不再只是谁有最好的 GPU 集群，而是整个计算资源的分配方式——云、边缘、本地——都在重新排布。去年十二月，某个东西突破了。这个洗牌，已经在进行中。

还有一条昨天快报过、今天多了新内容的消息值得多说两句。

Ramp CPO Geoff Charles 接受 Peter Yang 采访的完整视频今天上线。昨天我们提到了三阶段产品研究框架，完整视频里多了几句话，比框架本身的冲击力更强。

他说"Management is probably dead"。不是说不需要有人给反馈或做 coaching，而是说：现在这个时机，你应该优化的方向是"成为最优秀的 builder"，而不是"成为好的管理者"。另一个是他在 Ramp 推行的 L0 到 L3 框架——目标是让公司里每一个员工，不管是 PM、运营还是财务，都能提交生产环境代码。这不是愿景，是他们在落地的目标。

他还有一句话被大量转发："If you're not in Claude Code, no matter what your role is, you're probably underperforming。" 注意，这句话不是写给工程师的，是写给所有人的。这个访谈是一手材料，shownotes 里有链接。

快讯几条，快速过一下。

Peter Steinberger 今天两条 OpenClaw 动态值得知道。一是他用 OpenClaw 给自己的 Twitter 建了一个每五分钟跑一次的 AI 过滤 cron job，清理垃圾回复和广告推广。他说"Twitter 终于又好用了"——一千八百多个点赞，很多人说这是他们最想要的那种 agent 用例，不花哨，但真实有效。二是 /btw 功能即将进入下一个版本，你可以在 agent 执行任务途中随时插话提问，不用等它跑完。此外他透露正在规划更强大的插件体系，并支持 Claude Code 和 Codex 的插件 bundle，目前已有开发分支在推进。

Vercel CEO Guillermo 昨晚发了一个整整一小时的 TravisCore 构建演示，将近三千点赞，两千四百多个收藏，是今天所有推文里收藏量最高的一条。具体内容在 shownotes 里。

Matt Turck 的一条推文：产品路线图的长度，2022 年是一年，2024 年是六个月，2026 年是一周。他自己接了一句——2028 年不知道了，去问问 agent 它最近在做什么吧。这个段子笑着笑着笑不出来了。

Zara Zhang 观察到一个趋势：与其为各种包装 AI 的订阅产品一个个付费，不如直接拥有模型 API 订阅，加上自己的 agent skill，打一套真正适合自己需求的组合。她说"Bring your own API key"会成为一件事。这和 kepano 说的知识优势是配套的——原始 API 加上你独有的知识和配置，才是真正的个性化。

今天就到这里了。

今天几个话题看起来分散，但有一条线穿着。kepano 说优势来自模型不知道的知识；郭宇把实验基础设施变成了社区可用的工具；swyx 说去年十二月某个东西突破了，计算需求的形状已经在改变；Ramp CPO 说每个人都应该成为 builder。

加在一起，这大概是今天我带走的一句话：工具的门槛在快速消失，但对问题的判断力不会。拥有前者很容易，积累后者需要时间。好在，积累判断力的时间，AI 正在帮你省出来。
