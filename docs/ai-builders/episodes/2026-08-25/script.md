付费榜头部应用的体验，是不是倒退了十年？AI时代的产品设计，为什么反而在开倒车？企业销售有15个阶段，漏掉一个就完蛋，你能说全吗？
先从一条让很多产品人沉默的观察说起。

Anthropic 的产品经理 Robert Bye 昨天在 X 上发了两张 App Store 付费榜截图。
榜单前十的应用，他形容说，设计和体验完全是十年前的倒退。
他用了 surreal 这个词，意思是超现实、让人恍惚。
这不是一个泛泛的吐槽——发这条推的人是 Anthropic 的 PM，每天看到的 AI 能力是最前沿的。而他面前的 App Store，顶流付费应用却在 UI 和交互上全面退步。

另一边，Vercel 的 CEO Guillermo Rauch 昨天也分享了一段挺有意思的经历。
他发现终端里的 reset 命令特别慢，查了之后才知道，这个慢是 1979 年的设计遗产。
当年为了让机械打印机和墨水终端能稳定下来，代码里写死了一秒钟的睡眠。
Guillermo 让他的 AI 工具 fx 用 Zig 语言重写了一个替代品，只要一毫秒。他感叹说，技术栈里藏着很多这样的蜘蛛网——系统设计本身是好的，但偶尔就挂着一根几十年前的线头。

这两件事放在一起看，指向同一个问题。
AI 的能力在指数级增长，但我们日常使用的软件，从付费榜产品到底层终端，设计债务和体验倒退都在积累。
这有点像一个悖论：创造工具的能力越强，我们越是顾不上把它造得好看、好用。
如果你今天打开 App Store 付费榜看一眼，你大概率也会被那几款应用的界面给震住。

Perplexity 的 CTO Denis Yarats 昨天宣布了一个重要任命。
纽约大学副教授 Andrew Gordon Wilson 加入 Perplexity，担任研究负责人。
Wilson 教授在推文里说，他们将在开放环境中推进一些范式转移级别的研究，方向是持续学习、智能体协作，以及更前沿的强化学习。
Denis 补充说，他们内部已经在搭建大规模 RL 系统的基础设施，接下来会开源很多东西。他还直接留了自己的 DM 邮箱，说如果这三个方向——多智能体协作、持续学习、RL——对你有吸引力，欢迎直接联系他。
Perplexity 这是在向外界释放一个明确的信号：他们不满足于做好一个搜索产品，正在往底层模型研究的方向扎。

今天值得展开聊的，是这件事。

昨天，OpenAI 的 Peter Steinberger 转发了一条 DHH 的声明。
Omakub 基金会的资助金额刚刚突破了一千万美元。
DHH 是 Ruby on Rails 的创始人，37signals 的 CTO。Omakub 是他的一个开源项目，目标是让更多人能轻松部署和管理自己的 Web 应用。
Peter 转发时写了一句话，在圈子里传了一夜。他说：我们必须摆脱那种不能用 prompt 去修改的软件。

这句话乍一听有点激进，但仔细想，他触碰的其实是产品设计和软件开发之间那层正在被打破的边界。
同一天，Greg Isenberg——一位连续创业者，做了好几家 agent 方向的公司——他提出了一个概念叫 AX，Agentic Experience。他说 AX 是新的 UX。以前软件是给人点击用的，现在要重新为 agent 构建。
Stripe 花了八十亿美元收购 OpenRouter，在他看来就是押注互联网的主要用户将变成 agent。
Greg 的联合创始人甚至写了一本免费的电子书，专门讲 AX 的崛起。

而就在这些讨论发酵的同时，Anthropic 的 PM 在质疑 App Store 付费榜产品的体验倒退。

这三条线撞在一起，构成了一个挺刺耳的问题。
当软件从给人用转向给 agent 用，我们还要不要在乎界面的质感？

一个在昨天评论区里出现的高频声音，来自产品观察者 Nan Yu。
他引用了 Sam Broner 的观点。Sam 抱怨说，SaaS 公司都在给我们塞 agent，而不是提供 MCP 接口。用户从来没有想活在你的产品里，你的产品只是完成某件事的最佳方式。如果现在最佳方式是 headless、无界面的，那你应该让我用那种方式。
但 Nan Yu 反驳了这种极端的立场。他说，这种观点每次出现都能拿很多赞，但现实是，SaaS 公司既需要内置的 agent 来操作应用，也需要好的 MCP 或 hook 让 Codex 这类外部工具能接入。
用户现在是高度两极分化的状态——有些人完全不想开界面，有些人还是习惯在界面里操作。你不做哪一端，都会丢掉另一端的用户。

这个分析很冷静，也点出了今天产品人面对的真实困境。
你没法赌未来只属于 agent，也没法假装 GUI 不重要。
而现实是，当你把开发资源往 AI 能力上倾斜，UI 和体验就会最先被牺牲。
App Store 付费榜前十的设计倒退，或许不是某个团队不行。它是一种结构性的取舍——当产品价值的定义变了，打磨像素的优先级自然就掉下去了。

对听众来说，这其实是一个每天都会遇到的权衡。
如果你在做一个产品，不管是 toC 还是 toB，现在你手里只有有限的工程资源。你是先做好 MCP 接口和 agent 能力，还是先把新功能打磨到像素级？
Nan Yu 给出的建议是两者都要。但他没说的是，两者都要的背后，是对团队能力的极高要求。
换个角度想想，也许 Guillermo 修 reset 命令这件事本身就是一个隐喻。那些几十年前的设计债——那些为了兼容性而保留的慢、丑、旧——今天用 AI 来清理，成本已经低到可以随手做了。
UI 的倒退或许也可以这样被修复。不是靠堆人力，而是靠把 AI 用到设计流程里。

再说几条快讯。

Lenny 昨天和销售专家 Jen Abel 做了一期 84 分钟的深度对谈，把企业销售的完整流程拆成了 15 个步骤。Lenny 自己总结了 12 条笔记。里面有几个很反直觉的点——健康的赢单率是 25% 到 35%，超过了说明你定价太低；还有，绝对不要给潜在客户做全场演示，只演示他们关心的 20% 功能。如果你在做 B2B 销售，这期值得找来看。

Meta 的 AI 高级总监 Madhu Guru 昨天继续写他的 Evaluations 系列，今天讲到的是 eval 构建的金发女孩原则——别太粗、别太细，每个中间步骤都应该有独立的评估标准。他用金融分析 agent 举了一个例子，最后诊断出数据分析和最终推荐的准确率差了两截，一下就定位了问题。这个系列已经连着更新了几天，如果你在做 AI 产品质量评估，可以回头翻一下前面的几期。

Justine Moore 昨天提到，MrBeast 又回头用 AI 做视频缩略图了。去年因为用 AI 替代人类缩略图设计师还引发过不小的争议。现在他的做法更精细——同一张缩略图，根据不同国家观众的语言，自动把警车样式换成当地的版本。

如果你正在搭自己的 eval 体系，Madhu 那个按步骤拆分的思路，你会用在你的产品里吗？
