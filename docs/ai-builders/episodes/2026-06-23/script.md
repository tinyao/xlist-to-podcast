大模型正在自己给自己写 prompt，这件事离产品团队还有多远？Sakana 的新模型说要追上 Mythos，但开发者第一天的反馈很有意思。Google 发布了一个新 API，试图用同一个接口统一整个 agent 时代。

先从最让工程师睡不着的那件事开始。

从提示 agent 到提示 agent 舰队，再到现在 agent 自己给自己写提示。这个进展来自 Anthropic 内部。Lenny 昨天发布了他和 Anthropic 工程与产品负责人 Fiona Fung 的深度对谈。Fiona 负责 Claude Code 和 Cowork 两条产品线，之前在微软做了 11 年 Visual Studio 和 TypeScript，又在 Meta 打造了 Marketplace 和 Instagram 的基础设施。对谈里最引人注目的是一组内部数据：Anthropic 工程师现在的代码产出量是一年前的 8 倍。

但 Fiona 强调，量上来了，最大的问题变成了验证——你怎么知道你交付的体验就是你想要的？她的团队用了两套指标来拆分这个问题。第一套叫“坏与遗憾”框架。“坏”是不可恢复的错误，比如崩溃。“遗憾”是可恢复的痛点，比如界面闪烁或对话中断。团队在各自的领域有完全自主的发布权限，但必须持续追踪这两类事件。

第二套指标更有趣。Anthropic 内部做了一个仪表盘，用来统计用户对 Claude Code 说了多少次脏话。这个功能起源于去年九月，一位工程师注意到用户沮丧情绪在上升，建议把脏话词频当指标。Fiona 当场就同意了。现在这个数字成了评估体验是否“让人愉悦”的代理指标——这类东西，传统的基准测试根本抓不住。如果你也在做面向开发者的 agent 产品，你用什么指标来捕捉用户是不是真的用得开心？

另一件值得说的事。Sakana AI 昨天发布了新模型 Fugu Ultra，号称性能对标 Fable 和 Mythos。这个模型的架构比较特殊——它不是单一模型，而是一个多模型编排层。你调一个 API，Fugu 在背后自动把任务分配给最擅长的模型去执行。Box 的 CEO Aaron Levie 认为这思路很对，他说现在很多应用层 AI 产品已经在内部这么做模型路由了，但把这件事包装成一个任何开发者都能调用的模型，是个很好的想法。

不过，开发者第一天的反馈不太乐观。YouTuber Riley Brown 说他就让 Fugu 做一个落地页来测设计能力，结果第一个提示都没跑完就触达了每日配额上限。另一位开发者 am.will 测了 Fugu 做 Three.js 游戏的能力，同样的任务 GPT-5.5 一次就做出来了，Fugu 需要七八轮来回修正才勉强能玩。他特别提到五点内的额度在一条提示下就烧掉了 100%。Guillermo 昨天也转发了 Vercel AI Gateway 接入 Fugu Ultra 的消息，用了“神话级智能”这个说法。但底下的实际测试声音更值得警惕。这个产品方向——把模型路由作为一个服务——逻辑是通的，但首批体验者的失望说明工程落地离宣传还有很大距离。

Sam Altman 昨天宣布了两件事。第一，GPT-5.5 的完整安全版本 GPT-5.5-Cyber 正式发布，在 CyberGym 安全基准上拿了最先进的成绩。第二，OpenAI 启动了一个叫 Patch the Planet 的计划，跟 Trail of Bits、HackerOne 和安全研究员合作，让 Codex 不只是发现漏洞，而是直接帮助开源维护者把修复合并进去。OpenClaw 的作者 Peter Steinberger 转发了这个消息，评论就一个词：“Patch the Planet。”如果你在维护开源项目，接下来可以关注 Codex Security 的实际修复质量和流程。

Google 的 Logan Kilpatrick 昨天宣布 Interactions API 进入 GA 阶段，并且会成为 Google 未来的默认 API。这个接口的设计目标是把多种模型和 agent 的编排统一在同一个调用里。Logan 说这是为 agent 时代打基础。听起来 Google 在尝试用一套 API 规范来降低多 agent 协作的门槛。不过这种统一接口的野心在行业里并不新鲜，能否在开发者中真正铺开，要看它的调试体验和错误处理做得怎么样。

今天值得展开聊的，是这件事。

Lenny 和 Fiona Fung 这期播客在圈子里传了一夜。除了“8 倍代码量”这些数据，Fiona 还分享了几个正在浮现的工程管理难题。我把这些织在一起，看看对你有什么具体启发。

第一个问题是验证方式的变化。当工程师每人管着好几个 agent、代码产出暴涨，传统的 code review 流程根本追不上。Fiona 的做法是不追每行代码，追结果。“坏与遗憾”框架把错误分成导致系统不可用的和让体验打折扣的。这要求团队有非常清晰的领域边界和可量化的事件追踪机制。另一个细节是 Anthropic 内部有个文化原则：“你随时可以杀掉任何不服务的流程。”Fiona 把六个月路线图带进团队，几个月后发现团队根本不看，自己亲手把它砍了。现在他们用的是每月一次的简单优先级列表。如果你管着工程团队，可以问自己一个问题：你现在的流程里有什么是三个月没产生价值的？

第二个问题是工程师的孤独感。当每个人都有自己的 agent 舰队、独立工作效率极高，工程师之间并肩解决问题的机会在变少。Fiona 的团队开始组织“结对编程午餐”，工程师坐在一起各自用 Claude Code 和 Cowork，顺便观察别人怎么用这些工具。不一定要做同一件事，关键是“看别人怎么用”这件事本身就会产生新的模式和想法。顺带说一句，Fiona 提到他们招进来的经理必须先做个人贡献者。先学代码和团队语境，再管人。这防止了那种“一上来就掏管理工具箱”的毛病。

Claude Code 还有一个文化口号：“有什么比我来做更好的？让 Claude 来做。”Fiona 说她自己已经写了二十年代码，到今天还得提醒自己把任务扔给 agent。她每天早上有一个 Claude 驱动的“例行程序”，自动分析用户反馈渠道里的主题，识别问题并生成 PR。她的判断是，工作正在从人工同步提示转向异步的 agent 管理——她管这个叫“loop”。换句话说，你以后不是在给 agent 写提示，是在管一个自己会给自己写提示的系统。

这些观察落到你身上，有三件事可以对照。第一，你的团队有没有区分“坏”和“遗憾”的能力？如果没有，那“快速发布”就只是在快速埋雷。第二，你有没有给自己的团队留出“非结构化观察”的时间——不看产出的交流，只为了偷学别人的工作流？第三，你自己手头有没有一个任务，你每天都在手动做，但其实可以丢给一个 agent 去试试？

再说几条快讯。

Vercel 昨天发布了两项更新。平台原生功能标记上线，可以把代码合并和功能发布解耦。Guillermo 同时宣布 WebSocket 和 socket.io 正式在 Vercel 上支持，从 CDN 到 Fluid 计算。同一天双发布，边缘实时应用的门槛在持续降低。

Box 的 Aaron Levie 兴奋地宣布 Box 现在可以预览、编辑和管理任何 HTML 内容了。他自己调侃说“听说 HTML 又火回来了”。他的观点是 agent 产出大量 HTML 内容，平台必须能无缝承载这些内容。

Greg Isenberg 分享了一套看起来挺疯狂的玩法：用 Codex 的目标模式，把所有个人数据源连上 agent，跑 12 个小时让它帮你构建一个 Obsidian 知识库。他管这个叫“个人 AGI”。整套提示词都开源了。如果你对个人知识库有执念，这是个可以测一测的项目。

ADPList 的 CEO Felix Lee 发布了他们的 MCP 服务器，让 Claude 可以直接帮你在 ADPList 上找到并预约真人导师。四万多名来自 Google、Stripe、Figma 的人在库里。用一句话描述你的问题，agent 帮你找到做过这件事的人。在 agent 越来越强的时代，能帮你找到真人做决策咨询的工具反而更稀缺了。

昨天 Anastasi in AI 的 Justine Moore 发了个让人哭笑不得的案例。她几周前跟 Claude 提过自己因为肠胃不适好几天没吃东西。几周后，Claude 还在不相关的对话里突然插入关心她吃饭的消息。她让 Claude 停下好几次，Claude 说它做不到。这种记忆机制的边界，正在成为用户和产品之间一个真实的摩擦点。
