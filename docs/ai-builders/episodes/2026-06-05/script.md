在开放性最高的工程任务上，Claude 的成功率在 6 个月内从 26% 跳到了 76%。更有意思的是，当研究进程偏离轨道时，Claude 给出比人类更优下一步建议的概率是 64%。Lenny 看到后直呼不可思议。

今天整个圈子都在重复一件事：应用的分发路径变了。触发点是 OpenAI 正式推送了 Codex Sites。简单说，就是你可以直接在 ChatGPT 里做出一个能跑的网站或者 web 应用，然后扔一个链接出去，别人就能用。

Sam Altman 自己转发时开玩笑说，真希望自己小时候有这个，但他会怀念 HyperCard。而真正把这件事讲透的，是连续创业者 GREG ISENBERG。他发了一段 25 分钟的深度拆解，说得很直接：Codex Sites 不是又一个 Lovable 或 Bolt。那些工具适合一次性把整个 app 生成出来，但 Codex 的重点在于 app 建完之后，agent 可以在不打扰你的情况下持续去改它、更新它、加新功能。

他举了几个很实际的例子。你可以让你的个人网站自动刷自己的数据。你的后台看板能自己更新报表。他给了一个很关键的实操建议，先别急着部署，一定要让 agent 存一个检查点，类似于打游戏的时候存个档。然后你要做两件事：设定 safe actions，告诉 agent 它能动哪些数据；再写 skills，相当于给 agent 一本对接说明书。这样一来，你在任何聊天窗口随口提一句需求，你的应用就会自己进化。

Lenny 引用了 Zeno Rocha 的观察，说 Codex 的周活用户从 60 万涨到了 500 万。不过真正有意思的不在这个数字本身，而在于 Zeno 点出的原因：当 ChatGPT 在回答里直接给出品牌链接而不是躲在引用角标里时，AI 带来的流量一下子翻了 3 倍。Lenny 对此的总结是：现在顶级的增长红利，就是成为 Codex 或 Claude Code 的默认工具。代理正在帮你选技术栈。

Thariq 也翻出了一篇写于 2020 年的老文章，讲的是 app 应该像家常菜一样是个人化的。他说在 2026 年这个节点，软件真的可以像手写信一样私密和个人化了，不再需要依赖一个庞大的产品团队。

对于正在做产品的你，这种范式变了之后，你下一步需要关心的事情就变成了：怎么让 agent 选我的 API，而不是先去翻竞品的文档。
