Boris Cherny 提出了一套全新的人才框架，这是昨天圈子里传得最厉害的一篇帖子。

Claude Code 团队成员 Boris Cherny，昨天晚上发了一个长帖。他说，工程师、产品经理、设计师、数据科学家这些传统岗位正在融化成一种新的角色。他在 Claude Code 团队里观察到五种原型，跟岗位没关系，跟你在做什么有关。第一种是原型师，不断出新点子，大多数不落地。第二种是构建者，快速把原型变成可上线的产品。第三种是扫尾者，专门清理 UI、简化代码、下架烂功能、优化性能。第四种是增长者，在已有产品上反复迭代找 PMF。第五种是维护者，管成熟系统，让它在规模上跑得更稳、更快、更安全。

Boris 特别指出，一个人通常会跨两到三种原型，不同的产品阶段需要不同的配比。新产品、还没找到 PMF 的，要靠原型师加构建者加扫尾者。正在增长的，需要构建者、扫尾者和增长者。已经很成熟的，扫尾者、增长者和维护者主导。他说这可能就是未来团队的组织方式——不是按岗位分工，而是按工作形态配人。

这帖子为什么被传了一整夜？因为它在解释一个人人都在感知、但很难说清楚的东西。

Guillermo 之前也说过类似的意思。他说你不用 LinkedIn，你需要的是一个网页，把你自己做出来的东西列在上面。ADPList 的 CEO Felix Lee 紧接着转发说设计师们，他说得对。你做出来的东西就是证据。ADPList 的 CEO Felix Lee，他的平台是全球设计师导师网络。他补充说，别再打磨简历了，把你交付的东西写清楚。

Boris 的框架把这件事推到更深一层——不只是作品集的问题，而是你整个职业身份的重写。你是什么角色，不是你简历上那个头衔决定的，是你这周每天在干什么的平均值。如果你在写代码、画界面、跟用户聊天、改产品流程，你就是那个混合物。Boris 说 Claude Code 团队里一些设计师属于原型师，一些属于构建者，一些属于扫尾者，跟设计师这个头衔本身已经没太大关系了。

这个趋势到底有多普遍？Lenny 昨天那天深度对话提供了另一个佐证。

Lenny 采访了 OpenAI Codex 的产品负责人 Andrew Ambrosino。Andrew Ambrosino，OpenAI Codex 桌面应用的产品负责人。Codex 目前周活用户超过 500 万，OpenAI 内部几乎百分百的员工每天都在用。Andrew 亲口说，设计师在写代码，工程师在做设计，PM 在交付产品——你的角色不是被任命的，是被你在时间轴上画出来的那团点的重心决定的。

Lenny 自己总结了一个更直白的版本。你的角色现在就是你时间分配的平均值。如果你花百分之四十的时间写代码，百分之三十画原型，百分之三十跟用户聊需求，那你就是那个百分之四十、三十、三十的混合体。这套表达和 Boris 的五原型框架几乎完美咬合。

这跟你有什么关系？如果你现在在做产品、做设计、做工程，去拿一周的记录看一下，你的时间到底花在哪了。你做的那些事，在 Boris 的五个原型里占几个？如果你发现自己单一标签太久，扫尾者的活完全没碰过，或者原型师的事从来没做，那可能就是你下一步要主动补的。

说完这个我们再聊另一件事。

Cursor 的 iOS 应用昨天正式上线了。这个产品让开发者在手机上启动长期运行的云端 agent，或者远程控制桌面端的 agent。Cursor 的设计师 Ryo Lu，之前在 Notion 和 Stripe 做设计，这次为 iOS 产品写的标题是"哪里冒出想法，哪里就能写代码，桌子和电脑变成可选项"。

Hamel Husain 第一时间上手试了。Hamel 是做 eval 工具的知名独立开发者，他在体验后提醒大家，要启用这个功能需要在两个地方分别打开设置，文档里藏得比较深。他的第一印象是，目前还不像 Codex 远程版本那样打磨得那么规整，比如你看不到哪个任务跑在哪台机器上，得点进会话才能知道。不过 Hamel 自己也说了，这是第一版，抛光空间还在。

同一时间，Claude Code 也公布了下一个版本的更新方向。

Claude Code 的 Boris Cherny 说，下个版本里，子 agent 会默认后台运行。你可以一边跟主 Claude 对话，一边让子 agent 在后台继续工作。如果你想让 agent 跑到前台来，直接告诉 Claude 就行。这对长期任务的体验是个明显的升级，你不用再干等着子任务跑完才能继续聊。

另一个值得展开聊的细节，是 Peter Yang 的一个观察。

Peter Yang 昨天说，纯粹用网页版 Claude 写文章、做编辑，体验依然比 Codex 和 Claude Code 好。他觉得问题可能出在编程 agent 的系统提示上，那些提示把模型调成了工程师思维，写作能力反而打了折扣。这个点很有意思，但 Peter 没有展开，更多是他自己的使用感受。

说到产品工作本身，Lenny 昨天那期对话给出的信息量非常大。接下来这段我们多说几句。

Lenny 和 Andrew Ambrosino 聊了一个多小时，Andrew 分享了十条核心思考。我们挑几个跟你日常工作直接相关的展开说。

最反直觉的一个点，是关于产品和模型的时间差。Andrew 说，Codex 在今年二月上线的这个版本，如果去年十一月原样推出去，会彻底失败。产品一模一样，什么都没改，唯一变的只有底层模型。他的教训是，别急着砍掉一条体验还不行的功能，它可能只是还没遇到够强的模型。他现在的做法是，每次新模型出来，就会把之前搁置的原型捞出来重跑一遍。这条对产品经理来说太重要了——你现在笔记本里躺着的那些做了一半没做好的东西，也许不是在告诉你它不行，而是在告诉你它还没等到时候。

第二个是 PM 的工作方式。Andrew 说 Codex 的 PM 团队用了一种"区域防守"策略。每年做自上而下的年度规划已经不管用了，因为想法从四面八方涌过来。所以他们把 PM 分散到整个公司，每人看守一片区域，保证没有盲区。如果两个 PM 的工作范围靠得太近，中间没有缝隙，那反而是坏信号，说明有人重叠、有人漏掉。缝隙得用产品型工程师填。这个逻辑跟传统管理学的职责明确、边界清晰正好反过来。

第三点，Andrew 直接说为什么 AI 目前做不好设计。两个原因。一个很实际，设计比代码更难打分，实验室优先考虑编程能力，因为编程能直接加速 AI 研究。另一个更深层，好的设计需要新鲜感和文化感。如果一个模型每次输出的都是类似 Linear 官网那种风格，那不叫品味，那叫复制。而且从视觉到代码之间还有一个模型现在跨不过去的抽象层。Andrew 认为实际操作层面的问题迟早会解决。但新鲜感、文化判断、抽象跨越——这几个挑战可能没那么快消失。

Andrew 还有其他一些锐利的观点。他说"PRD 已死"这句话也完全是错的，他反对非工程师一上来就做原型，也反对工程师写长文档。他的判断标准是，如果你要在一个模糊地带建立产品清晰度，那应该是文档。如果你在测试交互模式行不行，那应该是原型。以前你手里拿的工具本身会暗示你处于流程的哪个阶段，现在这个暗示没了，你得自己有判断。

他还提醒，小心那些打磨得特别完美的原型，看起来已经能上线了，但其实研究还没做，全屋的人还都以为进度已经过半了。他说这是当前设计流程里最大的坑——多人并行探索，却输出看似已经完工的东西。

Vercel 昨天不是发了一条，而是连发了好几条。

首先是 Voice Agent 上线。Vercel 的 AI Gateway 现在支持实时语音和转录了，AI SDK 7 同步上线了 useRealtime、generateSpeech 和 transcribe 三个 API。Guillermo 转发了这个消息，语气跟以往不太一样，只说了一句话——语音 agent，现在跑在 Vercel 上。这次是在基础设施层直接开了一条语音通道，不是包装一个第三方服务。

其次，Vercel Functions 扩容了二十倍。包体积上限从 250 MB 一步拉到 5 GB，跑在 Fluid compute 上。这意味着你可以把 Python 的 AI 和数据库、浏览器自动化、图像处理这些重型依赖直接搬到 Vercel 上。Guillermo 补了一句，说任何东西现在都能部署到 Vercel 上了，明天还有更多。他之前还发了一条神秘预告，说这周 Vercel 会有大动作，"有些人会说这是等了十年的事"。

另外，Next.js 16.3 预览版也发布了。Turbopack 这次更新能在开发环境减少最多百分之九十的内存占用，通过文件系统缓存把构建速度提升到原来的五倍半。Guillermo 特别点出一个新场景：在一个 agent 反复执行 next build 的世界里，文件系统缓存的优势被放大了。

同一时间，Hamel Husain 还发了一篇新博客，标题叫"难以评估是一种产品异味"。观点很直接——如果你觉得很难验证 AI 的输出，那你的用户大概率也觉得很难。瓶颈不在评估工具，而在于产品设计本身。他在文章里嵌入了三个交互式的前后对比案例，覆盖 AI 数据 agent、教案生成工具和五十页医疗报告的自动撰写。Hamel 说这属于 AI 工程里一个被低估的问题，它在评估链路的上游。
