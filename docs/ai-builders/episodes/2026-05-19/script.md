Cursor 昨天低调上线了 Composer 2.5，一个全新的模型。
Cursor 的设计师 Ryo Lu 说它又聪明又省 token，同一条推文里还转发了 Cursor 与 xAI 合作训练更大模型的消息，用的是 xAI 那个有百万张 H100 算力集群 Colossus 2。

这件事有意思的地方在 Riley Brown 的反应。
他是 Codex 的重度用户，昨天发推说时隔半年重新打开了 Cursor。他的判断很具体：在做设计相关工作时，Cursor 非常强。他觉得 Cursor 的内置浏览器是所有“超级应用”里做得最好的，设计模式也很好用。

但 Riley 没有说要切换，只是在重新评估。
这背后其实是现在 AI 编程工具竞争的一个缩影：没有任何一个工具能通吃所有场景。Cursor 在设计和快速迭代上强，Codex 和 Claude Code 在复杂 agent 任务上各有优势，用户开始在它们之间按任务分配工作。

另一件值得说的事。
Vercel 的 CLI 工具昨天上线了一个新命令，叫 firewall。
CEO Guillermo Rauch 转发这条公告时写了句很有意思的话：一个你的 agent 也会喜欢的防火墙。

他说 Vercel 防火墙最酷的地方，是它的全球传播速度只要大约 300 毫秒。
而行业里传统 CDN 和 WAF 的规则生效，往往需要好几分钟。
这个对比的潜台词很明确：当 agent 开始大规模管理基础设施时，规则生效必须跟上机器的速度。人手动改了防火墙，等几分钟还行，但 agent 不行。如果一个 agent 检测到攻击、自动生成了一条屏蔽规则，然后要等几分钟才生效，那这套自动化就毫无意义。

Guillermo 把这条推文当成了 Vercel 对 agent 时代基础设施的一次表态。

Thariq 昨天发了一条提示词，在 X 上传播速度极快。他是 Anthropic Claude Code 团队的工程师。
这条提示词的核心是，让 agent 在实现需求的同时，维护一个运行中的 implementation-notes.html 文件。文件里记录 agent 在做什么决策、哪里偏离了需求、当时有哪些替代方案被放弃了、还有哪些问题需要人确认。

Thariq 后来补了一条说明，说原帖写得有点乱，让 Claude 帮忙重写了一版。新版本更清晰，但逻辑没变。
他还解释了自己为什么用这招：不管你需求写得多细，执行过程里一定会冒出歧义和未知的未知。这条提示词给了模型一个出口，让它自己做决定，但同时把人留在信息环里。

这条推文的收藏数极高，不是没有原因。
它解决的其实是一个所有用 agent 做工程的人都踩过的坑：agent 跑了很久，吐出一堆代码，但你完全不知道它在中间做了哪些假设。等你发现某个地方不对劲，你没办法判断是需求没写清楚，还是模型擅自改了逻辑。

Thariq 的思路是，把 agent 的思考过程从黑箱变成可追溯的文档。
而且他特别强调用 HTML 格式。这个跟前两天他说“HTML 是新的 Markdown”是同一条线。HTML 可以做成交互式的成品，人可以快速浏览，agent 也能更新。

Claire Vo 前几天发布了一期对 Thariq 的深度访谈，Lenny 昨天也转发了。
Thariq 在访谈里讲了更多细节。他用 HTML 做交互式的需求文档，做一次性的微型 UI，维护一套活的设计系统。他给 Claude 的提示词里会写“whatever is needed”，给模型空间自己去想。

他说了一句话很容易被忽略，但很关键。他说，需要在运行时间很长的 agent 任务里保持人在环。这个“人在环”不是传统的审批机制，而是设计一种方式，让 agent 主动把人需要知道的信息推到眼前。

另一个人也在讲类似的逻辑，只是从完全不同的角度。
Peter Yang 昨天发了对 Anthropic 研究员 Alex Albert 的访谈要点，其中有一条跟 Thariq 的做法形成了印证。Alex 说，设计系统时要让 Claude 能检查自己的输出并迭代。比如给编程 agent 一个能操作电脑的工具，让它自己去点击网站，跑 QA 测试，自己抓 bug。这是让 agent 拥有自我纠错能力，而 Thariq 的提示词是让 agent 把纠错的过程暴露给人看。两条线合在一起，才是一套完整的 agent 工作流设计逻辑。

如果你现在在用 agent 做开发，有一个很直接的启发。试着在下次给 agent 的需求末尾，加一行：执行过程中保持一个笔记文件，把你做的所有判断、偏离和待确认项写进去。然后观察一下，你第一次发现 agent 做错了你没预想到的事时，能不能从那份笔记里找到原因。Thariq 这条提示词，值得每个人在自己的项目里试一次。
