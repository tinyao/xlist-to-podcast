OpenAI 的核心高管 Fidji Simo 为什么突然转任顾问？GPT-5.6 发布第一天，圈内怎么评价 Sol 这个新模型？Bun 的作者为什么要用 Fable 把整个运行时从 Zig 重写成 Rust？先从最让人揪心的事说起。

OpenAI 的首席运营官 Fidji Simo 昨天宣布，将离开全职岗位，转为兼职顾问。原因是慢性疾病的严重复发。她在告别信里写了一段很坦诚的话——三个月前她开始休病假，当时很多人说她有勇气优先考虑健康。但她说，自己现在才做这个决定，是因为之前太多次都失败了。几年前 Facebook 曾主动提出给她一整年的病假，她当时想都没想就拒绝了。扎克伯格劝她应该打长期比赛，她说后悔没听进去。

Sam Altman 随后转发了这封信，说非常难过，也很感激 Fidji 为 OpenAI 所做的一切。他写了一句很直白的话——"这事儿真的很糟糕"。Fidji 在信里还提到，过去七年她一边帮别人构建未来，一边同时应对一种至今没有治愈方法的疾病。这段经历让她更坚信，AI 最重要的机会之一，是帮人们解决健康、财务、时间这些日常生活的真实问题。她特别指出，治愈疾病是 AI 能做到的最重要的事。

这不仅仅是人事变动。Fidji 在 OpenAI 负责的是把技术变成产品、把产品推向用户的整个链条。她离开后，这部分工作会重新分配。如果你在关注 OpenAI 的产品节奏和商业化推进速度，这件事值得留意。

换个方向。GPT-5.6 昨天正式发布了，圈子里讨论了一整天。Sam Altman 说这是他见过的最好的模型，也是 OpenAI 最好的博客文章。这次发布有三个产品层面的东西：ChatGPT Work、新的桌面应用、以及托管网站功能。其中 ChatGPT Work 是核心——它由 Codex 驱动，可以跨应用和文件执行任务，跟着一个项目跑好几个小时，把目标直接变成完成的工作。

关于模型本身，圈内形成了一个有意思的对比。Mitchell Hashimoto 提前用了一个月，他的评价是 Sol 更快、计划和判断能力和 Fable 差不多，整体产出更好。他用了一个比喻——Sol 是一个有魅力、高效、有才华的同事，你会嫉妒的那种。Fable 则是一个天才隐士，在自己的专注领域里无人能及，但你不会想跟它一起出去玩。他说 Fable 在高度针对性的调试、安全和性能任务上仍然无敌，但 Sol 在其他方面更好或持平，而且更让人享受合作过程。

Peter Gostev 给出了另一个角度。他说 Fable 是"智慧猫头鹰"，深思熟虑、表达清晰。Sol 是"罗威纳犬"，咬住问题就不松口。Fable 在纯粹智力上更强，但 Sol 在稳健性和可靠性上完胜——你给它一个八项任务的清单，它会全部完成。他还分享了一个有趣的指标：他有一个"脏话计数器"，用来记录自己对 Codex 发脾气的频率。GPT-5.5 时代是百分之四到五，用 Sol 测试期间降到了百分之一到二，切回 5.5 之后直接飙升到百分之七。

如果你今天就要决定默认用哪个模型，这些信息应该够你做判断了。你是更看重纯粹智力，还是更看重可靠性和不让你抓狂？

另一件值得说的事。Lenny 发布了 2026 年科技行业从业者调查的第二份报告。结果用四个字概括：两极分化。一半的人觉得被 AI 放大了能力——更有信心、更兴奋。另一半的人觉得被 AI 动摇了——不确定自己的价值，不确定还有没有自己的位置。最让人意外的是，最大的恐惧不是"被 AI 取代"，只有百分之二十二的人担心这个。真正让人焦虑的，是被要求做更多的活却拿同样的钱，陷入不可持续的工作节奏，以及工作质量下滑。

Lenny 的总结很精准——在 2026 年，最能预测一个科技从业者感受的，不再是"你做什么工作"或者"你在哪家公司"，而是"AI 对你的自我认知做了什么"。这个调查覆盖了几千人，如果你在带团队或者自己在创业，这份报告值得翻一翻。

说到技术决策，Bun 的作者 Jarred Sumner 正在用 Fable 5 把 Bun 从 Zig 重写成 Rust。这个项目花了超过十六万五千美元的 API 费用。Replit 的 CEO Amjad Masad 看到之后发了一条评论——我们什么时候才能停止拿自主 agent 的产出和手写代码比较？他说你不会拿编译器去跟手写汇编的工程师比。Claude Code 团队的 Boris Cherny 说这件事很史诗。

这条新闻的意义不在于 Bun 要换语言。而在于一个运行时作者，选择用 AI 来执行一个涉及数万行底层代码的重写工程，而且愿意公开这个过程和成本。这比任何基准测试都更能说明 Fable 在系统编程领域的实际能力。

先把节奏放慢一点，说一下今天最值得想清楚的一件事。

GPT-5.6 和 Fable 5 的对比，表面上是在聊两个模型谁更好。但如果你把昨天所有讨论放在一起看，你会发现大家真正在争的，不是基准分数，而是"你更愿意跟哪种智能一起工作"。

Mitchell Hashimoto 说 Sol 像个有魅力的同事，Fable 像个天才隐士。Peter Gostev 说一个是罗威纳犬，一个是猫头鹰。Sam Altman 自己调侃说，Sol 也不太会约会。这些比喻都在指向同一个东西——模型的人格化感知，已经成了开发者选择工具的实际标准。

而 Zara Zhang 昨天分享了一个很反直觉的案例。她说跟一个重度 agent 化的创始人聊过，整个团队都用 Codex Max，每个人都靠跟自己的 Codex 对话来完成工作。结果呢？副作用是同事之间不再说话了。会议取消了，协作降到最低，团队文化变差了。她说现在很多企业 AI 使用都是单机模式，但问题是——当团队成员都跟 agent 说话而不跟彼此说话的时候，我们牺牲了什么？她提出的方向是，需要从人机协作，走向"人-人-agent"的三方协作。

这跟 Lenny 的调查形成了呼应。AI 让个体生产力暴涨，但团队层面的连接在松动。一半的人感觉被放大，另一半感觉被掏空。被放大的那一半，可能正在变成更高效的单机。而被掏空的那一半，恰恰需要团队的支持和连接。

郭宇昨天也发了一条很长的思考。他在把 Grok build 接入自己的 wanman 项目，发现不同 agent 之间共享数据和记忆，只能依赖一个外部数据源，而不是各自的工作空间。他说这就像一家公司——有月薪十万的高级程序员，也有月薪两万的初级程序员，还有一天两百块的实习生。他们的工作有交叉，但工作空间完全不同。他认为以后所有 AI 应用都不得不处理混合模型的问题，不是因为成本，而是因为不同的模型各有所长。

这三条线索放在一起，指向了同一个正在浮现的工程挑战：当 agent 变得越来越能干、越来越像"同事"，我们怎么设计系统，让它们不只是替代人的协作，而是增强人的协作？怎么让不同层级的智能在同一个工作空间里，既能各司其职，又能共享上下文？

如果你正在设计一个多 agent 系统，或者正在推团队里的 AI 使用，今天可以问自己一个问题——你的 agent 之间能互相说话吗？还是它们只跟人类说话？
