先从昨天最让人手痒的那件事说起。

Claude Design 在昨天晚上正式上线了，Anthropic Labs 把它和 Claude Code、Claude Cowork 放在一起，打出了整套创作的牌。

这是 Anthropic 在 Claude Opus 4.7 发布之后马上接上的第二招。Matt Turck 管这波发布叫“generation run”，一连串的名字：Claude Code、Skills、Claude Cowork，现在加上 Claude Design。

Alex Albert 做的定义很简单：Claude Design 可以让任何有视觉想法的人，通过和 Claude 对话，直接输出高质量的设计稿、原型、PPT 和一页纸的说明。后台跑的是 Opus 4.7 的视觉模型，目前在 Pro、Max、Team、Enterprise 这几个计划里以研究预览的形式开放，昨天开始慢慢推。

Peter Yang 试用的第一反应是“说不出话”。他把 Claude Design 的官方博客和几条 Anthropic 员工的 tweet 直接贴进去，三十秒就生成了一条介绍视频，被他形容为“像变魔术一样”。Justine Moore 更不老实，她让 Claude Design 帮 X 的用户做了一个约会 app，结果这个产品直接跳过了传统滑卡界面，设计了一个每日精选推送的匹配逻辑。她在推特上感叹 Opus 4.7 挺幽默的，还在界面里藏了不少彩蛋——唯一的抱怨是 Max 计划的速率配额，不到三十分钟就被她打满了。

Riley Brown 的动作更快。他把 Claude Design 的代码和技能拆了出来，做成了一个通用 agent skill，可以让任何 agent 调用。他测试的结果是，因为 Codex 自带评论和 web 预览，所以在 Codex 里也能跑出差不多的效果。他的判断挺直接：Claude Design、Claude Cowork、Claude Code，过不了多久就应该统一成一个“Claude”。

Peter Yang 的另一条 tweet 说得更狠。他认为 Anthropic 或者某种 AI 原生工具，会从设计工具和办公套件这两端同时碾压过来。理由是以前这些工具都为人手一张张做幻灯片、文档、表格设计的，现在一个 agent 靠接收你的脑 dump 就能批量生成。虽然最后 10% 的打磨可能还是得自己来，但前面 90% 的效率差，已经不是同一个量级了。

如果你今天把 Claude Design 打开，试着把你下一次评审需要的几张核心页面，用一两段话描述清楚丢给它——看看它能帮你省掉几轮来回。

另一件值得说的事。Kevin Weil 昨天宣布，他在 OpenAI 的最后一天到了，OpenAI for Science 会被分散进其他研究团队。

Kevin Weil 是 OpenAI 的 VP of Science，之前做过 CPO 和产品负责人。他说的很克制，把这两年的经历形容为“脑洞大开”，最后给 Sam Altman、Mark Chen 和其余核心团队留了一句“加速科学会是 AGI 最令人震惊的正向结果”。

这个变动本身不算突然，但结构挺有意思。OpenAI for Science 本来是公司内部一个相对集中的垂类布局，覆盖化学、蛋白工程、基因组学，还有一些自研工具和数据库。现在把它拆散到其他团队，意味着 OpenAI 不再用专门的团队来推科学研究，而是回到了更早的那套逻辑：基础模型能力溢出，让科学案例自己长出来。

这对一线做垂类模型的团队来说，是一个微妙的信号。大厂重兵投入的科研产品线，也可能在组织架构变动里被模块化掉。

与此同时，Salesforce 丢出来的 Headless 360 产品，更像是从企业端印证了同一个趋势。

Marc Benioff 昨天宣告的 Headless 360，核心是把整个 Salesforce、Agentforce 和 Slack 平台全部通过 API、MCP 和 CLI 的方式暴露出来，不再需要浏览器当入口。Aaron Levie 转发时写了一大段判断，他说未来 agent 用软件的量会是人用的一百倍，企业平台必须彻底转型成 headless，否则就没法在代理时代活下去。

Aaron Levie 还补充了一个容易被忽略的观察：这不是零和游戏。过去软件的价值天花板被用户数卡着，一个公司能买多少席位，就只能创造多少价值。但代理没有上限——它们可以七天二十四小时并行跑，跨系统整合流程，释放出以前根本没法想象的新场景。

如果把 Kevin Weil 的离开和 Salesforce Headless 360 放在一起看，你会发现一个有意思的交错。一端是前沿模型公司把科学专用团队拆掉，回归通用底座；另一端是企业软件公司拼命把自己拆干净，让任何 agent 都能直接吃掉数据和工作流。两边都在做同一件事：让位给代理，只是姿势刚好相反。

接下来这段我们多说几句。

昨天 Peter Steinberger 在 TED2026 做了一个演讲，题目就叫“龙虾已经跑了，不会再回缸里了”。紧接着他在 AI Engineer 的舞台上，扔出了 OpenClaw 五个月维护背后的一组安全数字，说真的，这组数把代理工具的真实战斗烈度扎扎实实地晾了出来。

先听数字。Peter Steinberger 给的数据是：OpenClaw 收到的安全报告是 curl 的 60 倍。在所有社区提交的技能贡献里，有 12% 到 20% 是恶意的。他们还建了一个“狗屁分类学”，专门给无效和虚假的安全报告分级。国家层面的攻击也出现了，GitHub 上有人一天烧掉好几个 Codex Pro 额度在刷恶意贡献。

swyx 当场追问了一个很尖锐的问题：ClosedClaw 的未来是什么？Peter Steinberger 那会儿的表情你可以去翻视频——笑得很复杂。

这组数字可怕的地方在哪？以前我们聊开源安全，话题基本停留在代码扫描和漏洞修复上。像前天 Discourse 做的，是用 AI 跑多天扫描，一个月修复 50 个 CVE。那个方向虽然辛苦，但逻辑是防守型的：加固代码，堵住漏洞。可 OpenClaw 面对的是完全不同的东西——agent 本身既是产品，也是攻击入口。任何贡献者通过技能提交，都可以直接接触到用户的本地环境。12% 的恶意率，意味着你每接收十个社区的能力扩展，就至少有一个是带着枪来的。

Nan Yu 昨晚接连发了好几条推文，口气带点半开玩笑也半认真。他说我们正在从第一原理重新发明设计师，重新发明产品经理，重新发明工程师。放在 OpenClaw 这场安全攻防旁边，这句话突然多了一层毛边：我们也在从第一原理重新发明攻击向量。

如果你在构建和代理有关的开发工具、或者是社区驱动的 agent 平台，Peter Steinberger 这套数字应该钉在你的安全看板上。能不能做到每次技能提交都跑一次沙箱隔离？有没有能力自动识别恶意贡献的类型？能不能把贡献者的身份和权力分级，做成和云服务一样的 IAM？这些不是未来的事了，就是今天凌晨两点你被报警叫醒的那个问题。

再说几条快讯。

Lenny 把他的 Lennybot 集成进了 Substack。这个 bot 用了他差不多 350 篇 newsletter 和 300 期访谈的内容训练，用户在订阅里就能直接对话。他还留了个电话号码，听众可以发短信或者打过去直接跟 bot 聊天。如果你已经是他的付费用户，这个体验值得试一下。

Replit 的 Agent 昨天秀了一个非常实际的用例：把 web 应用重构成了原生 React iOS app，跑了一个多小时，执行了 69 个测试，花了 7 美元。Amjad Masad 自己在用的时候说，这功能最近对提一些微小但关键的体验改进特别在行。如果你手里有几个一直想尝试移动端的个人项目，十几美元的门槛基本等于零。

Cursor 的设计师 Ryo Lu 公开了一个叫 baby glass 的新工具，是他们内部新的原型环境。设计师可以在里面用代码快速想象、混搭和测试创意，底层组件和 Cursor 3 的新界面是同一套。Ryo 说这是让设计师在代码里随手“玩玻璃”的东西，听起来像是一个更贴身的 Figma 杀手锏。

郭宇的 tuwa 昨天上线了“同步听”功能，把手机放在电视或者电台边上，就能用母语实时听到翻译后的节目内容。这个功能对跨语言学习挺实用，免费用户也能用。
