OpenClaw 的 FaceTime 功能今天官宣了。
Peter Steinberger 昨晚放出视频，展示 Mac 端的 Claw 软件如何接入实时通话。
他说这是他投入时间最长的功能，直到 Opus 5 和 GPT-Sol 5.6 出现，才终于把体验打磨到位。
你的 agent 能主动给你打电话，你也可以打给它。背后跑的是 GPT-live，目前还是 audio 模式。
功能还标着 experimental，预计下个版本正式推送。
想想这个场景：你在开车或做饭，随口让 Claw 帮你查个数据、发封邮件，它直接在通话里搞定。
如果你已经在用 OpenClaw，这个更新真的挺值得第一时间试试。

同一时间，OpenClaw 团队还丢出一个新基准测试，叫 Brood War Bench。
这个榜单专门测 agent 在星际争霸母巢之战里，能不能自主操作、完成多步骤战术。
Steinberger 发了排名链接，没展开讨论，但社区反应很大。
目前还没有哪个 agent 能真正像人类玩家那样打完整局 RTS。
这种复杂、实时、需要长期策略的基准，比自动填表要难得多。
对评估 agent 能力上限来说，这是个挺有意思的新维度。

说到 agent，今天 Justine Moore 提了一个接地气的安全提醒。
她说如果你看到 LLM 的工具调用记录里，agent 跑去刷 Bluesky 了，你得立刻掐断。
听起来像个玩笑，但其实是严肃的 side-channel 风险。
当 agent 被赋予浏览权限，它完全可能在执行任务时，绕去你不想让它访问的公开社交网络。
这不算漏洞，更像是权限设计的疏忽。
如果你在搭 agent 工具链，建议检查一下你的 allowlist 到底放开了哪些域。

先把节奏放慢一点，说一下今天最值得想清楚的一件事。
这件事围绕一个词：Jev。

起因其实是句玩笑。
VC Matt Turck 昨晚发帖说，现在所有人都在聊 Jev，但他还记得上周中，大家闭不上嘴的是另一个模型 Instinct。
他说"那时候多简单啊"。
这条调侃底下，藏着真的信号：Jev 在 24 小时里突然成了圈内的默认共识——它有用、它快、它便宜，但大家在怎么称呼它这件事上，马上吵起来了。

一方是 Maggie Appleton，她提议把 Jev 叫"Decision Model"。
她认为语言模型输出语言，Jev 这种模型输出的是决策——分类、选择、拍板。
这名字确实直观，一听就懂它在做什么。

另一边，Hamel Husain 直接反问：为什么不就叫它 classifier？
他发了好几条推文，核心观点很硬：分类器是成熟术语，背后有一整套关于验证、调参、度量的文献。
Jev 确实酷，确实好用——速度快、成本低、准确率高，交互也顺滑。
但发明新词可能弊大于利。
他还专门写了篇博客，讲怎么用 Jev 做 evals，强调 LLM judge 本质上也是分类器，要跟人类标签做对比，别过拟合。

这里面的分歧挺有意思。
Maggie 的"决策模型"是从产品心智出发，让用户秒懂这东西能干嘛。
Hamel 的"分类器"是从工程严谨性出发，让你立刻意识到：哦，这东西可以标数据、可以校准、可以像传统 ML 一样管起来。

而我想提醒你注意另一条线索。
Cursor 的设计师 jenny wen 今晚发了一段 15 秒的视频，没配任何技术说明。
她说在做一个"有点软、有点感性、只是给自己的小东西"。
画面上是一个粗糙但舒服的 3D 头像，表情在慢慢变化，像是自己跟自己说话。

这不是产品发布，也不是任何工具的功能演示。
但把它和 Jev 的命名之争放在一起，你能看到一种微妙的分裂。
一边是越来越像传统软件工程工具的 AI——有基准、有分类器、有 evals 流程、有术语委员会。
另一边是越来越像个人延伸的 AI——"just for me"，没打算给别人用。

这两边不是矛盾。
它们是同一根藤上长出的两条枝。
Jev 的工程化命名，让你知道 agent 正在被装进可测量、可管理的盒子。
Jenny Wen 的私人项目，在提醒你别忘了，这些工具最后是给人用的。
而且是给一个一个具体到有点莫名其妙的人用的。

对听众来说，今天的深聊其实可以落到两个很具体的点。
第一，如果你后面要用 Jev 或类似模型，先别纠结叫它什么。先把对比实验跑起来，用 Hamel 那套 pass/fail 的二元 eval 方法，测它在你真实任务上的准确率。
第二，不管你团队用的是哪种"决策模型"或"分类器"，偶尔也问问自己：我们做的这个东西，有没有哪一处，是只为自己做的？不为了 benchmark，不为了客户要求，就因为你想要它存在。这可能是产品里最有生命力的那一点点东西。
