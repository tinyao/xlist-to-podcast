OpenAI 正式推出“Daybreak”网络安全加速计划，同时宣布成立一家全新的部署公司。
Sam Altman 昨天连发两条推文，亲自官宣了这两件事。
Daybreak 的目标是帮企业持续加固软件安全。Sam 说得很直白：AI 在网络安全上已经很强，而且马上会变得超级强。
他们现在就想跟尽可能多的公司合作，帮它们持续保护自己。

而另一件事，分量更重。
OpenAI 成立了一家叫 OpenAI Deployment Company 的新实体。
这家公司由 OpenAI 控股，联合了 19 家投资机构、咨询公司和系统集成商。
它专门帮企业把前沿 AI 部署到生产环境中，第一天就通过收购 Tomoro 获得了 150 名 forward deployed 工程师。

Box 的 CEO Aaron Levie 随后发了一篇长文分析这件事。
他的核心判断是：agent 部署的专业服务需求，现在是一个巨大的机会。
他说，从模拟到数字、从本地到云，每一次技术浪潮都催生了新一代的咨询和部署服务。
但这一次的规模会比前两次大得多。

原因在于，agent 不是在换一个软件系统，而是在重写业务流程本身。
而业务流程充满了各种特殊的、定制的细节。
CPG 行业的营销 agent，跟医疗行业的营销 agent，长得完全不一样。
B2B 软件公司的销售 agent，跟汽车经销商的销售 agent，也不是一回事。

而且这件事在技术上一点都不简单。
你得先把数据基础设施现代化，让 agent 能安全地接入。
权限和访问控制要重新设计，确保 agent 和人都能各司其职。
模型升级之后，agent 的表现要持续评估和维护。
最后，还要做流程变革管理——决定哪些活人干，哪些活 agent 干。

Aaron 说，这需要大量的技术和领域知识。
他透露 Box 自己已经开始招聘“AI 自动化工程师”了。
这个岗位会直接跟业务部门合作，帮他们用 agent 放大产出。
他预计，未来大多数公司都会出现各种变体的这类角色。

如果你在做面向企业的 AI 产品，这个信号值得认真想一下。
以前大家抢的是“谁先做出最强的模型”。
现在战场正在往“谁能让模型在企业里真正跑起来”转移。
而这件事需要的不是更好的 prompt，是更深厚的行业 know-how。

同一时间，Claude Code 发布了一个叫 Agent View 的新功能。
Anthropic 的 Thariq 在深夜发了推文，说这是他最推荐的原生多会话管理方式。
用法很简单：在一个包含所有仓库的高层目录里运行 claude agents。
它会追踪哪些会话需要你的输入，让你能快速恢复之前的工作。

Thariq 的原话是，这有点像给 Claude Code 定制的 tmux。
团队花了很多时间打磨细节，现在是 research preview 阶段。
如果你同时跑多个 agent 会话，这个功能能省掉大量来回切换的麻烦。

换个方向，Replit 的 CEO Amjad Masad 昨天宣布了一个新功能：Parallel Agents。
简单说，就是可以同时跑最多 10 个 agent，每个 agent 在自己的环境里工作，最后自动合并。
Amjad 说了一句话挺有意思：如果你只用过单个 agent，你还没真正感受到 AI 的进步速度。
真正的突破不在于“能并行”，而在于编排正确、无缝合并、让项目进度快十倍。

另一边，Karpathy 昨天发了一篇长文，讲的是人机交互的输入输出进化。
他的核心观点很简洁：音频是人类偏好的输入方式，但视觉才是 AI 应该偏好的输出方式。
他给了一个非常实用的建议：在 prompt 结尾加上一句“请把回复结构化输出为 HTML”。
然后直接在浏览器里打开生成的 HTML 文件。

Karpathy 说，人类大脑有三分之一是专门处理视觉的并行处理器。
这是信息进入大脑的十车道高速路。
所以他画了一条进化路线：从纯文本，到 markdown，再到 HTML。
目前大家默认用 markdown，但 HTML 能提供更丰富的排版、图形甚至交互。
他预测，这条路的终点，是某种由扩散神经网络直接生成的交互式视频。

Thariq 也转发了 Karpathy 的推文，说自己已经在用 HTML 做规划、写规格、做代码审查和报告了。
他说，在百万 token 上下文时代，会话管理反而需要更仔细地思考，不是更少。
如果你还没试过让 AI 输出 HTML，今天可以试一次。
在 prompt 末尾加一句“structure your response as HTML”，然后把文件拖进浏览器。

过去 24 小时，有三条线同时指向了同一个方向。
第一条是 OpenAI 的部署公司。第二条是 Aaron Levie 的分析和 Box 的招聘动作。
第三条是 Greg Isenberg 昨天发的一篇长文，列出了七个可以用 agent 做的小创业想法。

Greg 是 Late Checkout 的 CEO，一直在做创业想法孵化。
他列出的七个想法，每一个都遵循同一个框架：找到一个需要人花几个小时去盯、去查、去扫描的工作。
然后把它变成一个 agent。
比如，一个监控域名过期拍卖的 agent，早上给你发一份排名清单。
一个监控本地餐厅倒闭和破产拍卖的 agent，设备价值三万美金的东西，一折就能拿下。
一个监控竞争对手的 agent，定价变了、新页面上了、招人了、创始人发推了，早上七点给你一份简报。

Greg 说他每个想法都在二十分钟内用 Genspark 跑通了原型。
这些想法单个看起来都很小，但串在一起，就是一条很清晰的线索。
agent 正在从“帮工程师写代码”，扩展到“帮任何知识工作者盯信息”。

把这三条线放在一起看，你会发现一个正在成型的职业市场。
OpenAI 和 Box 在招的是高端部署人才——懂技术、懂业务、能把 agent 塞进企业流程里的人。
Greg 在探索的是低门槛的 agent 创业——一个人加一个 agent，就能跑起来的小生意。
这两端之间，还有大量的中间地带。

Aaron Levie 昨天在另一条推文里写得很直白。
他说，随着 agent 从编程扩展到其他知识工作，把它做好需要真功夫。
你得确保 agent 有正确的上下文和数据。
你得把系统安全地接给 agent。
你得验证 agent 的输出质量。
你得设计人和 agent 的协作流程。
模型升级之后，你还得持续维护 agent。

他的结论是：这不是一个副业，也不是晚上和周末能搞定的事。
这是一个高度技术性的工作，非常像 forward deployed 工程师的角色。
而且他预计，未来大多数公司都会有这种岗位的多种变体。

Peter Steinberger 昨天的几条推文，从另一个角度印证了这一点。
他让 Codex 去改进 OpenClaw 的端到端测试。
Codex 发现需要的 API 没开，就自己启动了 Computer Use，在 Google Cloud 管理后台里点击、打开。
整个过程没有人插手。
Peter 还发了一条说，他在 RepoBar 里内嵌了一个浏览器，方便在查看 issue 和 PR 时随时获取上下文。
他说了一句很实在的话：你得给自己造工具，才能更高效地工作。

这些场景背后，都有一个共同的角色。
这个人既不是纯粹的工程师，也不是纯粹的业务人员。
他知道怎么给 agent 设定边界、怎么判断 agent 的输出靠不靠谱、怎么把 agent 塞进一个真实的工作流里。
而这个角色，目前还没有一个统一的名字。
但 Aaron 已经在招了，OpenAI 已经在部署了，Greg 已经在教人怎么做了。

对听众来说，这件事有一个很直接的启发。
如果你现在的工作里有一部分是“盯信息”、“查状态”、“扫更新”，试着用一个 agent 把它自动化掉。
不是为了省时间，是为了积累那种“让 agent 替你干活”的手感。
这种手感，正在变成一种新的职业技能。
