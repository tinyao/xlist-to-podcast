Guillermo Rauch 说设计不应该被困在 Figma 里，那它应该变成什么？
Aaron Levie 告诉我们，工程师的工作不仅不会消失，还会出现在药企的招聘网站上，这背后的逻辑是什么？

先从今天最颠覆常识的那个观点说起。

Claude Design 的争论没停，但 Guillermo Rauch 直接把话题拉到了另一个维度。他认为，设计到底该放在 Figma 还是 Claude Design 里，这个问题本身是个干扰项。真正的大变化是，设计本身会变成一种自主能力，不再只是一款工具。未来的设计更像是一个标记文件，你可以把它叫做 DESIGN.md，它由运行在你软件工厂里的编程 agent 来读取和使用。

这个说法很具体。Guillermo 说自己很喜欢在 v0 里用提示词做设计，把它当成灵感的出口。但他同时也看到，新一代的产品已经在用 v0 的平台接口，把设计放到了自动驾驶模式上。他举了两个例子，tryflint 和 bloom，说这些 agent 已经在自动生成和维护设计及品牌系统，不需要人工介入。这意味着什么？你未来看到的公司官网，可能从头到尾都是一个 agent 在保持视觉一致性。

Guillermo 还特别提了一句更远的图景。他说全自动公司正在出现，像 durable 和 nanocorp 这样的 agent，甚至能帮你做增长和广告。他的原话是，那种“现有的东西加上 AI，某个职位就完了”的说法，实在太短视了。如果你正在规划下一代产品，这个建议值得听听——别再把 AI 当插件，而是想一下，整个流程能不能变成 agent 的工作流。

另一件值得说的事。Aaron Levie 昨天发了一篇长文，核心就一个意思：软件工程师的工作不会消失，但它会出现在你完全想不到的地方。

他觉得我们脑子里“工程师等于科技公司写代码的人”这个印象，太老了。因为 AI agent 的出现，地球上任何一家公司，现在都能为自己创造软件，用来做流程自动化。这在以前要么技术上做不到，要么经济上负担不起。

Levie 举了一个很有意思的例子。他随手打开礼来制药的招聘网站，找到了一个叫“实验室自动化软件工程师”的职位。他说，未来每一家公司都会有类似的新岗位。工程师的工作内容会变成设计系统、连接各种平台、指挥 agent 做事、维护系统、审查 agent 的输出。

这件事对听众意味着什么？如果你正在犹豫，是不是 AI 会把工程岗卷没，Levie 给出的判断是反直觉的——实体经济里对这类人才的需求，才刚刚开始冒头。

换个方向。Greg Isenberg 昨晚扔出了一套具体的创业作战图，他管这叫 agent-first 的万亿美元机会。

他的推理链条很清晰。Salesforce 已经宣布 Headless 360，把整个平台通过 API 暴露出来，不再需要浏览器。Greg 预测，十八个月内，每一家 SaaS 公司都会跟进，变成无头模式。而一旦所有 SaaS 都把自己拆成了 API，就会出现一种新的创业物种：agent 原生公司。这些公司的特点是，把 Salesforce、HubSpot、Workday 这类传统软件，当成一个笨重的后端数据库来用。真正的产品就是 agent 本身。

Greg 列出了几个关键推论。咨询服务会被压缩成软件，实施团队会被 agent 替代。按人头收费的订阅制会死，因为 agent 一分钟能打一万次 API 调用，你没法按座位数卖。定价会变成按效果付钱。最关键的护城河不再是代码，而是对垂直行业工作流的深度理解，以及分发能力。他甚至说，媒体加 agent 就是新的 SaaS，硅谷会变得像个 influencer 圈子。

说真的，这套推演虽然语气很 Greg，但逻辑链条咬得挺紧。如果你正在找方向，他的建议是：找到那些还在靠仪表盘、电话和 Excel 跑业务的行业，直接用 agent 重做整个端到端的工作流。

接下来这段我们多说几句。

今天值得展开聊的，是 Aaron Levie 和 Greg Isenberg 都在指向的同一件事——软件的消费者正在从人变成 agent，而这会彻底改写工程师和创业者的生态位。

起因很简单。两天前，Marc Benioff 宣告 Salesforce 无头化。这个动作本身，我们在前天的节目里聊过了。但昨天，Aaron Levie 和 Greg Isenberg 各自从不同角度，把这件事的后续推演到了非常具体的层面。

Levie 的角度是工程师。他的观察是，以前软件能产生的价值，被人的数量卡死了。一个公司买了多少席位，就只能释放多少生产力。但 agent 没有上限。它们可以二十四小时并行，跨系统串联流程。结果就是，agent 对软件的用量，会是人用的一百倍。而这个增量，会反过来制造巨大的工程需求——不是写 app 的需求，而是让 agent 跑得更顺、串得更好的需求。

Greg 的角度是创业者。他说得比较直接：以前那波 SaaS 浪潮，奖励的是能在难看的数据上做出漂亮界面的人。而这一次，会奖励那些能在暴露的 API 之上，做出智能 agent 的人。他甚至列出了具体的赢家画像——不是顶级工程师，而是那些对某个行业工作流熟到骨子里的前从业者。举个例子，知道一个物业经理每周花十四个小时在租约续签上，这个洞察本身，在他看来就值一亿美金。

两边一合，画面的颗粒度就出来了。一边是传统企业的工程师招聘变多了，因为 agent 需要人维护。另一边是创业门槛变了，代码变得简单，工作流知识变成了最稀缺的资产。这对你来说，有个很实际的对照：你是更享受写代码本身，还是更享受拆解一个行业的业务流程？这可能会决定你接下来三年，到底站在哪一边。

再说几条快讯。

Hamel Husain 昨天详细拆解了 Codex 桌面端电脑操控的五个优势。其中最让人心动的一点，是可以直接操作那些没有优质 API 的原生应用，比如 Slack、Google Sheets、备忘录，不需要额外装插件。他说五分钟就能上手，而且 UI 打磨得非常精致，不会打断你的心流。如果你还没升级 Codex 桌面端，这个功能值得今天试一下。

Google 把 ProducerAI 更名成了 Google Flow Music，并且发布了新的 remix 功能。VP Josh Woodward 说，目标没变，还是给创作者更多控制力。同一时间，Cursor 的设计师 Ryo Lu 转发了一份独立安全分析，结论是 Cursor 在功能性和安全性上是最佳代码agent平台，尤其搭配 Opus 4.7 之后效果提升明显。

Riley Brown 晒了自己的全套 Codex 配置，视频里他把 Codex 5.4 设成主力，Opus 4.7 专门做设计和视频，连了邮件、Slack、Linear 和 Notion。他说自己感觉“什么都能做”。哎，说到这个，你现在的 agent 工具链，是越搭越重，还是已经开始做减法了？
