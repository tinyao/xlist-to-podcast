今天是2026年3月7日，欢迎收听 AI Builders Daily。今天我们要聊三件事：Karpathy 让 AI 自己优化自己的代码、Claude 每天新增百万用户背后的产品信号，还有一个让所有 AI 工程师都在点头的观点——这年头，「subagent」才是正确的打开方式。我们开始吧。


先从今天最让我停下来反复看的一条内容说起。

Andrej Karpathy 昨晚发了一条推文，描述他的 nanochat 项目现在的状态。nanochat 是他在做的一个轻量级 GPT-2 训练实验，目标是把训练时间压缩到接近「交互式」的速度。最新进展是，在单个8块H100的节点上，训练时间已经从一个月前的三小时压缩到了两小时，关键是换了 NVIDIA 的 ClimbMix 数据集，效果出奇地好。

但这只是背景。真正让人眼前一亮的部分是他接下来说的：他现在已经把 AI Agent 接进来，让它自动在 nanochat 上迭代优化，自己跑实验、自己合并有效的改动、自己继续下一轮。他说过去12小时，agent 做了110次修改，把验证损失从0.862降到了0.858——他本人没有碰任何东西。

他的原话很有意思，他说"这就是 post-AGI 的感觉，我去桑拿了"。

然后他补充了一句更有分量的话：他现在真正关心的 benchmark，不是模型本身的指标，而是"哪套 agent 代码能让 nanochat 改进得最快"。这是一个视角的根本性转移。研究的对象从模型变成了 agent 流程本身。

我觉得这条推文值得多想一层。Karpathy 在说的，其实是一种新的研究范式——你不再是那个坐在键盘前跑实验的人，你是那个设计实验框架、让机器自己跑实验的人。他甚至说，过去两周他花在"meta-setup"上的精力，比花在 nanochat 代码本身还多。

这和 swyx 在同一天说的话形成了有趣的呼应。swyx 在 Latent Space 播客里提出了一个论断：2026年是 subagent 之年。他的逻辑是，几乎所有实际的多智能体问题，本质上都是 subagent 问题。你可以给 subagent 定义资源和合同，如果需要修改，你可以更新它，而 multiagent 系统做不到这一点。他还说，Cursor、Kimi、Claude、Cognition 这些工具，都在用 RL 训练 agent 去控制其他 agent。

说白了就是：别再想着搭一个平等协作的多 agent 网络了，想清楚谁是主、谁是子，层级清晰才能规模化。

这两个信号放在一起，我认为指向同一件事：AI 工程师的工作重心，正在从"写代码"转向"设计 agent 的工作流和约束边界"。这不是一个遥远的趋势，这是今天就在发生的事情。


好，我们来看第二个话题：Claude 的用户增长，以及 Anthropic 这段时间在产品层面的几个动作。

Anthropic 的 CPO Mike Krieger 前两天发了一条推文，说现在每天有超过一百万人注册 Claude。这个数字本身已经很惊人，但我更感兴趣的是，这背后发生了什么。

从产品侧来看，Claude Code 在同步推进。Thariq，也就是 Claude Code 团队的成员，昨天宣布了一个新功能：本地定时任务。你可以在 Claude Code 桌面版里设置定时任务，只要电脑开着，它就会按计划运行。他举的例子很实用——每隔几小时检查一次错误日志，然后自动给可操作的错误创建 PR。

这个功能看起来小，但它的意义在于：Claude Code 开始从"你主动调用它"变成"它主动帮你干活"。这是从工具到 agent 的关键一步。

另外，OpenAI 也在同一天宣布了 Codex for Open Source，给开源维护者提供 API 额度、六个月的 ChatGPT Pro 以及 Codex Security 访问权限。OpenAI 的 VP Kevin Weil 亲自转发，Peter Steinberger 也说这是他参与上线的第一个项目，反响热烈。

两家公司几乎同时在 coding agent 方向发力，而且都在往"自动化、持续运行"的方向走。这不是巧合，这是整个行业在往同一个方向收敛。

值得一提的是 Thariq 那条关于 PR 评论的推文，他说"在我们文化里，我们不说'我爱你'，我们说'我在你的 PR 里留了一条评论，那条评论本身就是一个可以直接发给 Claude Code 的 prompt'"。这条推文有一千五百多个赞。我觉得这种幽默背后有一个真实的信号：AI coding 工具已经深度嵌入到工程师的日常协作流程里了，不是偶尔用一下，而是变成了沟通语言本身的一部分。


第三个话题，我想聊一个更偏商业视角的观点，来自 Box 的 CEO Aaron Levie。

他引用了一段话，大意是：如果一项工作已经被外包出去了，这告诉你三件事。第一，公司已经接受这项工作可以在外部完成；第二，预算已经存在，可以被直接替换；第三，买家购买的是结果，不是过程。

他的结论是：用 AI 原生服务商替换现有外包合同，本质上是一次供应商替换，而不是一次组织重组。这让它变得容易得多。

这个视角我觉得非常实用。很多人在讨论 AI 对就业的冲击时，总是从宏观层面谈，说哪些岗位会消失。但 Levie 提供了一个更具操作性的框架：先看哪些工作已经被外包了，那些才是 AI agent 最容易切入的市场，因为采购决策已经做过一次了，你只需要让客户换一个供应商。

Greg Isenberg 在同一天也发了一条很长的分析，逻辑类似：下一波垂直 AI 公司，不是在卖"AI 工具"，而是在自动化生产那个客户真正在乎的"成品"。他举例说，不是"给房地产做个 AI 工具"，而是"做那个自动生成经纪人意见报告的 AI 员工"。先拥有那个输出物，再向外扩展，直到你拥有整个工作流。

两个人说的是同一件事，只是切入角度不同。一个从客户采购决策出发，一个从产品设计策略出发。放在一起，给想做垂直 AI 的创业者提供了一个相当清晰的路径图。


好，接下来是今天的快讯板块，我们快速过几条。

另外，Google Labs 发了一篇2026年前两个月的产品盘点，信息量很大。Flow 视频工具大更新、Jules agent 升级到 Gemini 3 Flash、NotebookLM 上线了手机端视频生成、还有 Project Genie——一个基于 DeepMind Genie 3 模型的早期研究原型，可以让用户创建和探索无限多样的虚拟世界，目前仅限美国 AI Ultra 订阅用户。两个月上线这么多东西，Google Labs 这次是认真的。

顺带一提，a16z 的 Justine Moore 观察到一个有意思的现象：旧金山街头，越来越多的人走路时抱着笔记本电脑，就是为了不中断正在跑的 agent 任务。她说这是我们进入 agent 时代最直观的信号之一。我觉得这个观察太准了，有点好笑，但也有点真实。

快速说一条，Lenny Rachitsky 转发了 Anthropic 劳动力市场影响报告里的一张图，评论说"我一直盯着这张图看，在想它对未来意味着什么"。这张图展示的是 AI 对不同职业的影响程度分布，白领工作集中在高影响区域。他的跟进评论是"园艺专业快要成为最热门的学科了"。有点玩笑，但确实值得认真想一想。

另外，Cursor 设计师 Ryo Lu 展示了他用 Cursor Cloud Agent 构建的 ryOS 新功能，包括 iCal 和仪表盘小组件。他说 agent 会自动截图、对比参考图、迭代直到达到80%的还原度，然后他再手动微调细节。这个工作流本身就是一个很好的"人机协作"示范。

还有一条，Hamel Husain 对最近流行的"语义搜索已死"论调做了一个很有价值的纠偏。他说很多人误解了这个说法。语义搜索并没有死，只是在某些场景下，基于文件的上下文检索效果更好。他提醒大家：在 Twitter 上看到"X 已死"这类断言，通常只意味着"在我们的具体场景里，我们没有使用 X"，不要过度解读。这种提醒在信息噪音很大的今天，其实挺必要的。

最后一条，关于提示词注入安全风险。有人发现，一次真实的攻击事件中，攻击者通过在 GitHub issue 标题里注入提示词，让一个 AI 分流机器人读取并执行了指令，最终拿到了 npm token。Linear 的产品负责人 Nan Yu 评论说："提示词注入加上 agentic commerce，等于无限印钞机"。这不是开玩笑，这是2026年真实存在的安全威胁，做 agent 的朋友们要重视。


好，今天就聊到这里。

如果说今天有一个最大的 takeaway，我觉得是这个：AI 工具的竞争，已经从"谁的模型更聪明"转向了"谁的 agent 工作流设计得更好"。Karpathy 在优化他的 agent 框架，Cursor 在推 Cloud Agent，Claude Code 在加定时任务，每个人都在往同一个方向走。

这意味着未来最值钱的能力，不是会用 AI，而是会设计 AI 的工作方式。
