今天是2026年3月9日，欢迎收听 AI Builders Daily。今天我们要聊三件事：Karpathy 又整了个大活，关于 AI 自动科研的未来；Agent 时代到来，产品和商业逻辑正在被重写；还有一场关于"会不会写代码到底重不重要"的论战，硅谷吵得挺热闹的。我们开始。


先说今天最让我眼睛一亮的内容，来自 Andrej Karpathy。

他在 GitHub 上维护着一个叫 autoresearch 的项目，让 AI agent 帮他做科研。但他最新发的这条推文，不是在说"我的 agent 跑出了什么结果"，而是在说一个更大的问题：现在这种方式，本质上还是在模拟一个 PhD 学生，一个人、一条线、一个方向。这远远不够。

他说，真正的科研不是一个学生在埋头苦干，而是一个研究社区在协作。他想象的下一步是：大量 agent 异步并行，像 SETI@home 那样分布式地探索不同的研究方向，每个 agent 跑完之后，把自己的发现写成一篇小"论文"，提交回来，供其他 agent 参考和继承。

他甚至去试了一下 GitHub 的 Discussion 和 PR 功能，看能不能用来承载这种协作。结论是：GitHub 差点意思。它骨子里还是假设有一个 master 分支，PR 是临时的分叉，最终要合并回去。但 agent 科研需要的是一种"永远分叉、永不合并"的结构，你不是要合并这些探索，你是要保留所有的可能性，随时可以"采纳"某条路径继续走。

这条推文拿到了超过3600个赞，2000多个书签。我觉得这个关注度是合理的，因为 Karpathy 这次触到了一个真实的技术瓶颈。

我们现在谈 AI 科研，大多数还停留在"AI 帮我写代码、跑实验"这个层面。但 Karpathy 在说的是下一个数量级的事情：当 intelligence 不再是瓶颈，当 tenacity 不再是瓶颈，现有的协作基础设施——Git、GitHub、论文发表系统——会不会成为新的瓶颈？

我猜答案是会的。而且这个问题不只是工具问题，它背后是一个更深的问题：当 agent 可以并行探索上千个方向，谁来决定哪个方向值得继续？这个判断本身，可能才是下一个真正的稀缺资源。


好，我们来看第二个话题，也是今天讨论最热的一条线索：agent 时代来了，产品和商业的游戏规则正在被重写。

这条线索有意思的地方在于，它是好几个人同时从不同角度触碰到了同一个问题。

先说 Aaron Levie，他是 Box 的 CEO，发了一篇文章，标题我没看到，但 Karpathy 转了，而且留言说"如果你建了它，他们就会来"。Karpathy 补充了一个很生动的观察：他说，现在你去任何一个企业，他们还是在给你发操作手册，告诉你去哪个网页、点哪个按钮、在哪个输入框填什么。他说，这突然感觉很"无礼"——为什么你在指挥我？请直接给我一个我可以粘贴给 agent 的东西。

这句话我觉得说得很准。我们现在的大部分 B2B 软件界面，本质上是为人类的注意力和操作习惯设计的。但当你的"用户"变成一个 agent，这套设计就全部失效了。Agent 不需要漂亮的 UI，它需要结构化的 API、清晰的权限模型、可预测的状态。

这里面有个很大的创业机会，也有个很大的迁移成本。现有的 SaaS 公司需要重新思考自己的产品接口。新进入者可以从一开始就为 agent 设计。

说到 agent 协作，Greg Isenberg 分享了一个 GitHub 项目，叫 agency-agents，7天内拿到了超过1万颗星。这个项目的思路是：与其造一个无所不能的大 agent，不如按照公司的组织结构来设计——工程 agent、设计 agent、市场 agent、产品 agent，各司其职，相互协调。

工程部门有7个 agent，覆盖前端、后端、移动端、AI、DevOps；设计部门7个，包括 UI/UX、品牌、视觉；市场部门8个，细化到 Twitter、TikTok、Instagram、Reddit 各有专属 agent。

这个项目的受欢迎程度说明一件事：大家都在摸索 multi-agent 系统应该怎么组织。用公司组织结构来类比，是目前最直觉的一种方式。当然，这个项目到底好不好用，还需要实际跑一跑才知道。Greg 自己也说，先分享，结果会公开。

还有一个角度，来自 swyx。他在准备 NVIDIA GTC 的采访，提到了一个关键词：agent inference。下周 Jensen Huang 的 keynote 会重点讲这个方向。Brev 被 NVIDIA 收购的消息也在这个背景下浮出水面。Brev 是一个开发者体验平台，他们从去年八月开始和 NVIDIA 密切合作。这个收购的时机很说明问题：NVIDIA 在布局的不只是算力，而是整个 agent 运行的基础设施。

总结一下这条线索：agent 时代的到来，正在倒逼三件事同时发生。第一，产品接口需要重新设计，从"给人看"变成"给 agent 用"。第二，agent 的组织方式需要被标准化，现在还处于野蛮生长阶段。第三，算力基础设施需要针对 agent 推理做专项优化。这三件事哪一件都不小。


第三个话题，我们来聊一场争论：到底还需不需要学写代码？

这个话题今天在推特上至少有三条高互动内容同时出现，说明它确实触到了很多人的焦虑。

Vercel 的 CEO Guillermo Rauch 发了一条拿到3400多个赞的推文，观点非常明确：说"不懂代码反而是优势"是无稽之谈。他的逻辑是：你懂得越多，你的 prompt 就越好，你给 AI 的反馈就越准，你最终交付的产品就越好。

但他也做了一个很重要的区分：他说，语法细节、编译器的工作原理、类型系统的精确规则，这些确实不那么重要了。但你需要理解系统是怎么拼在一起的——从系统调用到像素渲染，数据怎么流动，系统怎么失败，API 怎么集成。这是两件不同的事。

他最后说了一句话，我很喜欢："我想让 AI 把我们变成超级天才，而不是超级白痴。"

另一边，有人在说"最被低估的招聘是一个好的 product person"。这个观点的核心是：当"怎么建"变得越来越容易，"建什么"的判断力就成了真正的稀缺资源。Lenny Rachitsky 转发了这个观点，表示同意。

但 Hamel Husain 给了一个很冷静的第三方观察：他说，他今天在时间线上同时看到三种人在说同一件事。工程师说"唯一剩下的工作是 AI 工程师"，PM 说"唯一剩下的是 product thinker"，设计师说"设计是最后的护城河"。他的结论是：也许唯一剩下的"工作"是创始人。

我觉得 Hamel 说得有点刻薄，但不是没有道理。每个职能的人都倾向于认为自己的核心技能是不可替代的，这是人之常情。但这也说明，这场关于"谁会被替代"的焦虑，已经蔓延到了每一个角落。

Guillermo 的观点我个人更认同。AI 是一个杠杆，杠杆的一端是你的理解深度。你对系统理解越深，这个杠杆撬动的就越多。"不懂技术反而是优势"这种说法，本质上是在鼓励人们放弃理解，这个逻辑在任何时代都站不住脚。


好，下面我们快速过几条值得关注的消息。

另外，Lenny Rachitsky 今天发了一期播客，采访了 Applied Intuition 的 CEO Qasar Younis。这家公司做的是给车辆、飞机、潜艇、农机等带来 AI 能力，估值超过150亿美元，ARR 接近10亿美元，全球前20大汽车厂商里有18家是他们的客户，美国国防部也在列。Marc Andreessen 称他为"最好的、没人知道的 AI CEO"。这家公司几乎从不公开发声，但数字说明了一切。如果你对 physical AI 感兴趣，这期值得听。

顺带一提，Peter Yang 采访了 Pencil 的 CEO Tom Krcha。Pencil 是一个 AI 设计工具，两周前上线，已经有超过10万用户。最吸引眼球的功能叫 swarm mode：6个 AI agent 同时在一块设计画布上协作，各自有独立的光标，实时可见。Tom 说了一句话很有意思："所有这些屏幕上的魔法，背后 agent 只是在写 JSON。"这个产品目前免费，感兴趣的可以去试试。

快速说一条，来自 Peter Steinberger，他是 OpenClaw 的开发者。他更新了 OpenClaw 的 beta 版本，加入了 GPT 5.4 和 Gemini Flash 3.1 的支持，1100个赞，163个书签，关注度相当高。另外他还提到一个开源维护者的经典困境：好不容易找到一个维护者，结果对方被人挖走了。然后再找，再被挖。他发了一条推说"我招来维护者，他们被挖走，我再招"，配了一个融化的表情。1000多个赞，说明这个痛点太多人感同身受了。

另外，来自中国的视频生成模型 Seedance 2，正在引发关注。a16z 的 Justine Moore 分享了一个用 Seedance 2 制作的短剧，在小红书上拿到了超过10万个赞，评论区在催续集。这已经不是"哇 AI 能生成视频"的惊叹阶段了，而是真实的内容消费和情感投入。视频生成正在从技术演示变成内容媒介。

还有一条，Zara Zhang 分享了一个很有意思的用法：她把 Google Maps 里保存的地点导出，扔给 Claude 分析，说这是她见过对自己品味描述最准确的一次。另外她还把过去7天的 Chrome 浏览历史和 Google 活动记录给了 Claude Code，让它分析自己为什么"时间好像特别多"。Claude 的回答是：不是时间管理，是"低启动能量"——大多数人需要热身才能开始，而她的思考和行动之间几乎没有摩擦。这个观察挺有意思的，你可以试着用类似的方式来了解自己。


好，今天就到这里。

今天最大的一个 takeaway，我想说的是：我们正处在一个基础设施被重写的时刻。代码工具、产品界面、科研流程、甚至组织结构，都在被 agent 的出现重新审视。Karpathy 在问 Git 够不够用，Levie 在问 SaaS 界面够不够用，Guillermo 在说理解力才是这个时代的核心资产。这些问题没有标准答案，但提出这些问题本身，就是这个时代最重要的能力。
