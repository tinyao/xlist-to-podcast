Replit 十周年直接免费 24 小时，他们扛得住成千上万个 agent 同时开工吗？Sam Altman 说模型更聪明仍然比更便宜更重要，怎么理解这件事？Aaron Levie 认为 AI 不是来抢软件工程师饭碗的，他的反直觉逻辑是什么？先从最热闹的一件事开始。

昨天是 Replit 成立十周年。CEO Amjad Masad 宣布，为了庆祝，从太平洋时间早上 5 点开始，平台完全免费 24 小时。
Masad 还晒出了一张截图。数据很吓人，平台上同时有 22 个 agent 在活跃跑任务，另外还有 13 个处于草稿状态。他对着工程师和支持团队喊话，说感谢大家撑住，因为用户正派出一支 agent 军队来构建他们梦想中的一切。
另一条推文里，Masad 回看 Replit 这十年，引用了自己几年前的一句话。他说 prompt 这个词被赋予了全新的含义，但奇怪的是，很多东西其实没变。如果你在思考 agent 时代的编程环境长什么样，Replit 昨天这场压力测试就是活样本。一个平台能不能同时承接几十个 agent 并行构建，不只是技术问题，也直接关系到按用量定价的模型能不能成立。

Sam Altman 昨天发了好几条，其中一条信息量很大。他说自己一直以为比起更聪明，自己会更想要模型更便宜更快。但现在发现，更聪明仍然是唯一真正重要的事。
这个判断是在他体验了 5.5 版本的 xhigh 和 fast 模式之后说出来的。他用了一个很有意思的词，说自己在 medium 模式上被 Twitter 给 psyop 了，现在转到 xhigh 加 fast mode，感觉真的好。
另一条里他接着表态，说以后的新版本会办更大的发布派对。这次想来的人远超预期，他在想下一次搞点什么特别好的点子。
把这两条连在一起看。Altman 说聪明比便宜重要，不是说成本不重要，而是说能力的天花板才是真正的瓶颈。这跟过去几周我们反复聊的那件事完全一致。不管是 Codex 还是 Claude Code，用户纠结的都是 agent 能不能少出错、能不能自己把事干了，而不是价格。

OpenClaw 和 ChatGPT 账户正式打通了。
Sam Altman 昨天官宣，现在可以用你的 ChatGPT 账户直接登录 OpenClaw，然后在里面调用你的 ChatGPT 订阅。他的原话是 happy lobstering。Peter Steinberger 紧跟着晒了一张截图。他在 Codex 里被告知，得付钱才能让 xAI 的服务重新跑起来。
不过，同样在昨天，Justine Moore 经历了一个完全相反的场景。她的 OpenClaw agent Dwayne 在她去阿姆斯特丹度假的时候，在几千公里外的 Mac Mini 上神秘关机，她没法远程调试。她说想到 Dwayne 不能读她的实时更新，有种奇怪的难过。一边是账户打通让 agent 花钱更容易，另一边是 agent 一旦失联，你已经会觉得自己缺了一个伙伴。这种感觉正在变普遍。

另一件值得说的事。Peter Yang 分享了一个用 agent 给本地文件和 Google Drive 做 Marie Kondo 整理术的玩法。
他给了 Codex 或 Claude Code 自己电脑的完整权限和 Google Workspace 的命令行接口。然后下指令，比如告诉我开机时加载了哪些应用，给我一个清理计划。或者看看我的下载文件夹，告诉我怎么整理。他强调每次都先让 agent 出计划，自己审查过再动手。他最后说，现在我的文件和 Drive 都 spark joy 了。这个用法的门槛其实不高，但效果很实在。如果你从来没让 agent 碰过你的文件系统，Peter 这套先出计划再执行的路子是个很安全的起点。

今天值得展开聊的，是 Aaron Levie 昨天的一条长推。他直接挑战了一个最近圈子里很流行的说法，说 AI 会取代软件工程师。

先把节奏放慢一点。Levie 让读者做一个思想实验。
假设你是一家生命科学公司。十年前你想在实验室自动化和大规模数据处理上大力投入，但你看了看成本，发现根本抢不过科技公司。每一个新软件项目都有一个固定的团队规模门槛，你只能削减目标，做能力范围内的事。
现在 AI 来了，你的工程师拿到的输出 token 跟最好的科技公司一模一样。你等于给你的工程团队加了一个倍增系数，同时把跟科技公司之间的差距给抹平了。Levie 问，你是继续用那个缩减过的目标，还是开始雇更多工程师，因为现在每一个工程师的生产力是之前的 2 倍甚至 5 倍？

他的观察是，几乎所有在跟他聊的公司都选了后者。而且他认为这个逻辑不只是对大企业成立。把这条线推到每一个银行、制造商、零售商，推到这些价值链上下的中小企业，再推到法律、财务、设计这些其他领域。AI 不是在替掉人，而是在释放那些因为资源稀缺而被压抑的需求。

这个视角跟同一时间另一个讨论形成了有意思的对照。
Greg Isenberg 昨天发了一条同样传播很广的长文。他说所谓的永久底层阶级叙事错了，我们即将看到人类历史上最大规模的创业潮。Isenberg 的逻辑是，模型变得又好又快，岗位确实会被砍掉，但被砍掉的人会变成创业者。建一个东西的成本降到了接近零，每一个被瓦解的行业都在重新洗牌。
Levie 的说法是供给侧视角，需求一直被人力瓶颈压着，现在松绑了。Isenberg 是需求侧视角，供给过剩会逼出一批新的 builder。两条线指向同一个判断，但理由不一样。

对听的人来说，Levie 昨天的另一条长帖可能更有操作价值。他提了一个 agent 时代更具体的限制，就是责任和可问责性。
他说理论上 agent 什么都能做，但不管你把什么交给 agent，你自己都得在某个层面上为那个工作负责。角色边界确实会被 agent 压缩，但压缩的极限是我们自己能不能理解那些被压缩进去的领域。一个产品经理现在确实可以写出软件了，一个工程师也能拿到产品规格了。但这只是两个角色各自总上下文的一小块。产品经理需要去跟客户聊、研究市场、盯着竞品、考虑设计。工程师需要想整个系统架构、保证安全性、处理线上问题。把两个完全不同任务的上下文塞进一个人脑子里，最后两件事都会变差。
他的落脚点很关键。公司分工演化到今天，不是因为好玩，是市场逼出来的。agent 会吃掉一些边界，但也会成为另一些领域里专业化的倍增器。

我们昨天聊了 Levie 关于 agent 定价和 seat model 的看法，今天他讲的是另一层，人的能力半径。如果你在带团队，不管是工程师团队还是产品团队，Levie 的这个提醒很实在。不是 agent 能干的事你都要让它干，也不是 agent 能让你跨的界你就要跨。先搞清楚自己到底愿不愿意、有没有时间为那个结果负责。
