Peekaboo 3.0 正式发布了，这是一个让 AI 直接操控 macOS 桌面的工具。
它的作者 Peter Steinberger 昨天宣布了这个大版本，说是 2.0 之后最大的一次更新。
他本人就是 OpenClaw 的创始人，在 agent 圈子里很活跃。
这个版本主打“动作优先”的电脑操控，把截图和界面识别统一到了一起。
同时清理了 CLI 和 MCP 之间的 JSON 通信格式，让 agent 调用更稳定。
Peter 自己说，他去年就开始做这个工具，但当时的模型根本不够聪明。
现在模型能力上来了，工具才能真正跑起来。

如果你在做桌面端的 agent 应用，Peekaboo 3.0 的架构思路值得看一眼。
它本质上是在解决一个很具体的问题：怎么让 AI 像人一样看屏幕、点按钮。
这个方向一旦成熟，大量重复性的桌面操作会被 agent 接管。

另一件值得说的事。
昨天圈子里传开了一篇技术文章，叫“GPT the Hard Way”。
swyx 转发了这篇文章，给了非常高的评价。
他说这个分量，跟当年 Kelsey Hightower 写的“Kubernetes The Hard Way”是一个级别的。
他的原话是，大部分时候他主张“即时学习”，但这一次，你得“以防万一”。
换句话说，这不是一篇随便翻翻的科普，而是一篇值得所有 AI 工程师从头啃一遍的底层原理拆解。

文章的作者是 Ahmad Osman，里面详细拆解了 GPT 类模型的内部机制。
从注意力头到前向传播，每一步都手把手讲清楚。
swyx 的判断是，在 agent 和模型能力快速膨胀的今天，理解底层反而变成了一种稀缺能力。
因为大部分人都习惯了直接调 API，出了问题只能猜。
而真正能把模型当工程系统来调试的人，会越来越值钱。

如果你正在带 AI 工程团队，这篇可以放进团队的必读清单。
不需要每个人都能手写反向传播，但至少要知道模型在“想”什么。

Sam Altman 昨天发了一连串推文，其中一条把 GPT-5.5 叫做“自闭症天才”。
他说这个模型的命名品味非常奇怪，但能力极强。
他用了一个很短的补充句：“自闭症天才级别的智能。”
这个描述在圈子里引发了大量讨论。
有人觉得这是对自闭症群体的不尊重，也有人认为他只是在形容模型那种极度专注、不擅长社交的特征。

抛开措辞争议不谈，Sam 想表达的核心意思是，GPT-5.5 在某些认知维度上已经超过了正常人。
但它在“人情世故”上仍然很笨拙。
这跟很多工程师的实际体验是一致的——模型能解复杂的数学题，却在简单的对话中偶尔说出完全不合时宜的话。

Sam 还发了一条更生活化的推文。
他说自己早上丢了一堆 Codex 任务，然后带孩子在外面晒太阳。
等孩子午睡时回来，发现所有任务都跑完了。
他说这种体验让他对未来非常乐观。
这听起来像 CEO 的日常分享，但背后是一个真实的信号：agent 的可靠性已经达到了可以“丢下不管”的程度。
至少在他自己的使用场景里，任务完成率足够高。

换个方向。
Anthropic 的 Alex Albert 昨天转发了一组数据，来自安全评估机构 METR。
他们测试了 Claude Mythos Preview 的一个早期版本，时间窗口是今年三月。
结论是，这个模型在 METR 的任务组上，完成时间的中位数超过了 16 个小时。
用另一个更直观的指标看，在 80% 成功率的基准线上，它的持续时间是第二名模型的两倍以上。

这是什么概念？
就是 agent 可以独立工作的时间长度，在快速拉长。
以前我们讨论 agent，更多是“能不能做对”。
现在竞争维度多了一个：“它能连续做多久而不跑偏”。
Anthropic 在这一点上暂时领先。
如果你在做需要长时间自主运行的产品，比如代码重构、数据分析流水线，这个指标比单纯的准确率更值得关注。

Zara Zhang 昨天用 OpenAI 的 Realtime 2 API，做了一个浏览器扩展。
她管它叫“YouTube 实时助手”。
这个 agent 能跟你一起看视频，你随时可以用语音问它刚才说了什么。
最让她惊讶的一点是，它可以区分 YouTube 的音频流和你的声音。
不会把视频里的对话当成指令，也不会在你没叫它的时候插嘴。

这个细节很关键。
之前的语音交互，最大的痛点就是“谁在说话”这个问题解决不好。
背景音、视频声、旁边的人，全部混在一起。
现在模型能自己判断哪个声音是发给它的，这个进步比语音识别的准确率提升更重要。
如果你在做语音相关的产品，Realtime 2 的音频分离能力，值得专门测试一下。

今天值得展开聊的，是这件事。

Aaron Levie 昨天写了一篇长推文，提出了一个很多创业者还没注意到的问题。
Token 预算，正在成为大企业里的真实议题。
他是 Box 的 CEO，对 enterprise 市场的嗅觉一向很准。
他说，随着 agent 能执行越来越长时间的任务，消耗的算力也在暴涨。
企业内部的 token 分配，正在变成一件需要严肃管理的事。

他的逻辑链很清晰。
公司会花大量时间决定花多少钱在人才、营销、设备、甚至午餐上。
Token 不会例外。
而且 token 的管理难度更大。
因为你不希望月底发现，预算全被一些低价值的任务烧光了。
真正重要的任务反而没钱跑。

更大的麻烦在于可视化。
在大型组织里，agent 的工作流是层层嵌套的。
你很难从中心视角看清楚，到底哪些 agent 在消耗 token，消耗在了什么地方。
Aaron 判断，这件事会催生一个全新的软件品类。
专门用来做 agent 级别的资源分配和预算控制。
他甚至说，这可能是一个创业机会。

这个视角跟过去两周我们反复聊的“分发是护城河”、“数据 refinery”都不在一个层面上。
它跳出了“怎么建产品”的阶段，直接进入了“怎么管 agent”的阶段。
如果你正在做面向企业的 AI 产品，token 消耗的透明度，可能会变成一个关键卖点。
财务总监和 CTO 会想知道，这十万美金的 API 账单，到底花在了哪里。

对听众来说，这个问题可以拿来做一个小预判。
你现在用的 agent 工具，有没有给你一个清晰的 token 消耗视图？
如果没有，未来半年内，大概率会出现专门的解决方案。
而谁先解决这个问题，谁就能在企业市场上拿到一张入场券。
