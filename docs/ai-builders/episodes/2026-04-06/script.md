Anthropic 突然开始锁死第三方编排层，要求开发者自带算力，开源项目会怎么应对？Karpathy 说别让 AI 偷偷记住你，你应该拥有一本可被 Agent 翻阅的个人 Wiki。OpenAI Codex 团队透露他们几乎不写规格，设计师写的代码比工程师还多。先从最让工程师猝醒的那件事开始。

Claude API 昨晚开始系统性地阻止第三方 harness 调用。具体来说，当你在命令行里通过 --append-system-prompt 这类参数，把 Claude 接入 OpenClaw 等第三方编排工具时，现在会直接收到 400 错误。
OpenClaw 的开发者 Peter Steinberger 最先踩了这个坑。他当时在测试自己工具的 GPT 5.4 适配，结果 Anthropic 返回的信息很明确：第三方应用现在已经从你的额外用量里扣，不再走计划内的额度。说白了，就是“请自带 API 额度，别再用中间层白嫖”。
这件事之所以炸，是因为它直接影响了一大批 agent 工具。OpenClaw、Codex 的 CLI 封装、甚至一些个人笔记里的 Claude 集成，全都面临被切断。 Steinberger 的应对方式是立刻在 OpenClaw 的开发频道里放出了 GPT 5.4 的升级版本，并且开始用 OpenClaw 自己来测试自己，他在做一个编排器 agent——能自动提需求、验证结果、失败了再派子 agent 去修。这可以绕开 Anthropic 的限制，把调用的底层模型换成别的。
有意思的是，圈内对 Anthropic 此举的看法比较分裂。前字节工程师、退休后一直在密集用 AI 做产品的郭宇，昨天也发了一条推文。他的判断很直接：如果 Anthropic 没法快速把模型成本降下来，在 harness 时代就很难跟住。他把 Anthropic 的思路类比成中国公司——期望所有人用他们的产品，而不是模型。
这其实是一个挺深的博弈。一边是 Anthropic 希望护住自己的产品层，另一边是整个生态正无可逆转地走向开放编排。如果你正在用 Claude Code 或任何三方客户端做生产级的 agent，今天的第一件事就是检查一下连接还通不通，以及计算一下切换到自带额度的成本。

同一时间，Replit 的 iOS 应用经历了一次诡异的“被封仍登顶”。CEO Amjad Masad 说，他们的更新突然被苹果阻止，但应用靠着自然增长，居然又冲到了 App Store 分类第一。
Replit 在苹果生态里已经四年了，这次没有任何预兆就被卡住了。Masad 的态度挺克制的，更像是把这事当成一个奇怪的数据点抛出来。但这恰好暴露了一个现实：哪怕你的增长完全不受制于更新，平台的一次行政操作就能让你动弹不得。如果你正在做面向移动端的 AI 原生应用，苹果的审核作为隐形风险，或许应该早早放进你的决策模型里。

再说一条非常宝贵的一手信息。Peter Yang 昨天放出了和 OpenAI Codex 团队的深度访谈。代号 Alex 和 Romain 的两位成员几乎是毫无保留地分享了他们的内部打法。
最反直觉的点，是他们不写规格。整个团队写出来的东西，大概就是十行 bullet point。而他们的设计师现在写的代码，比六个月前工程师写的还多。团队里有一条原则是“决定越纯粹，房间里需要的人就越少”。
这件事的冲击力在于，它可能彻底改变职能边界。Linear 的产品负责人 Nan Yu 昨天也推了一句话，说得更前卫——未来没有设计师和工程师，只有“设计工程师”。
如果你自己的团队里，设计师还只是出图，工程师还等着 PRD，这个访谈或许值得拿出来跟团队聊一聊。你们的设计师开始碰编辑器了吗？

昨天同样值得关注的一个数据点，来自 Lenny Rachitsky 和 Anthropic 的增长负责人 Amol Avasare。Lenny 在播客里爆了一个惊人的数字：Anthropic 的 ARR 从一年前的 10 亿美元，猛增到现在的 190 亿。仅仅二月这一个月，他们就做出了 60 亿的新增 ARR。作为对比，Palantir 和 Atlassian 走到 50 亿 ARR 花了十五到二十年。Anthropic 现在一个月的增量已经超过这个数。
这笔账不只是业绩好看。它解释了为什么 Anthropic 有底气在前面那一步锁死第三方访问——因为增长的飞轮已经成形了。同时，Amol 还在播客里重点提到了“激活”这个词，他认为这是 AI 增长里杠杆效应最强的环节。Lenny 这期节目的链接我会放在 shownotes 里，很适合在路上听完。

Karpathy 昨天在 X 上解读了一个叫 Farzapedia 的项目。独立开发者 Farza 用自己的 2500 条日记、笔记和 iMessage 记录，让一个 LLM 自动生成了一本包含 400 个条目的个人 Wikipedia。他把它当作自己 Agent 的知识底座——给 Claude Code 读取，用来辅助设计、写文案、甚至在创建新项目时自动把新旧灵感关联起来。
Karpathy 看完之后发了一篇很长的分析，他把它总结成一个词：File over app。也就是文件胜于应用。他给出了四条原则：你的记忆必须是显式的，你可以翻看和修改，而不是藏在某个模型的黑箱里；数据必须是你自己的，存在你本地的文件系统上；格式必须是通用的，比如图片和 Markdown，这样任何 Agent 或工具都能直接读取；最后，你可以自由选择接哪个 AI 来处理这些文件，永远不必被一家供应商锁定。
这其实是对“AI 越用越懂我”这种模糊叙事的直接反击。有意思的是，同一天，Mckay Wrigley 和 GREG ISENBERG 都在不约而同地推 Obsidian 加 Claude Code 的组合。Isenberg 甚至开了一个免费教程，教你怎么把 Obsidian 的本地 vault 变成 Agent 的长期记忆。而 Obsidian 的创始人 kepano 则调侃了一句：他们的公司只有 7 个全职员工，完全远程，没有例会，产品哲学全写在宣言里。这种小而美的工具，恰好构成了 Karpathy 说的那套文件的基石。
对在听这档播客的我们来说，启发其实很具体。你现在的核心知识、你总结的方法论、你的审美偏好，究竟是锁在某个云端笔记的专有格式里，还是躺在你自己可以随意迁移的 Markdown 文件夹里？当你的 AI Agent 需要调用你的全部经验去完成一项任务时，它看到的是一堆零散的聊天记录，还是一本结构化、可被你随时审计的个人 Wiki？郭宇昨天凌晨吐槽 Codex 总爱说“如果你要”，气得在 X 上骂人。如果他的 Agent 早就有了一本他亲手设计的个人 Wiki，也许它根本不需要再问那么多废话。一个真正了解你的 Agent，是从你自己的知识库里长出来的，而不是从通用语料里猜出来的。
