AI 领域的 agent 创业手册，昨天出现了可能是今年最详细的版本。Lenny 和 Dan Shipper 对赌十个未来预言，其中包括一个让 SaaS 创业者松一口气的判断。OpenClaw 开始给自己减肥，但另一个趋势让开发者有点烦。先从昨天持续发酵的一个更大判断说起。

高盛 CEO 明确站到了 AI 就业悲观论的反面。
Box 的 CEO Aaron Levie 转发了这条消息，并附上了一段自己的长分析。
他的核心逻辑是，世界不是静态的。如果我们回到几十年前，看到当时的生产效率，肯定会觉得那时候的人已经把活儿都干完了，不会有新工作了。但现实是，每次效率提升之后，市场对产品和服务的要求也跟着水涨船高。

自动化帮我们省出来的精力，没有变成更便宜但一模一样的交付物。总有公司会先用自动化去做更多事，把竞争门槛推高。然后所有人都得跟上。
结果就是，财务分析师出更全面的报告，律师提供更深度的建议，医疗健康领域能负担得起更细致的检测。需求没有消失，只是被升级了。

Aaron 说，当你不再认为世界是静态的，你对 AI 和就业的看法会完全不一样。
这个视角和昨天 Dan Shipper 的一个预测正好形成对话。Dan 对 Lenny 说，AI 不会带来就业末日，但人必须跟着模型一起进化。

Lenny 昨天发布了和 Every 联合创始人 Dan Shipper 的播客下半场。
他开了一份十个预测的清单，准备一年后回头复盘。
我挑几个立刻能用得上的判断来说。

第一个判断。Dan 说他现在几乎所有工作都在 Codex 里完成。写文档、查邮件、做研究，全部在那个 agent 的浏览器里操作。他说未来的工作界面不是把 AI 装进 SaaS 工具，而是反过来，在 Codex 或 Claude Code 这类 agent 的环境里调取 SaaS 工具。

第二个判断和自动化有关。Dan 的原话是，自动化是个谎言。他们团队极其 AI 化，但公司人数反而翻了一倍。原因很简单，每一条自动化流程上面，都需要一个人盯着它别翻车。这也是为什么他看空那些单纯依赖基准测试的乐观判断——基准测试只衡量已经被框好的问题，但真实世界里永远有更高一层的框架要处理。

第三个判断，PM 和设计师会成为赢家。Dan 举了个例子，他们团队里一位前 Axios 的 PM，现在用 AI 的速度比谁都猛。Dan 说，当写代码这件事被 AI 接过去之后，剩下唯一重要的事就是搞清楚该做什么、以及做出来好不好。这正是 PM 和设计师的基本功。设计师尤其被解放了——以前做出来的精美交互还要求着工程师实现，现在不用交接，自己就能把东西搭出来。

第四个判断可能会让很多人松一口气。Dan 说他看好 SaaS 股票。
原因很具体。当用户用自己的 agent 去访问 SaaS 产品时，token 成本是用户自担的，不是 SaaS 公司扛。这会保住 SaaS 公司的利润率。另外，agent 也需要自己的账号和席位，大量 agent 会以高频率使用这些服务，这可能创造新一轮的需求。

还有一个关于组织形态的预测。Dan 说他之前以为每个员工都会拥有自己的个人工作 agent，但现在完全推翻了这个想法。他发现 agent 需要有人在乎它、维护它。一旦某个员工懒得打理自己的 agent，它就废了。所以赢家更可能是一个公司里有一个超级 agent，由一位 AI 熟练的工程师全职维护，全公司一起用。Shopify 内部已经在跑这种模式了。

Dan 在最后加了一段关于写作的判断，也很直接。他说大家以后会读到更多 AI 生成的内容，而且你还会挺喜欢的。日常的内部文档、策略报告，AI 写得比大多数人都好。人类的独特价值在于利用模型产出的冰冷能力，加上现场的具体情境，做出有意思的新东西。

同一时间，Peter Yang 也发了一期和独立开发者 Ryan Carson 的访谈。
Ryan 是一个人用 AI agent 跑整家公司。
Peter 说这次访谈里最大的启发是一句话：以前我们说先做 MVP，别浪费时间搭系统。现在反过来了，你必须先把文档和系统搭好。Ryan 把技能文件写好、文档配齐，再塞进定时任务里，一个人就撬动了十个人的产出。

Ryan 把 OpenClaw 当 AI 参谋长，管邮件和销售拓展。
把 Codex 和 Devin 当工程团队，他睡觉的时候 agent 帮他提交功能。
他还特别强调了一件事：把你的 agent 当真正的员工对待。给它一个真实的邮箱、日历权限和 GitHub 账号。

这两期访谈放在一起看，指向同一个方向。AI 原生的生产力，不是靠一个更聪明的模型就能解锁的。它需要你先把上下文喂进去，把系统搭起来，把 agent 当成一个有权限、有记忆的团队成员。

昨天有一条推文被收藏了上千次，来自 Greg Isenberg。
他写了一整套垂直 AI agent 的创业手册，从零到一，步骤极细。
这不是那种讲趋势的文章，是给你一张可以直接拿去执行的路线图。

Greg 的第一步是反直觉的。他说，先别急着写代码。去找一个无聊行业里最疼的工作流，然后找十个每天重复这件苦活的人，把他们的每一步都画出来。用了什么工具、填了哪个表格、打了什么电话，全记下来。然后你自己先手动跑一遍这个流程。在你变成 agent 之前，先去理解人是怎么干的，把那些最诡异的边缘案例找出来，用结构化的 markdown 写进 Obsidian。

第二步才是搭 agent 栈。Greg 推荐用 Hermes 做编排层，Obsidian 当知识库，Composio 处理跨应用的认证。前三个技能只解决最核心的痛点。不是一口气做一个全知全能的 agent，是先做三件事，让它跑起来。

然后他用了一个很关键的策略。把前五家客户免费拉进来，观察他们真正用 agent 做了什么。他说客户一定会让你意外。你以为他们需要 A，结果他们会告诉你隐藏需求是 B。

定价上 Greg 也给了非常具体的建议。按结果收费，而不是按人头。每续签一份租约、每处理一笔理赔、每找到一个合格候选人，按这个收费。这样 ROI 对话只需要十秒钟。

他还说大多数 agent 创业公司不应该融资。利润太好了，没必要分出去。同时他用 OpenRouter 来精准分配模型——GPT 5.5 处理工具调用，开源模型跑轻量任务，对应任务分配对应模型，利润直接翻倍。

最后他提了一个最有价值的护城河概念。让 agent 每次完成任务之后，往自己的记忆里写一段记录。跑得越久，积累的上下文越多，agent 就越聪明。竞对可以克隆你的产品，但没法克隆六个月的时间里一个 agent 在真实任务里积累的决策记忆。

Greg 的总结很接地气。一个 agent 是 side project，五个 agent 跑在五家客户那里，就是一个生意。每个跑在自己的环境里，你一天检查一次就够了。

这条推文里没有大话，没有范式转移，就是一条一条可以做的事。
如果你正在想怎么进垂直 SaaS 或 agent 赛道，这条推文值得当成 check list 来读。

再说几条快讯。

OpenClaw 的依赖清理还在继续。Peter Steinberger 昨天宣布移除了 Sharp 和 Jimp 两个图像处理库，换成了一个叫 photon 的 WebAssembly 模块，用编译后的 Rust 跑图像处理。体积从 140MB 跌到 2MB。

不过 Peter 也表达了一点新的烦恼。他说现在最烦的是，有些 CLI 工具会在不打招呼的情况下，自动往他的系统里装新的技能文件。他专门写了一个 skill，用来扫描哪些技能文件写得又臭又长——有些人在技能描述里写了整整一本书，这些内容每次都会塞进 agent 的上下文窗口。如果你的 agent 最近响应变慢了，查一下是不是 skill 文件本身太长了。

Google AI Studio 公布了一个数据。上周他们上线了直接在浏览器里构建原生安卓应用的功能，到现在用户已经创建了超过 25 万个应用。Logan Kilpatrick 说，这 25 万人里绝大多数以前从来没写过安卓应用。现在完全不用写代码就能做到了。

Justine Moore 分享了一个案例。亚马逊的原创剧《House of David》首季吸引了接近五千万观众，冲上了美国排行榜第一。剧集制作人 Jon Erwin 说，没有 AI 的帮助，这部片子根本拍不出来。Justine 出了一期完整的访谈，她的判断是，几年之内，每一部电影和剧集都会用 AI 来提升质量、降低成本。
