今天是2026年3月14日，欢迎收听 AI Builders Daily。今天我们要聊的关键词是：Claude Code 的周五大礼包、郭宇用纯 Qwen 跑了一晚上的游戏公司实验、还有 Chrome 146 的一个更新，正在悄悄改变 AI agent 操控浏览器的方式。我们开始。

先说今天最集中的一批消息，来自 Anthropic，而且全部集中在昨天下午。

Claude Opus 4.6 和 Sonnet 4.6 的一百万 token context window，正式 GA 了。不是 beta，不是限量邀请，是直接面向所有人全面开放。

对于 Max、Team 和 Enterprise 的订阅用户来说，一百万 context 的 Opus 4.6 现在直接成为 Claude Code 的默认模型。Boris Cherny 在推特上宣布，然后补了一句："我个人过去几个月一直只用一百万 context，非常好用。"Thariq 也说，自从用了一百万 context，他发现自己新开 session 的频率大幅降低了，因为 compaction 少了很多，session 可以跑很久。

API 层面有几个重要变化值得划重点：不再有长 context 的额外加价了，不需要 beta header，而且单次请求最多可以塞六百张图片进去。

Pro 和 Sonnet 用户可以用 /extra-usage 选择性开启。

这个更新的实际意义是什么？我觉得有两层。第一层很直接：你在做一个大型代码库的时候，不需要担心 context 被压缩，历史不会丢失，Claude 在整个会话里保持对整个项目的完整理解。第二层更深一点：一百万 token 大约等于七十五万个英文单词，或者一千个代码文件。当这个成为默认，而不是付费选项，这说明 Anthropic 认为长 context 已经是基础能力了，不是溢价功能。

但 1M context GA 只是周五下午这批更新的一条。

另一个让我感到有点意外的是：Claude Code 现在可以从手机上远程启动。Boris Cherny 转发了一个视频演示，标题是 "Remote Control"——你可以在 Claude Code 的移动端 App 里，直接在你的笔记本上 spawn 一个新的 session，然后在手机上远程操控它跑任务。这个功能目前对 Max、Team 和 Enterprise 用户开放，版本要求 2.1.74 以上，需要先在手机上配好 GitHub。

你想一想这个场景：你在通勤，或者在健身房，突然想让 Claude Code 跑一个任务，以前你只能等回家开电脑，现在掏出手机就能把任务塞进去，让笔记本在家帮你跑着。Boris 说"第一次用的时候直接惊了"。这个功能的互动量很高，八百多个点赞，将近五百个收藏，说明很多人在认真想这个工作流。

同一波更新里还有 Voice Mode 的 100% 全量推送。Boris 发推说正式向所有用户开放了，Anthropic 的 Mobile PM Robert Bye 分享了他自己的用法：对着 Claude Code 说五分钟话，直接描述一个想法，然后让 Claude 帮你整理成结构清晰的文档，顺便挑战你的逻辑。这个用法比打字输入 prompt 自然很多，也比用 /btw 插话更适合"我有一堆脑子里的东西想梳理"这类场景。

还有一个收藏量超高的推文，来自 Anthropic 工程师 cat，她分享了三个 Claude Code 快捷键：第一，`!` 前缀可以直接在 Claude 对话里执行 bash 命令，命令和输出都会进 context；第二，`ctrl+s` 可以临时存档你正在写的 prompt，去做别的事，之后可以弹回来继续；第三，`ctrl+g` 把你的 prompt 或者 plan 直接在系统的 $EDITOR 里打开，适合写很长的指令。这三条快捷键，七百多个点赞，五百四十个收藏——说明是真的有用，不是凑数。

另外 Thariq 还发布了 Claude Code Review 的新功能：你现在可以在 GitHub PR 或者 comment 里手动输入 `@claude review`，按需触发 Code Review，不用每个 PR 都自动跑。这个改动让 Code Review 的使用更灵活——你可以选择在哪些 PR 上认真审，而不是全量开着但产生噪音。

好，把今天这一批 Claude Code 更新放在一起看：1M context 成为默认、手机远程启动、Voice Mode 全量、代码审查可以手动触发、三个实用快捷键。这不是某一个大功能的发布，而是一批"让你的实际工作流更顺的"小打磨。Anthropic 在这方面的节奏变得越来越密，而且每次都踩在工程师的真实痛点上。

好，我们换个话题，聊聊郭宇。

昨天我们聊过郭宇用 wanman AI 模拟日本汽车软件公司的实验，那次用的是 Claude Opus 4.6 做 CEO 和 CTO，跑了两百个工作日循环。今天早上他发了一条新的报告，这次实验完全不同。

他用的是自己的 Gaming PC，跑的是纯 Qwen 3.5 35B——注意，没有任何 Opus 模型。目标换了：在日本创办一家只雇佣 AI 员工的游戏公司，面向日本中年女性开发游戏并上线，持续运营直到盈利。这次跑了一千零一十九轮，大约六个小时。

结果怎么样？Qwen 自己设计并开发了一款种花的放置游戏。郭宇说 Claude Code 评估效果不错。

这里有几个值得单独拎出来说的点。

第一，完全没有用 Opus，只用 Qwen 3.5 35B，一个本地跑的中型模型。这说明这类"长循环商业模拟"的可行性，不是只依附于顶级模型的。成本低得多，可访问性高得多。

第二，一千零一十九轮，六个小时，这比之前的实验长了将近五倍。循环能跑这么久，说明郭宇在 wanman 的架构层面做了一些改进，解决了之前在 175 循环停滞的问题。

第三，他提到接下来要开发"无限运转"模式，希望 wanman 能自动上线产品并自己推广。这是一个很大的步骤——从"模拟一个公司"到"真实运营一个公司"，边界开始模糊了。

另外，郭宇还在 Sandbank Cloud 上做了新进展：现在在 microVM 层面也支持有限的浏览器自动化了，可以操作中小网站，不需要额外花钱买爬虫 MCP 服务。这部分他说开源后会放到 Sandbank 的 Cloud 适配器里。两个项目同时在推进，他的实验节奏很快。

说到浏览器和 AI agent，今天有一条我觉得在这批 posts 里被低估的消息。

Chrome 146 发布了，里面有一个功能：通过一个简单的开关，你可以把你当前正在运行的 Chrome 会话，通过 MCP 暴露给你的 CLI agent。也就是说，你的 agent 可以直接控制你的真实浏览器——包括你已经登录的账户、你当前打开的标签页、你的 cookies——而不是一个无状态的 headless 浏览器。

Petr Baudis 发了这个消息，Peter Steinberger 立刻转发说要今晚把这个功能加进 OpenClaw。这条推文一千两百五十个点赞，六百多个收藏。

为什么这个很重要？你想想，之前 AI agent 做浏览器自动化，通常有两种方案：一是用 headless 浏览器，但你需要重新登录所有账号，很麻烦；二是用屏幕截图加模拟点击，不稳定且慢。Chrome 146 的这个 MCP 接口相当于开了第三条路：把你的真实会话直接交给 agent，它可以用你的身份去操作任何你已经登录的网站。

当然，这个功能的安全边界是一个值得认真讨论的话题。你基本上是在把你的完整浏览器会话权限交出去，agent 能做的事情的上限，就是你自己在浏览器里能做的事情的上限。Perplexity 的 CTO Denis Yarats 昨天刚刚专门回应了一个安全研究者关于 session token 暴露的问题，解释说那是一个临时代理 token，不是真正的 API key，是短周期的，绑定在 session 上的。这两件事加在一起，说明随着 AI agent 越来越深入地接管浏览器操作，安全边界的设计会变成一个越来越关键的工程问题。

快讯时间，我们快速过几条值得知道的消息。

Meta 的新模型 "Avocado" 被推迟发布了。内部测试发现它在推理、编程和写作方面落后于 Google、OpenAI 和 Anthropic 的模型。swyx 转发了这条消息。这个新闻本身不让人意外——大家都知道 Meta 在前沿模型竞赛上一直在追赶——但"内部测试不合格，直接延迟"这件事说明 Meta 对发布质量有了更高的标准，或者说竞争压力让他们不敢轻易出手了。

Aaron Levie，Box 的 CEO，发了一条关于推理容量的分析。他说当前前沿的 AI 使用场景，消耗的 token 量大概是一年前的一百倍。coding agent 在跑越来越长、越来越复杂的任务，已经在用掉惊人的推理容量。他说这只是知识工作的一小部分，等 agent 全面接管知识工作，每个 agent 都有自己的计算机可以用，可以写代码执行代码，推理容量的需求会是现在的另一个数量级。他的结论是："推理容量的争夺战要开始了。"这个判断和昨天我们聊 Karpathy 关于 intelligence brownout 的那句话，其实在说同一件事。

LangChain 的 CEO Harrison Chase 接受了 FirstMark 的 Matt Turck 的专访，主题是"AI 模型会不会把 agent 框架层吃掉"。这个问题在圈子里争议很大，Chase 的观点是框架层会有真实价值，但具体的价值点在哪里、护城河怎么建，他也在认真思考。这个访谈涵盖了 harness、MCP、memory、sandbox 等等议题，对于在做 agent 工程的人来说是不错的一手材料，后台链接我放在 shownotes 里了。

Google 的 Josh Woodward，就是负责 Gemini 和 NotebookLM 的 VP，在采访里透露了一个数据：Google 现在百分之二十五到三十的代码是由 AI 写的。他说的另一句话我觉得值得记一下："最有价值的技能，是重新发明自己的能力。"

另外有一个开发者把 Anthropic 的 Generative UI 反向工程了，重新给 Pi AI 实现了一遍，还写了一篇文章说明怎么做的，从对话导出中提取了整套设计系统，用 morphdom DOM diffing 做 live streaming HTML 到原生 macOS 窗口。这个 270 个收藏的推文说明有不少人在认真想怎么给 AI 对话加上动态 UI 层。

最后一条，Obsidian 的作者 kepano 更新了 Defuddle 工具，现在支持 YouTube 转录了，可以给视频生成带时间戳的 Markdown 文档，还有章节分段和发言人识别。MIT 开源协议，实用。
