Anthropic 为什么突然砍掉了第三方工具的订阅权限？Simon Willison 说他同时跑四个 agent，到上午 11 点脑子就转不动了，这到底是效率革命还是认知灾难？Cursor 的设计师为什么说“AI 越强，玻璃越重要”？先从最紧迫的事说起。

Claude 订阅从今天中午开始不再覆盖第三方工具。准确说，是太平洋时间中午 12 点，也就是北京时间明天凌晨 3 点之后，你用 OpenClaw 这类第三方工具调用 Claude 模型，就不能再走订阅套餐了。

消息来自 Anthropic 的 Boris Cherny。他在 Claude Code 团队，昨天深夜发了一条 thread 解释原因。原话是：订阅体系本来就不是为第三方工具的使用模式设计的，容量是他们需要谨慎管理的资源，现在要优先保障直接使用产品和 API 的客户。

这个变化影响挺大的。OpenClaw 是最近圈子里最火的 agent 工具之一，很多人把它当成 Claude 的“外骨骼”在用。政策调整后你有两个选择：一是买 Anthropic 新推出的折扣用量套餐，二是直接接 Claude API key。

作为补偿，现有订阅用户会拿到一笔一次性额度，金额等于你的月费。想全额退款的，今天会收到邮件，里面有退款链接。

如果你正在用 OpenClaw 做日常开发，今天就得做个决定了。是切 API、买套餐，还是直接退订。别等到周一开电脑才发现 agent 不干活了。

另一件值得说的事。Lenny 和 Simon Willison 的深度对谈昨晚在圈子里传疯了。Simon 是 Django 的联合创始人，也是“prompt injection”这个词的提出者，在 AI 工程圈属于那种说话有分量的人。他跟 Lenny 聊了两个多小时，信息密度极高。

最让人有共鸣的一段是 Simon 描述自己的工作状态。他说用好 coding agents 这件事，正在榨干他 25 年的软件工程经验。他可以同时启动四个 agent 并行处理不同问题，但到了上午 11 点整个人就废了。不是因为体力，是认知被拉满了。即使不逐行审查 agent 的代码，光是同时在脑子里 hold 住四个任务的状态，就已经到极限了。

Simon 说这不是效率问题，是人的认知有上限。他提出一个观点：我们这代人需要学会一项新技能，就是找到自己在 agent 时代的新边界。什么叫负责任的用好这些工具？不是无限压榨产出，而是搞清楚自己能承受多少认知负荷，然后守住那条线。

Lenny 自己也发了一条总结，提炼了十个要点。其中几个特别值得拿出来说。

第一个，Simon 认为 2025 年 11 月是 AI 编码的真正拐点。GPT 5.1 和 Claude Opus 4.5 在那个时间点跨过了一道门槛，coding agents 从“大部分时候能用”变成了“几乎总是能做到你想让它做的事”。很多工程师在假期里鼓捣了一下，回来就意识到这东西真的可靠了。

第二个，中年工程师最危险。不是初级，也不是资深。AI 能让有经验的人放大几十年的模式识别能力，也能让新人一个月变一周就上手。Cloudflare 和 Shopify 各自招了一千个实习生，因为 AI 把 ramp-up 时间从一个月砍到了一周。但那些卡在中间、经验积累不够深、又已经吃到了新手红利的人，处境最尴尬。

第三个，“暗工厂”模式。一家叫 StrongDM 的公司定了一条规矩：没人写代码，也没人读代码。他们用 AI 模拟了成千上万个假员工，24 小时不停地向系统发请求，一天烧掉一万美元的 token 费。连 Slack、Jira、Okta 这些外部系统都是用 agent 根据 API 文档生成的模拟版，就为了绕过调用频率限制。Simon 说这是目前最激进的一场 AI 开发实验。

第四个，红/绿 TDD 是最高杠杆的 agent 工程模式。让 agent 先写测试、看着测试失败、再写实现、再看测试通过，产出的代码质量明显更好。你只需要五个字：“use red/green TDD”，agent 就能理解整个流程。

第五个，鹈鹕骑自行车。这是 Simon 编出来嘲讽数字基准的一个梗，让各模型生成一只鹈鹕骑自行车的 SVG。结果意外发现，画得好的模型干别的也强，没人能解释为什么。现在这已经成了圈内的一个 meme，Gemini 3.1 的发布视频里甚至专门出现了一只骑自行车的鹈鹕。

如果你最近也感觉被 agents 搞到认知过载，Simon 的这期访谈值得完整听一遍。链接我放在 shownotes 里。

今天值得展开聊的，是 Cursor 设计师 Ryo Lu 昨天发的一篇长文。标题叫“玻璃 vs 黑箱”。

起因是这样的。Cursor 3 刚发布没几天，Peter Yang 试完之后说新界面好多了，旧版按钮太多妨碍跟 agent 对话。Ryo 转发了这条，然后写了一篇接近一千字的宣言，解释 Cursor 的设计哲学。

Ryo 的核心观点很明确。他说终端是个黑箱，一行命令进去，几行输出出来，你得学着像机器一样思考。AI 把这个黑箱保留了，还让它更上瘾了。你现在是输入一个愿望、拉一下拉杆，然后整个东西吐出来，你选择接受或拒绝。你看得越来越少，想得越来越少，模型越好你越像一个被动的消费者。

然后他提出“玻璃”这个概念。玻璃就是把黑箱打碎，让你能看到里面发生的一切。

他说 PM 可以写计划、看着计划变成现实。设计师可以画草图、在代码里实时迭代。工程师可以在写第一行代码之前先拆系统架构。新手程序员可以读每一个 diff、提问、学习、建立直觉。资深的人可以放手让 agent 跑，只在感觉不对的时候介入。

同一个工具，不同的使用深度。agent 是可见的，diff 就在那里，计划可以编辑，状态一目了然。你可以随时 Tab 进文件直接改。没有任何东西藏起来，也没有任何东西是强制的。

Ryo 说了一句很关键的话：AI 越强大，玻璃越重要。不是因为你需要盯着每一步，而是最好的工作发生在你知道自己可以盯的时候。当你加上了只有你才会想到的那一笔，当你抓住了模型漏掉的东西，当你把它塑造成符合你思考方式的样子。

你的快捷键、你的模式、你的品味。工具学你的方式，而不是反过来。

最后他给了一个很清晰的立场：把方向盘交出去，你得到的是平庸。握住它，你才能做出真正好的东西。Cursor 是玻璃。看着 agents，停下它们，操控它们，让它们变成你的。

这篇文章的评论区很有意思。有人问这和传统 IDE 有什么区别，Ryo 的回答是：传统 IDE 让你看到代码，但看不到 agent 的意图和决策过程。玻璃要展示的是“为什么生成这段代码”以及“接下来打算做什么”。

坦白说，Ryo 这篇文章触及了一个挺根本的问题。过去半年 AI 工具都在拼谁更“自动”，谁能让用户少动手。但 Cursor 在走另一条路：不是让你少动手，而是让你能在更高的层面上去“动手”。不是省掉思考，而是给你一个更好的思考界面。

这对你的启发是什么？如果你在选 AI 工具，不管是 IDE 还是 agent 框架，可以多问一句：这个工具是让我越用越会想，还是越用越不会想？它是在教我放弃判断，还是在帮我放大判断？这个区别，可能比一时的效率提升重要得多。

再说几条快讯。

Grok Imagine 的图像生成能力大升级。Justine Moore 发了一个详细的测评 thread，从文字渲染、场景构建、食物摄影、信息图到动漫风格都测了一遍。新模型在长文本渲染上进步明显，可以直接根据你提供的文字生成蛋糕上的祝福语，也能自己写“剧本”生成白板风格的内容。Justine 建议更新 App 或用桌面端网页版体验，她认为后续加上编辑和参考图功能后，这会是一个很强的产品摄影工具。

Google Labs 的 Stitch 推出了 Live Mode。Zara Zhang 发了一段演示视频，说这像是跟一个设计师开实时会议，对方能展示工作过程还能在会议中直接应用修改。她说语音加视觉是人机交互的未来方向，虽然目前还不完美。

Obsidian Web Clipper 1.3 发布了。kepano 宣布 Reader 模式新增了主题和排版设置、高亮功能以及保存选项。还专门为 Reddit 和 Hacker News 的嵌套评论做了新的阅读体验。Chrome 和 Safari 已经可以更新，Firefox 还要等一下。

Box 的 CEO Aaron Levie 分享了他做 AI agent 的一个核心教训：对旧架构要冷酷无情。他说模型能力不断变强，你之前为弥补模型不足而搭建的脚手架，很快就会变成拖累。他的做法是不断删掉旧系统，释放新模型的能力，然后去解决更难的下一组问题。别对你写过的代码产生感情。

你会不会也在某些工具或流程上，守着一些“模型早就不需要了”的旧习惯？今天可以翻出来审视一下。
