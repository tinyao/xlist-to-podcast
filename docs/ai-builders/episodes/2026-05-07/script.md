Anthropic 和 SpaceX 的算力合作，对这个行业的真实影响是什么？Greg Isenberg 用一张图告诉你现在该冲哪个方向。而 Peter Yang 测试了市面上所有的个人 agent 之后，为什么说这场仗还没人打赢？先从最让工程师睡不着的那件事开始。

Anthropic 的 Claude Code 使用上限翻倍了，同时取消了高峰时段限制。这个调整昨天开始生效。具体来说，Pro、Max、Team 以及按席位计费的企业版，每 5 小时的用量额度直接加倍；Pro 和 Max 用户在高峰时段被降速的规则，也拿掉了。Anthropic 的 Claude Code 团队成员 Boris Cherny 明确说，背后的支撑是一份新的算力协议——SpaceX 将在下个月内提供超过 300 兆瓦的新增容量，以及 22 万块 NVIDIA GPU。

这单买卖的逻辑，Box 的 CEO Aaron Levie 点得很透。他说 SpaceX 把自己变成一家垂直整合的 AI 算力公司，简直是疯了但极其合理。Anthropic 另一位哲学家 Amanda Askell 转发了同事 Tom Brown 的话，说他们要在 Colossus 上大幅提升 Claude 的推理密度，而这件事需要快速搬动大量原子——地球上或者地球外，没有谁比 SpaceX 更擅长这个。

Guillermo Rauch 转发了 John Resig 的反馈，为 Vercel 之前开源的 deepsec 安全审计工具加了注脚。John Resig 是 jQuery 之父，现在在可汗学院。他说用 deepsec 扫了他们主要的后端仓库，揪出了一些非常刁钻的边缘案例。然后他直接派了一组 Claude agent 去修掉了所有高危问题。他说这种事放在以前，可能要花几周甚至几个月。

Riley Brown 继续在 GPT 5.5 上做极限测试。他昨天发了一段录屏，描述了一个对工程师来说很刺激的场景：他先用 Codex 建了一个带数据库、存储和认证的 Web 应用，然后几乎在同一个 prompt 里，要求 Codex 把这个 Web 应用转成桌面端和 Swift iOS 原生应用。Codex 跑了 41 分钟，没停，直到三个端都跑通。Riley 说自己还在震惊中。

另一边，Codex 的服务器端状态栏工具 CodexBar 发布了 0.24 版。维护者 Peter Steinberger 给了一个很短的日志：新增了对 Windsurf、Codebuff 和 DeepSeek 的支持，加入了 Copilot 多账户切换，还修了两个严重影响续航和渲染的 bug。如果你日常工作在几种不同的 agent 之间来回切，这个小工具值得装一下。

今天值得展开聊的，是这件事。

Greg Isenberg 画了一张 AI 原生公司的 2x2 矩阵。横轴是“复杂度”，纵轴是“重复频次”。他说大多数人都在错误的象限里建东西。左上角，简单且重复——已经商品化了。左下角，简单但不重复——痛点不够。右下角，复杂但不重复——做起来累，但赚不到复利的钱。钱在右上角：高复杂度、高重复频次。他举了几个例子：保险理赔、招聘筛选、合规审查、法律文书初审。这些领域流程复杂，但每天都在大量重复发生。他说，这就是 agent 的主战场。

如果你听完觉得这个框架有点耳熟，没错，前两天我们刚刚展开聊过 Greg 对“全球只有一千家真正 AI 原生的公司”的判断。那张矩阵，可以看作是那个判断的延续和具体化。上一次他定义了标准：公司里每一条信息都必须结构化到 agent 可以直接消费的程度。这一次他给了你一张地图，告诉你有了这种信息架构之后，该往哪里打。

有意思的是，Zara Zhang 从另一个角度接住了这个话题。她不是搞 VC 的，而是一个 Builder，常年泡在 GitHub 上都代码。她昨天说，现在的开发者工具面临一个巨大的错失——产品本身已经对任何能使用 agent 的人都有用了，不只是专业开发者。但几乎所有工具的营销和传播语言，仍然只对开发者讲话，用词让人紧张、看不懂。如果你正在做一款面向 agent 使用者的产品，她的言下之意很明确：别再只盯着写代码的那群人说话了。会问 agent、会指挥 agent 的人，远比你想的多。

Peter Yang 昨天发了一份个人 agent 的深度横评。他把自己当小白鼠，长时间泡在 OpenClaw、Hermes、Claude Code、Codex 和 Gemini 里，结论很有意思。他说实话，这场仗还没人打赢。他给了一个很直观的打分：OpenClaw，最灵活但最容易崩。Hermes，目前看起来比 OpenClaw 可靠。Claude Code，最喜欢 Opus 的人格，但 98% 的可用率对他来说不够。Codex，桌面端体验最好，GPT 5.5 很强，但没有移动端，这个对他来说直接出局。Gemini，理论上最应该赢，但连在 app 里编辑 Google Docs 这种基础功能都还没有。

把 Greg 的矩阵、Zara 的错失提醒、Peter 的横评放在一起，就能看到一个正在形成的画面。Greg 说钱在那些高复杂度、高重复的垂直流程里。但 Peter 测试的结果是，当下没有一个 agent 能让你在这些高复杂度流程里闭着眼信任它，不管是断连、遗忘还是漏步骤，问题都还存在。Zara 讲的是另一层：就算你有能用的工具，你怎么跟不用终端、不写代码的人解释这个工具能帮他做什么？这三件事同时成立，恰恰说明现在是一个结构和工具在同时演进、但还没对齐的阶段。

如果你是创业者，Greg 那张矩阵值得存下来。下次跟人聊方向的时候，直接问一个问题：这个活，复杂度够高吗？每天会重复发生多少次？如果答案都是低，也许你花掉的时间，只是在帮已经商品化的东西做装修。

再说几条快讯。

Lenny Rachitsky 跟 Replit 一起发起了 Buildathon，用他过去的内容和播客数据去建点东西。奖品包括跟 Amjad Masad 的一对一职业辅导，五千美金的 Replit 额度。如果你正在找一个有真实数据集的练手项目，这件事门槛很低。

Google Labs 的设计系统提示文件 Design.md 昨天在圈子里被大量转发。这是一个开源的 markdown 文件，规定了字体、颜色、间距等设计的 DNA。把它附在你的 prompt 里，agent 就能在不同页面和不同媒介之间保持一致的视觉风格。

Kepano 说了一句很容易被忽略但很重要的话。他是 Obsidian 的创始人。他说这个世界的 .md 应用还不够怪。怪不是只指视觉，而是指偏离常规的原则——你得有一些别人可以合理反对的东西。他回忆六年前 Obsidian 刚出来时，本地文件、反向链接这些东西都是非常怪的，现在大家都在用了。

郭宇转发了一个叫 Cofounder 2 的产品。他说看介绍视频，完成度不错，本质上是把 engineer、sales、marketing 这几个 agent 编排成一个可以运营一家公司的 harness 产品。如果你对 agent matrix 这个方向感兴趣，可以去看一眼它的交互设计。
