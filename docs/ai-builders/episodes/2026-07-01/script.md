Vercel 和 Shopify 联手重写 Hydrogen，这次的关键词是 agent-first。Lenny 发布了一份 AI 原生 PM 的行动框架，里面提到的“杠杆阶梯”是什么？以及，今天圈子里都在聊的“软件工厂”这个比喻，为什么 Charlie Holtz 和 Peter Yang 都觉得它不对劲？先从最让工程师睡不着的那件事开始。

Claude Desktop 正式登陆 Linux。Anthropic 的 Claude Code 团队成员 Boris Cherny 昨天宣布了这个消息，官方也同步更新了文档。目前支持 Ubuntu 和 Debian，以 beta 版发布。这意味着你在 Linux 上也能获得完整的桌面端体验，包括 Claude Code、Claude Cowork 和聊天功能。对于很多习惯在 Linux 环境里开发的工程师来说，这补上了一个挺大的缺口。如果你之前因为系统限制一直在用网页版，现在可以切换到桌面端，体验会完整很多。

Vercel 和 Shopify 宣布，要从头开始重建 Hydrogen。Guillermo Rauch 说，这次重建的核心是 agent-first，并且 runtime-agnostic，能在任何 JavaScript 运行环境里跑。Vercel 官方说法是，新 Hydrogen 会深度整合进 Next.js 的开发者预览版。这件事值得关注的点在于，Hydrogen 是 Shopify 电商生态的核心前端框架，而 Vercel 把它拉进自己的体系里，意味着 agent 构建能力正在进入电商基础设施层。Guillermo 还特意提到，跟 Shopify 创始人 Tobi 的合作非常愉快。如果你在电商领域做开发，这个变动值得放进待办清单里。

Nano Banana 2 Lite 和 Gemini Omni Flash 发布了。Google 的 Logan Kilpatrick 昨天一口气宣布了两个新模型。Nano Banana 2 Lite 是一个极快的图像生成模型，生成一张图不到 4 秒，价格是每千张 0.034 美元。Logan 的原话是“快得感觉像魔法”。Omni Flash 则主打视频编辑，定价每秒 0.10 美元，和 Veo 3.1 Fast 持平。这两个模型现在都可以在 Gemini API 和 AI Studio 里用。图像生成速度拉到这个程度，对需要低延迟的交互类产品会是个挺大的变量。如果你在做视频工具或内容生产类产品，Omni Flash 的视频编辑能力也值得测一下。

Etched 正式走出隐身模式。Replit 的 CEO Amjad Masad 转发了这个消息，并且给了一句很直接的评价：AI 推理成本高的原因之一，是大部分工作负载还跑在为大模型出现之前设计的通用硬件上。Etched 是第一套从零开始为现代推理设计的系统。官方公布的数据是，A0 流片成功，手握超过 10 亿美元的客户合同，融资 8 亿美元，第一批机架今年夏天发货。圈内对这件事的反应挺分裂的。Amjad 明显看好，认为这是推理层的一次硬件重构。而另一边，前字节工程师郭宇提出了一个很实际的问题：到底能降多少推理成本？以及，最先在哪些云上提供？这两个问题目前还没有公开答案。如果你在做推理成本敏感的 infra 决策，Etched 的后续进展值得持续关注。

Box 的 CEO Aaron Levie 贴出了 Claude Sonnet 5 的企业级跑分。他们在 Box AI Complex Work Eval 这个 agent 基准测试里，用真实的企业文档工作流跑了一遍。结果显示，Sonnet 5 在多个核心行业领域都领先 Sonnet 4.6——能源行业高出 4.7 个百分点，零售高 4.4 个百分点，专业服务高 2.6 个百分点。Levie 举了几个具体例子。在融资尽调任务里，Sonnet 5 从原始资产负债表里算出了公司的流动性和杠杆比率，并且发现源报告自己写的负债权益比低估了实际杠杆，标记出三条贷款契约全部违规，而不是只承认文档里提到的那几条。在大修成本分析里，它正确地把“总成本”限定为公司的 KPI 定义，单独分离出停产损失成本，还抓到了一个损坏的引用单元格。在 SKU 收入分析里，它用正确的子类别分母计算了每个产品的贡献率，避开了直接用类别总数除的常见错误，还解释了为什么宠物类没有产品进入前 9 名。Sonnet 5 很快会进入 Box AI Studio，供客户构建自定义 agent。

接下来这段我们多说几句。

今天把节奏放慢一点，说一下圈子里正在发酵的一场争论：我们到底该怎么描述 AI 时代的工作方式。

起因是昨天 Charlie Holtz 提了一个观点，他说“软件工厂”这个词暗示的是流水线式的任务，这不可能是 AI 时代工作的未来。Peter Yang 紧随其后，用了一个很生动的比喻。他说，我们跟 agent 协作，应该像指挥家与管弦乐队，或者电影导演与剧组，或者主厨带领厨房。工作必须是创造性的。

这个比喻迅速在圈子里传开。有意思的是，Factory AI 的 CEO Matan Grinberg 也加入了讨论。他的公司名字就叫 Factory，但他完全不介意这个争论。他还自嘲说，既然公司注定会变成名字的反面，他对自己的选择非常满意。这是一种挺轻松的态度，但也说明“工厂”这个词确实触动了很多人。

而另一边，Linear 的产品负责人 Nan Yu 把一个更尖锐的问题摆上了台面。他转发了关于 GLM 的传闻——据说 GLM 的编程计划背后有一个内部路由器，会把高价值的、超出 GLM 自身能力范围的查询路由给 Claude，然后把追踪记录加进蒸馏数据集。Nan Yu 的评论是：“蒸馏”的定义本身就有意思。照这个逻辑，Cursor 早期的训练数据，就是从 Claude 那里蒸馏出来的。

你看，这两条线其实汇到了一起。一边是“工厂”隐喻的争论——我们不想把 agent 当成流水线工人。另一边是“蒸馏”定义的模糊——当大家都在用更强模型来训练更弱模型的时候，谁才是谁的工厂？

对听众来说，这场争论的启发其实很具体。第一，你团队内部的隐喻很重要。如果你把 agent 部署成“工厂”，你招来的人和设计出的流程，就会往流水线方向走。如果你用“管弦乐队”的隐喻，你会更注重人的指挥角色和 agent 的创造性输出。第二，“蒸馏”这个词在 2026 年已经不是一个纯粹的技术术语了，它变成了一种商业策略。当你的产品依赖第三方模型 API 的时候，你其实也在参与这场“谁蒸馏谁”的游戏。你最近有没有想过，你用的那些工具，底层到底是谁在服务谁？
