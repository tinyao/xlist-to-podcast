Claude Code 的桌面端和自动化任务今天一起更新了，具体有哪些变化？Vercel 开源了一个叫 Open Agents 的平台，这对想自建编程 agent 的团队意味着什么？Box 的 CEO 为什么说，未来每家公司都会出现一个叫"agent 部署经理"的新角色？
先从最让工程师睡不着的那件事开始。

Vercel 昨天开源了一个叫 Open Agents 的参考实现，专门给企业搭建自己的编程 agent 平台。
Guillermo Rauch 亲自发布的。他在帖子里点出了一组很有趣的现象：Stripe 在内部做 Minions，Spotify 在做 Honk，Block 在做 Goose。
这些不缺钱的公司，都没直接用现成的 coding agent，而是选择自己造轮子。

Guillermo 给了两个理由。
一个是技术层面的。现成的 coding agent 在巨型 monorepo 上跑不动，也不懂你公司内部的架构和流程。
另一个是商业层面。他认为软件公司的护城河，会从"写了什么代码"，转移到"代码的生产方式"本身。

Open Agents 绑定了 Vercel 自家的整套 agent 基础设施。
Fluid 负责跑 agent 的大脑，Workflow 保证长时间任务不掉链子，Sandbox 做隔离的代码执行，AI Gateway 管理多模型的 token。
不过 Guillermo 也强调，因为是开放 SDK 和运行时，即便不用 Vercel 托管，这份代码本身也很有参考价值。

说到这个，我想起 郭宇 昨天也点评了这件事。
他的观察是，这种 harness engineering 和 Claude Code 本身之间的界限正在模糊。
他的建议是：如果要在这上面持续投入，得基于 Claude Code 这种快速演化的基础做 harness，否则效果打折。
如果你所在的团队正打算自建编程 agent，Open Agents 省了从零搭架子的功夫。你怎么看自己搭还是直接用现成的？

另一件值得说的事。Claude Code 桌面端今天迎来了一次大更新。
Anthropic 的研究员 Alex Albert 说，现在在桌面端里搭配使用 Cowork 和 Code，他几乎不用再打开其他应用了——连终端都不用开。

这次更新最大的亮点是支持多会话。
你可以同时跑好几个 Claude Code 会话，从同一个窗口里用侧边栏管理它们。
Anthropic 的产品经理 Robert Bye 说，这个版本终于把他从命令行里拽了出来。
这在事实上向 Cursor 等以多任务界面为卖点的工具靠拢了。
同时，VibeCode 的联合创始人 Riley Brown 也在问，新的桌面端上线了没有——看得出来，大家都在盯着这个更新。

Claude Code 还推出了一个叫 Routines 的重要功能。
简单说，你可以设定一个任务，指定代码仓库，配上触发条件，它就会在 Anthropic 的服务器上 24 小时跑。
Greg Isenberg 对此特别兴奋。他把它和 Larry Ellison 的一句话联系了起来："钱从来不在技术里，在技术跑在的基础设施里。"
Greg 的框架是这样的：模型是商品，触发器才是产品。谁能把现实世界最有价值的信号，跟最具体的行业工作流对接，谁就能建出真正庞大的东西。

比如说，一份许可证被批了，一个客户的使用量一周掉了 40%，一笔合同离续约还有 90 天。
这些全是触发器。
在这些时刻，agent 可以在人还没反应过来之前就介入，做点什么。
不过 Peter Yang 倒是给了一盆冷水。他说自己得时刻提醒自己，用这些东西的时候，到底是在设真正的工作流，还是仅仅在优化 OpenClaw 和 Claude Code 的折腾环境。
你最近有没有也掉进过这种"优化工具本身好像比工作还有意思"的陷阱里？

换个方向。Box 的 CEO Aaron Levie 昨天发的一条长推，在圈子里传了一夜。
他提出，企业里正在出现一个新的角色，叫 agent 部署和管理者。
这个角色要做的事，是找出团队里哪些流程，如果扔 agent 进去，能快一百倍或者多做一百倍的量。
可能是处理海量销售线索，自动做合同审查，或者简化客户入驻流程。

Aaron 特别强调了这个人需要具备的能力。
他得懂业务流程，能画出来怎么改造。
同时还得够技术，能熟练使用 Skills、MCP、命令行这些工具。
而且公司得信任他，让他直接连接业务系统去推动自动化。
这个人可能在业务部门，也可能属于 IT 或 AI 团队。
Aaron 认为，这对那些懂技术又愿意拥抱 AI 的年轻人来说，会是个极好的工作。

同一时间，Lenny 也发了一期新播客，嘉宾是 Keith Rabois。
Keith 是前 Square 的 COO，PayPal 帮的成员，投过 Stripe、Airbnb、DoorDash。
他抛了一个关于用人的比喻：弹药和枪管。
大多数公司融完资就招很多人，结果 CEO 发现人多了，烧钱快了，但产出没多。
Keith 的说法是，因为能独立把一件事从头推到尾的"枪管"太少了。招来的人大多只是"弹药"，只能堆在同一个项目上。
他还说，CMO 正在超过工程师，成为消耗 AI token 最多的人。

今天值得展开聊的，是这件事。
Figma 的 CEO Dylan Field 昨天跟 Peter Yang 做了一场对谈，里面有不少反直觉的观点。
起因是 Peter 问他：AI 能教出设计品味吗？当代码变得免费的时候，Figma 的角色又是什么？

Dylan 的回答很直接。他说，把 AI 的一次输出当成最终结果，这是个严重错误。
他打了个比方：AI 的输出像黏土，你得去捏它、塑形。
你才是系统的最终裁判，因为可能性几乎是无限的，你得自己判断什么是好的、什么值得继续探索。

Dylan 还提了一个让我印象深刻的观点。
他说，如果你是个产品经理，觉得自己的工作就是写文档、做幻灯片，那你会爱上这个新世界——因为你能直接做东西了。
反过来，Julie Zhuo 昨天也发了一篇对知名设计师 Soleio 的访谈，里头有句话和 Dylan 的观点形成了共振。
Soleio 说，那些把影响力和策略都丢给产品经理的设计师，"没有资格要求优秀这个头衔"。

这两边一拼，画面就清楚了。
AI 让"能做东西"这件事的门槛急速下降。
PM 能直接做东西了，设计师反而被要求往策略层走，不能只等需求。
对听众来说，这其实是个具体的选择题：你的角色正在被重新定义的机会窗口里，你是往"能做更多东西"的方向走，还是往"定义什么东西值得做"的方向走？
这没有标准答案，但它就是眼下正在发生的位移。
