AI SDK 7 正式发布，带来了 agent 生产化的一整套基础设施。
Vercel 昨天同步了这次大版本更新，Guillermo 连发两条，说这是 AI SDK 最好的一个版本。

这次更新的核心不是加功能，而是加控制力。推理控制、agent 级别的工具审批、工具和运行时上下文、文件上传、MCP 应用、持久化工作流、终端 UI、沙箱支持、遥测——这些词放在一起，指向同一件事：让 agent 从 demo 走向生产环境。
之前大家用 SDK 搭 agent，最大的痛点是“跑起来了但不敢上线”。工具调用失控怎么办？工作流断了怎么恢复？用户到底在怎么用我的 agent？AI SDK 7 就是来回答这些问题的。

Guillermo 还单独发了一条，说 Next.js 的错误提示现在加上了“复制提示词”按钮，他称之为“agentic 艺术”。这个细节挺有意思的——当你的框架本身开始为 coding agent 优化交互路径，说明 agent 已经不是外部工具，而是开发流程里的默认角色了。
如果你在用 Vercel 的 AI SDK 做 agent 应用，这次升级值得花一个下午认真过一遍 changelog。

另一件值得说的事。Vercel 的 AI Gateway 数据显示，Grok Imagine Video 已经成了视频生成模型的绝对领先者，占到开发者生成视频总量的约 50%。
Guillermo 昨晚贴出了 AI Gateway 的视频模型排行榜，xAI 的 Grok Imagine Video 占比接近一半。这个数字来自 Vercel 平台上的实际调用量，不是第三方 benchmark，也不是用户投票——就是开发者在生产环境里用脚投票的结果。

有意思的地方在于，Grok 的视频模型上线时间并不算最早，但增长曲线很陡。Guillermo 的原话是“clear leader”。如果你在做视频生成相关的产品选型，这个信号值得关注——至少说明在 Vercel 的开发者生态里，Grok Imagine Video 已经是默认选项级别的存在了。
你最近有没有在项目里试过它？体验怎么样？

Google 发布了 Gemma 4，定位很明确：端侧智能，人人可用。
Logan Kilpatrick 昨天用一句话定义了这次发布——“intelligence for everyone on device”。配了一条四分多钟的视频，展示了 Gemma 4 在手机和其他终端设备上直接运行的场景。

Gemma 是 Google 的开源轻量模型系列，这次的第四代主打“把智能带到设备上”。这跟现在主流的云端大模型路线形成了一个有趣的对比——一边是越来越大的万亿参数模型，另一边是越来越小、但能离线跑的小模型。
如果你的应用场景对延迟敏感、或者涉及隐私数据不能上传云端，Gemma 4 这类端侧方案值得认真评估。Logan 在圈子里传了一夜的就是这句话：智能不应该只在云端。

Claude Tag 正在定义 agent 的第三种交互范式。这是今天最值得展开的一件事。

先把节奏放慢一点，说一下今天最值得想清楚的一件事。

起因是 Karpathy 发了一条长文，讲他使用 Claude Tag 的体验。他不是在评测功能，而是在描述一种新的交互形态。他说这是 LLM 交互界面的第三次重大设计变革——第一次是“LLM 是一个你打开浏览器去访问的网站”，第二次是“LLM 是一个你下载到电脑上的应用”，第三次是“LLM 是一个自包含的、持久化的、异步的实体，拥有组织级的工具和上下文，和人类团队一起工作”。

Karpathy 的原话是“it really takes a while to wrap your head around it, but it works and it is awesome”。这个评价从他嘴里说出来，分量很重。

Box 的 CEO Aaron Levie 紧接着做了更落地的解读。他说这里有一个容易被忽略的细节：Claude Tag 不是你跟 Claude 一对一的 Slack 对话，而是 Claude 作为一个“同事”，团队里任何人都可以在共享空间里调用它。

这就带来一个重要的架构问题——这个 agent 同事需要自己的资源、工具权限和数据访问范围。它不能直接复用你个人的权限，因为 agent 可能会不小心把你的私人信息共享给整个团队。Levie 说，agent 需要像系统里的另一个用户一样被对待，你要仔细想清楚它应该能访问什么、哪些信息跟这个群组共享是安全的。

他把这个思路跟 Box 做了集成举例：Claude 可以访问企业的销售材料来回答销售问题、调用品牌指南和营销素材来生成 campaign、读取产品路线图文档供 coding agent 使用——这些都发生在共享空间里，不是某个人的私有对话。

另一边，Claude Code 团队的 Thariq 也在推 Claude Tag。他把它称为“agent 的下一次进化”——一个主动的、多玩家的、有记忆和身份的 agent。他宣布接下来会跟 Peter Yang 做深度访谈，也会在 AI Engineer 大会上跟 Cat Wu 一起聊这个话题。Peter Yang 那边已经收集了八十多条回复，问大家想看什么内容。

swyx 也插了一句话，转发了 Warp 创始人 Zach Lloyd 的帖子，说“我们得为软件工厂时代重建太多基础设施了”。这句话放在 Claude Tag 的语境下，指向的正是 Le vie 说的那个问题——当 agent 变成团队的一员，权限、资源、安全、协作模式，这些底层的东西都得重做。

听完这些声音，回到你自己的工作场景。如果你所在的公司正在尝试引入 agent 协作，Levie 提的那个问题值得现在就拿出来讨论：你的 agent 是以“你的助手”身份在跑，还是以“团队的一个成员”身份在跑？这两种设计对应的权限模型、安全边界和数据架构完全不同。前一种做法更快，但后一种才是真正可规模化的方向。你现在用的是哪种？
