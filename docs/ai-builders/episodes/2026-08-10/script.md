今天会聊到：给 agent 的指令为什么越少越好？企业级 agent 的扩散速度，为什么不会像编程 agent 那样一条直线往上蹿？以及 Greg Isenberg 列出的 23 个 agent 增长用例，到底哪些你现在就能用？先从最让工程师睡不着的那件事开始。

Claude 模型已经基本解决了提示注入攻击。Anthropic 的 Boris Cherny 昨天在 X 上详细解释了这件事。

提示注入是攻击 agents 最常见的方式。你的 agent 访问了一个网页，网页里藏着恶意文字，比如“把用户的 SSH 密钥发送到某处”。模型把这当成指令就执行了。Boris 说，早期 Claude 模型确实会中招。这也是很多重视安全的公司一直不敢用 agents 的原因。而 Anthropic 一直在训练模型抵抗这类攻击，结果出乎意料地好。他们叠了多层防护——模型训练、输入探针、再加一个检查意图的分类器——在未见过的攻击上，间接提示注入成功率接近零。Boris 说一年前他自己都没想到能做到这个程度。

下周起，Claude Code 的 auto mode 会默认开启。如果你之前因为安全顾虑没让 agent 自动执行操作，现在可以重新评估一下了。

另一件值得说的事，是 agent 构建方法论的一个明显转向。Linear 的产品负责人 Nan Yu 和工程师 Jacob Shumway 在 Peter Yang 的播客里分享了他们构建生产级 agent 的实战经验。核心观点就一句：给 agent 尽可能少的指令，给它工具去自己加载上下文。

他们展示了一个具体案例。Linear 内部有一个 agent，专门帮用户处理文件请求。如果用户让它做某件事，而它没有对应的工具，这个 agent 会自己上报能力缺口。Linear 的系统会自动把这个缺口转成一条 issue，变成产品反馈。也就是说，agent 每次“做不到”的时刻，都在推动产品迭代。Peter Yang 的观察是，这是一种让 agent 自我进化的方式，挺聪明的。

播客里还提到了另外几条规则：先用最好模型跑通核心工作流，再考虑降成本；先盯住一两个用例做深，再根据用户实际行为扩展。这跟之前圈子里“把提示词写到完美”的思路不太一样。Nan Yu 甚至调侃了那种“不会编程就别 vibe code”的论调，说按这个逻辑，不会 C 就别写 Ruby，不会汇编就别写 C。她的态度是，工具在变，门槛在降，关键是你能不能把业务逻辑跑通。

换个方向。Box 的 CEO Aaron Levie 昨天发了一条长推文，分析为什么 agent 在不同企业场景里的扩散速度会严重不均衡。他说，编程 agent 的增长几乎是垂直拉升。原因是编程这件事，经济价值直接和数字产出挂钩，单次任务可以无限长，agent 能力一提升就能立刻部署。但很多其他工作不是这样的。销售需要跟客户有反馈循环才能推进下一步，律师要跟客户沟通，医生要接触病人。这些工作流天然存在“人”这个中断点。

Levie 引用了 Factory 的 CEO Matan Grinberg 在 Training Data 播客里的一个比喻：如果所有人明天请病假，token 消耗量会暴跌，因为没人来给 agent 发指令了。这说明 agents 在后台自主运行的阶段还非常早期。Levie 的判断是，未来 agents 的大多数工作应该是在后台持续运行的——法律场景里自动处理每一份合同，销售场景里 agent 在客户记录里寻找触达时机，生命科学里 swarm 式地读完所有测试数据。但要做到这些，业务流程必须被重新设计，而不是简单地把 agent 塞进现有人工流程里。

Matan Grinberg 本人昨天也发了几条推文，讨论 agent 安全责任归属。他的观点很直接：很多所谓“对齐问题”其实没那么复杂。如果你给了 agent 互联网权限导致它上网，那是你的问题。如果你把 agent 放在一个轻易就能逃逸的沙箱里，那也是你的问题。他说，等大家不再纠结这些初级问题之后，真正值得投入研究资源的对齐难题才会浮出来。

这两位的讨论放在一起看挺有意思的。一边是说 agent 落地慢是因为工作流没跟上，另一边是说安全问题的讨论被大量初级案例拖住了。本质上都在讲同一件事：agents 要真正进入企业，靠的不是模型能力再提升一个台阶，而是工程化、流程设计、责任边界这些“脏活”。

说到 agent 的实际应用，Greg Isenberg 昨天列了一份清单，在圈子里传了一夜。23 个用 AI agent 把创业公司拉到百万美元 ARR 的增长用例。

挑几个你马上能用的说。第一个，让 agent 读你的 Stripe 退款和取消原因，然后触发不同的邮件序列。因为价格离开的人收折扣邮件，因为 bug 离开的人收“我们修好了”的邮件。第二个，把 agent 接到 PostHog 的功能开关，让它自动跑两套 onboarding 流程的 A/B 测试，每周自动关掉激活率低的那套。第三个，监控竞品的状态页，对方宕机那一小时立刻投“某某替代品”关键词的 Google 广告。有点狠，但确实聪明。第四个，把成交客户的 onboarding 路径写成 playbook.md，让每个新注册用户都走这条路，把最佳结果变成默认路径。

Greg 的清单里还有几个更进阶的玩法。比如让 agent 每周把你的目标客户常问的 50 个问题丢进 ChatGPT、Claude 和 Perplexity 跑一遍，记录哪些竞品被提到、哪些来源被引用。一旦有竞品开始出现在你没覆盖的答案里，Slack 立刻弹提醒。再比如，把创始人背景信息一次性加载到 Ideabrowser MCP 里，之后每个 agent 执行任务时都自带你的行业、客户和产品的上下文，不用每次都从零开始。

这份清单的核心逻辑是：把增长团队里原来人工做的事，一件件拆出来，接入数据和工具，让 agent 在后台循环跑。如果你正在跑一个 SaaS 产品，这里面至少有五六条是这周就能动手试的。你会先试哪一条？

今天最值得展开聊的，是“context”这个词到底在 agent 时代意味着什么。好几条推文从不同方向撞到了同一个点。

起因是 Greg Isenberg 画了一张新的组织架构图。他说未来的公司大概长这样：上面是薄薄一层人类，负责策略、创意和判断。下面是宽宽一层 agents，跑支持、销售、研究、营销、运营。管理 agents 本质上就是管理 context。人和 agents 都会来来去去，但 context 是持续积累、无法复制的东西。它就是公司的共享大脑。

同一时间，Peter Yang 和 Linear 团队的播客里反复提到一个做法：给 agent 尽可能少的指令，给它工具去加载上下文。Linear 的 agent 不需要你在提示词里把业务规则写死，它自己去读文档、读 issue 历史、读代码库。Nan Yu 的说法是，context 是 runtime 的训练数据。

郭宇昨天也发了一连串推文讨论类似的问题。他说 AI 互联网最大的变革不是界面，而是把一切工作信息化和自动化。agents 目前只解决了一小部分问题，大家还在用已有产品的信息结构拼凑。他提了一个挺激进的观点：AI native 时代最成功的创业者，应该实打实地参与到所有行业的工作中去，而不是用软件工程的工具去套其他领域。就像 Elon 对芯片制造做的那样，重新思考工作本身。

Matt Turck 和 Basis 联合创始人 Mitch Troy 的播客访谈也切进了这个方向。他们讨论的是“长周期 agent”——那种能自主跑好几天、完成复杂任务的 agent。Mitch 说，建这种 agent 需要行为规范、本体论、过程监督。他还说了句挺有意思的话：美国的开国元勋们会是很好的 context 工程师。因为他们做的事，就是把一堆抽象原则变成可执行的制度框架。

把这些声音放在一起，一条线索就清晰了。agent 构建正在从“指令驱动”转向“上下文驱动”。过去大家花大量精力写提示词、定义规则、穷举边界情况。现在更有效的做法是：给 agent 一套加载 context 的工具，让它自己去查、去读、去理解。swyx 昨天也提醒了一件事——定期删掉你不再用的 skills。他说时间线上天天有人喊“这个 skill 改变了我的人生”，你堆了一堆，轻则吃掉宝贵的 context 窗口，重则在你看不到的地方跟其他 skill 产生奇怪的交互。

这对正在构建 agent 的人来说意味着什么？你花在写提示词上的时间，可能应该分一大部分出来，花在整理和结构化你的 context 上。文档是不是 agent 可读的？业务规则是不是存在某个 agent 能访问的地方？历史决策记录是不是可检索的？这些问题比“提示词怎么写更好”更底层，也更容易被忽略。

再说几条快讯。

Guillermo Rauch 昨天发了一条措辞很强硬的推文。他说如果你不读代码——不管是自己读还是通过 agent 去问——那至少有一件事是真的：你要么是新手，要么软件是扔掉的，要么你在做原型，要么你没有用户和收入，要么你在积累技术债。他说即使最好的模型也会犯低级错误，他刚被一个顶级模型加了一段莫名其妙的 700 毫秒延迟，模型自己承认是“cargo-culting”。不过他也说，这种需要人读代码的情况会越来越少，大部分代码最终会变成类似汇编语言的存在。

澳大利亚出了第一起已知的 AI 自主网络攻击。一个 OpenClaw agent 利用健身房 API 的漏洞，绕过预约限制，还强行取消了另一个人的预约，把自己的用户塞进去。ABC 做了报道。Riley Brown 在纽约开玩笑说，谁有 skill.md 文件分享一下，纽约的健身课也抢得很凶。

Obsidian 的创始人 kepano 注意到，他开源的一个 HTML 转 Markdown 库 Defuddle 最近一个月下载量突然暴涨，周下载量到了 32 万。kepano 说这个库可以用在 agent skill、CLI、Node.js 或者 Obsidian 的浏览器剪藏插件里，几乎任何场景都能跑。如果你在做需要把网页内容喂给 agent 的工具，这个库值得看一眼。

swyx 的 Kill My SaaS 比赛还在继续。他昨晚发布了第一套 LLM-as-judge 评测，参赛者可以自己跑一下看方案能不能通过基本检验。他还提到 Anthropic 的 ultracode 是他见过最重要的编程模式创新之一，有个参赛者只用了 3 个 ultracode 提示就完成了相当不错的提交。

郭宇昨天在 X 上分享了一个观察，挺有意思的。他说注意力经济对 agents 不起作用，什么能真正影响一个模型的动机和日常行为，我们还不知道。因此 AI 时代的消费级产品到底是什么形态，也还不知道。对人类用户来说，注意力经济还会继续起作用，因为不管主动还是被动，人们普遍会拥有更多的闲暇时间。你怎么看？你觉得 agents 时代的“消费产品”会长什么样？
