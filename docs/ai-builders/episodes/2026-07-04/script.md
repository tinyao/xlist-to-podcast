Fable 5 突然限时回归，只剩四天窗口期，怎么用才不浪费？Vercel 给 agent 装上了“自我反思”能力，这意味着什么？Box 的 CEO 说 AI 的终极战场是“上下文”，这个判断对创业者有什么启发？先从最紧迫的事说起。

Claude 最强的模型 Fable 5 重新上线了。但这次不是常规回归，而是一个限时窗口。

Anthropic 的开发者关系负责人 cat 昨天确认，Fable 5 已经可以在 Claude 订阅里使用。不过窗口期极短，只到 7 月 7 日。之后它会转为按量付费，每百万 token 十到五十美元，是 Anthropic 目前最贵的模型。

即便在免费窗口内，Fable 5 消耗配额的速度也是 Opus 的大约两倍。而且每周最多只能用掉你订阅额度的 50%。Greg Isenberg 昨晚发了一条很实在的建议，他说 Fable 5 就像一套精致瓷器，别拿来热剩饭，要留给那顿真正重要的大餐。

Peter Yang 也给出了自己的策略。他用便宜模型准备上下文，让 Fable 做规划，执行层面交给其他模型。他还特别提醒，Fable 真正的超能力是 100 万 token 的上下文窗口。把整个代码库、一堆合同、或者几个月客户对话记录一次性扔进去，让它做那种你本来得切成十块的分析。

如果你打算认真测，Greg 的建议是直接上 200 美元一个月的 Max 套餐。低配套餐很容易撞墙。

Riley Brown 用了几天后的反馈是，感觉和几周前下架的那个版本几乎一样，没太大差别。但 Anthropic 内部工程师 Thariq 分享了一个更值得关注的角度。他说用 Fable 最重要的不是让它干活，而是用它来发现自己不知道的东西。他让 Fable 先列出它认为你知道什么，再列出它认为你不知道什么。这个做法在圈子里传了一夜。

另一件值得说的事。Vercel 昨晚给 agent 装上了“自我反思”能力。

Guillermo Rauch 亲自演示了 Agent Runs 功能。现在部署到 Vercel 的 agent 可以回溯自己过去的执行记录，自动发现低效步骤、错误、重复的工具调用。然后生成新的提示词和技能来改进自己。

Guillermo 说这就是 agent 的自我进化。关键在于，Vercel 把 agent 可观测性直接内置进了部署流程。agent 跑完之后，追踪数据自动被收录，可以被 agent 自己调取分析。

同时 Vercel Sandbox 现在支持 FUSE 文件系统和 Docker 了。Guillermo 说 MicroVM 是“不断在给的礼物”——即时启动、无限制运行时。他用十行代码演示了 agent 挂载 S3 文件系统。

换个方向。Box 的 CEO Aaron Levie 昨天发了一条长文，把 AI 行业正在发生的事概括成一句话：AI 的终极战场是“上下文”。

他的核心逻辑是这样的。agent 能不能干好活，取决于它有没有正确的领域知识、能不能接触到正确的上下文和工具、能不能嵌入到用户的工作流里。所以，能捕获和利用最好上下文的平台，就是 agent 干活最漂亮的地方。

Aaron 认为这就是为什么应用层远远不只是“LLM 包装器”。应用层要做的是组织关键知识，用可治理的方式维护它，并且持续改进 agent 的上下文。未来这一层会在不同模型之间路由任务——用前沿模型做规划和审查，用低成本模型跑海量日常任务。

他还提到了一个容易被忽略的点。应用层也是工作流变革管理的发生地。这就是为什么“前沿部署工程师”这个角色变得这么重要。客户要的是某个供应商端到端地解决一个具体的业务问题。谁能做到这一点，谁就有最深的护城河。

Hamel Husain 昨天提出了一个相关的质疑。他说现在 AI 圈同时流行两种互相矛盾的叙事。一种是你现在可以用 AI 干 20 个人的活，学会用 Claude 就够了。另一种是我们正在花几十亿美元部署前沿工程师，因为你自己搞不定，太费时间也太难了。

Hamel 说他更偏向第一种。但他觉得这两种说法放在一起，逻辑上说不通。他的追问很尖锐：当这些顾问离开之后，AI 系统怎么办？企业会不会对顾问产生终身依赖？顾问有没有动力让自己变得多余？

如果你在创业公司做 AI 落地，或者在大厂负责 agent 部署，这个问题值得你周末想一想。

今天值得展开聊的，是 Thariq 提出的那个方法——用 Fable 5 来“发现自己的未知”。

Thariq 是 Anthropic 内部负责 Claude Code 的工程师。他昨天发的推文和配套网页，在圈子里传了一夜。他的核心观点是，用 Fable 最重要的不是让它写代码，而是让它帮你找出你不知道的东西。

具体做法是这样的。在开始一个项目之前，他让 Fable 先列出“我认为 Thariq 已经知道的东西”。然后再列出“我认为 Thariq 还不知道的东西”。第二步产出的那个列表，往往就是他真正的盲区。知道盲区在哪之后，他就能更精准地写提示词。

他还做了一个 HTML 小工具，把未知项可视化出来。他说这个方法受到了 Geoffrey Litt 的启发，两人在 AIE 大会上深入讨论过，后来他又加上了测验功能。

这个思路跟 Greg Isenberg 的建议形成了有趣的互补。Greg 说要把 Fable 用在最重要的事情上。Thariq 则告诉你，怎么判断哪件事才是最重要的——让模型自己告诉你，你漏掉了什么。

Linear 的产品负责人 Nan Yu 昨天也转发了一条相关的观察。Alpha School 的 Nat Eliason 说，AI 在教育内容设计上表现极差。原因是学习科学在学术界实施得太差了，这些糟糕的实践已经嵌入了训练数据。模型自然会重蹈覆辙，还意识不到自己在犯错。

Nan Yu 的评论一针见血：如果一个领域产不出好的训练数据，那这个领域本身大概就充满了垃圾。

说回 Thariq 的方法。对听众来说，这个思路可以立刻复用。不管你用的是 Fable 5、Codex 还是其他模型，在开始一个复杂任务之前，先问模型一句：关于这件事，你觉得我还不知道什么？你得到的那份清单，可能就是接下来四天窗口期里最值得投入的方向。

Lenny 昨天发布了和 Codex 桌面应用负责人 Andrew Ambrosino 的深度访谈。Andrew 透露 Codex 的周活用户已经超过 500 万，比二月份翻了六倍。OpenAI 内部几乎所有员工都在用，不只是工程师。Andrew 的个人目标是做出“史上最好的桌面应用，没有之一”。他说了一句很有意思的话：人们过度强调了品味里的美学部分。Paul Graham 穿大裤衩，但品味明显很好。品味更多是关于系统思维、关于“我们要去哪”、关于怎么把东西呈现给用户。
