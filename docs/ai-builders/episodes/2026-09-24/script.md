Claude 独自发现了一种可能改写基因编辑规则的新机制，整个过程像在复刻一个博士生的高光时刻。Claude Code 的 plan mode 也许要没了，工程师们吵翻了天。而在硅谷的另一端，梦工厂的联合创始人写了一篇长文，他说，AI 不懂创造，但它是一块新的画布。先从最像科幻小说的那条新闻说起。

Claude 发现了一种隐藏在噬菌体 DNA 里的未知酶系统。它旁边有一段重复的 DNA 阵列，结构看着有点像 CRISPR。就在几个小时前，Dario Amodei 亲自公布了这项由 Claude 主导的生命科学发现。这个系统到底能做什么，现在还没人知道。但已知的是，拥有类似特征的系统都能切割、复制和粘贴 DNA。Dario 的原话是，这是他在读博时都会引以为傲的工作。Anthropic 的生命科学团队给了 Claude 一个大方向，它自己读文献、筛基因组数据，找到了这个异常点。然后它提了一组实验方案，由人类研究员在实验室完成验证。

这让人没法不联想到 CRISPR 的故事。当年 CRISPR 被发现后，直接催生了基因编辑药物。而今天，这个新系统背后是一种叫做逆转录酶的分子基础，正处在整个领域的研究热潮里。Dario 还提到斯坦福的一个独立团队最近也发表了一个类似的系统，但它们是完全独立进化的。也就是说，这可能不是孤例，而是一整类尚未被充分挖掘的分子机器。

Dario 把这件事放在一个更大的坐标系里。从 2023 年 AI 做高中数学题都很吃力，到今天能解决数学领域最顶尖的几个开放问题，生物学正在复刻同一条指数曲线。他认为 AI 推动生物学发现的速度被严重低估了，理由很简单——实验可以靠人机协作来完成。他甚至把这视为实现他"5 到 10 年内治愈大多数疾病"那个目标的第一步。如果你现在还没让 Claude 或同类模型碰过任何跟生物数据有关的事，也许可以想一想，这里面有没有你一直想验证、但缺人力的假设。

说到 Vercel，Guillermo Rauch 今天把 agent 的拆解思路讲得很直白。他画了一张图，说所有成功的 agent 都是三个部件的组合：大脑、手和文件。这件事的背景是，Vercel 的 Sandbox 环境今天正式上线了持久化存储功能，叫 Drives。它像一个可以随时插拔的外置硬盘，允许你在不启动完整 agent 计算机的情况下，直接读写文件。这让 agent 的记忆整理、夜间任务这类操作，不再需要烧着整台云电脑。

Guillermo 的原话是，把 agent 拆成独立部件不止省钱，还会大幅度提升安全性和可审计性。他甚至认为不拆开就没法做出安全的 agent。另一边，一直在死磕 agent 的 Peter Steinberger，也就是 OpenClaw 的创造者，今天也发了下个版本的路线图，准备让 OpenClaw 自己用一个决策模型自动判断该把新指令插队执行，还是放进队列。如果你正在纠结 agent 该跑在云端还是本地 Mac Mini 上，Guillermo 今天的这个脑、手、文件三分法，值得抄走当设计检查清单。

Google 这边，Gemini 3.8 Flash TTS 发布了。Logan Kilpatrick 一口气列了一串能力：2000 多个开箱即用的语音，覆盖 100 种语言，支持语音复刻。还有一个新的语音设计体验，以及即将推出的语音混音功能。直接的结果是它在 Hume  AI 的语音基准测试里拿了第一名。成本比上一代 ​3.1 Flash TTS 更低。如果你在做需要语音交互的产品，无论是客服、播客还是实时翻译，值得拉出来跑一遍。

再说一条在圈子里传了一夜的开源更新。CodexBar 的作者 Peter Steinberger 宣布，这个小工具现在支持插件系统了。你可以把 TypSafe、Nous Portal、Mus e Code、CodRabbit 甚至 HuggingFace 这些服务，写成一个 JavaScript 插件接入。它正在从一个单纯的编码辅助条，变成一个 agent 能力集散地，野心明显大于名字本身。

今天 Claude Code 团队的 Thariq 扔了一个问题出来，直接让评论区的工程师们吵得不可开交。他问，我们在考虑移除 plan mode，把 shift plus tab 这个快捷键改成切换努力程度。你们这些 plan mode 死忠粉能不能告诉我，为什么现在还离不开它？他的理由很简单，现在的模型已经不需要先把思路写出来再执行了。

但评论区的反驳很有意思，而且不止是情绪化的抵制。有开发者说，plan mode 对他来讲不是给 AI 看的，是给他自己看的。他在 Claude 开始动手改代码之前，需要先用 plan 确认大方向，这让他有掌控感。另一位指出，在做复杂重构的时候，plan 是唯一的刹车机制。一旦模型直接执行，改掉几十个文件，review 的成本太高了。还有一条被反复提及的观点是，plan mode 降低了信任成本。团队成员在共享 Claude Code 的会话记录时，plan 部分可以快速让别人理解当初的设计意图，不需要去追着几百行代码猜。

这些反对的声音，其实核心在讲一件事：plan mode 的功能已经从辅助模型思考，变成了辅助人类协作。它有点像一对编程时，你同伴在动手前跟你解释的那几句话。没有这几句话，代码可能跑了，但完全不知道为什么要这么写。而对 Thariq 提到的用快捷键调 effort level 这个新方案，有人问了一个很具体的问题：能量化吗？如果我今天晚上只是想快速跑一个实验，和明天上午要做一整个模块的开发，我真的会记得去调那个 effort level 吗？

听众里有大量在用 Claude Code 的。你是坚决站在 plan mode 这一边，还是觉得确实可以被 effort level 取代？如果你来设计，有没有第三条路？
