Vercel 因为一个第三方 AI 工具被攻破，攻击者是怎么绕过整个防御体系的？Lenny 和 Nikhyl 坐下来聊了一期播客，说一半的产品经理在未来两年会被甩出去，为什么？Aaron Levie 认为，你现在正在调试的 agent 架构，过不了几个季度就得推倒重来，这个节奏有解吗？先从昨晚最让人睡不着的那件事说起。

Vercel 的客户环境变量昨天遭到了未经授权的访问，攻击源头是一家做 AI agent 评估的创业公司 Context.ai。Vercel 的 CEO Guillermo Rauch 和官方账号在几个小时内连发了多条公告，把整条攻击链和应对措施摊在了桌面上。

按照 Guillermo 的陈述，事情是这样的。一名 Vercel 员工在使用 Context.ai 这款 AI 工具时，因为 Context.ai 自身被入侵，导致这名员工的凭证泄露。攻击者先拿到了这名员工被攻破的 Vercel Google Workspace 账号。接着，通过一系列提权操作，攻击者摸进了 Vercel 的内部环境。

这里有一个非常关键的细节。Vercel 在存储客户环境变量时，默认是全部静态加密的，布了多层纵深防御。问题出在一个功能设计上：Vercel 允许把某些环境变量标记为非敏感，不强制加密。攻击者很可能是通过枚举这些非敏感变量，找到了进一步渗透的机会。

Guillermo 原话里有一句挺重的判断。他说这个攻击组织极其老练，而且他强烈怀疑整个攻击被 AI 大幅加速了。攻击者展现出的移动速度和他们对 Vercel 内部架构的理解深度，都不太像传统的手工操作。Vercel 目前认为受影响的客户数量相对有限，已经优先联系了有顾虑的客户。

这件事的波及面可能会比公告里写的要宽。Vercel 紧接着公布了具体的处置动作：建议所有客户立即轮换密钥，监控对 Vercel 环境及关联服务的访问，并正确使用敏感环境变量功能。他们还在面板里新推了一个环境变量概览页，同时改进了敏感环境变量的创建和管理界面。

另外，第三方 AI 工具 Context.ai 的 OAuth 应用被确认是初始入侵点。Vercel 呼吁所有 Google Workspace 管理员立刻检查自己组织里有没有安装这个应用。

这起事件对听众有一个相当直接的提醒。你团队里任何一个人，在任何一个第三方 AI 工具上授权 Google Workspace 登录，就相当于把一整串权限委托出去了。攻击者只要拿下那个 AI 工具，就能顺着 OAuth 令牌直接走进你的核心系统。

如果你在用 Vercel，今天第一件事是去看那份安全公告。第二件事，检查你的团队都在哪些 AI SaaS 上做了 Google 账号授权，把不用的全部吊销。

另一件值得说的事。Lenny 昨天发布了一期和 Nikhyl 的深度对谈，里面对产品经理这个群体的判断可以说是毫无保留。

Nikhyl 的几个核心预测是这样的。未来两年会是 PM 历史上最混乱的时期。现在这一代产品经理里，可能有一半人熬不过这次转型。那些简历上挂着大厂 logo 的人，这次反而不占优势。Nikhyl 在大量顶级 PM 身上观察到了一种他称之为微笑型疲惫的状态，意思是不管嘴上怎么说，身体和心力都在透支。

他给出了一个非常具体的数字：整个行业可能会裁掉三万个 PM 岗位，然后重新招八千个 AI 原生 PM。Lenny 自己补充了一句很扎心的引语：那些在过去游戏里玩得最好的人，反而是这次重塑阶段最难转身的。

如果你自己是 PM，这期播客提供了一个对照框架。不是听结论本身，而是去听 Nikhyl 描述的那种能在下一阶段活下来的 PM 画像到底是什么样的，然后拿自己的工作流对一遍。

换个方向。Aaron Levie 昨晚转发了一则观察，接着写了一段非常实诚的白板分析，讲的是技术架构的迭代速度正在吃掉工程师的前期投入。

他的核心观点是这样的。模型进步太快了，快到你在部署 agent 时必须每隔一个或两个季度，就扔掉大量之前为了补偿模型短板而搭建的系统。他举了几个具体例子。你以前为了解决上下文窗口限制做的那些设计，现在已经没用了。以前需要各种复杂的 RAG、GraphRAG、多 agent 编排，现在很多时候直接把更多算力砸进一个更强的模型，效果反而更好。

他说的第二层更残酷。你不光要扔掉自己写的系统，连你部署 agent 的最佳实践，每隔十八个月就完全不同。你今天在用的企业级 agent 部署方法，放到一年半前根本不可行。而这一切没有要停下来的迹象。

Levie 最后留了一句话，说这就是为什么所有人现在都这么拼。因为你刚把一套最佳实践固定下来，模型又跳了一个量级，你之前的工就白做了。

这对听众来说，有个很实际的决策锚点。如果你正在搭 agent 的工具链，问自己一个问题：你现在的架构里，有多少比例是在补模型短板的，有多少是在真正释放业务价值的。前者的比例越高，下一次被模型更新掀桌子的风险就越大。

今天值得展开聊的，是 Aaron Levie 和 Nikhyl 都在指向的同一件事——AI 正在把职业和技术的折旧周期压缩到让人跟不上的程度，而不同角色感受到的痛感完全不一样。

先看工程师这一侧。Levie 说的是一套纯技术逻辑：每过几个季度，你上次的架构决策就废了。这不是渐进式优化，是直接推倒。以前一个后端工程师学会一套框架可以吃五年，现在可能连十八个月的保质期都不到。

再看 PM 这一侧。Nikhyl 讲的不是工具迭代，而是价值锚点的位移。过去 PM 的核心能力是协调资源、管理需求、写 PRD。但 AI 让执行成本暴跌之后，一个 PM 的价值不再体现在能不能把需求传下去，而是能不能在极度模糊的环境里，找到值得被实现的那个问题本身。

Roblox 的产品 Peter Yang 昨天也在反复倒腾自己的工具链，把 Claude Code 从终端版切到桌面版，又发现 Telegram 集成断了。他不是在炫配置，而是真的在用行动证明一件事：最佳工作流根本不存在，只有当下的最佳折腾路径。

郭宇昨天写了一段话，说在家 vibe 熬大夜只能算 60 分的辛苦，边 vibe 边和各种人解释自己在做什么，辛苦程度要到 90 分。他的建议是，思考和表达最好维持七三开。这其实和 Zara Zhang 早上说的事情撞在了一起。

Zara 的判断是，AI 越好用，产品团队越应该把时间花在外部沟通上：跟用户聊、跟客户聊。因为内部沟通的开销会随着团队变小而自然下降，真正值钱的部分变成了你对问题的理解。她特别提到一些独立创业者，现在的做法是整天跟客户聊天，然后把录音丢给 agent 处理，自己只管输入问题。

把这些声音放在一起看，你会发现一件事。不管你是 PM 还是工程师，折旧都在加速，但保值的方法在收敛。技术会旧、架构会旧，但对行业和用户痛点的深度理解，是模型暂时还撞不穿的护城河。

如果你最近正在考虑下一步该把时间砸在学新技术上，还是去多聊几个用户身上，Zara 那条建议值得认真想想。
