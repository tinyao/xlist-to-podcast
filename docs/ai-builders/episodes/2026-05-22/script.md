ClickUp 裁员 22%，CEO 说不是为了省钱，而是要重组成一个 100 倍产出的 AI 原生组织。这篇长文到底说了什么？Codex 和 Claude Code 同一天发布更新，agent 开始读取你的屏幕了。Justine Moore 反驳了一个流行的说法——AI 时代真的没有爆款消费应用吗？先从 ClickUp 那篇让 Lenny 连说两遍必读的长文开始。

ClickUp 裁员 22%，CEO Zeb Evans 发布了一篇长文，解释背后的逻辑。
Lenny Rachitsky 转发时标注了"重点阅读"，Peter Yang 随后也写了一篇评论。
这篇文章的标题叫"100x 组织"，核心论点很有争议性。

Zeb 首先说，这不是因为公司缺钱。ClickUp 现在是历史上最强的业务状态。
大部分节省下来的人力成本，会直接回投到留下的人身上。
他们甚至要引入百万美元级别的现金年薪带宽，几乎全公司都有路径争取。

但这个操作的关键不在薪酬。他在重新定义什么叫高效团队。
Zeb 说，AI 并没有让所有工程师都更高效。
恰恰相反，它让顶级工程师变成 100 倍产出的 builder，而其他人的存在，反而在拖慢这些人。

他想表达的逻辑是这样：现在代码不是写的，是 agent 生成的。
顶级工程师的工作变成了两件事——编排 agent 做什么，审核 agent 做出来的东西。
所以瓶颈就两个：谁能给 agent 最清晰的指令，谁能快速判断 agent 的输出靠不靠谱。

如果顶级工程师还要花时间审其他人的代码，或者审其他人让 agent 生成的代码，
那这个顶级工程师本身就成了瓶颈。他的时间被低质量的审阅消耗掉了。
所以 Zeb 说，正确的做法不是让每个工程师无限用 token 狂写代码。
那样只会让你的顶级工程师审 PR 审不过来，全是瓶颈。

他还特别提了 PM 和设计师的角色。
他说 PM 应该写代码，但只能在 playground 里写，用来快速验证和迭代想法。
那部分代码绝对不能进生产环境。
否则 PM 写的代码又变成顶级工程师的新瓶颈。
设计师和 PM 的边界在消融——设计师要懂用户，PM 要有 UX 直觉。
用户调研的瓶颈也消失了，一个 agent 指令就能启动整个研究流程。

Zeb 还说了一个他自己承认"今天还很争议"的观点。
他说在 AI 时代，如果某件事不在"管理系统、编排 AI、审核输出"这三件事里，那它大概率就是个瓶颈。
因此会出现一个全新的角色：系统管理者，或者说 agent 管理者。
那些主动学会用 AI 自动化自己工作的人，反而永远有工作——因为他们变成了这些 AI 系统的 owner。

Peter Yang 在自己的评论文章里提出了一个不同的角度。
他的标题是：别再写"是 AI 让我们不得不裁人"这种备忘录了。
他说这个 memo 模板已经烂大街了——CEO 宣布裁员，归因于科技进步和 AI 战略。
实际上这只是一种商业选择，外包归因为技术进步，显得好像没有别的人该负责。
Peter 说，真正需要回答的问题是：到底在做出这个选择的时候，公司考虑了哪些替代方案、承担了多少反思成本。

坦白说，ClickUp 这篇长文里最有价值的东西，不是裁员这个决定本身。
而是一套被明确写出来的假设和对未来的判断。
这些判断对不对，可以讨论。但它们白纸黑字写在那儿了，就逼着每个做工程团队管理的人去思考一个问题：
你的组织架构如果按"agent 生成代码，人只做编排和审核"来重新设计，会长什么样？

另一件值得说的事。
Codex 昨天更新了，Sam Altman 亲自转发。
这次更新的核心是一个叫 Appshots 的新功能。

Mac 用户按 Command-Command，就能把当前应用窗口的截图和文本内容一起喂给 Codex。
文本内容不止屏幕上能看到的部分，还包含屏幕外的隐藏内容。
Sam 说这是新版本的 Codex。
根据 OpenAI 开发者账号的说明，Appshots 在所有付费计划里可用，企业版也快了。

同一个时间，Claude Code 的 Boris Cherny 发了一条推文。
他说下一版 Claude Code 会多一个 /usage 命令。
敲一下就能看到 Skills、Agents、MCPs、Plugins 各自消耗了多少 token。
CLI 先上，Desktop 随后更新。

这两件事放在一起看，有一个信号。
agent 工具正在从"能不能干活"进化到"干活的成本能不能看、能不能管"。
Appshots 解决的是上下文供给——让 agent 看到的不是一段复制粘贴的代码，而是整个应用窗口的完整信息。
Claude Code 的 /usage 解决的则是 token 成本的可观测性。
这跟昨天我们聊的 Aaron Levie 说的 token 成本谜题，是同一条线上的不同拼图。

Justine Moore 昨天直接 refute 了一个常见说法。
有人说 AI 时代没有出现像 Flappy Bird 或 Wordle 那样让人记住的消费应用。
Justine 的回复很直接：ChatGPT 达到一亿月活只用了两个月。
而 TikTok 用了九个月，Instagram 用了三十个月。
她附了一张 App Store 截图，上面 AI 应用一排接一排。
她的意思很清楚：如果你觉得没看到 AI 爆款，可能只是你看的地方不对。

不过 Peter Yang 问的那个问题，跟 Justine 说的其实不矛盾。
Peter 在 slide 制作上的一个痛点今天被很多人共鸣。
他想用 HTML 加 Codex 或 Claude Code 做 slides，但每次插入图片都是一个巨大的痛苦。
得先把图片导出到一个文件夹，再让 agent 去认。
他问能不能直接粘贴图片到对话里让 agent 直接构建 slide。
回复里很多人说目前确实没办法，这是一个很具体的体验断层。

前天我们聊了 I/O，昨天聊了数学突破和 Exa 融资。
今天 ClickUp 这篇长文，把 AI 对组织的冲击，从技术层面直接推到了人事决策层面。
不妨把几件事连起来看，会更清楚这条线。

ClickUp 的 Zeb 说，100 倍工程师不做执行，只做编排和审核。
Anthropic 的 Boris 今天发布 /usage 说，你可以看到 agent 管线的每一个环节的 token 消耗了。
Anthropic 的研究员 Zara Zhang 昨天在 I/O 的分享会上，传了一张 T 型图——纵向是领域深度，横向是跨领域的宽知识，顶层是熟练使用 AI 的能力。
Zara 加了一句，这在每个职业角色上都适用，不只是开发者。

一条线穿下来的逻辑是：AI 不会均匀地提升每个人。
它会让一些人变得极其高效，同时让另一些人的工作变成瓶颈。
但瓶颈这个词，指向的不是某个人本身，而是原来那套工作流。
Zeb 的解法是把团队拆成 builder、agent manager、front-liner 这三种新角色。
他用裁掉 22% 旧岗位的实际动作，把这个逻辑翻译成了公司账本上的数字。

Peter 的提醒更实用。他说裁人就是一个商业选择。
不管你用"AI 转型"还是别的什么词来包装，最终要回答的问题就是一个。
这个选择到底是经过认真权衡的，还是只是节省认知成本，贴一个方便的标签。

对听众来说，哪怕你不在 ClickUp 工作，这篇长文也值得看两遍。
第一遍看框架——他画了一个 AI 原生组织的职能结构，不管准不准，至少画出来了。
第二遍把里面每一句话对照自己的团队问一遍：这一条在我们这儿成立吗？如果不成立，是模型能力还没到，还是我们的工作流根本不需要这样拆？

Felix 说他真的很佩服这种长期主义和专注力。

Justine Moore 转发了演示视频，评价说可控的图像编辑真的来了。

Riley Brown 昨天提了一个值得多想一秒的问题。
现在 codex 加 GPT 5.5 x-high，你可以直接让它帮你写一个"个人应用商店"，然后把你想要的应用列出来。用 /goal 模式，配上 Vercel AI Gateway 或 OpenRouter，它就能自动研究各应用的核必功能然后构建。
他说这不是夸张，试一下就知道。
Riley 也提到了 Vercel AI Gateway，说这是被严重低估的基础设施。如果你还没试过，这个周末也许可以试一下。

Box 的 CEO Aaron Levie 昨天对 FDE——也就是前向部署工程师这个角色——做了一段分析。
他说这个岗位会一直存在到 AI 停止快速变化为止。
但现在 AI 每三个月变一次，比当年云计算的迁移节奏快得多。
而且 agent 不仅影响技术栈，还直接改变人的日常工作流，所以推行 agent 的工程里，有一半是变更管理。
很多企业宁愿请第三方 partner，就是因为他们见过几百次实施过程，知道坑在哪里。
Aaron 说这会是很多技术人才的非常好的早期职业路径。
