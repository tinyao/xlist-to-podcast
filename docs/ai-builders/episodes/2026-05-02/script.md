Codex 的新功能 pets 和 hatch 是怎么回事，Sam Altman 为什么亲自下场说它比看起来更有用？Aaron Levie 怎么重新定义 agent 时代的软件定价，从 seat 到 consumption model 意味着什么？Stripe 的新 wallet for agents 会不会成为 agent 经济的关键基础设施？先从最热闹的那件事说起。

Codex 昨天发布了两个新功能：pets 和 hatch。
准确说，是 /pet 和 /hatch 两个命令。Peter Steinberger 先晒出了自己的 pet，说这个功能 "slaps"。Sam Altman 随后转发了 Peter 的帖子，说自己有一种奇怪的冲动，想让一个任务跑出史上最长的记录。没过多久，他又专门发了一条推文亲自站台，原话是 "这确实不是我们做过的最重要的事，但它比我一开始以为的要更有用"。
pets 是什么？简单说，是在 Codex 里养一个虚拟宠物。你可以唤醒它、和它互动。而 hatch 更关键一点。Nick Dobos 发了一个演示，称 /hatch 是他今年见过的最酷的 prompt：它可以自动生成并迭代一个完整的 sprite sheet。这对做游戏或者做像素美术的人来说，等于是把一整条素材生成管线塞进了一个命令里。Riley Brown 的评论很直白："我刚觉得 OpenAI 开始聚焦了，他们就上线了宠物"。
同时，Sam Altman 昨天还发了一条关于工具选择的态度帖，点赞数很高。他说那些"哪个更好"的投票都很蠢，用 Codex 或者用 Claude Code，什么顺手用什么。他很感激我们活在一个有这么多好工具、而且有选择的时代。
Peter Yang 呼应了这种感受。他说自己在一台没装 Codex 或 Claude Code 的电脑上工作时，会觉得像没穿衣服一样。这是个什么概念？这些 agent 已经从"生产力工具"变成了"工作环境的一部分"，缺了它们你会觉得不完整。如果你最近也有同感，那说明底层基础设施已经越过了一道心理门槛。

另一件值得说的事。Stripe 正式发布了 Link wallet for agents。
Riley Brown 转发了这个消息。这个产品让 agent 可以代表你花钱，但你的支付凭证永远不暴露，每一笔购买都需要你亲自批准。它的定位很清晰：agent 经济里的支付层。
郭宇在同一天也提到了支付的事。他在用自家的 wanman agent 做成本核算时发现，短信发送费用竟然非常高。而 wanman 的最新更新里就加了一个逻辑：如果 agent 在跑任务时需要付费，CEO agent 会在对话里请求你的许可，费用结算通过 Stripe 的 Link 服务处理。
一边是 Stripe 把 agent 支付做成标准化产品。另一边是郭宇的产品已经在实际跑这个流程。两条线碰在一起，说明 agent 经济在从"让 agent 干活"往"让 agent 花钱"这个方向走。如果你在搭 agent 产品，支付和审批流程可能会是接下来绕不开的一层。

说到 Aaron Levie，他昨天连发三条长帖，信息量很大，今天值得展开聊的，是这件事。

先把节奏放慢一点，说一下今天最值得想清楚的一件事。

Levie 的第一条长帖是接着之前几天讨论的那个话题往下走的。他引用了 Sam Altman 的一句话：OpenAI 想造的是增强和提升人的工具，而不是替代人的实体。
Levie 的观察是，硅谷以外的大多数企业想要的 AI 用例，就是增强和加速现有的工作方式。不是因为别的，而是因为大多数公司对自己现在的产出量根本不满意。他们总有一个瓶颈卡着。所以他们盯着那些又慢又低效的流程，想知道 AI 能不能让他们发更多产品、更快完成客户入驻、更好地解决客户问题。
他说了一句很关键的话：AI 的成本削减，很快就会被竞争侵蚀掉。因为你的对手会用 AI 更好地服务客户、更有效地竞争。减掉的成本，很快会被倒逼着再投回去。

第二条长帖更硬。Levie 直接抛了一个问题：当 agent 成为软件最大的用户，所有软件都必须以一种 headless 的方式被调用。agent 不会点你的 UI，只会调你的 API。那软件和这种 headless 模式的商业模型是什么？
他给了三点判断。
第一，人的 seat 不会消失。但每个 seat 必须带一定量的 API 调用额度，让 agent 能代替这个用户使用系统。如果你不做这件事，你就死了。
第二，agent 可能会有自己的 seat，但定价会完全不同于人的 seat。如果一家公司用一个 agent 做完所有事，另一家公司拆成一千个 agent，你没法按人头收费。这里每个平台会走不同的路，很难有一个统一方案。
第三，占主导地位的会是 consumption model，也就是按用量计费。很多企业级软件以前就有 PaaS 的定价经验，agent 在系统里看起来就像是另一个机器用户。有些情况下 API 会按本来面目定价，但也可能需要出现新类型的 API——不是一串调用，而是一个代表 agent 一次性完成某件事的"结果型"API。

郭宇昨天有一条推文，无意中给 Levie 的人 seat vs agent seat 提供了一个真实场景。他提到 AIDC 的概念，也就是推理加沙箱一体化的 AI 数据中心。他说 agent 的出现导致计算资源的某些供应链环节被大量放大，但还没有出现他预测中的那种新型数据中心。这里面的逻辑是同一件事：agent 不只是新写一段代码的用户，而是会改变整个资源消耗结构。

Levie 第三条帖子的落脚点很具体。他说 agent 的用量增长是真正无上限的，因为 agent 在系统里操作数据的场景会远远超过人今天对自己的数据和工具的用量。任何想过上 agent 这条船的平台，都得接住这个模型。有些平台一开始会抗拒，但这是必然的——平台外面的 agent 永远会比平台里面的人多。

回到听众的视角。Levie 把一件事讲清楚了。seat 不会消失，因为人还在。但 seat 的定价结构会被改写，因为它必须同时覆盖人和 agent 的用量。对于那些对接企业软件的你来说，这会直接影响到你选谁做底层系统、以及你的 agent 调用成本怎么设计。它会变成价格表上的一个白分比，还是一个新的收费项，现在还不好说。但不管怎样，它不会留在现在的价目表上不动。

Peter Steinberger 发布了 Crabbox 0.1.0。这是一个远程 Linux 测试箱工具，支持 AWS 和 Hetzner，能自动做 dirty checkout sync，闲置时自动释放。他一句话概括："agent 太多、测试套件太多、Mac 太累了"。

郭宇的 wanman agent 完成了一轮大更新。最关键的改动是增加了自动部署能力。agent 可以自己在 Cloudflare 上的用户账户下创建基础设施，从编码到部署全部由自己完成。需要付费时，agent 会在对话里请求你授权。

Justine Moore 发了一条调侃："我们太幸运了，特朗普的总统任期恰好发生在 AI 视频的黎明期"。她附了一段 Dilloneckes 做的 AI 视频，讽刺效果拉满。如果你对 AI 视频生成在政治内容里的边界感兴趣，这条值得点开看一眼。
