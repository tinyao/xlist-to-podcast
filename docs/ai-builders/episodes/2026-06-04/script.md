Replit 推出了第一个 vibe coding 的基准测试，结果和我们想的不太一样，是怎么回事？Uber 给员工的 AI 编程工具设了报销上限，这背后是多大的企业市场？还有，X 平台开始对内容搬运下手了，这对内容生态意味着什么？先从最让工程师睡不着的那件事开始。

Codex 的生态昨天出现了密集更新，它正从一个聊天工具，变成许多产品的默认界面。
开发者 Riley Brown 连续发了好几条帖子，演示了一个新玩法：Codex 刚上线的 Sites 功能，结合 Convex 新发布的数据库插件，能让你在三分钟内搭出一个可交互的内部工具。
流程是这样的：你告诉 Codex 你的想法，比如“我需要一个待办事项应用”，它直接生成一个带 Convex 后端的完整页面。
随后你还能写一个 skill，让 agent 在以后的任何对话里，都能直接读写这个数据库。
Riley 的演示视频里，整个搭建过程流畅到像在变魔术。
另一个值得注意的观察来自 Guo Yu。他提到，过去三个月，越来越多的产品不再构建自己的 UI，而是直接尝试接入 Codex。
他不禁发问，不知道 Stripe 看到这个趋势后会是什么心情。
你觉得呢？当你的产品入口变成别人的 AI 对话界面，壁垒还存在吗？

Replit 的 CEO Amjad Masad 昨天扔下了一枚重磅炸弹，发布了 ViBench，这应该是业界第一个专门评估 vibe coding 的基准测试。
结果很有意思。在编码基准测试上表现最好的 GPT 5.5，在端到端应用生成上，居然输给了 Opus 4.8。
Amjad 强调，Opus 4.8 的赢是全方位的，不仅质量更高，成本和性能也都更优。
这就引出了一个核心问题：现有的 SWE 基准测试，真的能衡量 AI 开发应用的能力吗？
ViBench 的测试集完全由真实世界的应用创建任务构成，和刷题式的测试完全是两码事。
如果你平时就在用 AI 做应用，我应该不用多解释，这个结果你很可能会在现实里对上号。

Uber 给员工 vibe coding 的工具费用设了每人每月一千五百美元的上限，原因是有人用超了。
这个数字本身不是重点，重点是 Box 的 CEO Aaron Levie 的点评。
他指出，企业为每个员工在 AI token 上的花费，已经远远超过了以往任何软件授权费。
过去，为一个员工买企业软件，公司每月花十到五十美元很正常。
现在，为了提效，每月花几百甚至几千美金在 token 上。
Levie 说，这很清楚地展示了企业里“智能”的总潜在市场有多大。
AI 的市场正在显著地超越传统软件市场的规模。

更具体的业务场景也在快速出现。Meta 昨天正式发布了一个面向企业的 AI agent。
扎克伯格在发布会上说，这个 agent 不仅能回答客户问题、预约服务，还能完成销售转化。
最终目标是让它能运营一整个业务。
Replit 的 CEO Amjad 转发了这条新闻，补了一刀：你可以逃，但你躲不开 B2B SaaS。
你会发现，无论是消费端还是企业端，通用大模型都在像一把热刀一样切进具体的工作流。

X 平台昨天宣布，要开始对所谓的“集成账号”或者说“内容搬运号”下手了。
Nikita Bier 发文说，这些聚合器是社交网络的毒瘤，全都在自动巡航。
X 会公开取消那些最恶劣的收集账号的变现资格，把他们拿出来当作典型示众。
平台的长期原则是，绝不会为重复的内容付两次费，只会奖励那些带来新增信息的人。
Riley Brown 对此评论道，任何一种自动化的社交媒体策略，寿命最多三个月。
在未来，唯一可持续的内容策略，就是做一个真人，真诚地去建立信任。

先把节奏放慢一点，说一下今天最值得想清楚的一件事。是关于 AI 开发范式的基建化。
这些信号我试着帮你穿起来。

起因是 Guo Yu 昨天抛出了一个非常大胆的预感。
他说，今年下半年，我们对模型 API 的请求，会逐步变成对模型 harness 的请求。
简单来说，模型不再是个你叫一声它就动一下的无状态计算单元了。
它需要一个挂载了必备工具的运行环境，就像是一个操作系统。
也就是说，未来的互联网应用，都会围绕这种 agent 操作系统来构建。

这个观点不是孤立的。
你看，我们刚聊了 Codex Sites 和 Convex 的整合。
本质上，这就是在给 AI 提供标准和指令都确定好了的“积木块”。
开发者 Riley Brown 的另一条推文就是专门讲这个的。
他认为未来 AI 为任何人搭建任何东西时，用的都是这些“积木块”。
这些积木对用户是透明的，agent 在后台默默调用它们、付点微服务费用就好。
Riley 特别提到，现在还有很多不显眼的、不性感的、无法立刻被验证的领域，这些积木还没人去造。
这就是机会。

另一边，Factory AI 宣布推出了“模型路由”功能。
Box 的 CEO Aaron Levie 对此作了深度评论，这简直就是 Guo Yu 那个预言的商业侧佐证。
他解释了为什么“模型路由”是 AI 应用层企业最大的差异化所在。
未来企业的token预算会成为一笔巨大的运营支出。
你不可能让所有的活儿都用最贵、最强的模型去干。
你必须深入理解自己业务的不同工作模式，配合强大的评估体系，把合适的任务分发给成本更低的模型去执行。
Levie 认为，单个企业自己搞不定这件事。
所以，能智能地将工作流路由到不同级别模型的产品，将拥有巨大的需求聚合优势。

你发现没有，从前端交互（Codex Sites），到后端任务分发（模型路由），再到整体的架构理念（模型 harness）。
都在朝着同一个方向走：把 AI 的开发能力“基础设施化”。
对个人开发者来说，现在入场的玩法不是去和巨头比做平台。
而是去寻找 Guo Yu 和 Riley 说的，那些还没有被做成标准积木的、不起眼的角落。
然后你去造好它，成为 agent 可以依赖的那个可信赖的模块。
这比空谈概念要具体得多，且现在就能动手。
