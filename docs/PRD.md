# XList to Podcast — 产品需求文档 (PRD)

**版本**: v1.0
**日期**: 2026-02-27
**状态**: Draft

---

## 1. 产品概述

### 1.1 背景

Twitter/X 上存在大量优质内容聚合在各类 List 中，但内容消费依赖碎片化刷屏。XList to Podcast 将用户订阅的 Twitter List 自动转化为每日播客，让用户在通勤、运动等场景中以音频方式消费推文内容。

### 1.2 目标用户

- 重度 Twitter 信息消费者，希望解放双眼
- 播客爱好者，希望将关注的 Twitter List 转为音频订阅
- 信息工作者，需要每日摘要某个垂直领域的推文动态

### 1.3 核心价值

| 价值点 | 描述 |
|--------|------|
| 自动化 | 每天自动抓取、生成、发布，零人工干预 |
| 个性化 | 用户自定义播客名称、封面、音色 |
| 标准化 | 生成标准 RSS Feed，兼容所有主流播客客户端 |

---

## 2. 用户流程

```
用户创建播客
    │
    ▼
填写表单 (List URL / 名称 / 音色 / 封面)
    │
    ▼
系统每日定时任务 (UTC 00:00)
    │
    ├─► 抓取 Twitter List 过去24小时推文
    │
    ├─► LLM 整理生成 Script + Shownotes
    │
    ├─► OpenAI TTS 生成音频 MP3
    │
    ├─► 上传 MP3 到阿里云 OSS
    │
    └─► 更新 feed.xml 到阿里云 OSS
         │
         ▼
    用户在播客客户端订阅 RSS URL 收听
```

## 3. 功能需求

### 3.1 播客创建 (P0)

**页面**：Web 表单（单页）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Twitter List URL | URL 输入 | ✅ | 格式：`https://x.com/i/lists/{list_id}` 或 `https://twitter.com/{user}/lists/{slug}` |
| 播客名称 | 文本 | ✅ | 最长 100 字符，用于 RSS title 和音频元数据 |
| 播客描述 | 文本域 | ❌ | 最长 500 字符，用于 RSS description |
| 音色选择 | 下拉选择 | ✅ | OpenAI TTS 支持的音色：alloy / echo / fable / onyx / nova / shimmer |
| 播客语言 | 下拉选择 | ✅ | 默认中文，支持中/英 |
| 封面图 | 图片上传 | ✅ | 建议 3000×3000px，JPG/PNG，≤5MB |
| 每日发布时间 | 时间选择 | ❌ | 默认 08:00 (Asia/Shanghai)，生成任务执行时间 |

**提交后**：
- 系统返回播客唯一 ID 和 RSS Feed URL
- 显示订阅引导（如何添加到 Apple Podcasts / Spotify / 小宇宙）

### 3.2 推文抓取 (P0)

- 使用 Twitter API v2 获取指定 List 的 Timelines
- 时间范围：过去 24 小时（基于任务执行时间）
- 过滤规则：
  - 排除纯转推（无附加评论的 RT）
  - 排除回复（以 @ 开头）
  - 排除字数少于 20 字的推文
- 每次最多处理 **100 条**推文（API 限制内）

### 3.3 内容生成 (P0)

使用 LLM（GPT-4o）将推文列表处理为：

**Script（播客朗读稿）**
- 风格：新闻播报风，流畅口语化，适合 TTS 朗读
- 结构：
  1. 开场白（今日日期 + 播客名）
  2. 主体内容（按主题归类推文，不逐条念，提炼核心观点）
  3. 结尾语
- 时长目标：**5~15 分钟**（约 1500~4500 汉字 / 750~2250 英文词）

**Shownotes（节目说明）**
- Markdown 格式
- 包含：内容摘要、关键话题标签、原始推文链接列表
- 用于 RSS `<description>` 和网页展示

### 3.4 语音合成 (P0)

- 使用 OpenAI TTS API（`tts-1-hd` 模型）
- 输出格式：MP3
- 根据用户选择的音色渲染
- 对于超过 4096 token 的 Script，自动分段合并

### 3.5 OSS 存储与 RSS 管理 (P0)

**文件结构**（阿里云 OSS bucket）：

```
/{podcast_id}/
    cover.jpg               # 封面图
    feed.xml                # RSS Feed（持续更新）
    episodes/
        {YYYY-MM-DD}.mp3    # 音频文件
        {YYYY-MM-DD}.md     # Shownotes
```

**RSS Feed 规范**：
- 遵循 RSS 2.0 + Apple Podcasts 扩展标签
- 每次生成新 episode 后追加 `<item>` 并更新 `<lastBuildDate>`
- 保留最近 **30 期**节目

### 3.6 播客管理页面 (P1)

- 查看已创建的播客列表
- 查看每期节目的 Shownotes
- 手动触发生成（用于测试）
- 删除播客

### 3.7 通知 (P2)

- 每日生成成功/失败后，发送邮件或 Webhook 通知

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 可用性 | 每日生成任务成功率 ≥ 95% |
| 时延 | 单期播客生成端到端时间 ≤ 5 分钟 |
| 安全 | API Key 不暴露前端；OSS 音频文件公开可读（播客需要） |
| 扩展性 | 支持单用户管理多个播客 |
| 容错 | 任务失败自动重试 3 次，记录错误日志 |

---

## 5. 约束与边界

- **不提供**播客托管 Web 播放器（用户自行用客户端订阅）
- **不支持**实时生成（仅每日定时）
- Twitter API 免费额度限制，每个 List 每天最多抓取 100 条
- 不处理视频、图片内容，仅处理文字推文

---

## 6. 成功指标

- 播客创建到首次 RSS 可订阅：< 30 秒
- 每日生成任务无人工介入完成率：≥ 95%
- 生成音频可在主流播客客户端正常播放
